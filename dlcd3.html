1. Sequential Building Blocks

Sequential building blocks are digital circuits that store information and change their state in response to a clock. Unlike combinational circuits, whose outputs depend only on their current inputs, sequential circuits have memory. This memory is generally implemented using flip-flops.

Two important sequential building blocks:

  1. Counters — a counter stores a binary value and changes that value according to a fixed counting sequence. A binary counter normally increments its stored value by 1 on every rising edge of the clock.
  2. Shift registers — a shift register stores multiple bits and moves the stored bits from one flip-flop to another on every clock edge.

2. N-bit Binary Counter

An N-bit binary counter is a sequential arithmetic circuit with:

  • A clock input
  • A reset input
  • An N-bit output Q

When reset is asserted, the counter is initialised to zero. After reset is released, the counter increments by 1 at every rising clock edge. It continues until it reaches its maximum value and then wraps around to zero.

COUNTER OPERATION
Qnext = Q + 1
Example: if Q = 0101, then at the next rising clock edge Q = 0110. Reset → Q = 0; thereafter on each rising edge Q → Q + 1.

2.1 Number of states

An N-bit binary number can represent 2N different combinations, so an N-bit counter has 2N states with values from 0 to 2N − 1.

STATES OF AN N-BIT COUNTER
number of states = 2N · range = 0 … 2N − 1
  • 3-bit counter: 2³ = 8 states: 000 → 001 → 010 → 011 → 100 → 101 → 110 → 111 → 000. After 111 the next value is 000 because all 8 combinations are exhausted.
  • 8-bit counter: 2⁸ = 256, so it counts 0 to 255 before returning to 0.
  • 4-bit counter: 16 states (0 to 15) — a MOD-16 counter.

2.2 Reset and clock

  • Reset initialises the output to 0.
  • The counter increments on the active clock edge (rising edge in the synchronous design above).
  • Reset → Q = 0, and subsequently on each rising edge Q → Q + 1.

2.3 HDL (synchronous reset has priority over increment)

module counter #(parameter N = 8)
               (input clk, input reset, output reg [N-1:0] q);
  always @(posedge clk)
    if (reset) q <= 0;       // reset has priority
    else       q <= q + 1;   // otherwise increment
endmodule

When both reset and the clock edge occur, reset wins (q <= 0).

3.1 Why T and JK flip-flops are preferred

T (toggle) flip-flop

  • Single input T
  • When T = 1, the output toggles on each clock edge
  • Directly divides clock frequency by 2 — ideal for counters and frequency dividers
  • Simple design, minimal logic

JK flip-flop

  • Versatile: Set, Reset, Hold and Toggle depending on J and K
  • J = K = 1 behaves exactly like a T flip-flop (toggle mode)
  • Eliminates the invalid-state problem of SR flip-flops
  • Widely used in counters for flexibility and reliability

4. Asynchronous (Ripple) Counters

In an asynchronous counter there is no common clock. Only the first flip-flop is driven by the main clock; each subsequent flip-flop is triggered by the output of the previous one, so the count ripples through the circuit. A ripple counter is a cascade of flip-flops where the output of one flip-flop acts as the clock input for the next.

From the timing diagram: Q0 changes at the falling edge of the clock, Q1 changes at the falling edge of Q0, and the same pattern continues for Q2 and Q3. This step-by-step change is why it is called a ripple counter or serial counter.

4.1 MOD-2 (1-bit) and MOD-4 (2-bit) counters

MOD-2 counter

  • With input logic 1, the FF output toggles on every falling clock edge
  • Output frequency = f/2
  • 2 unique output states (0 and 1)
  • Known as binary / MOD-2 / bit ripple counter

MOD-4 counter

  • Two FFs in series; output of one acts as the clock for the second
  • Second FF changes only when the first FF output is 1 and a falling edge occurs
  • Output Q1 frequency = f/4 (divide-by-4)
  • 4 unique states; output taken as Q1 (MSB) Q0 (LSB)

4.2 4-bit ripple counter (MOD-16)

  • Q0 toggles every pulse; Q1 every 2 pulses; Q2 every 4 pulses; Q3 every 8 pulses.
  • Together they form the binary sequence 0 → 15; each stage divides frequency by 2 (Q0 = f/2, Q1 = f/4 …).
  • The 4-bit ripple counter has 16 states.

4.4 3-bit asynchronous up/down counter

An up/down counter is used more than separate up or down counters. A mode control input M selects up or down mode, and a combinational circuit is inserted between every pair of flip-flops to decide whether the next flip-flop is clocked from Q (up) or Q′ (down).

5. Synchronous Counters & Design Procedure

A synchronous counter uses a single global clock that drives all flip-flops simultaneously, so all outputs change in parallel. It can operate at higher frequencies because it does not suffer from cumulative delay. Hence it is also called a parallel counter.

5.1 Design steps

  1. Decide the number of flip-flops (and their type).
  2. Write the excitation table of the chosen flip-flop.
  3. Draw the state diagram and the circuit excitation table.
  4. Solve for the flip-flop inputs using K-maps.
  5. Draw the logic diagram (all flip-flops on the same clock).

Equivalent detailed version: determine the counting sequence and number of states → number of flip-flops → state diagram → present-state/next-state table → select flip-flop type and use its excitation table → find required inputs of each flip-flop → simplify with Boolean algebra/K-maps → implement → connect all flip-flops to the common clock → verify the sequence.

6. Ring Counter & Johnson Counter

6.1 Ring counter

  • A shift-register-based counter in which the output of the last flip-flop is fed back to the first.
  • Consists of n flip-flops connected in a circular manner; a single 1 circulates with each clock pulse.
  • 4-bit example: 1000 → 0100 → 0010 → 0001 → 1000 → …
  • For n flip-flops → n valid states → MOD-n counter.
  • All flip-flops share a common clock; Q0 → Q1 → Q2 → Q3 → Q0.
ORI (OVERRIDING INPUT)

If PR (preset) = 0 then Q = 1; if Clr = 0 then Q = 0. ORI is used to initialise (preset) the ring counter to a valid starting state, usually 1000, before normal counting begins. ORI = 0 → initialise; ORI = 1 → normal ring-counter operation. ORI is not the clock — it is an overriding control that establishes the initial 1 in the ring.

Advantages

  • Simple circuit design; fast operation
  • Directly provides decoded outputs
  • No additional decoding logic required

Applications

  • Sequence generation
  • Timing and control circuits; timing signal generation
  • Stepper motor control
  • Digital control systems

Limitations

  • Needs n flip-flops for n states
  • More hardware than binary counters
  • Requires proper initialisation
  • 0000 is an invalid / stuck state

6.2 Johnson (twisted-ring / switch-tail) counter

  • A modified shift-register counter; also called a Twisted Ring or Switch-Tail Ring counter.
  • The complement of the last flip-flop output is fed back to the first: D0 = Q3′.
  • For n flip-flops it has 2n valid states (4-bit → 8 states).
  • Sequence from 0000 (repeats after 8 clock pulses): 0000 → 1000 → 1100 → 1110 → 1111 → 0111 → 0011 → 0001 → 0000

7.1 Exercise 5.43 — 32-bit synchronous up/down counter

Inputs: Reset, Up, CLK. Output: Q[31:0]. If Reset = 1 → Q = 0; if Reset = 0 and Up = 1 → count up; if Reset = 0 and Up = 0 → count down.

NEXT-STATE EQUATION
Q⁺ = 0 (Reset = 1)
Q⁺ = Q + 1 (Reset = 0, Up = 1)
Q⁺ = Q − 1 (Reset = 0, Up = 0)
Compact form: Q⁺ = Q + (2·Up − 1). Practical hardware: a 32-bit register, a 32-bit adder/subtractor controlled by Up (or a MUX choosing +1 / −1), and constant 1. Reset is synchronous — it overrides D on the clock edge, not an immediate clear.

7.2 Exercise 5.44 — 32-bit counter that adds 4 each clock

Inputs: Reset, CLK. Output Q[31:0]. Upon reset, Q = 0; every clock edge Q⁺ = Q + 4.

Hardware: a 32-bit register, a 32-bit adder and the constant 4 (a synchronous reset forces the register to 0).

8. Shift Registers

  • A chain of flip-flops sharing one clock.
  • On each clock edge a new bit enters at Sin; every stored bit moves forward one position; the oldest bit exits at Sout.
  • After N cycles all N bits sit together on the parallel outputs Q0 … QN−1.
  • Function: converts a serial (one-bit-at-a-time) stream into a parallel N-bit word.

8.1 Internal structure

  • Built from N flip-flops connected in series; each flip-flop's output feeds the next flip-flop's input.
  • All flip-flops share the same clock; some designs add a reset to clear all flip-flops to 0.

8.2 Adding parallel load

The basic shift register only does serial-to-parallel conversion. Adding a parallel data input D[N−1:0] and a control signal Load (a mux before each flip-flop) also supports parallel-to-serial.

LoadAction
1All flip-flops load directly from D (parallel load, one cycle)
0Register shifts normally (Sin feeds in, bits move forward)

8.3 HDL description

always @(posedge clk or posedge rst)
  if (rst)       q <= 0;
  else if (load) q <= data_in;          // parallel load
  else           q <= {q[N-2:0], sin};  // shift in sin
assign sout = q[N-1];
  • rst clears everything and has the highest priority.
  • load loads the full word from data_in in one cycle.
  • Otherwise bits shift up and sin fills the empty slot.
  • sout is always the top bit of the register.

Applications: serial-to-parallel and parallel-to-serial conversion, digital testing, data movement and temporary storage.

9. Testing Sequential Circuits: Scan Chains

9.1 The problem

  • Combinational circuits are easy to test: apply an input, check the output.
  • Sequential circuits are hard to test because the output depends on internal state.
  • Example: to verify bit 31 of a 32-bit counter flips 0→1, naively reset it and apply ~2 billion clock pulses.
  • There are also too many flip-flops to give each its own test pin.

9.2 The solution — scan chains

  • Connect all flip-flops in the system into one long shift register called a scan chain.
  • Normal mode: each flip-flop loads from its regular D input; scan connections are ignored.
  • Test mode: flip-flops shift data serially in/out via Sin/Sout — internal state can be read out or overwritten directly.
  • The mux that switches modes is usually built into the flip-flop itself, forming a scannable flip-flop (schematic, symbol, and an N-bit scannable register).

9.3 Worked example: testing a 32-bit counter

  1. Shift in the test pattern 0111…111 (32 bits) — 32 cycles.
  2. Switch to normal mode and run 1 clock cycle (the counter increments).
  3. Shift the result out — 32 cycles — and verify it reads 1000…000.
TEST TIME
32 (shift in) + 1 (count) + 32 (shift out) = 65 cycles
Compared with ≈ 2 billion cycles for the naive approach.

10. Memory Arrays: Overview & Organisation

A memory array stores many words using a 2-D array of 1-bit cells. Think of a spreadsheet: each row = one word, each column = one bit.

  • N address bits select one of 2N words.
  • Each word contains M data bits.
  • Depth = number of words (rows); width = bits per word (columns).
  • Memories are specified by size and by the number and type of ports.
MEMORY SIZE
Size = depth × width = 2N × M bits
Example: 10 address bits and 32-bit data → 2¹⁰ = 1024 words → 1024 × 32 = 32768 bits = 32 Kb.

4 × 3 example: 2 address bits select 1 of 4 words, each word has 3 bits, so total storage = 4 × 3 = 12 bits. Practical memories are much larger, but their operation can be understood with this small array.

Another example: 12 address bits and a 16-bit word → 2¹² = 4096 words; 4096 × 16 = 65,536 bits = 8,192 bytes = 8 KB.

10.1 Bit-cell organisation

  • The array is built from bit cells, each storing 1 bit.
  • Each cell connects to a wordline (selects the row) and a bitline (carries data to or from the cell).
  • For each address combination, a decoder asserts exactly one wordline.
  • When the wordline is HIGH, the selected cells are connected to their bitlines; when LOW the bitline is disconnected from the cell.
  • The circuitry used to store the bit depends on the type of memory.

10.2 Reading and writing a bit cell

Read

  1. Bitline is initially left floating (Z)
  2. Wordline is turned ON
  3. The stored bit drives the bitline to 0 or 1 (cell → bitline)

Write

  1. Bitline is strongly driven to the desired value
  2. Wordline is turned ON
  3. The strongly driven bitline overpowers the existing bit (bitline → cell)
  4. The value is stored

10.3 4 × 3 array: read and write walk-through

OperationSteps
Read address 10Decoder asserts wordline₂ → bitlines (initially floating) are driven by the selected row, which holds 100 → 100 appears on the Data bitlines
Write 001 to address 11Data bitlines driven to 001 → decoder asserts wordline₃ → 001 is stored in that row
REMEMBER

READ: wordline ON → stored data drives bitlines. WRITE: drive bitlines → wordline ON → store data.

10.4 Memory ports

A port gives access to one memory address. Memories may be single-ported or multiported. Example: a three-port memory has two read ports (addresses A1 and A2 read simultaneously) and one write port (writes WD3 to address A3 on the rising clock edge when the write is enabled). Practical example: a register file reads two source registers while writing one destination register in the same cycle.

12. DRAM, SRAM & Area / Delay

DRAM (Dynamic RAM)

  • Stores each bit as charge on a capacitor (charged = 1, discharged = 0)
  • Charge leaks → periodic refresh required
  • Reading disturbs/destroys the value, so the data is restored after a read
  • Simplified cell ≈ 1 transistor per bit → very dense

SRAM (Static RAM)

  • Stores the bit using cross-coupled inverters
  • No refresh needed while power is applied
  • The inverters restore the value if noise disturbs it
  • Typical cell ≈ 6 transistors per bit → larger but faster

12.1 Why "dynamic" and "static"?

  • Dynamic: stored charge leaks with time, data may be lost, so the value must be periodically refreshed.
  • Static: the two inverters continuously reinforce each other's state — if Q = 1 the feedback keeps Q = 1 and Q′ = 0; if Q = 0 it keeps Q = 0 and Q′ = 1. As long as power is supplied no refresh is needed.
  • Why SRAM is faster: DRAM must sense charge from a capacitor; in SRAM the logic state is already maintained by the transistor circuit.

12.2 Volatile memory: area and delay

MemoryTransistors / bitRelative latencyKey characteristic
Flip-flop≈ 20FastOutput available immediately
SRAM6MediumFaster access than DRAM
DRAM1SlowHigh density

More transistors generally mean more area, power and cost. Flip-flops give data immediately but need at least ~20 transistors; DRAM uses only 1 transistor per bit so it is the most area-efficient.

12.3 Why DRAM is slower

  1. During a read, charge moves from the capacitor onto the bitline.
  2. The bitline is not actively driven by a transistor.
  3. Charge movement is relatively slow → higher latency than SRAM.

DRAM also has lower throughput: it must periodically refresh its data and refresh after a read.

12.4 SDRAM and DDR SDRAM

  • SDRAM (Synchronous DRAM): uses a clock and pipelines memory accesses.
  • DDR SDRAM (Double Data Rate): transfers data on both rising and falling clock edges, doubling throughput for a given clock speed. DDR was first standardised in 2000 (100–200 MHz); DDR2, DDR3 and DDR4 increased clock speeds.
TAKEAWAYS

DRAM → lower area per bit but higher latency and lower throughput. SRAM → faster, more transistors. Flip-flop → fastest but largest per bit. Larger memories also tend to be slower than smaller ones; the right memory type depends on speed, cost and power.

13. Register Files

A register file is a group of registers used to store temporary variables in a digital system. It is usually a small multi-ported SRAM array, more compact than the same registers built from flip-flops, and it allows several registers to be accessed simultaneously.

13.1 32 × 32 three-ported register file

  • 32 registers × 32 bits each.
  • Two read ports: A1 → RD1, A2 → RD2.
  • One write port: A3, WD3, controlled by CLK and the write enable (WE3).
  • Each address is 5 bits because 2⁵ = 32.
  • Two registers can be read and one written in the same cycle (e.g. two source registers and one destination of an instruction).
REGISTER FILE NUMERICALS
address bits = log₂(32) = 5
total storage = 32 × 32 = 1024 bits

Summary: register file → small multi-ported SRAM → temporary storage → multiple simultaneous accesses.

14. Read-Only Memory (ROM)

14.1 Bit-cell working

  1. The bitline is weakly pulled HIGH.
  2. The wordline is turned ON.
  3. If a transistor is present it pulls the bitline LOW → stored bit = 0.
  4. If a transistor is absent the bitline stays HIGH → stored bit = 1.

Why ROM is nonvolatile: its bit cell is a combinational circuit and has no state that is lost when power is removed.

14.2 Dot notation

  • Rows → wordlines / addresses; columns → bitlines / data bits.
  • A dot at an intersection means stored bit = 1; no dot means 0.
  • Example 4 × 3 ROM: 2² = 4 words of 3 bits → 12 bits. The top wordline has a dot only on Data1, so the stored word is 010.

14.3 ROM as two-level logic

A ROM can be viewed as AND gates → OR gates. The first level (AND) generates all minterms and so works as a decoder; the second level (OR) combines selected minterms. So Address → Decoder → OR gates → Data, and a ROM can implement any two-level logic function (in practice transistors replace the gates to cut size and cost).

14.4 Types of ROM

  • Mask ROM: contents set during manufacturing (a transistor is present or absent); cannot be changed by the user.
  • PROM (programmable ROM, one-time programmable): transistors initially present; programming blows fuses with a high voltage. Fuse intact → transistor connected to GND → stores 0; fuse blown → transistor disconnected → stores 1. A blown fuse cannot be repaired, so it is one-time programmable.
  • EPROM (erasable programmable ROM): uses a floating-gate transistor. Programming: high voltage moves electrons onto the floating gate. Erasing: intense UV light removes them. Program electrically, erase with UV.
  • EEPROM: programmed and erased electrically; individual cells can be erased; no UV needed.
  • Flash: similar to EEPROM but erases larger blocks, needing fewer erasing circuits, so it is cheaper than EEPROM.

15. Logic Using Memory Arrays (LUT)

Memory arrays are primarily for storage, but a 2N-word × M-bit memory can implement any combinational function with N inputs and M outputs: the N inputs form the address, each input combination selects one row, and the M data bits stored in that row are the outputs. A memory array used to perform logic is a Lookup Table (LUT).

LUT SIZE
LUT size = 2N × M
Inputs → address → memory array → data outputs. The stored contents are the truth table.

15.1 Example: 4 × 3 ROM

4 words (2² → 2 inputs), 3-bit data (3 outputs): three functions of two inputs. Contents (address A1A0 → Data2 Data1 Data0): 00 → 011, 01 → 110, 10 → 100, 11 → 010. Hence Data2 = A1 ⊕ A0 (XOR), Data0 = NOR of the address inputs, and Data1 = A1′ + A0.

16. Memory HDL (RAM & ROM)

16.1 RAM

A 2N-word × M-bit RAM is declared as an array of M-bit words (N = 6, M = 32 gives 64 × 32). It has address, data in, data out, clock and write-enable.

logic [M-1:0] mem [2**N-1:0];

// synchronous write
always_ff @(posedge clk)
  if (we) mem[adr] <= din;

// immediate (asynchronous) read
assign dout = mem[adr];
  • Write happens on the rising clock edge when WE = 1: wait for the edge → check WE → store din at the selected address.
  • Read is immediate (asynchronous): the addressed location is connected to the output.
  • RAM contents are unpredictable at power-up.

16.2 ROM

Contents are fixed with a case statement on the address (the 4 × 3 ROM above):

always_comb
  case (adr)
    2'b00: dout = 3'b011;
    2'b01: dout = 3'b110;
    2'b10: dout = 3'b100;
    2'b11: dout = 3'b010;
  endcase

17. What is Computer Architecture?

Computer architecture is the programmer's view of a computer. It defines how software communicates with hardware by specifying:

  • Instruction Set Architecture (ISA) — the set of instructions the processor understands
  • Operand locations — registers and memory
  • Data representation and instruction formats — how data and instructions are encoded in bits

17.1 Why study computer architecture?

  • Bridges the gap between hardware and software
  • Determines how programs are executed by the processor
  • Helps design efficient, compatible and high-performance computer systems
  • Provides a foundation for understanding processor organisation and programming

17.2 Architecture vs microarchitecture

Analogy: architecture is like the controls available to a car driver; microarchitecture is the internal engine design used to implement those controls.

17.3 Many architectures, one idea

  • Many architectures exist, e.g. x86 (most PCs and desktop computers — Intel, AMD), MIPS (gaming consoles, networking, embedded — Nintendo, Cisco, Silicon Graphics), SPARC (workstations and servers — Sun Microsystems), PowerPC (computers and embedded systems — IBM, Apple).
  • Each architecture defines its own instruction set.
  • Instruction sets are like dialects of a language: they share the same basic ideas (arithmetic, logic, load/store, branch) but differ in names and formats. Once you learn one, learning another is fairly straightforward.
  • Instructions are the words of a computer's language; even complex applications compile down to simple instructions like add, subtract and jump, which the processor fetches and executes one after another.
  • The ISA is the interface between software and hardware: a program must be compiled for the ISA of the machine on which it runs. Software compiled for an ISA runs on any hardware implementing it; designers may implement the same ISA in different ways to trade off performance, cost and power.

18. Assembly Language & the MIPS Architecture

Instructions are commands in a computer's language. Assembly language is the human-readable format of instructions (mnemonics, e.g. add $s0, $s1, $s2); machine language is the computer-readable format of 1's and 0's (32-bit in MIPS, e.g. 0x02328020). An assembler translates assembly into machine code; the processor executes only machine code.

18.1 MIPS

  • MIPS = Microprocessor without Interlocked Pipelined Stages, a family of RISC (reduced instruction set computer) ISAs.
  • Developed by John Hennessy and colleagues at Stanford in the 1980s; commercialised by MIPS Computer Systems (now MIPS Technologies), United States.
  • Used in commercial systems such as Silicon Graphics, Nintendo and Cisco.
  • Philosophy: a small set of simple, regular instructions with 32-bit data and 32-bit instructions that can be decoded and executed quickly. Contrasts with CISC architectures like Intel x86.
  • Once you have learnt one architecture, it is easy to learn others.

18.2 Basic instructions

C codeMIPS assembly
a = b + c;add a, b, c
a = b - c;sub a, b, c

add/sub is the mnemonic (operation to perform); b, c are the source operands; a is the destination operand to which the result is written.

18.3 Multiple instructions

More complex code is handled by multiple MIPS instructions: a = b + c - d; becomes

add t, b, c    # t = b + c
sub a, t, d    # a = t - d

A RISC architecture minimises hardware complexity and the instruction encoding by keeping the set of distinct instructions small. An instruction set of 64 simple instructions needs log₂64 = 6 bits to encode the operation; 256 complex instructions would need log₂256 = 8 bits. In a CISC machine, complex instructions may be used rarely, yet they add overhead to all instructions, even the simple ones. Each MIPS instruction has only two sources and one destination, so longer expressions need temporary registers.

19. Four Architecture Design Principles; RISC vs CISC

  1. Simplicity favors regularity — uniform instruction formats simplify encoding, decoding and hardware. Arithmetic instructions all have two source operands and one destination (add $s0,$s1,$s2, sub $t0,$t1,$t2 → Destination = Source1 OP Source2). Regular designs are faster, more reliable and easier to design.
  2. Make the common case fast — optimise frequently executed operations. MIPS has a small set of simple, commonly used instructions that decode and execute quickly; complex operations are built from several simple ones (RISC), whereas x86 (CISC) makes individual instructions do more complex tasks.
  3. Smaller is faster — small structures such as the 32-entry register file have lower access time than large memory. Frequently accessed data stays in registers; compilers try to keep frequently used variables in registers.
  4. Good design demands good compromises — every design trades off performance, cost, power and complexity (e.g. RISC vs CISC). MIPS chooses simple instructions: simpler hardware, faster execution, lower power; the cost is more instructions per program.

20. Operands: Registers

An operand is the data used by an instruction. The three operand locations in MIPS:

  • Registers — high-speed storage inside the CPU for frequently accessed data
  • Memory — large storage for instructions and data that do not fit in registers
  • Constants (immediates) — fixed values encoded directly in the instruction

Example: addi $t0, $t1, 10 — $t0 destination register, $t1 source register, 10 immediate ($t0 = $t1 + 10).

20.1 Registers

  • MIPS has 32 general-purpose registers, each 32 bits wide — hence a "32-bit architecture" (registers and ALU operate on 32-bit data).
  • Registers are accessed much faster than memory; frequently used variables live in registers, less frequently used data in memory.
  • Every register name is prefixed with $ (e.g. $0 is read "dollar zero").
  • Why only 32? — "smaller is faster": a small register file has lower access time and balances performance and hardware complexity.

21. Operands: Memory, Byte/Word Addressing & Endianness

The 32 registers are insufficient for all program data, so main memory holds additional data and instructions. Memory is large but slower than registers. Data moves between memory and registers using load word (lw) and store word (sw).

21.1 Memory organisation

  • Memory is an array of data words. MIPS uses 32-bit addresses and 32-bit data words, and is byte-addressable (each byte has a unique address).
  • A 32-bit address can identify 2³² = 4,294,967,296 byte locations = 4 GB.
  • For explanation, a word-addressable memory is introduced first, then MIPS byte-addressable memory.

Word-addressable memory

  • Each address refers to one complete word (32 bits = 4 bytes)
  • Addresses increase by 1 word (0, 1, 2, 3 …)
  • Individual bytes cannot be addressed directly
  • Address 2 means the third word, not the third byte

Byte-addressable memory

  • Each address refers to exactly one byte (8 bits)
  • A 32-bit word occupies 4 consecutive addresses
  • Consecutive words start at 0, 4, 8, 12 …
  • More flexible: individual bytes can be accessed; used by MIPS
WHY ADDRESSES INCREASE BY 4

Example: bytes AA, BB, CC, DD at addresses 1000–1003 form one 32-bit word (AA BB CC DD); the next word starts at 1004. For an int array A: A[0] → 0, A[1] → 4, A[2] → 8, A[3] → 12 (0 → 4 → 8 → 12, not 0 → 1 → 2 → 3). Word address = word number × 4.

21.2 Reading memory — lw (load)

Syntax lw destination, offset(base). Reading memory into a register is a load.

EFFECTIVE ADDRESS
EA = Base Register + Offset
In MIPS the offset in lw/sw is measured in bytes, not words.
  • Word-addressable: lw $s0, 5($t1) with $t1 = 20 → address 20 + 5 = 25; the word at address 25 is loaded into $s0. lw $s3, 1($0) → EA = 0 + 1 = 1, memory word 1 (e.g. 0xF2F1AC07) loaded — one instruction transfers an entire 32-bit word.
  • Byte-addressable: lw $s3, 4($0) → EA = 4; bytes 4, 5, 6, 7 are combined into one 32-bit word and loaded into $s3.

21.3 Writing memory — sw (store)

Syntax sw source, offset(base); the register value is copied to the computed location. Example sw $t4, 0x7($0) → EA = 0 + 7 = 7; $t4 is written to memory word 7. In byte-addressable MIPS, the code reads words 0, 2, 3 and writes words 1, 8, 100 using word address = 4 × word number (offsets can be decimal or hex).

Load/store architecture: memory is accessed only by lw/sw — bring values into registers, operate on them, then store results back.

21.4 Big-endian and little-endian

A word has several bytes, so a rule is needed for numbering bytes within a word. Big-endian: numbering starts at the big (most significant) end — the MSB is stored at the lowest byte address. Little-endian: starts at the little (least significant) end — the LSB is stored at the lowest byte address. The word address is the same in both. The names come from Gulliver's Travels (eggs broken at the big or little end); it does not matter except when two systems share data.

Word 0x23456789 at address 0byte 0byte 1byte 2byte 3
Big-endian23456789
Little-endian89674523

Example: $t0 = 0x23456789, then sw $t0, 0($0) and lb $s0, 1($0) (loads the single byte at address 1). Big-endian: byte at 1 is 0x45 → $s0 = 0x00000045. Little-endian: byte at 1 is 0x67 → $s0 = 0x00000067.

Can an assembly program detect endianness? Yes, if byte-level access (lb/sb) exists: store a known word (e.g. 0x12345678 at address 1000) and load the first byte from that address. If it reads 0x12 → big-endian; 0x78 → little-endian. Equivalent: store 1 as a word, lb byte 0 — 1 means little-endian, 0 means big-endian.

addi $t0, $0, 1
sw   $t0, 0($0)
lb   $s0, 0($0)    # 1 -> little-endian, 0 -> big-endian

Without byte-level instructions (only lw/sw), endianness is not observable: it only affects the order of bytes within a multi-byte word, and if only whole words are stored and retrieved the internal byte order is invisible (bytes would have to be separated by shifts and masks).

21.5 Worked: word 42 and word 15 (Exercises 6.3, 6.4)

  • Byte address of word 42 = 42 × 4 = 168 = 0xA8; it spans 0xA8, 0xA9, 0xAA, 0xAB.
  • Storing 0xFF223344 (bytes FF 22 33 44; FF = MSB, 44 = LSB): big-endian A8:FF, A9:22, AA:33, AB:44; little-endian A8:44, A9:33, AA:22, AB:FF.

22. Operands: Constants / Immediates & Translation Examples

  • Constants are embedded directly within the instruction, so they are immediately available.
  • MIPS uses a 16-bit signed (two's complement) field for immediates.
  • They avoid loading small constants from memory (no extra memory access or register) and reduce the number of instructions.
  • addi adds a constant to a register; andi, ori, xori do bitwise operations with a constant.
WHY NO subi?

Subtraction of a constant is done by adding a negative immediate: addi $s1, $s0, -12 is b = a - 12. A separate instruction is unnecessary (regularity; make the common case fast).

# $s0 = a, $s1 = b
# a = a + 4;  b = a - 12;
addi $s0, $s0, 4      # a = a + 4
addi $s1, $s0, -12    # b = a - 12

22.1 Example 6.1 — translating high-level code

Assume a–c are in $s0–$s2 and f–j are in $s3–$s7.

# a = b - c;
sub $s0, $s1, $s2

# f = (g + h) - (i + j);    # f=$s3 g=$s4 h=$s5 i=$s6 j=$s7
add $t0, $s4, $s5     # t0 = g + h
add $t1, $s6, $s7     # t1 = i + j
sub $s3, $t0, $t1     # f  = t0 - t1

22.2 Left shift by 3 using only add and sub

Shifting left by 3 = multiplying by 2³ = 8; it can be done by adding a value to itself three times (doubling each time). With N in $s0:

add $t1, $s0, $s0    # t1 = 2N
add $t2, $t1, $t1    # t2 = 4N
add $t3, $t2, $t2    # t3 = 8N   (N shifted left by 3)

This uses registers $s0, $t1, $t2, $t3 — 4 registers in total (a single-register version add $t0,$s0,$s0 repeated three times also works, overwriting itself).

22.3 nor + addi + add sequence

With $s1 = 7 and $s2 = 4, the sequence nor $s3,$s0,$s2 / addi $s3,$s2,1 / add $s3,$s1,$s2 overwrites $s3 each time, so only the last instruction matters: $s3 = $s1 + $s2 = 11 (the sequence performs addition). Related idea: NOT x + 1 (nor with $0, then addi 1) is two's-complement negation, so nor $s3,$s2,$0 / addi $s3,$s3,1 / add $s3,$s1,$s3 would compute $s1 − $s2 = 3.

24. R-Type Instructions

  • Register-type, with 3 register operands: rs, rt — source registers; rd — destination register.

25. I-Type & J-Type Instructions

25.1 I-type

  • Two register operands and one immediate: rs, rt, and a 16-bit imm (two's complement for negative numbers).
  • All instructions have an opcode ("simplicity favors regularity"); the operation is completely determined by the opcode.
  • rs and imm are always source operands. rt is the destination for some instructions (addi, lw) but another source for others (sw).
InstructionRead it as

In load/store, rs = base register and imm = byte offset. addi/lw/sw sign-extend the immediate; andi/ori/xori zero-extend it. The 16-bit immediate is used in 32-bit operations: for positive immediates the upper half is all 0's, for negative immediates all 1's.

26.2 Immediate logical instructions

andi, ori, xori are I-type. Because they operate on a 32-bit register and a 16-bit immediate, the immediate is first zero-extended to 32 bits. nori is not provided — the same functionality is easily built from other instructions.

# $s1 = 0x000000FF, imm = 0xFA34 (zero-extended to 0x0000FA34)
andi $s2,$s1,0xFA34   # 0x00000034
ori  $s3,$s1,0xFA34   # 0x0000FAFF
xori $s4,$s1,0xFA34   # 0x0000FACB
WHY NO nori?

MIPS avoids instructions whose behaviour can be built from existing ones. nori would compute NOT(rs OR imm); this takes two instructions:

ori $t0, $s1, 0x00FF
nor $t0, $t0, $zero      # $t0 = ~( $s1 | 0x00FF )

nor with $zero works as bitwise NOT, so a dedicated nori is unnecessary.

27. Shift Instructions

Shift instructions move the value in a register left or right by 0 to 31 bit positions, multiplying or dividing by powers of two. MIPS has sll (shift left logical), srl (shift right logical) and sra (shift right arithmetic).

  • Left shifts always fill the least significant bits with 0's.
  • Right shifts: logical (0's shift into the MSBs) or arithmetic (the sign bit is copied into the MSBs).
  • Shifts are R-type: rt holds the 32-bit value to shift, shamt gives the amount, the result goes to rd (e.g. sll $t0, $s1, 4).

27.1 Variable shifts

  • sllv, srlv, srav take the shift amount from a register: sllv rd, rt, rs.
  • rt holds the value to be shifted; the 5 least significant bits of rs give the shift amount; the result goes to rd.
  • The order of rt and rs is reversed compared with most R-type instructions, and the shamt field is ignored (all 0's).
  • Memory tip: the variable amount comes from a register, not from the instruction bits (e.g. $s2 = 8 shifts by 8).

28. Generating Constants

16-bit constant: int a = 0x4F3C; uses addi with $0: addi $s0, $0, 0x4F3C → $s0 = 0x00004F3C.

29. The Stored Program Concept

  • Both 32-bit instructions and data are stored in memory; a program is stored as machine code (binary), each instruction at a unique address.
  • The only difference between two applications is the sequence of instructions stored; to run a new program there is no rewiring — it is simply stored in memory.
  • The processor fetches instructions from memory in sequence and performs the specified operation, one at a time.
  • Machine code is executed directly by the CPU (binary/hex, hard for humans, e.g. 0x8C0A0020); assembly code is the human-readable mnemonic form (lw $t2, 32($0)), easier to write, understand and debug.
PROGRAM COUNTER (PC)

To interpret machine language, decipher the fields of each 32-bit word. All formats start with a 6-bit opcode.

  3. Otherwise the opcode itself identifies the I-type or J-type instruction.
  4. Convert register numbers to register names carefully.
  5. Interpret the immediate as signed or unsigned as the instruction requires (andi/ori/xori zero-extend).

31. Arithmetic, Multiplication & Division

High-level languages (C, Java, Python) work at a higher abstraction level with if/else, for and while loops, arrays and function calls. This unit shows how to translate these constructs into MIPS assembly.

add  $t0, $s1, $s2     # $t0 = $s1 + $s2      (25 + 10 = 35)
sub  $t0, $t3, $t5     # $t0 = $t3 - $t5
addi $t0, $s3, -12     # $t0 = $s3 - 12

Logical instructions (and, or, xor, nor and their immediate forms) were covered under machine language.

31.1 Multiplication and division

These can produce more than one 32-bit result, so MIPS uses two special registers: HI (upper 32 bits) and LO (lower 32 bits).

  • mult $s0,$s1 — 32 × 32-bit gives a 64-bit product: HI = upper 32 bits, LO = lower 32 bits.
  • div $s0,$s1 — LO = quotient, HI = remainder.
  • Move results to general registers with mflo $t0 and mfhi $t1.
  • mul $s1,$s2,$s3 gives a 32-bit result directly in a general-purpose register.
# $s0 = 20, $s1 = 6
div  $s0, $s1
mflo $t0        # $t0 = 3  (quotient)
mfhi $t1        # $t1 = 2  (remainder)     20 ÷ 6 = 3 remainder 2
REMEMBER
div → LO = quotient, HI = remainder
mult → HI:LO = 64-bit product

32. Branching

Branch instructions change the normal sequential order of execution.

32.1 Conditional branches

  • beq rs, rt, label — branch if equal. If the registers are equal, control transfers to the label; otherwise execution continues with the next sequential instruction.
  • bne rs, rt, label — branch if not equal; branches only if the registers differ.
  • A label identifies the address of an instruction and acts as the branch destination; labels end with a colon and cannot be reserved keywords.

beq example

  • $s0 = 4; $s1 = 2 then doubled to 4
  • $s0 == $s1, so the branch is taken
  • Instructions between beq and target are skipped
  • At target, $s1 becomes 8 (4 + 4)

bne example

  • Same registers equal → bne condition false
  • Branch not taken; execution continues sequentially
  • addi updates $s1 4 → 5, sub updates 5 → 1
  • At target, $s1 becomes 5 (1 + 4)

32.2 Unconditional branches

  • j label — jump; always transfers control to the label, skipping the instructions between. Uses: skipping a block, implementing loops, moving to another program section. (Example: $s0 = 4, $s1 = 1, j target skips sra/addi/sub; at target $s1 becomes 5.)
  • jr rs — jump register; R-type; jumps to the address in a register, decided at run time (e.g. addi $s0,$0,0x2010 then jr $s0 skips 0x2008 and 0x200C and resumes at 0x2010 executing lw $s3, 44($s1)). Uses: returning from functions (jr $ra), computed jumps, indirect control transfer.
  • jal label — jump and link; jumps to a function and saves the return address (PC + 4) in $ra (e.g. jal at 0x00400200 → $ra = 0x00400204).

33. Conditional Statements

if, if/else and switch/case execute a block only when a condition holds. In MIPS they use conditional branches and labels.

33.1 if statement

if (i == j)
  f = g + h;
f = f - i;

    bne $s3, $s4, L1      # skip if i != j
    add $s0, $s1, $s2     # f = g + h
L1: sub $s0, $s0, $s3     # f = f - i

If i ≠ j the branch to L1 skips f = g + h; if i == j it is not taken and the add executes. Why bne instead of beq? Assembly tests the opposite condition so it can skip the if-block when the condition is false, giving simpler and more efficient code.

33.2 if/else statement

Needs a conditional branch to choose the block and an unconditional jump to skip the other block.

if (i == j) f = g + h;
else        f = f - i;

    bne $s3, $s4, L1
    add $s0, $s1, $s2
    j   done              # skip the else block
L1: sub $s0, $s0, $s3
done:

If i == j the if-block runs and j done skips the else; if i ≠ j control goes to L1; both paths continue at done.

33.3 switch/case

Selects one of several blocks by value; implemented as a series of conditional tests (nested if/else), with a default block when no case matches.

34. Loops (while, for) & Magnitude Comparison

34.1 while loop

Repeats a block while the condition is true; the condition is tested before every iteration. A conditional branch exits the loop and an unconditional jump repeats it.

while (pow != 128) { pow = pow * 2; x = x + 1; }

while: beq  $s0, $t0, done    # $t0 = 128; exit when pow == 128
       sll  $s0, $s0, 1       # pow = pow * 2
       addi $s1, $s1, 1       # x++
       j    while
done:

The C test is pow != 128, but the assembly tests the opposite (pow == 128) to decide when to leave the loop.

34.2 for loop

Components: initialisation (once, before the loop), condition (evaluated at the start of each iteration), statement (body), loop operation / update (end of each iteration, before the condition is rechecked). Flow: Initialisation → Condition → Statement → Update → Condition … → Exit. Ideal for count-controlled iteration.

for (i = 0; i != 10; i++) sum = sum + i;

      addi $s1, $0, 0       # sum = 0
      add  $s0, $0, $0      # i = 0
      addi $t0, $0, 10      # loop limit
for:  beq  $s0, $t0, done
      add  $s1, $s1, $s0
      addi $s0, $s0, 1
      j    for
done:

The loop exits when i == 10; final sum = 0 + 1 + … + 9 = 45.

34.3 Magnitude comparison with slt

beq/bne test only equality. slt $t1, $s0, $s1 sets $t1 = 1 if $s0 < $s1, else 0 (e.g. 5 < 8 ⇒ $t1 = 1). Combined with beq or bne it implements <, >, ≤ and ≥.

for (i = 1; i < 101; i = i * 2) sum = sum + i;

       addi $s1, $0, 0
       addi $s0, $0, 1
       addi $t0, $0, 101
loop:  slt  $t1, $s0, $t0     # i < 101 ?
       beq  $t1, $0, done     # exit if i >= 101
       add  $s1, $s1, $s0
       sll  $s0, $s0, 1       # i = i * 2
       j    loop
done:

Values added: 1 + 2 + 4 + 8 + 16 + 32 + 64 = 127. Key idea: slt converts a magnitude comparison into a 1/0 result that a branch can test.

35. Arrays & Character Arrays

An array stores same-type elements in sequential memory; the index starts at 0 and array[0] is at the base address.

ARRAY ADDRESSING
int array: address of array[i] = Base + 4i
byte (char) array: address of chararray[i] = Base + i

Base 0x10007000: array[0] → 0x10007000, array[1] → 0x10007004, array[2] → 0x10007008. Load the base with lui $s0, 0x1000 / ori $s0, $s0, 0x7000, then access with byte offsets:

# array[0] = array[0]*8; array[1] = array[1]*8;
lw  $t1, 0($s0)    # array[0]
sll $t1, $t1, 3    # x 8
sw  $t1, 0($s0)
lw  $t1, 4($s0)    # array[1]  (4 bytes after array[0])
sll $t1, $t1, 3
sw  $t1, 4($s0)

35.1 Array access in a loop

For a 1000-element array, compute the address from the index. sll $t0,$s1,2 gives i × 4 (since i × 4 = i × 2²).

# for (i = 0; i < 1000; i++) array[i] = array[i] * 8;   $s0 = base, $s1 = i
sll $t0, $s1, 2      # t0 = i * 4  (byte offset)
add $t0, $t0, $s0    # address of array[i]
lw  $t1, 0($t0)
sll $t1, $t1, 3      # array[i] * 8
sw  $t1, 0($t0)

35.2 Byte arrays and characters

  • lb load byte (sign-extends), lbu load byte unsigned (zero-extends), sb store byte (stores only the least significant byte of a register).
  • Consecutive elements are 1 byte apart: offset i, not 4i.

Lowercase → uppercase: ASCII 'a' = 0x61, 'A' = 0x41, so subtract 32 (0x20). With $s0 = base of char chararray[10]:

    addi $s1, $0, 0        # i = 0
    addi $t0, $0, 10       # limit
loop: beq $t0, $s1, done   # if i == 10, exit
    add  $t1, $s1, $s0     # address of chararray[i] = base + i
    lb   $t2, 0($t1)       # load chararray[i]
    addi $t2, $t2, -32     # lowercase -> uppercase
    sb   $t2, 0($t1)       # store result
    addi $s1, $s1, 1       # i = i + 1
    j    loop
done:

36. Function Calls, the Stack & Recursion

Functions make code reusable and modular. MIPS convention between caller and callee: $a0–$a3 carry the input arguments (more than four go on the stack); $v0–$v1 carry the return value. The caller calls with jal (saves PC + 4 in $ra and jumps); the callee returns with jr $ra.

jal simple          # call function
...
simple:
  jr $ra            # return to caller

36.1 diffofsums(f, g, h, i) = (f + g) − (h + i)

# caller
addi $a0, $0, 2
addi $a1, $0, 3
addi $a2, $0, 4
addi $a3, $0, 5
jal  diffofsums
add  $s0, $v0, $0       # result in $v0

# callee (simple version)
add $t0, $a0, $a1
add $t1, $a2, $a3
sub $s0, $t0, $t1
add $v0, $s0, $0
jr  $ra

Numerically (2 + 3) − (4 + 5) = 5 − 9 = −4, returned in $v0.

36.2 The stack

  • A LIFO memory structure for temporary data and local variables; it grows toward lower addresses; $sp points to the top.
  • If $sp = 0x7FFFFFFC and a function needs two more words, addi $sp,$sp,-8 gives $sp = 0x7FFFFFF4 (each word = 4 bytes).
  • Five steps for saving registers: allocate stack space → store registers → execute the function → restore registers → deallocate space. The space allocated is the function's stack frame.
# saving three registers: 3 x 4 = 12 bytes
addi $sp, $sp, -12
sw   $s0, 8($sp)
sw   $t0, 4($sp)
sw   $t1, 0($sp)
# ... function operations ...
lw   $t1, 0($sp)
lw   $t0, 4($sp)
lw   $s0, 8($sp)
addi $sp, $sp, 12
jr   $ra

36.4 Recursive functions — factorial

A leaf function calls no other function; a nonleaf function does; a recursive function is a nonleaf function that calls itself. factorial(n) = n × factorial(n − 1), base case factorial(1) = 1 (n = 3: 3! = 6). Each call gets its own frame to preserve $a0 and $ra (8 bytes).

factorial:
  addi $sp, $sp, -8
  sw   $a0, 4($sp)
  sw   $ra, 0($sp)
  addi $t0, $0, 2
  slt  $t0, $a0, $t0       # n < 2 ?
  beq  $t0, $0, else
  addi $v0, $0, 1          # return 1
  addi $sp, $sp, 8
  jr   $ra
else:
  addi $a0, $a0, -1
  jal  factorial
  lw   $ra, 0($sp)
  lw   $a0, 4($sp)
  addi $sp, $sp, 8
  mul  $v0, $a0, $v0       # n * factorial(n-1)
  jr   $ra

For factorial(3) the calls go 3 → 2 → 1, then returns give 1 → 2 × 1 = 2 → 3 × 2 = 6.

36.5 Additional arguments and local variables

First 4 arguments → $a0–$a3; additional arguments → stack (the caller expands its stack for them; the callee can access them in the caller's frame). The callee's frame may hold local variables/arrays, $s0–$s7 (if needed), $a0–$a3 (if needed), the return address and additional arguments. Flow: arguments → jal → callee → return value → jr $ra.

37. Addressing Modes

An addressing mode specifies how the CPU locates the operand(s) needed to execute an instruction. Operands may be in registers, memory locations, or inside the instruction itself. Addressing modes determine where operands are located, influence execution speed and memory usage, give flexibility for constants, variables, arrays, loops and function calls, and reduce instruction size.

MIPS has five modes: register-only, immediate, base, PC-relative, pseudo-direct.

37.1 1. Register-only addressing

  • All source and destination operands are CPU registers; used by all R-type instructions. The ALU reads operands from the register file, operates, and writes back to a register.
  • No memory access → fastest mode. Example: add $s0,$t2,$t3 → $s0 = $t2 + $t3.
  • $0 is hard-wired to 0, so sub $t8,$s1,$0 copies $s1 into $t8.

37.2 2. Immediate addressing

  • A 16-bit constant is encoded in the instruction along with a register operand; used by I-type addi, ori, andi, lui.
  • No memory access for the constant → faster. Uses: initialising registers, loop counters, increment/decrement, arithmetic/logic with constants.
  • addi $s4,$t5,-73 → $s4 = $t5 − 73; ori $t3,$t7,0xFF → $t3 = $t7 OR 0x00FF.

37.3 3. Base addressing

  • Used to access memory data by lw and sw. The processor computes the effective address, then reads (lw) or writes (sw).
  • The offset is a 16-bit signed value (positive or negative), so locations before or after the base are reachable.
  • lw $s4, 72($0): EA = 0 + 72 = 72, word at address 72 loaded into $s4. sw $t2, -25($t1): EA = $t1 − 25; $t2 stored there.
  • Applications: arrays, stack frames, structures, dynamically allocated memory — one instruction format.
  • Numerical: base register 5000, offset 24 → EA = 5000 + 24 = 5024.

37.4 4. PC-relative addressing

  • Used by conditional branches beq/bne. The instruction stores a 16-bit signed offset relative to the PC instead of the full address — shorter instructions, forward and backward branches.
  • The immediate stores the number of instructions to skip, not an address; hardware sign-extends it, multiplies by 4 (word aligned) and adds it to PC + 4.
0x10   beq  $t0, $0, else
0x14   addi $v0, $0, 1
0x18   addi $sp, $sp, 8
0x1C   jr   $ra
0x20 else: addi $a0, $a0, -1
0x24   j    factorial

PC = 0x10 → PC + 4 = 0x14; target else = 0x20; distance = (0x20 − 0x14)/4 = 3 instructions. Encoding: op = 4 (beq), rs = $t0 = 8, rt = $0 = 0, imm = 3. Check: 0x14 + 3 × 4 = 0x20.

Numerical: PC = 1000, offset = 5 → PC + 4 = 1004; 5 × 4 = 20; target = 1004 + 20 = 1024.

37.5 5. Pseudo-direct addressing

  • Used by j and jal (J-type): a 26-bit address field instead of the full 32-bit target. "Pseudo" because only part of the destination address is stored.
  • The processor forms the 32-bit JTA by taking the upper 4 bits of PC + 4, appending the 26-bit field, and adding two trailing 0 bits.
  • Jumps reach anywhere within the same 256 MB region (same upper 4 bits of PC + 4).
  • Why shift by 2: every instruction is 4 bytes and word-aligned, so the last two address bits are always 00 — omitted and restored by hardware. Unlike PC-relative, an address part (not an offset) is stored.

Example: 0x0040005C j sum with 0x004000A0 sum: add $v0,$a0,$a1. JTA = 0x004000A0 = 0000 0000 0100 0000 0000 0000 1010 0000; dropping the last two bits gives the 26-bit field 0x0100028; opcode for j = 000010.

38.1 Text segment

Stores the machine language program; large enough for almost 256 MB of code. The top 4 bits of every text address are 0, so j can jump directly to any program address. (Analogy: a recipe book; the PC is your finger on the current line.)

38.2 Global data segment

  • Stores global variables, visible to all functions, defined at start-up before execution (declared outside main in C); large enough for 64 KB.
  • Accessed with the global pointer $gp, initialised to 0x10008000. Unlike $sp it does not change during execution. Any global is reachable with a 16-bit positive or negative offset from $gp — known at assembly time, so base addressing with constant offsets is efficient.

Holds data not known at start-up, allocated/deallocated during execution; the largest segment (almost 2 GB).

  • Why link: large programs have many files; if only one changes, recompiling the rest is wasteful; library files almost never change; an unchanged file's object file need not be updated.

40. Parallelism: Latency, Throughput & Types

Parallelism is performing multiple operations simultaneously (or overlapping them) to improve performance, using additional hardware or overlapping stages. Its main objective is to increase throughput without significantly affecting the latency of an individual task.

Why? Simply raising the clock frequency leads to higher power consumption and heat, so performance must come from doing more work at once (like two chefs in a kitchen). Parallelism mainly improves throughput rather than reducing latency.

40.1 Latency and throughput

  • Latency — time for a single task (token) to travel from input to output.
  • Throughput — number of tasks completed per unit time.
LATENCY AND THROUGHPUT
Throughput = tasks completed / unit time
non-parallel: Throughput = 1 / Latency
High throughput does not necessarily reduce latency; latency may stay the same or even increase.

40.2 Cookie example (Ben): rolling 5 min, baking 15 min

Latency = 5 + 15 = 20 min per tray. Throughput = 60/20 = 3 trays/hour (no overlap).

40.3 Spatial vs temporal parallelism

Spatial

  • Multiple copies of hardware, each doing a different task simultaneously
  • Examples: multiple processors, ALUs, multicore CPUs
  • Higher hardware cost; true simultaneous execution

Temporal (pipelining)

  • One task divided into stages; different tasks occupy different stages (assembly line)
  • Example: Fetch → Decode → Execute → Memory → Write back
  • Reuses hardware → lower cost, better utilisation
CaseLatencyThroughput
Base (no overlap)20 min3 trays/hour
Spatial — Alyssa helps, both bake20 min3 + 3 = 6 trays/hour

Conclusion: parallelism improves throughput but does not reduce latency.

40.4 Mathematical model

THROUGHPUT MODEL (task latency L)
No parallelism: 1 / L
Spatial (N units): N / L
Temporal (N equal stages): N / L
Unequal stages: 1 / L₁ (L₁ = longest stage)
More stages help only if the work is evenly balanced.

41. Pipelining Numericals

41.1 Circuit without pipeline

Clock-to-Q delay 0.3 ns, logic blocks of 3, 2 and 4 ns, setup time 0.2 ns:

Tc = 0.3 + 3 + 2 + 4 + 0.2 = 9.5 ns
Latency = 9.5 ns
Throughput = 1 / 9.5 ns ≈ 105 MHz

41.2 Two-stage pipeline (register inserted after block 2)

Stage 1 = 0.3 + 3 + 2 + 0.2 = 5.5 ns
Stage 2 = 0.3 + 4 + 0.2     = 4.5 ns
Tc = max(5.5, 4.5) = 5.5 ns
Throughput = 1 / 5.5 ns ≈ 182 MHz
Latency = 2 × 5.5 = 11 ns   (about the same)

Cycle time falls 9.5 → 5.5 ns and throughput rises 105 → 182 MHz (an improvement of (181.82 − 105.26)/105.26 ≈ 72.7%), while latency stays about the same. The clock period equals the longest stage.

41.3 Three-stage pipeline: stage delays 3.5, 2.5, 4.5 ns

Tc = max(3.5, 2.5, 4.5) = 4.5 ns
Latency = 3 × Tc = 13.5 ns
Throughput = 1 / 4.5 ns ≈ 222 MHz

41.4 Why pipelining is attractive

  • No duplicate hardware; divides long combinational logic into shorter stages; enables a shorter clock period; improves throughput; uses hardware efficiently.
  • Pipeline registers isolate consecutive stages, preventing one token from interfering with another.

42. Parallelism: Advantages, Limitations, Hazards & Applications

Advantages

  • Increases throughput
  • Improves processor utilisation
  • Enables higher clock frequencies
  • Forms the basis of modern pipelined processors
  • Essential in multicore CPUs and GPUs

Limitations

  • Spatial parallelism needs additional hardware
  • Pipelining adds pipeline registers and control complexity
  • Unequal stages reduce efficiency (longest stage sets the clock)
  • Data and control hazards reduce performance

Applications: multicore processors, GPUs, supercomputers, digital signal processors, machine-learning accelerators. Modern processors combine spatial and temporal parallelism.

42.1 Pipeline hazards

Conditions that prevent instructions from flowing smoothly through the pipeline; they introduce stalls (bubbles) and reduce throughput.

  • Data hazard: an instruction needs data still being produced by an earlier instruction and must wait.
  • Control hazard: caused by branch/jump; wrong instructions may be fetched until the decision is known.
  • Structural hazard: two instructions need the same hardware resource at the same time.
KEY TAKEAWAYS

Latency = time for one task; throughput = tasks per unit time; spatial = multiple hardware units; temporal = overlapping via pipelining; parallelism mainly improves throughput while latency often stays unchanged.

43.2 Problem 2 — 4-bit counter FSM with run/hold and 7-segment output

Inputs clk, reset (synchronous, active high), run; outputs count[3:0] and seg[6:0] (common-cathode, active high). Two Moore states: RUN (run = 1) and HOLD (run = 0).

  • State diagram: RUN —run=1→ RUN (self-loop); RUN —run=0→ HOLD; HOLD —run=0→ HOLD (self-loop); HOLD —run=1→ RUN.
  • Next-count logic: RUN → count + 1 (mod 16, 1111 wraps to 0000); HOLD → count. A 2-to-1 MUX selects between (count + 1) and count, controlled by run, and feeds the D inputs of four flip-flops.
  • seg is generated combinationally from count.

module cnt7(input clk, reset, run, output reg [3:0] count, output reg [6:0] seg);
  wire [3:0] nxt = run ? count + 4'd1 : count;     // 2-to-1 MUX on run
  always @(posedge clk)
    if (reset) count <= 4'd0; else count <= nxt;
  always @* case (count)                           // seg = {a,b,c,d,e,f,g}
    4'h0: seg=7'b1111110; 4'h1: seg=7'b0110000; 4'h2: seg=7'b1101101; 4'h3: seg=7'b1111001;
    4'h4: seg=7'b0110011; 4'h5: seg=7'b1011011; 4'h6: seg=7'b1011111; 4'h7: seg=7'b1110000;
    4'h8: seg=7'b1111111; 4'h9: seg=7'b1111011; 4'hA: seg=7'b1110111; 4'hB: seg=7'b0011111;
    4'hC: seg=7'b1001110; 4'hD: seg=7'b0111101; 4'hE: seg=7'b1001111; 4'hF: seg=7'b1000111;
  endcase
endmodule
