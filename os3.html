UE25CS242A — Operating Systems · Unit 3

Memory Management

Main memory hardware and control structures, address translation, dynamic loading/linking, mmap(), swapping, fragmentation, segmentation, paging, page-table structures, TLB and EAT; virtual memory, demand paging, page faults, copy-on-write, page replacement (incl. clock), frame allocation, thrashing and NUMA.

Hardware & control structures

The CPU can directly access only registers (1 cycle) and main memory (many cycles, so a cache sits between). Programs must be loaded into memory to run. The OS must protect itself from users and users from each other.

Base and limit registers

Each process gets a contiguous legal range: the base register holds the smallest legal physical address and the limit register the size of the range. Every user-mode address is checked in hardware; a violation traps to the OS (addressing error). Only the OS, in kernel mode, can load these registers.

Legal address check
base ≤ address < base + limit

Logical vs physical address

A logical (virtual) address is generated by the CPU; a physical address is what the memory unit sees. The Memory-Management Unit (MMU) maps one to the other at run time. In the simplest scheme the relocation register (= base) is added to every logical address. The user program only ever sees logical addresses.

Dynamic relocation
physical = logical + relocation register

OS support & contiguous allocation

The OS keeps a table of which memory is free (holes) and used. In variable-partition allocation each process gets one contiguous block; freed blocks merge with adjacent holes. A hole is chosen by:

  • First fit — first hole big enough; fast.
  • Best fit — smallest adequate hole; must search the whole list; leaves tiny leftovers.
  • Worst fit — largest hole; leaves the largest leftover; usually worst.

First fit and best fit are better than worst fit in time and utilisation. The OS also provides protection (limit check), relocation, sharing, and memory for its own kernel (usually in low memory with the interrupt vector).

Dynamic loading, linking & shared libraries

Dynamic loading: a routine is not loaded until it is called; it sits on disk in relocatable form. Better memory use (unused code never loaded), no special OS support needed — it is the programmer's job.

Static linking: libraries are copied into the binary (large, self-contained). Dynamic linking: linking is postponed until run time; the image holds a stub that finds (or loads) the library routine and replaces itself with its address. Needs OS help to check that the library is in the process's address space.

Shared libraries (.so on Linux, .dll on Windows) are dynamically linked libraries whose code pages are shared by all processes (one physical copy), saving memory and allowing library updates without relinking; versioning avoids incompatibility.

Memory-mapped files & mmap()

A file is mapped to part of the virtual address space; reads and writes become ordinary memory accesses. Pages are loaded on demand (page fault reads a page-sized piece of the file) and written back later. No read()/write() system calls, no extra copy.

void *p = mmap(NULL, len, PROT_READ|PROT_WRITE, MAP_SHARED, fd, 0);
p[0] = 'A';          /* modifies the file */
munmap(p, len);      /* unmap; msync() forces write-back */
  • MAP_SHARED — changes visible to other mappers and written to the file; used for shared memory/IPC.
  • MAP_PRIVATE — copy-on-write; changes are not written to the file.
  • MAP_ANONYMOUS — no file; zero-filled memory (how malloc gets big blocks).

Swapping

A process can be swapped out to a backing store (fast disk) and later swapped back in, so total process memory can exceed physical memory. Needs execution-time binding if it returns to a different place. A process with pending I/O cannot be swapped (or I/O uses OS buffers). Standard swapping moves whole processes and is slow (transfer time dominates); modern systems swap pages, and mobile OSes avoid swapping and kill/ask apps to release memory.

Swap time
time = latency + size ÷ transfer rate (×2 for out + in)

Segmentation

Memory is viewed as a set of segments (main, functions, stack, heap, symbol table, arrays) — the user's view. Logical address = <segment-number s, offset d>. The segment table has a base and limit per segment; STBR/STLR locate the table.

Translation
if d < limit[s] → physical = base[s] + d, else trap (addressing error)

Pros: matches user view, easy sharing/protection per segment. Cons: segments are variable size → external fragmentation.

Paging

Physical memory is split into fixed frames, logical memory into equal pages (power of 2, 512 B–1 GB). A page table maps page → frame. No external fragmentation; some internal fragmentation (avg ½ page per process).

Address split (logical space 2m, page size 2n)
page number p = high (m − n) bits; offset d = low n bits
physical = frame(p) × page size + d
Sizes
pages = logical space ÷ page size · frames = physical memory ÷ page size
page table size = entries × entry size

The page table is in memory; PTBR points to it (PTLR gives its length). PTEs hold frame number plus valid/invalid, read/write/execute protection, dirty and referenced bits. Pages can be shared (e.g. reentrant code) by mapping the same frame. Every access costs two memory accesses unless a TLB is used.

Structure of page tables

Hierarchical (multilevel)

The page table is itself paged. Two-level (32-bit, 4 KB pages): p1 (10) | p2 (10) | d (12); p1 indexes the outer table, p2 the inner table. Unused regions need no inner tables. 64-bit addresses need more levels (x86-64 uses 4–5), each adding a memory access.

Hashed page table

Virtual page number is hashed; each bucket is a chain of (vpn, frame, next). Common for >32-bit spaces; clustered variants store several pages per entry (sparse spaces).

Inverted page table

One entry per physical frame holding (pid, page number). Table size depends on RAM, not on the number of processes, but lookup is a search (use a hash table) and shared pages are hard.

Translation Lookaside Buffer (TLB)

A small, fast associative cache of recent (page → frame) translations (64–1024 entries). Searched in parallel. Hit: frame obtained at once. Miss: page table is read from memory and the entry is loaded into the TLB (replacing an old one, e.g. LRU); some entries are wired down. An ASID in each entry identifies the process so the TLB need not be flushed on a context switch; without ASIDs it must be flushed.

Effective Access Time (EAT)

Paging with TLB (hit ratio α, TLB time ε, memory time m)
EAT = α(ε + m) + (1 − α)(ε + 2m)
Worked example

m = 100 ns, ε = 20 ns, α = 80%: EAT = 0.8(120) + 0.2(220) = 96 + 44 = 140 ns (40% slowdown). With α = 99%: 0.99(120) + 0.01(220) = 121 ns.

With demand paging (page-fault rate p)
EAT = (1 − p) × memory access + p × page-fault service time
Worked example

Memory = 200 ns, fault service = 8 ms: EAT = 200 + p × 7,999,800 ns. For <10% slowdown need 220 > 200 + 8,000,000p → p < 0.0000025 (1 fault in 400,000 accesses).

Virtual memory & demand paging

Virtual memory separates logical from physical memory: a program need not be entirely in memory, the virtual space can exceed physical RAM, more processes fit, and less I/O is needed. Implemented by demand paging (or demand segmentation).

Demand paging: a page is brought in only when referenced, by a lazy pager. The valid/invalid bit shows whether the page is in memory (v) or not (i). Pure demand paging starts a process with no pages in memory. Needs hardware support: page table with valid bit, secondary memory (swap space), and the ability to restart an instruction after a fault. Locality of reference makes it practical.

Page-fault handling

  1. Reference to a page marked invalid → trap to the OS.
  2. OS checks an internal table: invalid reference → terminate; just not in memory → continue.
  3. Find a free frame (if none, run page replacement).
  4. Schedule a disk read of the page into the frame.
  5. On completion, update the page table (frame, valid = v) and OS tables.
  6. Restart the instruction that caused the fault.

Fault service = trap + disk read (≈ 8 ms) + restart, so the fault rate must be tiny. Pre-paging and a pool of free frames reduce cost.

Copy-on-Write (COW)

After fork(), parent and child share the same pages marked copy-on-write. Only when either writes to a shared page is that page copied, so only modified pages are duplicated. This makes fork() cheap, especially when followed by exec(). Free frames for the copy come from a zero-fill-on-demand pool. vfork() lets the child use the parent's address space directly (parent suspended) — very fast but dangerous.

Page replacement

When there is no free frame, choose a victim: find the page on disk, pick a victim frame, write it out only if its modify (dirty) bit is set, read the new page, update tables, restart. Goal: lowest page-fault rate on a reference string.

Worked example — 3 frames

Reference string 7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1: FIFO = 15 faults, LRU = 12, OPT = 9.

Stack property Algorithms whose set of pages in n frames is always a subset of those in n + 1 frames (OPT, LRU) never show Belady's anomaly.

Clock (second-chance) replacement

Pages are on a circular list with a pointer (the clock hand) and a reference bit. To pick a victim: if the page under the hand has ref = 0 → replace it; if ref = 1 → set it to 0 (second chance), leave it, and advance the hand. If all bits are 1 it degenerates to FIFO after one full sweep. Enhanced clock uses the pair (reference, modify): prefer (0,0) best, then (0,1), (1,0), (1,1) — it favours pages that need no write-back.

Allocation of frames

  • Minimum frames per process come from the instruction set architecture (the instruction plus all its indirect operands must fit); the maximum is total frames.
  • Equal allocation: m frames ÷ n processes each.
  • Proportional allocation: by process size.
  • Priority allocation: proportional by priority, or priority-plus-size.
Proportional
aᵢ = (sᵢ ÷ S) × m, S = Σ sᵢ

Global replacement: victim from any process (better throughput, but a process's fault rate depends on others). Local replacement: victim only from the process's own frames (more consistent behaviour, possibly underused memory).

Thrashing

A process is thrashing when it spends more time paging than executing. Cause: it has fewer frames than its active locality needs, so faults replace pages that are needed immediately → CPU utilisation drops → the OS (wrongly) raises the degree of multiprogramming → worse.

  • Working-set model: WSSᵢ = pages referenced in the last Δ references. If D = Σ WSSᵢ > m, thrashing; suspend a process. Choose Δ well.
  • Page-fault frequency (PFF): set upper and lower fault-rate bounds; above upper → give more frames; below lower → remove frames; no frames free → suspend a process.
Thrashing condition
D = Σ WSSᵢ > m (total frames)

NUMA basics & memory locality

In NUMA multiprocessors each CPU (or board) has fast local memory and slower remote memory reached over an interconnect, so access time depends on location. The OS should schedule a thread on the CPU nearest its memory (processor affinity) and allocate memory from the local node; Linux/Solaris use locality groups (lgroups). Locality of reference (temporal: reuse soon; spatial: nearby addresses) is why caches, TLBs and demand paging work.
