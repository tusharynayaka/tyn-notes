Digital Logic and Computer Design

PART 01

Finite State Machines

How synchronous sequential circuits are modelled, designed, encoded and turned into hardware.

What is an FSM?

A Finite State Machine (FSM) is a model used to design synchronous sequential circuits. It works by moving between a limited (finite) number of states based on the current inputs and the present state of the circuit.

A circuit containing k registers can have 2^k different states, because each register stores one bit of information. The FSM can only be in one state at a time — this is what makes it "finite" and deterministic.

KEY POINT Finite State Machine (FSM): a digital circuit that stores its current state and changes to the next state on every clock edge. "Finite" means the machine has only a limited number of possible states.

Basic structure of an FSM

An FSM consists of five parts:

  • M Inputs — signals received from the external system.
  • N Outputs — signals produced by the circuit.
  • k-bit State Register — stores the current state of the FSM.
  • Clock Signal (CLK) — controls when the state changes.
  • Optional Reset Signal — returns the FSM to its initial state.
Fig. Basic FSM structure — Next-State Logic → State Register → Output Logic, with present state fed back.

The three main components and their jobs:

  1. Next-State Logic — computes the next state of the FSM.
  2. State Register (Memory) — stores the present state; updates it on every clock edge.
  3. Output Logic — generates the output signals of the FSM.

Working principle — on every clock edge, the FSM:

  1. Reads the current state.
  2. Accepts the current inputs.
  3. Computes the next state.
  4. Updates the state register.
  5. Produces the required outputs.

Moore vs Mealy machines

The outputs of an FSM are determined by which of the two classic models it follows:

Moore Machine
  • Output depends only on the current state.
  • Input changes do not immediately affect the output.
  • Output changes only after the state changes (one clock delay).
  • Outputs are written inside the state circles.
  • Usually needs more states than a Mealy machine for the same problem.
Mealy Machine
  • Output depends on the current state and the current input.
  • Output can change immediately when input changes.
  • Generally requires fewer states than a Moore machine.
  • Outputs are written on the transition arrows.
Moore output
Output = f(Current State)
Mealy output
Output = f(Current State, Current Input)
KEY POINT Moore machines usually require more states than Mealy machines for the same problem, but their outputs are glitch-free and stable — because they never depend on the input directly.

State & output encoding

Before implementing the FSM in hardware, states and outputs must be represented in binary — a process called Encoding.

1. State Encoding

Each state is assigned a unique binary code.

2. Output Encoding

Each traffic-light colour is also represented using binary values.

Why encode? Converts symbolic states into binary values, makes the FSM compatible with digital circuits, and simplifies the derivation of Boolean equations. After encoding, every state and output has a unique binary representation — the FSM has become a form that can be implemented in hardware.

Next-state logic & output logic

The Next-State Equations determine which state the FSM should move to, based on the current state and sensor inputs. The Boolean equations from the state transition table are simplified using Karnaugh Maps (K-Maps) or by inspection — reducing the number of gates and improving hardware efficiency. The Output Logic is derived the same way from the output table.

State encoding: binary vs one-hot

State encoding is the process of assigning binary codes to FSM states. The choice directly affects the hardware implementation — number of logic gates, propagation delay, and overall circuit complexity. Finding the theoretically optimal encoding is impractical for large FSMs (it means checking every possible combination), so designers pick a suitable encoding for the application, or let CAD tools choose one.

Worked example — Divide-by-3 counter

A Divide-by-3 Counter is a sequential circuit that reduces the frequency of the input clock by a factor of 3. It has one output Y and three states S0, S1, S2; Y becomes HIGH for one clock cycle out of every three. The counter cycles continuously: S0 → S1 → S2 → S0 → …

Current StateNext StateOutput Y
S0S11
S1S20
S2S00

To implement this in hardware, each state needs a binary code — using either Binary Encoding (2 bits) or One-Hot Encoding (3 bits, one flip-flop per state, only one bit HIGH at a time).

FSM Implementation — both encodings Binary encoding needs 2 flip-flops and combinational logic to decode 3 valid states out of 4 possible. One-hot encoding needs 3 flip-flops, but next-state logic simplifies to simple shifting between the "hot" bits, at the cost of extra hardware.

Factoring state machines

As FSM complexity grows, designing and maintaining a single machine becomes difficult. Factoring splits one complex FSM into multiple smaller, interacting FSMs — the output of one becomes the input to another, creating a hierarchical, modular design.

Extended example: the traffic controller gains a Parade Mode — while a parade is in progress, the Bravado Blvd light (L_B) stays green. Two new inputs are added: P (Parade — enables the mode) and R (Resume — exits it). When P=1 the controller enters Parade Mode and follows its normal sequence until L_B turns green, then holds it green throughout; R=1 exits Parade Mode and resumes normal operation.

Unfactored FSM (single machine)
  • States S0–S3 → Normal Mode, S4–S7 → Parade Mode.
  • The two halves are almost identical, except Parade Mode holds state S6 while L_B stays green.
  • One large FSM, more states, complex transitions, hard to debug or modify.
Factored FSM (two machines)
  • Mode FSM — tracks Normal vs Parade Mode, outputs signal M.
  • Lights FSM — controls the lights using T_A, T_B and M.
  • Multiple smaller FSMs, fewer states each, simpler transitions, modular and easy to extend.

Deriving an FSM from a schematic

Scenario: Alyssa P. Hacker's keypad lock has been rewired and the original unlock code no longer works. She has the circuit diagram and suspects it's controlled by an FSM — she must derive the FSM from the circuit to find the correct unlock sequence.

General procedure (7 steps):

  1. Examine the circuit and identify inputs, outputs, and state bits.
  2. Write the next-state and output equations.
  3. Create the next-state and output tables.
  4. Remove unreachable states.
  5. Assign symbolic names to valid states.
  6. Draw the state transition diagram.
  7. Describe the overall function of the FSM.

FSM design review — general procedure

  1. Identify the inputs and outputs.
  2. Draw the State Transition Diagram.

Part 02

Digital Building Blocks — Arithmetic Circuits

Adders, subtractors, comparators, the ALU, shifters, multipliers, and dividers.

Building blocks, hierarchy & modularity

Digital building blocks include gates, multiplexers, decoders, registers, arithmetic circuits, counters, memory arrays, and logic arrays. They all demonstrate three properties:

  • Hierarchy — built from a hierarchy of simpler components.
  • Modularity — well-defined interfaces and functions.
  • Regularity — a regular structure that easily extends to different sizes.

These blocks are later used to build a microprocessor.

A full adder differs from a half adder by accepting a carry-in C_in, which lets full adders be chained to add multi-bit numbers.

Multibit adders (Carry Propagate Adders)

Three types of CPA, trading off speed against hardware cost:

TypeSpeedHardware
Ripple-carrySlowLeast
Carry-lookaheadFastMore
PrefixFasterMost

Ripple-carry adder

Chains 1-bit full adders together — each carry ripples through the entire chain. Simple, but slow for wide words.

Ripple-carry delay
t_ripple = N · t_FA
where t_FA is the delay of a single 1-bit full adder

Carry-lookahead adder (CLA)

Computes the carry-out for k-bit blocks directly, using generate and propagate signals — instead of waiting for the carry to ripple.

  • Column i generates a carry-out if A_i AND B_i are both 1.
  • Column i propagates a carry-in to the carry-out if A_i OR B_i is 1.
Generate / propagate per column
G_i = A_i · B_i
P_i = A_i + B_i
C_i = A_iB_i + (A_i+B_i)C_{i-1} = G_i + P_i·C_{i-1}

Carry-lookahead addition, 3 steps:

  1. Compute G_i and P_i for every column.
  2. Compute block-level G and P for k-bit blocks.
  3. C_in propagates through each k-bit propagate/generate block.
4-bit block example
G3:0 = G3 + P3(G2 + P2(G1 + P1·G0))
P3:0 = P3·P2·P1·P0
General block form
Gi:j = Gi + Pi(Gi-1 + Pi-1(Gi-2 + Pi-2···Gj))
Pi:j = Pi·Pi-1·Pi-2···Pj
Ci = Gi:j + Pi:j·Cj-1
Fig. 32-bit CLA built from four cascaded 4-bit CLA blocks — carry passes between blocks, not between every single bit.
CLA delay (N-bit, k-bit blocks)
t_CLA = t_pg + t_pg_block + (N/k − 1)·t_AND_OR + k·t_FA

where t_pg is the delay to generate all P_i, G_i; t_pg_block is the delay to generate all block-level P_i:j, G_i:j; t_AND_OR is the delay from C_in to C_out of the final AND/OR gate in a k-bit block.

KEY POINTAn N-bit carry-lookahead adder is generally much faster than a ripple-carry adder for N > 16.

Prefix adder

Computes the carry-in for every column ahead of time, then computes all sums in parallel:

Sum equation
S_i = (A_i ⊕ B_i) ⊕ C_i

It computes G and P for 1-, 2-, 4-, 8-bit blocks etc., until every carry-in (G_i) is known — this takes log₂N stages. Column −1 holds C_in, so G_{-1} = C_in, P_{-1} = 0. The carry into column i equals the carry out of column i−1:

C_{i-1} = G_{i-1:-1}
S_i = (A_i ⊕ B_i) ⊕ G_{i-1:-1}

The goal is to quickly compute the "prefixes" G_{0:-1}, G_{1:-1}, G_{2:-1}, …

Generate / propagate for a block i:j
G_i:j = G_i:k + P_i:k · G_{k-1:j}
P_i:j = P_i:k · P_{k-1:j}

In words: block i:j generates a carry if the upper part (i:k) generates one, OR the upper part propagates a carry generated in the lower part (k-1:j). It propagates a carry only if both upper and lower parts propagate.

Prefix adder delay
t_PA = t_pg + log₂N·(t_pg_prefix) + t_XOR

where t_pg is the delay to produce P_i, G_i (an AND/OR gate) and t_pg_prefix is the delay of a "black" prefix cell (an AND-OR gate).

Adder delay comparison — worked example

Compare a 32-bit ripple-carry, carry-lookahead (4-bit blocks) and prefix adder. Assume: 2-input gate delay = 100 ps, full-adder delay = 300 ps.

Worked calculation
t_ripple = N·t_FA = 32(300 ps) = 9.6 ns
t_CLA = t_pg + t_pg_block + (N/k−1)t_AND_OR + k·t_FA
   = [100 + 600 + (7)(200) + 4(300)] ps = 3.3 ns
t_PA = t_pg + log₂N(t_pg_prefix) + t_XOR
   = [100 + log₂32(200) + 100] ps = 1.2 ns

This is the concrete payoff of the lookahead / prefix structures: roughly 3× and 8× faster than a plain ripple-carry adder at 32 bits.

Subtractor

A subtractor reuses the adder: to compute A − B, invert every bit of B (one's complement) and feed the result into an adder with C_in = 1 — this performs two's-complement subtraction, A + (~B) + 1, using the same hardware as addition with one extra XOR stage on the B inputs and the carry-in tied to a subtract-select signal.

Comparators

Equality Comparator

XORs each corresponding bit pair of A and B, then NORs all the results — output is 1 only if every bit pair matched, i.e. A = B.

Less-Than Comparator

Built from a subtractor: computes A − B and looks at the sign bit of the result — if it's 1, A < B.

Arithmetic Logic Unit (ALU)

A single reconfigurable block that performs all the standard arithmetic and logical operations, selected by a 3-bit control input F2:0:

Internally, a multiplexer selects between AND, OR, and a shared adder/subtractor path; F2 controls whether the adder acts as an adder or subtractor (by inverting B and setting C_in), and F1:0 selects the final output from the multiplexer.

Shifters

  • Logical shifter — shifts left or right, filling empty spaces with 0s.
  • Arithmetic shifter — same, but on a right shift fills empty spaces with the old most-significant bit (preserves sign).
  • Rotator — rotates bits in a circle; bits shifted off one end reappear at the other.
OperationExample (5-bit)Result
Logical right, >> 211001 >> 200110
Logical left, << 211001 << 200100
Arithmetic right, >>> 211001 >>> 211110
Arithmetic left, <<< 211001 <<< 200100
Rotate right, ROR 211001 ROR 201110

A shifter is usually built as a chain of multiplexer stages (a "barrel shifter"), each stage shifting by a power-of-two amount, selected by one bit of the shift-amount input — giving log₂N stages instead of N sequential single-bit shifts.

Shifters as multipliers / dividers

A << N = A × 2^N
A >>> N = A ÷ 2^N
Examples 00001 << 2 = 00100 (1 × 2² = 4)
11101 << 2 = 10100 (−3 × 2² = −12)
01000 >>> 2 = 00010 (8 ÷ 2² = 2)
10000 >>> 2 = 11100 (−16 ÷ 2² = −4)

Multipliers

Partial products are formed by multiplying each single digit of the multiplier with the entire multiplicand; the shifted partial products are then summed to form the final result — exactly like long multiplication in decimal, but in binary.

Fig. Partial-product formation for a 4×4 binary multiplier (illustrative).

A 4×4 multiplier takes two 4-bit inputs and produces an 8-bit product, using an array of AND gates to form partial products and a tree/array of adders to sum them.

Dividers

Division identity
A / B = Q + R/B

Restoring-division algorithm (as used by the 4×4 divider):

Algorithm 
R' = 0
for i = N-1 to 0
  R = {R' << 1, A_i}
  D = R - B
  if D < 0:  Q_i = 0, R' = R
  else:      Q_i = 1, R' = D
R' = R

Each iteration shifts in the next bit of the dividend, subtracts the divisor, and either keeps the subtracted (restored) remainder or reverts — producing one quotient bit per iteration.

Part 03

Number Systems

Fixed-point and IEEE-754 floating-point representation, rounding, and floating-point arithmetic.

Representing numbers in binary

  • Positive numbers — Unsigned binary.
  • Negative numbers — Two's complement, or Sign/Magnitude.
  • Fractions — need a different notation entirely (see below).

Two common notations for numbers with fractions:

  • Fixed-point — the binary point is fixed at an agreed position.
  • Floating-point — the binary point "floats" to the right of the most-significant 1.

Fixed-point numbers

The binary point is implied at a position both sides agree on beforehand — e.g. 4 integer bits and 4 fraction bits.

Example — represent 7.5₁₀ using 4 integer + 4 fraction bits Answer: 0111.1000 (stored as 01111000)

Signed fixed-point numbers

Two representation schemes:

Example — represent −7.5₁₀ using 4 integer + 4 fraction bits Sign/Magnitude: 11111000 (just flip the sign bit of +7.5)

Two's Complement:
  1. +7.5 → 01111000
  2. Invert all bits → 10000111
  3. Add 1 to the LSB → 10001000

Floating-point numbers

The binary point floats to the right of the most-significant 1 — similar to decimal scientific notation. E.g. 273 = 2.73 × 10².

Scientific notation
± M × B^E
M = mantissa, B = base, E = exponent (here M=2.73, B=10, E=2)

Three refinements are layered on top of this idea; the final version is the IEEE 754 floating-point standard.

IEEE 754 — building the format, step by step

Worked example — represent 228₁₀ as a 32-bit float
  1. Convert decimal to binary: 228₁₀ = 11100100₂
  2. Write in binary scientific notation: 11100100₂ = 1.11001₂ × 2⁷
  3. Fill in the 32-bit fields:
    • Sign bit = 0 (positive)
    • 8 exponent bits represent the value 7
    • remaining 23 bits are the mantissa (fraction)

Implicit leading 1 — the first bit of the mantissa is always 1 (since numbers are normalised), e.g. 228₁₀ = 1.11001 × 2⁷, so it never needs to be stored: only the 23 fraction bits after the point are kept.

Biased exponent (bias = 127 = 01111111₂ for single precision)
Biased exponent = bias + exponent
Exponent of 7 → stored as 127 + 7 = 134 = 10000110₂

Full 32-bit IEEE-754 layout: 0 | 10000110 | 11001000000000000000000 → hexadecimal 0x43640000.

Worked example — represent −58.25₁₀
  1. Convert to binary: 58.25₁₀ = 111010.01₂
  2. Binary scientific notation: 1.1101001 × 2⁵
  3. Fields: sign = 1 (negative); 8 exponent bits = 127+5 = 132 = 10000100₂; 23 fraction bits = 1101001 0000000000000000
In hexadecimal: 0xC2690000

Floating-point addition

Algorithm (8 steps):

  1. Extract exponent and fraction bits.
  2. Prepend the implicit leading 1 to form the mantissa.
  3. Compare exponents.
  4. Shift the smaller mantissa if necessary (align the binary points).
  5. Add the mantissas.
  6. Normalize the result mantissa and adjust the exponent if necessary.
  7. Round the result.
  8. Assemble exponent and fraction back into floating-point format.
Worked example — add 0x3FC00000 + 0x40500000

1. Extract fields
N1: S=0, E=127, F=.1  |  N2: S=0, E=128, F=.101

2. Prepend leading 1
N1 = 1.1  |  N2 = 1.101

3. Compare exponents
127 − 128 = −1 → shift N1 right by 1 bit

4. Shift smaller mantissa
N1: 1.1 >> 1 = 0.11 (× 2¹)

5. Add mantissas
0.11 × 2¹
+ 1.101 × 2¹
= 10.011 × 2¹

6. Normalize
10.011 × 2¹ = 1.0011 × 2²

7. Round
No rounding needed — fits in 23 bits.

8. Reassemble
S=0, E = 2+127 = 129 = 10000001₂, F = 0011 00…

Result: 0x40980000

  4. Both A and B
Answer: c) Excess-127
The material lists Sign/Magnitude and Two's Complement as signed fixed-point representations; Excess-127 is a floating-point exponent bias scheme, not a fixed-point representation.
Q2. In IEEE 754 single-precision floating-point format, how many bits are allocated for the exponent?
  1. 1
  2. 8
  3. 11
  4. 23
Answer: b) 8
Single precision uses 1 sign bit, 8 exponent bits, and 23 fraction (mantissa) bits.
Q3. Which IEEE 754 representation corresponds to NaN (Not a Number)?
  1. Exponent = 00000000, Fraction = 0…0
  2. Exponent = 11111111, Fraction = 0…0
  3. Exponent = 11111111, Fraction ≠ 0
  4. Exponent = 00000000, Fraction ≠ 0
Answer: c
NaN is represented by an all-ones exponent together with a non-zero fraction field.
Q4. During floating-point addition, what is the first operation performed after extracting the exponent and fraction bits?
  1. Normalize the mantissa
  2. Round the result
  3. Prepend the implicit leading 1 to form the mantissa
  4. Compare the exponents
Answer: c
After extracting the fields, the hidden leading 1 is restored before comparing exponents and performing the addition.
