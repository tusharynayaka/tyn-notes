Unit 3: Application of Trees and Introduction to Graphs

Binary search trees with dynamic allocation and arrays, expression trees, threaded binary trees, heaps and priority queues (min and max), the balanced trees AVL and splay, and an introduction to graphs — properties, adjacency matrix and list representations, and DFS and BFS traversal — with every formula collected at the end.

1. Trees and Binary Trees

A tree is a non-linear data structure: an acyclic, connected graph. A tree of n nodes has exactly n − 1 branches (edges). Add one more edge and a cycle appears; remove any edge and the connectivity between every pair of nodes is lost.

A general tree is defined recursively: it is either empty, or it has a root followed by a number of subtrees.

1.1 Terminology

  • Root, nodes, internal nodes, leaves, branches (edges), path, ancestor, descendant.
  • Parent, child, grandparent, grandchild, siblings, uncle.
  • Height, depth, level and the degree of a node (number of children).

Height here is counted as the number of edges on the longest root-to-leaf path (a single node has height 0); some books count nodes instead, so the numbers differ by one. Whichever convention is used, use it consistently.

1.2 ADT for a general tree

Create a tree · destroy the tree · check empty · check full · add a node · remove a node · traverse a tree · find root · find children · check whether a node is a leaf · find the height of the tree · find the path from the root to a given node.

1.3 Binary tree

A binary tree is a tree in which every node has at most two children, distinguished as the left child and the right child. It is either an empty tree, or a root node together with two disjoint binary trees called its left subtree and right subtree. Because the definition is recursive, writing recursive functions for its operations is natural.

1.5 Counting facts

Edges and pointers (node-based binary tree of n nodes)
edges = n − 1   |   pointers = 2n   |   NULL pointers = 2n − (n − 1) = n + 1

The n + 1 NULL pointers are what threaded trees reuse (see Threaded Binary Tree).

Size limits (standard results; root at level 0)
max nodes at level i = 2i   |   max nodes in height h = 2h+1 − 1   |   min height = ⌊log2 n⌋

A skewed tree has height n − 1; a complete tree has height ⌊log2 n⌋.

2. Binary Tree Traversals

A tree cannot be visited from one end to the other the way an array or list can. One systematic way is to visit the left subtree somehow, the root, and the right subtree somehow — applying the same rule recursively to every subtree. If a tree is empty there is nothing to visit. The three standard orders differ only in when the root is visited.

TraversalOrder of visitingFor the tree above
Inorderleft subtree → root → right subtreeD B E A C F
Preorderroot → left subtree → right subtreeA B D E C F
Postorderleft subtree → right subtree → rootD E B F C A

2.1 Inorder, step by step

  • Before visiting A, visit the left subtree of A (the subtree rooted at B).
  • Before visiting B, visit its left subtree (rooted at D). D's left subtree is empty, so visit D; D's right subtree is empty, so subtree D is done.
  • The left subtree of B is done, so visit B, then its right subtree: visit E.
  • The left subtree of A is done, so visit A, then its right subtree: C, then F.

Result: D B E A C F.

2.2 Algorithms

Inorder / Preorder / Postorder

Inorder: if the tree is not empty — visit left subtree in inorder, then the root, then the right subtree in inorder.

Preorder: if the tree is not empty — visit the root, then the left subtree in preorder, then the right subtree in preorder.

Postorder: if the tree is not empty — visit the left subtree in postorder, then the right subtree in postorder, then the root.

static void disp_recursive_inorder(node_t* temp)
{
    if(temp)
    {
        disp_recursive_inorder(temp->left_);
        printf("%d ", temp->key_);
        disp_recursive_inorder(temp->right_);
    }
}
/* preorder: print first, then left, then right
   postorder: left, then right, then print          */
Key facts

The tree structure itself is not recursive — the node structure, which is self-referential, is. So the tree functions (e.g. disp_inorder) simply call a recursive counterpart on the node (disp_recursive_inorder) with the root.

Inorder traversal of a binary search tree visits the keys in sorted (ascending) order.

3. Binary Search Tree — Concept and Implementation

A binary search tree (BST) is a binary tree in which every component has a key and components are arranged by key:

  • If the tree is empty, the new component becomes the root.
  • Otherwise compare with the key at the root: if the new key is less than the root's key, insert into the left subtree; otherwise insert into the right subtree.
  • Insertion therefore always happens at a leaf.
BST property
keys(left subtree) < key(root) ≤ keys(right subtree)    (holds recursively at every node)

3.1 Node-based implementation (dynamic memory)

The tree has a root, just like a list has a head. The root points to a node structure; each node holds a component (the key) and two pointers to its left and right subtrees.

struct tree { node_t *root_; };
typedef struct tree tree_t;

struct node
{
    int key_;
    struct node *left_;
    struct node *right_;
};
typedef struct node node_t;

3.2 Interface

FunctionWhat it does
void init(tree_t *ptr_tree)Ground the root
void deinit(tree_t *ptr_tree)Walk through the tree; remove left subtree, right subtree, then the root
void disp(tree_t *ptr_tree)Inorder traversal: display left subtree, root, right subtree

3.3 Insert

insert creates a node (assuming malloc succeeds), populates it, and calls insert_recursive, which returns the root of the (sub)tree. If the tree is empty the new node becomes the root; otherwise the return value of the recursive call on the left (or right) subtree is assigned back to root->left_ (or root->right_). Draw it for a tree of at least three nodes to see why returning the root works.

void insert(tree_t *ptr_tree, int key)
{
    node_t *temp = (node_t*)malloc(sizeof(node_t));
    temp->key_ = key;
    temp->left_ = temp->right_ = NULL;
    ptr_tree->root_ = insert_recursive(ptr_tree->root_, temp);
}

static node_t* insert_recursive(node_t* root, node_t* temp)
{
    if(root == NULL)
        root = temp;
    else if(root->key_ > temp->key_)
        root->left_  = insert_recursive(root->left_,  temp);
    else
        root->right_ = insert_recursive(root->right_, temp);
    return root;
}

3.4 Deinitialize

deinit calls deinit_recursive, which clears the left subtree, then the right subtree, and only then the root (a postorder walk). The order matters: freeing the root first would lose the pointers to its children.

void deinit(tree_t *ptr_tree)
{
    deinit_recursive(ptr_tree->root_);
    ptr_tree->root_ = NULL;
}
static void deinit_recursive(node_t* root)
{
    if(root)
    {
        deinit_recursive(root->left_);
        deinit_recursive(root->right_);
        free(root);
    }
}

4. Recursive Functions on Trees

These functions show how recursive routines are formulated on trees. Most use the simplest model of a binary tree: empty, or root followed by a left and a right subtree.

4.1 Count the number of nodes

If root is NULL return 0; else return 1 + nodes(left) + nodes(right).

int number_of_nodes_recursive(node_t* temp)
{
    if(temp == NULL) return 0;
    else return 1 + number_of_nodes_recursive(temp->left_)
                  + number_of_nodes_recursive(temp->right_);
}

4.2 Count the number of leaves

If root is NULL return 0; else if both subtrees are empty return 1; else return leaves(left) + leaves(right).

int number_of_leaves_recursive(node_t* temp)
{
    if(temp == NULL) return 0;
    else if(temp->left_ == NULL && temp->right_ == NULL) return 1;
    else return number_of_leaves_recursive(temp->left_)
              + number_of_leaves_recursive(temp->right_);
}

4.3 Check whether two trees are the same

Both empty → true. Exactly one empty → false. Otherwise: root keys equal and left subtrees same and right subtrees same.

int are_same_recursive(node_t* root1, node_t* root2)       // node
{
    if(root1 == NULL && root2 == NULL) return 1;
    else if(root1 == NULL || root2 == NULL) return 0;
    else return root1->key_ == root2->key_ &&
                are_same_recursive(root1->left_,  root2->left_) &&
                are_same_recursive(root1->right_, root2->right_);
}
int are_same(tree_t* t1, tree_t* t2)                        // tree
{   return are_same_recursive(t1->root_, t2->root_);   }

4.4 Copy one tree to another

If T1 is empty, T2 is empty. Otherwise make a node, copy the root key, copy the left subtree to the node's left, copy the right subtree to the node's right, and return the new node. copy_recursive returns a pointer to a node (because it builds new nodes), while the tree-level copy is void — it only stores the returned root into the destination tree.

node_t* copy_recursive(node_t* ptr_src)                     // node
{
    node_t *temp;
    if(ptr_src != NULL)
    {
        temp = (node_t*)malloc(sizeof(node_t));
        temp->key_   = ptr_src->key_;
        temp->left_  = copy_recursive(ptr_src->left_);
        temp->right_ = copy_recursive(ptr_src->right_);
        return temp;
    }
    else return NULL;
}
void copy(tree_t* ptr_src, tree_t* ptr_dst)                 // tree
{   ptr_dst->root_ = copy_recursive(ptr_src->root_);   }

5. BST Search and Delete

5.1 Search

If the tree is empty the key is not found. If the key equals the root's key it is found at the root. If it is smaller, search the left subtree; otherwise the right subtree.

What should search return?

Not a printed message — a function should print only if its job is displaying; the client cannot access information that was only printed.

Not just true/false — the client usually wants the component found for that key.

The right design is an iterator (a concept of position), which is outside this course; so we return a pointer to the node (NULL if absent).

node_t* search_recursive(node_t* root, int key)
{
    if(root == NULL) return NULL;
    else if(key == root->key_) return root;
    else if(key < root->key_) return search_recursive(root->left_, key);
    else return search_recursive(root->right_, key);
}
node_t* search(tree_t *ptr_tree, int key)      // non-recursive wrapper
{   return search_recursive(ptr_tree->root_, key);   }

5.2 Delete a key

This is the most complicated function on trees met so far. delete_key hands over to delete_key_recursive, which returns the new root of the subtree. First locate the node: empty tree → nothing to do; key smaller → recurse on the left subtree; key larger → recurse on the right subtree. When the match is found there are four cases:

CaseAction
1. Key at a leafFree the node and return NULL (ground the pointer in the parent).
2. Node has no left subtreeAttach its right subtree to the parent: save root->right_, free the node, return the saved pointer.
3. Node has no right subtreeAttach its left subtree to the parent: save root->left_, free the node, return it.
4. Node has both subtreesFind the inorder successor (leftmost node of the right subtree), copy its key into this node, then delete that key from the right subtree.
node_t* inorder_successor(node_t* root)      // call with root->right_
{
    node_t* temp = root;
    while(temp->left_ != NULL)
        temp = temp->left_;
    return temp;
}

node_t* delete_key_recursive(node_t* root, int key)
{
    if(root == NULL) return NULL;                              // empty tree
    else if(key < root->key_) root->left_  = delete_key_recursive(root->left_,  key);
    else if(key > root->key_) root->right_ = delete_key_recursive(root->right_, key);
    else                                                       // match found
    {
        if(root->left_ == NULL && root->right_ == NULL)        // 1. leaf
        {   free(root); return NULL;   }
        else if(root->left_ == NULL)                           // 2. no left
        {   node_t* temp = root->right_; free(root); return temp;   }
        else if(root->right_ == NULL)                          // 3. no right
        {   node_t* temp = root->left_;  free(root); return temp;   }
        else                                                   // 4. both
        {
            node_t* temp = inorder_successor(root->right_);
            root->key_ = temp->key_;                           // replace
            root->right_ = delete_key_recursive(root->right_, temp->key_);
        }
    }
    return root;
}

5.3 Cost of BST operations

A BST lets us discard one subtree at every comparison, but that does not guarantee log2 n comparisons: inserting sorted keys makes the tree skewed, degenerating into a list where search takes time proportional to n. This is the motivation for height-balanced trees (AVL) and self-adjusting trees (splay).

Search / insert / delete in a BST
O(h)    best/average: h ≈ log2 n    worst (skewed): h = n − 1

h = height of the tree.

6. Storing and Restoring a Tree (Persistence)

A list can be stored by traversing it and writing the components to a file, then restored by reading them back and attaching each at the end. A tree is non-linear, so a single traversal does not define it. For example, if a 3-node tree has inorder traversal A B C, there are 5 different trees that produce it.

Rule

An inorder and a postorder traversal together uniquely define a binary tree. The rightmost key of the postorder list is the root; locating it in the inorder list splits the inorder list into the left subtree (before it) and right subtree (after it). Repeat on each part, scanning the postorder list from right to left.

Worked example (10 nodes)

  • Inorder: D B H E A F C G J I
  • Postorder: D H E B F J I G C A
  • Last in postorder is A, so A is the root. In the inorder list, D B H E lie left of A (left subtree) and F C G J I lie right of A (right subtree).
  • Moving left in postorder, the next key is C, which is on the right of A in inorder: C is the root of A's right subtree.
  • Continue the same way: right subtree of C is rooted at G (inorder: F | C | G J I), then I, with J as I's left child; left subtree of A is rooted at B, whose right subtree is rooted at E with H as its left child.

7. Implementing a BST Using Arrays

Three ways of implementing a binary search tree are discussed: (1) node-based with dynamic memory (done above), (2) an array that relates a parent to its children by index arithmetic, and (3) an array of node structures holding the indices of the children.

7.1 Array based on parent–child index relation

Only the components are stored — no indices or pointers. Whether or not index 0 is used changes the mapping:

IndexingParentLeft childRight child
0-basedi2i + 12i + 2
1-basedi2i2i + 1
Index mapping (1-based; root at index 1)
left(i) = 2i    right(i) = 2i + 1    parent(i) = ⌊i / 2⌋

0-based: left(i) = 2i + 1, right(i) = 2i + 2, parent(i) = ⌊(i − 1) / 2⌋.

  • Compact and good only for complete binary trees (all higher levels full, last level filled from the left). Otherwise many slots stay empty.
  • To know whether a slot is filled a dummy value that is not a valid key is needed.
  • This is the method used for heaps.

Example (1-based) for keys 50, 30, 70, 20, 40, 60, 80:

Each node has the key and the index of the left and right subtree instead of pointers; -1 plays the role of NULL. For keys inserted in the order 50, 30, 70, 20, 40, 60, 80:

The array content depends on the order of insertion. Whenever a new key arrives we must find a free slot; after deletions free slots appear at different places, so a robust implementation needs a simple memory manager keeping a list of free slots (give one on request, take it back on deletion). Otherwise insertion is limited by the array size, not by the slots actually free. The notes' example omits the memory manager and key deletion for simplicity.

7.3 Structure and interface

#define MAXSIZE 200
struct node { int key_; int left_; int right_; };   // indices, not pointers
typedef struct node node_t;

struct tree
{
    int root_;                 // index of root; -1 means empty tree
    int count_;                // number of slots used; also the next free slot
    node_t elem_[MAXSIZE];
};
typedef struct tree tree_t;

void init(tree_t *ptr_tree)  { ptr_tree->root_ = -1; ptr_tree->count_ = 0; }
void deinit(tree_t *ptr_tree){ ptr_tree->root_ = -1; ptr_tree->count_ = 0; }

The interface (init, deinit, disp, insert) is unchanged from the pointer version. Initially root_ is −1 (not a valid index); after the first insertion it becomes 0.

7.4 Insert

Check whether the array is full; take count_ as the slot for the new key and increment it; ground the new node's left and right (−1); then call the recursive routine, passing the array, the root and the index of the new node. Compared with the pointer version, the array (elem) is passed along, and the size of the array is not passed — the recursion is driven by −1 markers, not by array bounds.

void insert(tree_t *ptr_tree, int key)
{
    if(ptr_tree->count_ == MAXSIZE) { printf("tree full\n"); exit(1); }
    int temp = ptr_tree->count_++;
    ptr_tree->elem_[temp].key_ = key;
    ptr_tree->elem_[temp].left_ = ptr_tree->elem_[temp].right_ = -1;
    ptr_tree->root_ = insert_recursive(ptr_tree->elem_, ptr_tree->root_, temp);
}
static int insert_recursive(node_t elem[], int root, int temp)
{
    if(root == -1) root = temp;
    else if(elem[root].key_ > elem[temp].key_)
        elem[root].left_  = insert_recursive(elem, elem[root].left_,  temp);
    else
        elem[root].right_ = insert_recursive(elem, elem[root].right_, temp);
    return root;
}

7.5 Traversals and other functions

Identical to the pointer version with temp != -1 replacing temp != NULL and elem[temp].left_ replacing temp->left_.

static void disp_inorder_recursive(node_t elem[], int temp)
{
    if(temp != -1)
    {
        disp_inorder_recursive(elem, elem[temp].left_);
        printf("%d ", elem[temp].key_);
        disp_inorder_recursive(elem, elem[temp].right_);
    }
}
/* preorder: print before the two calls; postorder: print after them */

int number_of_nodes_recursive(node_t elem[], int temp)
{
    if(temp == -1) return 0;
    return 1 + number_of_nodes_recursive(elem, elem[temp].left_)
             + number_of_nodes_recursive(elem, elem[temp].right_);
}
int number_of_leaves_recursive(node_t elem[], int temp)
{
    if(temp == -1) return 0;
    else if(elem[temp].left_ == -1 && elem[temp].right_ == -1) return 1;
    else return number_of_leaves_recursive(elem, elem[temp].left_)
              + number_of_leaves_recursive(elem, elem[temp].right_);
}
int are_same_recursive(node_t elem1[], int root1, node_t elem2[], int root2)
{
    if(root1 == -1 && root2 == -1) return 1;
    else if(root1 == -1 || root2 == -1) return 0;
    else return elem1[root1].key_ == elem2[root2].key_ &&
         are_same_recursive(elem1, elem1[root1].left_,  elem2, elem2[root2].left_) &&
         are_same_recursive(elem1, elem1[root1].right_, elem2, elem2[root2].right_);
}

Copy is easier iteratively when dealing with arrays: copy the root, the count and every array element (whether to stop at count_ or copy up to MAXSIZE is debatable).

void copy(tree_t* ptr_src, tree_t* ptr_dst)
{
    ptr_dst->root_  = ptr_src->root_;
    ptr_dst->count_ = ptr_src->count_;
    for(int i = 0; i < MAXSIZE; ++i)
        ptr_dst->elem_[i] = ptr_src->elem_[i];
}

8. Expression Tree

An expression tree is a tree whose leaves are operands and whose internal nodes are operators. Here a postfix expression (operands assumed to be single digits) is converted into an expression tree, which is then evaluated.

Algorithm

Input: an expression in postfix. Process: construct the expression tree. Output: the value of the expression.

8.1 Phase 1 — construct the tree

Data structure: a stack of tree nodes. Scan the postfix expression left to right:

  • Operand: create a tree node and push it on the stack.
  • Operator: pop two tree nodes, create a new node with the operator as key, attach the popped nodes as its subtrees (first pop = right, second pop = left), and push the new node.

8.2 Phase 2 — evaluate

When the scan ends the stack must hold one and only one tree node (the root). Evaluate recursively: if the node is a leaf return the operand; otherwise evaluate the left subtree, evaluate the right subtree, and apply the node's operator to the two results.

8.3 Worked example: 5 3 + 8 2 - *

SymbolActionStack (bottom → top)
5push operand5
3push operand5, 3
+pop 3 (right), pop 5 (left); new node +(5+3)
8push operand(5+3), 8
2push operand(5+3), 8, 2
-pop 2 (right), pop 8 (left); new node −(5+3), (8−2)
*pop (8−2) (right), pop (5+3) (left); new node ×((5+3)×(8−2))
Traversals of an expression tree

Postorder gives the original postfix expression; preorder gives prefix; inorder gives infix (brackets are needed to preserve the structure).

Limitation of this design: an operand is a single character. To allow multi-digit operands, make the node a union of operand (int) and operator (char); no discriminator is needed because operands appear only at the leaves.

8.4 Data structures and interface

#define MAXSIZE 100
struct node
{
    char ch_;                       // operand digit or operator
    struct node *left_;
    struct node *right_;
};
typedef struct node node_t;

struct stack
{
    node_t* key_[MAXSIZE];          // array stack of node pointers
    int top_;
};
typedef struct stack stack_t;

void   init_stack(stack_t *ptr_stack);
void   deinit_stack();
void   push_operand (stack_t *ptr_stack, char ch);   // separate: pushes a leaf
void   push_operator(stack_t *ptr_stack, char ch);   // pops 2, builds node, pushes
node_t* pop(stack_t *ptr_stack);                     // returns a pointer to a node
int    is_empty(stack_t *ptr_stack);
int    is_full (stack_t *ptr_stack);
int    eval(stack_t *ptr_stack);

Compared with an ordinary stack: pop returns a pointer to a node, and pushing an operator needs two pops, a new node and two attachments, so a separate push_operator exists.

static node_t* create_node(char ch)
{
    node_t *temp = (node_t*)malloc(sizeof(node_t));
    if(temp == NULL) { printf("memory full\n"); exit(1); }
    temp->ch_ = ch;
    temp->left_ = temp->right_ = NULL;
    return temp;
}
void push_operand(stack_t *ptr_stack, char ch)
{
    if(! is_full(ptr_stack))
    {
        node_t* temp = create_node(ch);
        ptr_stack->key_[++ptr_stack->top_] = temp;
    }
    else printf("stack full; cannot push\n");
}
void push_operator(stack_t *ptr_stack, char ch)
{
    if(! is_full(ptr_stack))
    {
        node_t* temp = create_node(ch);
        temp->right_ = pop(ptr_stack);      // first pop  -> right subtree
        temp->left_  = pop(ptr_stack);      // second pop -> left subtree
        ptr_stack->key_[++ptr_stack->top_] = temp;
    }
}
node_t* pop(stack_t *ptr_stack)
{
    if(! is_empty(ptr_stack)) return ptr_stack->key_[ptr_stack->top_--];
    else { printf("stack empty; cannot pop\n"); return '\0'; }
}

8.5 Evaluation

eval pops the one and only node and calls eval_recursive on it. A leaf returns the numeric value of the digit (ch - '0'); otherwise the two subtrees are evaluated and combined using the operator at the root.

int eval_recursive(node_t* root)
{
    int left, right;
    if (root->left_ == NULL && root->right_ == NULL)
        return root->ch_ - '0';
    left  = eval_recursive(root->left_);
    right = eval_recursive(root->right_);
    switch (root->ch_)
    {
        case '+': return left + right;
        case '-': return left - right;
        case '*': return left * right;
        case '/': return left / right;
    }
    return 0;
}
int eval(stack_t *ptr_stack) { return eval_recursive(pop(ptr_stack)); }

9. Threaded Binary Tree

In a node-based tree of n nodes there are only n − 1 edges, so only n − 1 of the 2n pointers are structural pointers; n + 1 pointers are grounded (NULL). A threaded binary tree reuses them: for a chosen traversal order (inorder here) a NULL left pointer is made to point to the node's inorder predecessor and a NULL right pointer to its inorder successor. Such a pointer is called a thread.

Pointer count
NULL pointers (available for threads) = 2n − (n − 1) = n + 1

9.1 Telling a thread from a structural pointer

Two extra fields (flags) per node are needed: lthread_ is 1 if left_ is a thread, 0 if it is a structural pointer; likewise rthread_ for right_.

struct node
{
    int key_;
    struct node *left_;
    struct node *right_;
    int lthread_;      // 1 : left_  is a thread,  0 : structural pointer
    int rthread_;      // 1 : right_ is a thread,  0 : structural pointer
};
typedef struct node node_t;
struct tree { node_t *root_; };
typedef struct tree tree_t;

The interface does not change: init, deinit, disp, insert. init grounds the root. The left pointer of the leftmost node and the right pointer of the rightmost node are threads that may point to the root or be grounded (grounded here).

9.2 Advantages

  • No recursion and no stack are needed to traverse (inorder here) — efficient in time.
  • Makes use of pointers that would otherwise be wasted (NULL).
  • Cost: extra space to flag whether each pointer is structural or a thread.

9.3 Insert

A node is always added as a leaf. create_node sets both pointers NULL and both thread flags to 1 (a new leaf has no children). insert_key keeps a local parent (nodes have no parent pointer) and walks down: go left if key < curr->key_ and the left link is structural, go right if the right link is structural; stop when the link to follow is a thread — that means a leaf position has been reached. If the tree was empty, the new node is the root. Otherwise attach it to parent:

  • As left child: new node takes over the parent's old left link (temp->left_ = parent->left_, the predecessor thread) and its right thread points to the parent (the successor); then parent->left_ = temp; parent->lthread_ = 0.
  • As right child: temp->right_ = parent->right_ (successor thread), temp->left_ = parent (predecessor), then parent->right_ = temp; parent->rthread_ = 0.
static node_t* create_node(int key)
{
    node_t *temp = (node_t*)malloc(sizeof(node_t));
    if(temp == NULL) { printf("no more memory\n"); exit(1); }
    temp->key_ = key;
    temp->left_ = temp->right_ = NULL;
    temp->lthread_ = temp->rthread_ = 1;       // a new leaf: both are threads
    return temp;
}
void insert(tree_t *ptr_tree, int key)
{   ptr_tree->root_ = insert_key(ptr_tree->root_, key);   }

static node_t* insert_key(node_t* root, int key)
{
    node_t *temp = create_node(key);
    node_t *parent = NULL;
    node_t *curr = root;
    while (curr != NULL)                        // find the leaf position
    {
        parent = curr;
        if (key < curr->key_)
        {
            if (curr->lthread_ == 0) curr = curr->left_;
            else break;                         // thread => leaf reached
        }
        else
        {
            if (curr->rthread_ == 0) curr = curr->right_;
            else break;
        }
    }
    if (parent == NULL) return temp;            // empty tree: new root

    if (key < parent->key_)                     // insert as left child
    {
        temp->left_  = parent->left_;           // inherit predecessor thread
        temp->right_ = parent;                  // parent is the successor
        parent->left_ = temp;                   // now a structural pointer
        parent->lthread_ = 0;
    }
    else                                        // insert as right child
    {
        temp->right_ = parent->right_;          // inherit successor thread
        temp->left_  = parent;                  // parent is the predecessor
        parent->right_ = temp;
        parent->rthread_ = 0;
    }
    return root;
}

Why is temp->left_ (or temp->right_) not NULL? Because the new leaf lies in the gap between the parent and the parent's old predecessor (or successor); it inherits the thread the parent used to hold there.

9.4 Inorder traversal without recursion

leftmost keeps going left while the left link is structural (lthread_ == 0). inorder starts at the leftmost node, visits it, then moves on: if rthread_ == 1 follow the thread to the successor; otherwise take one step right and find the leftmost node of that subtree. Repeat until NULL.

static node_t *leftmost(node_t *temp)
{
    if (temp == NULL) return NULL;
    while (temp->lthread_ == 0)
        temp = temp->left_;
    return temp;
}
static void inorder(node_t *root)
{
    node_t *temp = leftmost(root);
    while (temp != NULL)
    {
        printf("%d ", temp->key_);
        if (temp->rthread_ == 1) temp = temp->right_;       // follow thread
        else temp = leftmost(temp->right_);                 // go right, then far left
    }
}

For the example table above this visits 20 30 40 50 60 70 80: after 20 the thread jumps to 30; after 30 (structural right) we go to 40; after 40 the thread jumps to 50; and so on.

10. Heap — Properties and Array Representation

The word heap has two meanings. In memory management it is the region used for dynamic allocation; in data structures it is a special binary tree that is not a search tree. (Similarly, a thread in an OS is a unit of execution, while a thread in a threaded tree is a pointer.) There are two kinds: max-heap and min-heap.

A heap (max-heap) is a tree with two properties:

  1. Complete binary tree: every level is filled; on the bottom level the nodes are filled from the left.
  2. Parental dominance (heap order): the key at a node is greater than the keys of its children, recursively. (For a min-heap the key is smaller than the keys of its children.)

There is no ordering between the left and right subtrees. Every leaf is trivially a heap. The root of a max-heap holds the maximum.

10.1 Array implementation

A heap is always implemented with an array: because the tree is complete, it maps onto the array with no gaps, and empty/full checks and traversal are simple.

MappingLeft childRight childParent
Root at index 02i + 12i + 2⌊(i − 1)/2⌋

Heap index relations (root at index 1)
left(i) = 2i    right(i) = 2i + 1    parent(i) = ⌊i / 2⌋    first leaf = ⌊n / 2⌋ + 1

10.2 Advantages of the array implementation

  • No pointers and no extra storage.
  • Easy to determine whether the heap is empty or full.
  • Simple traversal, either as an array or as a tree.
  • No memory is wasted, since the tree is complete.

10.3 Uses of a heap

  • Heapsort: theoretically as efficient as any comparison-based sort, but not cache friendly — so no language library implements it.
  • Finding the maximum (or minimum) repeatedly — e.g. a priority queue and n-way merge. Insert and delete are both proportional to log2 n.

11. Heap Operations

The heap structure holds the key array and the number of elements in use. Keys occupy indices 1 … n.

#define MAXSIZE 100

};

11.1 Heapify (sift-down)

Given that the left and right subtrees of node pos are already heaps, place the root element correctly so that the tree rooted at pos becomes a heap. The root value is copied to val so that location i becomes a hole. While j (the left child, 2i) is valid and the heap is not yet fixed:

  • if the right child exists and is greater than the left child, move to it (++j) — we compare against the larger child;
  • if a[j] > val, shift a[j] up into the hole and move down (i = j; j = 2i);
  • otherwise the position is found (is_heap = 1).

Finally copy val into a[i]. Each iteration discards half the tree by doubling j.

static void heapify(int a[], int n, int pos)
{
    int i = pos;
    int j = 2 * i;
    int val = a[i];
    int is_heap = 0;
    while(j <= n && ! is_heap)
    {
        if(j + 1 <= n && a[j+1] > a[j])
            ++j;                         // pick the larger child
        if(a[j] > val)
        {
            a[i] = a[j];                 // move the hole down
            i = j;
            j = 2 * i;
        }
        else
            is_heap = 1;
    }
    a[i] = val;
}

11.2 Build a heap from an array

Two parts: (1) copy the given array into the heap's array (key_[1..n]); (2) convert every subtree into a heap. All leaves are already heaps, so start at the last non-leaf, index n/2, and go down to the root, calling heapify on each.

void build_heap(heap_t *ptr_heap, int a[], int n)
{
    ptr_heap->n_ = n;
    for(int i = 1; i <= n; ++i)
        ptr_heap->key_[i] = a[i];
    for(int i = n / 2; i >= 1; --i)
        heapify(ptr_heap->key_, ptr_heap->n_, i);
}

Example. Array (index 1…7): 10 20 15 12 40 25 18, n = 7, start at i = 3.

11.3 Insert

Add the new element at the end of the array (++n), then propagate it up: while it is greater than its parent, swap them. It stops when the parent is larger or the root is reached.

void insert(heap_t *ptr_heap, int key)
{
    int pos = ++ptr_heap->n_;                     // add at the end
    if(pos > MAXSIZE) { printf("heap full\n"); exit(1); }
    ptr_heap->key_[pos] = key;
    while(pos > 1 && ptr_heap->key_[pos] > ptr_heap->key_[pos/2])
    {                                             // heapify upwards
        swap(&ptr_heap->key_[pos], &ptr_heap->key_[pos/2]);
        pos = pos / 2;
    }
}

11.4 Delete the maximum and peek

The maximum is at the root. Save it, overwrite the root with the last element, decrease the size by 1, and heapify from the root.

int delete_max(heap_t *ptr_heap)
{
    if(ptr_heap->n_ == 0) { printf("heap empty\n"); exit(1); }
    int res = ptr_heap->key_[1];
    ptr_heap->key_[1] = ptr_heap->key_[ptr_heap->n_];
    heapify(ptr_heap->key_, --ptr_heap->n_, 1);
    return res;
}
int peek_max(heap_t *ptr_heap) { return ptr_heap->key_[1]; }

Example on the heap 40 20 25 12 10 15 18: insert(50) places 50 at index 8; it swaps with its parent 12 (index 4), then with 20 (index 2), then with 40 (index 1) → 50 40 25 20 10 15 18 12. Then delete_max() returns 50, moves the last key 12 to the root, and heapify pushes it down past 40 and then 20 → 40 20 25 12 10 15 18.

Complexity of heap operations
insert = O(log2 n)    delete_max = O(log2 n)    peek_max = O(1)    build_heap = O(n)

Insert moves up by halving the index (toward the parent); delete moves down by doubling the index and discarding half the tree each time — so the work is proportional to the height, log2 n. (build_heap = O(n) is the standard bottom-up result.)

11.5 Min-heap

The interface and implementation of a min-heap are the same; only the comparison operator is reversed (“greater than” becomes “less than”). The root holds the minimum, and parent ≤ children.

static void heapify_min(int a[], int n, int pos)
{
    int i = pos, j = 2 * i, val = a[i], is_heap = 0;
    while(j <= n && ! is_heap)
    {
        if(j + 1 <= n && a[j+1] < a[j]) ++j;     // smaller child
        if(a[j] < val) { a[i] = a[j]; i = j; j = 2 * i; }
        else is_heap = 1;
    }
    a[i] = val;
}

Min-heap example. Insert 5, 3, 8, 1: [5] → [3 5] → [3 5 8] → 1 enters at index 4, swaps with 5 then 3 → [1 3 8 5]. delete_min() returns 1, moves 5 to the root and sifts it down past 3 → [3 5 8].

12. Priority Queue Using a Heap

A priority queue is a queue where elements leave in order of priority rather than arrival: enqueue a task, then dequeue the task with the highest priority. Both operations need to be efficient, and a heap gives both in time proportional to log2 n.

  • Max priority queue — built on a max-heap; the largest key is served first.
  • Min priority queue — built on a min-heap; the smallest key is served first.

12.1 Implementation using a heap

Whenever insertion and deletion repeatedly happen based on a key, a heap is the preferred data structure.

12.3 Application: running median with two heaps

To find the median of a stream, keep the lower half in a max-heap (left_half, root = largest of the smaller half) and the upper half in a min-heap (right_half, root = smallest of the larger half). For every incoming number x:

  1. Insert: if left_half is empty or x ≤ root(left_half), push x into left_half; otherwise into right_half.
  2. Balance: if left_half is larger than right_half by more than 1, move its root to right_half; if right_half is larger than left_half, move its root to left_half.
  3. Query median: if the total count N is even, the median is the average of the two roots; if N is odd, it is the root of the heap holding the extra element.

This is built in steps: understand callbacks (a pointer-to-function parameter makes the operation flexible; practise with map, filter, reduce), then write one flexible heap whose initializer takes a comparison function so the same code serves as both MaxHeap and MinHeap, then use two of them for the median.

13. AVL Trees

A BST lets us discard one subtree at each comparison, but the worst case is not log2 n: the tree can become skewed and degenerate into a list, so search becomes proportional to n. We want the tree to have nearly the same depth in every direction — a height-balanced BST. The AVL tree (Adelson-Velsky and Landis, two Russian mathematicians) is one such self-balancing BST.

AVL property

For every node, the heights of its left and right subtrees differ by at most 1.

Balance factor
BF(node) = h(left subtree) − h(right subtree)     AVL: BF ∈ { −1, 0, +1 }

+2 → left-heavy → imbalance  |  −2 → right-heavy → imbalance  |  a rotation is needed whenever |BF| = 2.

13.1 The four imbalance cases

CaseConfigurationFix
LLLeft-LeftRight rotation
RRRight-RightLeft rotation
LRLeft-RightLeft rotation, then Right rotation
RLRight-LeftRight rotation, then Left rotation
Memory rule

Same direction → single rotation. Opposite directions → double rotation. The case is read from the path of the two moves below the unbalanced node (the first move, then the second).

13.2 LL — right rotation

Insert 30, 20, 10. The path from the unbalanced node is 30 → 20 → 10 (both moves left). At 30: left height 2, right height 0, so BF(30) = 2 (left-heavy). Rotate right around 30.

13.3 RR — left rotation

Insert 10, 20, 30. Path 10 → 20 → 30 (both right). BF(10) = 0 − 2 = −2 (right-heavy). Rotate left around 10.

13.4 LR — left, then right

Insert 30, 10, 20. Path 30 → 10 → 20: first move left, second right. Step 1: rotate the subtree rooted at 10 to the left, turning it into an LL shape. Step 2: rotate right around 30.

13.5 RL — right, then left

Insert 10, 30, 20. Path 10 → 30 → 20: first move right, second left. Step 1: rotate right around 30, turning it into an RR shape. Step 2: rotate left around 10.

13.6 Generalised rotations (subtrees T1–T4)

X is the unbalanced node; Y and Z lie on the path of insertion. Each result is balanced, and the inorder order T1, …, T4 is preserved.

13.7 Worked insertion sequence: 10, 20, 30, 40, 50, 25

InsertResult / action

30RR imbalance at 10 → left rotation → 20 (10, 30)
40becomes right child of 30 — balanced

13.8 Rotation code and properties

Nodes also store their height. A rotation re-links three pointers and recomputes two heights.

struct node { int key_; int height_; struct node *left_, *right_; };
static int height(node_t *n) { return n ? n->height_ : 0; }
static void update(node_t *n) { n->height_ = 1 + (height(n->left_) > height(n->right_)
                                                  ? height(n->left_) : height(n->right_)); }
static int bf(node_t *n) { return height(n->left_) - height(n->right_); }

static node_t* rotate_right(node_t *x)          // fixes LL
{
    node_t *y = x->left_;
    x->left_  = y->right_;
    y->right_ = x;
    update(x); update(y);
    return y;                                   // new root of this subtree
}
static node_t* rotate_left(node_t *x)           // fixes RR
{
    node_t *y = x->right_;
    x->right_ = y->left_;
    y->left_  = x;
    update(x); update(y);
    return y;
}
/* after inserting into a subtree rooted at n, on the way back up:
   update(n);
   if (bf(n) >  1 && bf(n->left_)  >= 0) return rotate_right(n);                       // LL
   if (bf(n) < -1 && bf(n->right_) <= 0) return rotate_left(n);                        // RR
   if (bf(n) >  1) { n->left_  = rotate_left(n->left_);   return rotate_right(n); }    // LR
   if (bf(n) < -1) { n->right_ = rotate_right(n->right_); return rotate_left(n); }     // RL */
  • Balancing does not alter the BST property: rotations change the shape but not the inorder listing of the nodes.
  • Search, insertion and deletion require O(log2 n) operations.
  • Another similar tree, the red-black tree, is the one most commonly used in libraries.
Height bound (standard result)
minimum nodes N(h) = N(h − 1) + N(h − 2) + 1   ⇒   h < 1.44 · log2(n + 2)

Even the “most skewed” AVL tree stays logarithmic in height.

14. Splay Trees

A splay tree is a self-adjusting BST. Whenever a node is accessed (search, insert, delete), it is moved to the root; this operation is called splaying. There is no balance factor. The principle is that a key accessed recently is likely to be accessed again soon.

14.1 Features

  • No extra metadata: no balance data (height numbers as in AVL, colour bits as in red-black trees) — saves memory.
  • Locality of reference: a key accessed once moves to the top, so subsequent lookups of it are almost instant.
  • Efficiency: one worst-case operation can take time proportional to the number of elements, but a sequence of m operations is guaranteed to run in time proportional to m · log2 n.
  • Dynamic adaptation: the structure keeps morphing to fit the actual access pattern instead of enforcing a rigid shape.
Amortised cost
m operations on an n-node splay tree: O(m · log2 n) total   ⇒   O(log2 n) amortised per operation

14.2 Uses

  • Caches and memory allocation — a small subset of data requested repeatedly.
  • Network routers — quickly looking up frequently matched IP addresses.
  • Data compression — algorithms that exploit recurring patterns in data streams.

14.3 How a node is moved to the root

Splaying uses rotations. Let x be the accessed node, p its parent and g its grandparent.

ConfigurationSplay operationRotations
x is a child of the rootZigone rotation
x and p on the same side (LL or RR)Zig-ZigLL: two right rotations · RR: two left rotations (rotate g first, then p)
x and p on opposite sides (LR or RL)Zig-Zagone left and one right (rotate x twice)
Memory rule

One level from the root → Zig. Same direction → Zig-Zig. Opposite direction → Zig-Zag.

Case 1 — Zig

Access 30 when 30 is the left child of root 50: rotate right, and 30 becomes the root. Access 70 when it is the right child of 50: rotate left, and 70 becomes the root.

Case 2 — Zig-Zig

Access 20 where 20 is the left child of 30 and 30 is the left child of 50 (Left-Left). First rotate 50 right, then rotate 30 right. (Symmetrically, an RR case needs two left rotations.)

Case 3 — Zig-Zag

Access 30 where 30 is the right child of 20 and 20 is the left child of 50 (Left-Right). First rotate 20 left, then rotate 50 right; 30 becomes the root. (An RL case is the mirror image.)

14.4 Examples

Example 1 — search 20. In the BST with root 50 (children 30 and 70; 30 has children 20, 40; 70 has children 60, 80) the path is 50 → 30 → 20: 20 is the left child of 30 and 30 is the left child of 50, so this is Zig-Zig. After splaying, 20 is the root. The tree need not be balanced — the point is that the key just accessed is now at the root.

Example 2 — now access 60. The path is 20 → 30 → 50 → 70 → 60. At the bottom, 60 is the left child of 70 and 70 is the right child of 50: Zig-Zag (RL) — rotate 70 right, then 50 left, so 60 takes 50's place under 30. Next, 60 is the right child of 30 and 30 is the right child of 20: Zig-Zig (RR) — rotate 20 left, then 30 left. Now 60 is the root.

15. Graphs — Concepts and Properties

So far we have studied linear structures (list, stack, queue, circular list, doubly linked list) and the non-linear tree. A graph is a non-linear data structure used to represent relationships between objects. It consists of vertices (nodes) and edges connecting pairs of vertices.

Definition
G = (V, E)

V = set of vertices, E = set of edges.

A graph may be directed (edges have a direction: adding u→v is not the same as v→u) or undirected. If each edge carries a value — distance, time, cost… — it is a weighted graph.

The running example has 8 vertices, V = {A, B, C, D, E, F, G, H}, and 11 edges: AB, AC, BC, BD, CE, DE, DF, FG, EG, GH, FH. It is undirected.

15.3 Königsberg bridges, Euler and Hamiltonian graphs

The Königsberg bridge problem: there are 7 bridges across the rivers; can one start at any point, cross each of the 7 bridges once and only once, and return to the start? Euler proved it is not possible. Redrawn as a graph, it asks whether the diagram can be drawn without lifting the pen.

Euler's reasoning: passing through a vertex means entering it and leaving it, which uses two edges each time. So a closed walk using every edge exactly once is possible only if every vertex has even degree.

15.4 Applications of graphs

  • Road and transport networks: vertices = cities/intersections, edges = roads; weights = distance or travel time.
  • Social networks: vertices = people; edges = friendships, follows, interactions.
  • Computer networks: vertices = computers/routers; edges = communication links.
  • Course prerequisites: a directed edge means one course must be completed before another.
  • Software dependencies: vertices = modules, files or tasks; edges = dependencies.
  • Airline and logistics networks: vertices = airports/warehouses; edges = routes.
  • Web pages: vertices = pages; directed edges = hyperlinks.
  • Project scheduling: vertices = tasks; edges = precedence constraints.

16. Graph Representation and Implementation

16.1 Adjacency matrix

An adjacency matrix is a V × V array. The element in row i, column j is 1 if there is an edge from vertex i to vertex j, otherwise 0. For a weighted graph it holds the weight instead of 1. For an undirected graph the matrix is symmetric. The 8-vertex example needs an 8 × 8 matrix:

ABCDEFGH

C11001000
D01001100
E00110010
F00010011
G00001101
H00000110
Adjacency matrix
space = O(V2)    edge test (i, j) = O(1)    list all neighbours of a vertex = O(V)

Space grows with the square of the number of vertices; checking an edge takes constant time, independent of the number of vertices or edges.

#define MAXSIZE 10
struct graph
{
    int n_vertices_;                       // # of vertices
    int n_edges_;                          // # of edges
    int adj_mat_[MAXSIZE][MAXSIZE];        // 1 (or weight) if an edge exists
};
typedef struct graph graph_t;

void init_graph(graph_t *ptr_graph, int n_vertices, int n_edges);
void add_edge (graph_t *ptr_graph, int from, int to);
void dfs      (graph_t *ptr_graph, int u);      // depth first search
void bfs      (graph_t *ptr_graph, int u);      // breadth first search
void disp     (graph_t *ptr_graph);
void deinit_graph(graph_t *ptr_graph);

Small experiments on this representation: (a) find the number of edges, (b) find the degree of each node (row sums), (c) find the node with the maximum degree.

16.2 Adjacency list

A list of neighbours is stored for each vertex. For the example graph:

VertexAdjacent vertices

BA → C → D
CA → B → E

Adjacency list
space = O(V + E)    edge test (u, v) = O(deg u)    list all neighbours of u = O(deg u)

One node per vertex plus one node per edge (two per edge if undirected). It needs less space than a matrix, especially when |E| is small.

In the implementation each vertex's list is a linked list with both a head and a tail pointer so that appending is efficient, and the graph is an array of such lists.

struct node { int vertex_; struct node* next_; };
typedef struct node node_t;
struct list { node_t* head_; node_t* tail_; };       // tail: O(1) append
typedef struct list list_t;

struct graph
{
    int n_vertices_;
    int n_edges_;
    list_t adj_list_[MAXSIZE];                        // one list per vertex
};
typedef struct graph graph_t;

The interface is the same as for the matrix: init_graph, add_edge, dfs, bfs, disp, deinit_graph. init_graph grounds every list. add_edge(from, to) appends a node holding to to adj_list_[from]; if the graph is undirected, a node holding from is also appended to adj_list_[to].

17. Graph Traversal — DFS and BFS

A traversal visits the vertices of a graph. Two methods are discussed: DFS (uses a stack — implicitly through recursion) and BFS (uses a queue). Both are shown on the example graph; vertices are taken in alphabetical order.

17.1 Depth-first search (DFS)

Idea: explore as deeply as possible along one path before backtracking. DFS goes down a path and backtracks when it reaches a vertex with no unvisited neighbour. It can be written recursively or with an explicit stack. The visiting order depends on the starting vertex.

Start at A. A has neighbours B, C → visit B. B has C, D → visit C. C has the unvisited neighbour E → visit E, and so on.

StepActionVertex visited
1Start at AA
2Visit B from AB
3Visit C from BC
4Visit E from CE
5Visit D from ED
6Visit F from DF
7Visit G from FG
8Visit H from GH

DFS traversal: A, B, C, E, D, F, G, H. DFS does not visit vertices level by level; it follows a path and backtracks when necessary.

DFS on an adjacency matrix

An array visited tracks which vertices have been visited; initially none. dfs_recursive marks the vertex, visits it, then calls itself on the first unvisited neighbour (scan the row) — the recursion supplies the stack.

void dfs(graph_t *ptr_graph, int u)
{
    int visited[MAXSIZE];
    for(int i = 0; i < ptr_graph->n_vertices_; ++i)
        visited[i] = 0;
    dfs_recursive(ptr_graph->n_vertices_, ptr_graph->adj_mat_, visited, u);
    printf("\n");
}
void dfs_recursive(int n, int a[n][MAXSIZE], int visited[], int u)
{
    visited[u] = 1;
    printf("visited %c \n", u + 'A');
    for(int i = 0; i < n; ++i)
        if(a[u][i] && ! visited[i])
            dfs_recursive(n, a, visited, i);
}

DFS on an adjacency list

Same idea; the neighbours are found by walking the vertex's list instead of scanning a row.

void dfs_recursive(int n, list_t a[MAXSIZE], int visited[], int u)
{
    visited[u] = 1;
    printf("visited %c \n", u + 'A');
    node_t* temp = a[u].head_;
    while(temp)
    {
        int v = temp->vertex_;
        if(! visited[v])
            dfs_recursive(n, a, visited, v);
        temp = temp->next_;
    }
}

17.2 Breadth-first search (BFS)

Idea: visit all the neighbours of a vertex before going deeper. BFS uses a queue (DFS conceptually uses a stack). The queue is created and initialised at the start of the function and de-initialised at the end. All vertices are first marked not visited; mark the start vertex visited and enqueue it. While the queue is not empty: dequeue a vertex, visit it, then find all its neighbours not yet visited, mark them visited and enqueue them.

The same vertex never appears in the BFS queue more than once, because it is marked at the moment it is enqueued. In a stack-based DFS that pushes all neighbours and marks only when popping, the same vertex can be on the stack several times.

void bfs(graph_t *ptr_graph, int u)                 // adjacency matrix
{
    int n = ptr_graph->n_vertices_;
    queue_t q;
    init_queue(&q);
    int visited[MAXSIZE];
    for(int i = 0; i < n; ++i) visited[i] = 0;
    int v;
    visited[u] = 1;
    enqueue(&q, u);
    while(!is_empty(&q))
    {
        v = dequeue(&q);
        printf("visiting : %c\n", v + 'A');
        for(int i = 0; i < n; ++i)
            if(ptr_graph->adj_mat_[v][i] && !visited[i])
            {
                visited[i] = 1;
                enqueue(&q, i);
            }
    }
    deinit_queue(&q);
}

For an adjacency list only the inner loop changes: walk ptr_graph->adj_list_[u].head_ through next_, and for every neighbour v not yet visited, mark it and enqueue it.

    node_t* temp = ptr_graph->adj_list_[u].head_;     // inside the while loop
    while(temp)
    {
        v = temp->vertex_;
        if(!visited[v]) { visited[v] = 1; enqueue(&q, v); }
        temp = temp->next_;
    }

Disconnected graphs

A DFS or BFS started from one vertex visits only the vertices of that vertex's connected component. If the graph is not connected, these functions as written do not reach all vertices (and which ones they reach depends on the starting vertex). Covering every vertex requires restarting the search from each unvisited vertex — see connected components in Unit 4.
