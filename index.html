W01

Basic gates

Each gate is a small module driven by a continuous assignment. Typical forms:

assign c = a & b;        // and
assign c = !(a ^ b);     // xnor

The testbench declares inputs as reg and outputs as wire, instantiates the gate, then applies every input combination with #100 between vectors. $monitor prints values whenever any listed signal changes, and $dumpfile with $dumpvars writes the .vcd trace for GTKWave.

Build and run:

iverilog -o out gate.v gate_tb.v
vvp out
gtkwave file.vcd
W02

Simple circuits

Gates are written once as small modules (and2, or2, not2) and wired together as instances inside a larger module, using internal wires for the connections.

simple_circuit sets w1 = A·B, E = C and D = w1 + E, giving:

D = AB + C

circuit1 and circuit2 follow the same pattern:

Y = BC + A
Y = (BC + A) + AB  →  Y = A + BC

The AB term is absorbed by A, so circuit2 reduces to A + BC. Instances use positional port connection, for example and2 G1 (A, B, w1);, and the testbenches apply all eight combinations of A, B and C at #20 intervals.

W03

Combinational circuits with vectors

The full adder is built from gate modules. Sum and carry reduce to:

sum = i0 ⊕ i1 ⊕ cin
cout = i0i1 + (i0 ⊕ i1)cin
w1  = i0 ^ i1;
sum = w1 ^ cin;
w2  = i0 & i1;
w3  = w1 & cin;
cout = w2 | w3;

The vector testbench stores every pattern in an array and walks it with a loop:

reg [2:0] test_vecs [0:7];
`define TESTVECS 8
for (i = 0; i < `TESTVECS; i = i + 1)
  {i0,i1,cin} = test_vecs[i];   // i0 is the MSB

$finish ends the run. In example2 (circuit3) the sum and carry of the first adder feed the second. The input there is declared [0:2], so i1[0] is the leftmost bit, not the least significant one.

W04

Multiplexers and decoder

The 2:1 mux is a conditional assignment; j=0 passes i0 and j=1 passes i1.

assign o = (j==0) ? i0 : i1;

mux4 is built from three mux2 blocks. The two first-level muxes are selected by j1, choosing between i[0]/i[1] and between i[2]/i[3]; the output mux is selected by j0. The selected index is therefore

k = 2j0 + j1

decoder2X4 asserts one output per address:

Y0 = A1A0   Y1 = A1A0   Y2 = A1A0   Y3 = A1A0

Exactly one line is high for any 2-bit input, which is the one-hot property.

W05

D flip-flops

df is a positive-edge triggered flip-flop. The output must be a reg because it is assigned in a procedural block, and the assignment is nonblocking:

always @(posedge clk) df_out <= in;

Before the first rising edge the output is x.

dfr adds a synchronous, active-high reset using gates: reset' = ¬reset and df_in = in · reset'. The flop only clears on a clock edge while reset=1.

dfrl adds load through a mux2: with load=0 the flop's own output is fed back and the value holds, with load=1 the new input is taken.

The testbench clock runs at a period of 10:

initial clk = 0;
always #5 clk = ~clk;

Reset is held high until #12.5, so the first edge that captures data is at t = 15.

W06

4-bit ripple carry adder

ripple_c4b chains four full adders, each written with gate primitives (xor for sum, three ands and an or for carry). cin enters FA_0, the carry of each stage feeds the next through c1, c2 and c3, and the final stage drives cout.

Because every stage waits for the carry below it, total delay grows with the number of bits. Testbench results:

  • 0101 + 0011 → 1000, cout 0
  • 1111 + 0001 → 0000, cout 1
  • 1010 + 0101 + 1 → 0000, cout 1
W07–08

16-bit ALU

Two 16-bit operands i0 and i1, a 2-bit op, a 16-bit result o and a carry out. The opcode map is:

  • 00 add
  • 01 subtract
  • 10 AND
  • 11 OR

The block is purely combinational: 16 alu_slice instances with the carry chained between them, and the carry into bit 0 is op[0]. Inside a slice, addsub XORs i1 with op[0] before the full adder, so subtraction becomes two's complement addition:

o = i0 + i1 + 1

A mux2 selected by op[0] chooses AND or OR, and a second mux2 selected by op[1] chooses arithmetic or logic. The carry out is only meaningful for add and subtract.

Verified testbench results:

  • aa55 + 55aa → ffff
  • ffff + 0001 → 0000, carry out
  • 0001 + 7fff → 8000, signed overflow
  • aa55 − 55aa → 54ab
  • 0001 − 7fff → 8002
  • aa55 AND 55aa → 0000
  • aa55 OR 55aa → ffff
W09–10

Register file

reg_file holds eight 16-bit registers, each built from sixteen dfrl flip-flops (dfrl_16). It has one write port (wr, wr_addr, d_in) and two read ports (rd_addr_a to d_out_a, rd_addr_b to d_out_b).

On the write side, demux8 decodes wr and wr_addr into eight load lines, one per register, so only the addressed register loads on the clock edge and nothing loads when wr=0.

On the read side, two mux8_16 banks select one of the eight registers per bit from three address bits. Reads are combinational.

The library mlib.v provides mux2, mux4, mux8, demux2, demux4, demux8, df, dfr and dfrl. Reset clears every register to zero synchronously. Two read ports exist because the ALU needs two operands in the same cycle.

Worth noting: the assignment PDF says register 0 should always read as zero, but the supplied code treats it as an ordinary register. The testbench writes ba98 into it.
W11

Register file integrated with the ALU

reg_alu joins the two blocks: read ports d_out_a and d_out_b drive the ALU inputs i0 and i1. A 16-bit mux2_16 selected by sel decides the write data, taking the external d_in when sel=0 and the ALU result when sel=1.

The ALU carry out passes through a dfr, so cout is registered and arrives one clock later than the operation.

The testbench writes 1111 into reg1 and 3333 into reg2 with sel=0, reads them back, writes 5555 into reg6 and 2222 into reg7, then runs the ALU with sel=1:

  • reg1 + reg2 into reg3 → 4444
  • reg3 − reg1 into reg5 → 3333
  • reg6 AND reg7 into reg0 → 0000
  • reg6 OR reg7 into reg4 → 7777
REF

Verilog values and tooling

Verilog nets and registers carry four values:

  • 0 and 1 — driven logic levels
  • z — undriven, high impedance
  • x — unknown, the initial value of a reg, also the result of conflicting drivers

initial runs once at time 0. always repeats. = is a blocking assignment and <= is nonblocking, which is what flip-flops use. #n delays by n time units and $time returns the current simulation time. Without a `timescale directive, Icarus reports time in whole seconds.

iverilog -o sim design.v design_tb.v
vvp sim
gtkwave dump.vcd
