Unit 4: Graph Applications, Tries, Suffix Trees & Hashing

Connectivity and connected components, path finding with DFS backtracking and BFS parent chains, trie insertion/search/deletion, suffix tries and compressed suffix trees, then hash functions and every collision strategy: separate chaining, linear probing, quadratic probing, double hashing and rehashing — with code, traces, formulas and complexity.

1. Connectivity and Connected Components

Two vertices are connected if a path exists between them. In an undirected graph, connectivity is an equivalence relation: every vertex belongs to exactly one connected component, a maximal set of vertices that are mutually reachable. A graph is connected when it has exactly one component.

Undirected graph

A component is a maximal connected subgraph. An isolated vertex is a component of size 1. There is no direction to worry about: reachability is symmetric.

Directed graph

Strongly connected means every vertex reaches every other vertex following directions. Weakly connected means the underlying undirected graph is connected. Strong components are computed by algorithms such as Kosaraju or Tarjan; the simple traversal below counts weak components unless directions are respected.

1.1 Why one DFS/BFS is not enough

A DFS or BFS started at a vertex visits exactly the component containing that vertex. When its stack/queue empties, the traversal stops — even if other components remain. The visited array still contains zeros. The fix is an outer loop: while an unvisited vertex exists, start a fresh traversal from it and increment the component count. Each restart discovers one entire component.

mark all unvisited→ find unvisited vertex u→ DFS/BFS from u→ count++ & record component→ repeat until none 
/* Return an unvisited vertex, or -1 if every vertex is visited. */
int to_visit(int visited[], int n)
{
    for (int i = 0; i < n; ++i)
        if (visited[i] == 0) return i;
    return -1;
}

1.2 Connected components with DFS on an adjacency matrix

void dfs_rec(graph_t *g, int u, int visited[])
{
    visited[u] = 1;
    printf("%d ", u);                     /* list the component */

    for (int v = 0; v < g->n_vertices; ++v)
        if (g->adj[u][v] && !visited[v])
            dfs_rec(g, v, visited);
}

int connected_components(graph_t *g)
{
    int visited[MAXV] = {0};
    int count = 0;

    int u = to_visit(visited, g->n_vertices);
    while (u != -1) {
        printf("Component %d: ", ++count);
        dfs_rec(g, u, visited);
        printf("\n");
        u = to_visit(visited, g->n_vertices);
    }
    return count;
}

The same skeleton works with BFS: replace dfs_rec with a queue-based bfs(g, u, visited) that accepts the shared visited array. It also works unchanged for adjacency lists; only the neighbour loop changes. The matrix version costs O(V²); the list version costs O(V + E).

1.3 BFS variant

void bfs_component(graph_t *g, int start, int visited[])
{
    int q[MAXV], front = 0, rear = 0;
    visited[start] = 1;
    q[rear++] = start;

    while (front < rear) {
        int u = q[front++];
        printf("%d ", u);
        for (int v = 0; v < g->n_vertices; ++v) {
            if (g->adj[u][v] && !visited[v]) {
                visited[v] = 1;
                q[rear++] = v;
            }
        }
    }
}

int components_bfs(graph_t *g)
{
    int visited[MAXV] = {0};
    int count = 0, u;
    while ((u = to_visit(visited, g->n_vertices)) != -1) {
        printf("Component %d: ", ++count);
        bfs_component(g, u, visited);
        printf("\n");
    }
    return count;
}
Complexity

Adjacency list: each vertex is visited once and each edge is examined twice (once from each endpoint), so O(V + E). Adjacency matrix: for each visited vertex, all V columns are scanned, so O(V²). The to_visit scan adds O(V²) in the worst case for the matrix version; for the list version, a maintained unvisited list or a single linear scan can keep the total at O(V + E).

Applications: finding isolated subnetworks, grouping users in a social graph, counting islands in a grid, segmenting an image into regions, checking whether a network is partitioned after link failures, and determining whether a graph is connected before running an algorithm that assumes connectivity (such as an MST or an Euler tour).

2. Finding a Path in a Network

Connectivity answers "is there a path?" Path finding answers "which vertices form it?" The path is returned in an output array, with a separate length variable because the caller allocated the array and the function fills it. This is the same output-parameter pattern used for any variable-length result in C.

Path contract
find_path(graph, path, &len, from, to) → 1 if found, 0 otherwise

On success, path[0..len−1] contains the vertices in order. On failure, len is 0 and the contents are unspecified.

2.1 DFS with backtracking (adjacency matrix)

DFS walks forward, adding each vertex to the path. If it reaches the destination, it returns success. If a branch fails, it removes the last vertex from the path and tries the next neighbour of the previous vertex. This removal is the backtracking step.

int find_path_rec(graph_t *g, int path[], int *len,
                  int from, int to, int visited[])
{
    visited[from] = 1;
    path[(*len)++] = from;               /* tentatively include from */

    if (from == to) return 1;            /* destination reached */

    for (int v = 0; v < g->n_vertices; ++v) {
        if (g->adj[from][v] && !visited[v]) {
            if (find_path_rec(g, path, len, v, to, visited))
                return 1;                /* keep this successful branch */
        }
    }

    --(*len);                            /* dead end: backtrack */
    return 0;
}

int find_path(graph_t *g, int path[], int *len, int from, int to)
{
    int visited[MAXV] = {0};
    *len = 0;
    return find_path_rec(g, path, len, from, to, visited);
}
A subtle bug to avoid

Do not write return find_path_recursive(...) directly inside the loop unless you intend to abandon the search after the first neighbour. That returns failure immediately when the first branch is a dead end, without trying the remaining neighbours. The correct pattern is if (recursive_call(...)) return 1; so a failed branch falls through to the next iteration. The final --len is what removes the dead-end vertex.

2.2 BFS with a parent array (adjacency list)

BFS gives the shortest path in number of edges for an unweighted graph. Instead of storing the whole path at every step, store only each vertex's parent — the vertex from which it was first discovered. When the destination is reached, walk the parent chain backward and reverse it.

int find_path_bfs(graph_t *g, int parent[], int from, int to)
{
    int visited[MAXV] = {0};
    int q[MAXV], front = 0, rear = 0;

    for (int i = 0; i < g->n_vertices; ++i) parent[i] = -1;
    visited[from] = 1;
    q[rear++] = from;

    while (front < rear) {
        int u = q[front++];
        for (edge_node_t *e = g->adj[u].head; e; e = e->next) {
            int v = e->vertex;
            if (visited[v]) continue;
            visited[v] = 1;
            parent[v] = u;                /* v was discovered from u */
            if (v == to) return 1;        /* BFS: first discovery is shortest */
            q[rear++] = v;
        }
    }
    return 0;
}

void fill_path(int parent[], int path[], int *len, int to)
{
    *len = 0;
    while (to != -1) {
        path[(*len)++] = to;
        to = parent[to];
    }
    for (int i = 0, j = *len - 1; i < j; ++i, --j) {
        int t = path[i]; path[i] = path[j]; path[j] = t;
    }
}

int find_path_list(graph_t *g, int path[], int *len, int from, int to)
{
    int parent[MAXV];
    if (!find_path_bfs(g, parent, from, to)) { *len = 0; return 0; }
    fill_path(parent, path, len, to);
    return 1;
}

Network interpretation

In a network, vertices are routers/hosts and edges are links. BFS finds the minimum-hop route, which is what a hop-count routing protocol cares about. DFS finds a route and is the basis for reachability checks, loop detection and maze solving. If links have different costs or delays, BFS's "fewest edges" is not the cheapest path; Dijkstra's algorithm (a priority-queue BFS) is required. The parent-array technique is exactly the same: replace the FIFO queue with a min-priority queue keyed by distance.

3. Trie Trees: The Prefix Tree

A trie (pronounced "try"), also called a prefix tree, stores a set of strings by sharing their common prefixes. It is a general tree, not a binary tree: a node may have as many children as the alphabet has symbols. The key idea is that the edge represents a character, while the path from the root spells a prefix. A boolean flag at a node marks whether that prefix is a complete word.

Structural facts
  • The root represents the empty prefix and normally stores no character.
  • Each edge represents exactly one character.
  • A node may have many children — one per possible next character.
  • is_word_end distinguishes a complete word from a mere prefix.
  • A node can be a valid prefix without being a complete word (e.g. ca in a trie containing cat and cap).
  • Words sharing a prefix share the entire path for that prefix.

3.1 Node representation

With an alphabet of Σ symbols, the straightforward node stores Σ child pointers. For extended ASCII, Σ = 256. The array is sparse in practice: most entries are NULL.

#define ALPHABET 256

typedef struct node {
    struct node *child[ALPHABET];   /* one slot per possible character */
    int is_word_end;                /* 1 if the path to here is a complete word */
} node_t;

typedef struct {
    node_t *root;
} trie_t;

static node_t *make_node(void)
{
    node_t *n = malloc(sizeof *n);
    if (!n) { fprintf(stderr, "out of memory\n"); exit(1); }
    for (int i = 0; i < ALPHABET; ++i) n->child[i] = NULL;
    n->is_word_end = 0;
    return n;
}

void init_trie(trie_t *t) { t->root = make_node(); }
Memory reality check
naive node = Σ pointers + flag  ≈  256 × 8 bytes ≈ 2 KB per node

A trie with one million character-nodes would need gigabytes. Real implementations use one of: a 26-entry array for lowercase English, a hash map from character to child, a sorted linked list of children, or a compressed/radix trie. The asymptotic operation cost is unchanged; the constant and memory footprint change dramatically.

3.2 Insertion

Start at the root. For each character, follow the corresponding child if it exists; otherwise create it. At the end of the string, set is_word_end = 1. Insertion creates only the missing suffix of the path, so shared prefixes are reused automatically.

void insert_word(trie_t *t, const char *s)
{
    node_t *cur = t->root;
    for (int i = 0; s[i] != '\0'; ++i) {
        unsigned char c = (unsigned char)s[i];
        if (cur->child[c] == NULL)
            cur->child[c] = make_node();
        cur = cur->child[c];
    }
    cur->is_word_end = 1;
}

3.3 Search: exact word vs prefix

Exact search must follow every character and verify that the final node is marked as a word end. Finding the path alone is not enough: ca has a path in the trie above, but it is only a prefix. Prefix search stops after following the characters and only checks that the path exists.

/* Return the node reached by following s, or NULL if the path is absent. */
static node_t *walk(trie_t *t, const char *s)
{
    node_t *cur = t->root;
    for (int i = 0; s[i] != '\0'; ++i) {
        unsigned char c = (unsigned char)s[i];
        if (cur->child[c] == NULL) return NULL;
        cur = cur->child[c];
    }
    return cur;
}

int search_word(trie_t *t, const char *s)
{
    node_t *n = walk(t, s);
    return n != NULL && n->is_word_end;
}

int starts_with(trie_t *t, const char *prefix)
{
    return walk(t, prefix) != NULL;
}
Trie operation cost
insert / exact search / prefix search / delete = O(L)

L is the length of the query string, independent of the number of stored words n. This is the trie's defining advantage over a BST, whose search depends on tree height and key comparisons.

3.4 Displaying all words

A depth-first walk from the root accumulates the path in a buffer. When a node has is_word_end, print the buffer. Iterating children in character order produces lexicographic output. The buffer length is bounded by the longest word; no per-word allocation is required.

static void display_rec(node_t *cur, char word[], int depth)
{
    if (cur->is_word_end) {
        word[depth] = '\0';
        printf("%s\n", word);
    }
    for (int c = 0; c < ALPHABET; ++c) {
        if (cur->child[c]) {
            word[depth] = (char)c;
            display_rec(cur->child[c], word, depth + 1);
        }
    }
}

void display(trie_t *t)
{
    char buffer[1024];
    display_rec(t->root, buffer, 0);
}

To display every word with a given prefix, first walk to the prefix node, copy the prefix into the buffer, and run the same recursive display from that node. If the prefix node is itself a word end, print the prefix first.

3.5 Deletion with prefix preservation

Deletion is subtle because a node may be shared by several words. The safe algorithm works in two stages:

  1. Unmark: follow the path. If it does not exist or the final node is not a word end, do nothing. Otherwise set is_word_end = 0.
  2. Prune: walk back from the leaf. A node can be freed only if it is not the end of another word and has no children. Stop pruning at the first node that is still needed. Never free the root.
static int has_no_child(node_t *n)
{
    for (int c = 0; c < ALPHABET; ++c)
        if (n->child[c]) return 0;
    return 1;
}

/* Returns 1 if cur may be freed by its parent. */
static int delete_rec(node_t *cur, const char *s, int depth)
{
    if (cur == NULL) return 0;

    if (s[depth] == '\0') {
        if (!cur->is_word_end) return 0;    /* not a stored word */
        cur->is_word_end = 0;
        return has_no_child(cur);           /* prune only if nothing below */
    }

    unsigned char c = (unsigned char)s[depth];
    if (cur->child[c] == NULL) return 0;    /* word absent */

    int prune = delete_rec(cur->child[c], s, depth + 1);
    if (prune) {
        free(cur->child[c]);
        cur->child[c] = NULL;
        return !cur->is_word_end && has_no_child(cur);
    }
    return 0;
}

void delete_word(trie_t *t, const char *s)
{
    delete_rec(t->root, s, 0);              /* root is never freed */
}
Worked pruning examples on the trie above

Delete bat: unmark the t node and free it. Its parent a still has the l branch for ball, so pruning stops. ba remains a prefix.

Delete cap: unmark and free p. The parent a still has the t branch for cat, so pruning stops.

Delete cat: unmark and free t; a now has no children and is not a word end, so free a; c now has no children and is not a word end, so free c. The root remains. If ca had been a stored word, a would have been kept.

4. Trie vs BST and Real Applications

A trie and a balanced BST solve different versions of the "lookup" problem. A trie organizes by characters and prefixes; a BST organizes by whole-key comparisons.

4.1 Applications

ApplicationHow the trie is used
Autocomplete and search suggestionsWalk the typed prefix, then enumerate all words below that node, ranked by frequency or recency.
Spell checkers and autocorrectFind the longest valid prefix; search near-neighbour paths for edit-distance variants; suggest completions from the subtree.
IP routing (longest-prefix match)Store routing prefixes in a binary/radix trie of address bits. The deepest matching prefix selects the next hop. This is the basis of CIDR routing tables.
BioinformaticsIndex DNA/protein sequences; find common prefixes and motifs; suffix structures (next section) extend this to arbitrary substrings.
Keyword filtering and moderationMatch a stream against a dictionary of banned words; the trie shares prefixes and avoids rescanning repeated characters.

Word games / dictionariesCheck whether a rack of letters can form a word by walking the trie; prune branches when no prefix exists.
Why tries are not always the answer

The naive Σ-pointer node is memory-hungry, and cache behaviour can be poor because each character is a separate pointer chase. For a small set of long, unrelated keys, a hash table or a balanced BST is often better. Tries win when prefixes are shared and prefix queries are required; compressed tries (Patricia/radix) win when the alphabet is large and the strings are long.

5. Suffix Tries: Indexing Every Suffix

A normal trie is excellent for "is this a word?" and "which words start with this prefix?" It does not directly answer "is this pattern a substring of a text?" A suffix trie solves that by storing all suffixes of a text. The key observation is:

The substring–suffix equivalence
P is a substring of T  ⇔  P is a prefix of some suffix of T

Therefore, searching for P in a suffix trie is exactly the same prefix walk as searching for a word in an ordinary trie.

5.1 Definition and construction

Let T have length n. Append a unique terminator $ that does not occur elsewhere in the alphabet, producing T$. A suffix trie for T is the trie obtained by inserting every suffix of T$:

Suffixes of banana$
banana$ · anana$ · nana$ · ana$ · na$ · a$ · $   (start indices 0…6)

There are n + 1 suffixes including the empty suffix represented by $. Appending the unique terminator ensures that no suffix is a prefix of another, so every suffix ends at its own leaf.

Construction is deliberately simple: for each start index i, insert T[i..n−1] followed by $ into an ordinary trie. Shared prefixes are stored once automatically.

void build_suffix_trie(trie_t *t, const char *text)
{
    int n = strlen(text);
    char suffix[MAXLEN + 2];

    for (int i = 0; i < n; ++i) {
        strcpy(suffix, text + i);      /* suffix starting at i */
        strcat(suffix, "$");            /* unique terminator */
        insert_word(t, suffix);
    }
    insert_word(t, "$");                /* the empty suffix */
}

The path facts are exact: ana is reached through a → n → a, and its subtree contains leaves 3 and 1, corresponding to suffixes ana$ and anana$. The shared prefix a → n → a is stored once, but the unary chains above and below it still create one node per character in the worst case — which is exactly the quadratic cost.

5.2 Searching for a substring

To test whether pattern P occurs, start at the root and follow the characters of P:

  • If an edge is missing, P is not a substring.
  • If every character is consumed, P occurs. The walk may end at an internal node, not necessarily a leaf — that is expected for a substring.
  • The occurrence positions are the start labels of all leaves in the subtree below the ending node.
Search "ana" in banana$:
root → a → n → a     (path exists)
subtree leaves: 3 (ana$) and 1 (anana$)
⇒ "ana" occurs at indices 3 and 1.  ("banana": b a n a n a)

Search "nan":
root → n → a → n     (path exists)
subtree leaf: 2 (nana$)
⇒ occurrence at index 2.

Search "aa":  root → a → a   (no edge) ⇒ absent.

Search "a":  root → a (internal node)
subtree leaves: 5 (a$), 3 (ana$), 1 (anana$)
⇒ occurrences at 5, 3, 1.

5.3 Why the space is O(n²)

Suffix lengths are 1, 2, 3, …, n (plus the terminator), so the total number of characters inserted is:

Suffix trie size
1 + 2 + 3 + … + n = n(n + 1)/2 = Θ(n²)

Even though prefixes are shared, the worst case still creates a quadratic number of nodes. A suffix trie is a conceptual stepping stone, not a practical index for large texts.

OperationSuffix trie cost
BuildO(n²) time and space
Substring existenceO(|P|)
Report all occurrencesO(|P| + occurrences)
Longest repeated substringDeepest internal node; O(n²) to build

Applications: substring search, DNA motif lookup, plagiarism detection, text indexing, longest repeated substring, and as the conceptual basis for the suffix tree and suffix array.

6. Suffix Trees and Patricia Compression

The quadratic blow-up of a suffix trie comes from silly nodes: internal nodes with exactly one child. They encode no branching decision; they only lengthen the path and consume memory. A Patricia trie (compressed trie) removes them by merging each unary chain into a single edge whose label is the whole substring.

Patricia / compressed trie
  • A silly node is an internal node with exactly one child. It contributes no branching and only increases height and space.
  • A Patricia trie merges all silly nodes with their parent; a chain of single-child nodes becomes one edge labeled with the corresponding character sequence.
  • Every internal node now represents a genuine branching point and has at least two children.
  • Edges store substrings, typically as (start, end) index pairs into the original text, not copied strings.
  • The trie uses less memory and usually has lower height, so traversal is faster.

6.1 From suffix trie to suffix tree

A suffix tree for a string T is the Patricia trie of all suffixes of T$, where $ is a unique terminator not in the alphabet.

  • Each leaf is labeled with the starting position of the suffix it represents.
  • Every root-to-leaf path corresponds to a suffix of T$.
  • Edge labels are substrings of T$, represented by index pairs.
  • Every internal node (except possibly the root) has at least two children.
  • A suffix tree for a string of length n has n + 1 leaves and at most n internal nodes, hence O(n) nodes and O(n) space.

6.2 Pattern search on a suffix tree

Start at the root and match the pattern against edge labels. At an edge, compare characters until either the pattern is exhausted (success) or a mismatch occurs (failure). Because each edge can be skipped in O(1) once its label is known, matching a pattern of length m takes O(m) time, independent of the text length. All leaves below the ending point give the occurrence positions.

Suffix tree search
substring query = O(m + occurrences)

The text itself is not scanned again; the tree is the index. This is why suffix trees are used for large, static texts.

6.3 Construction and space

MethodTimeSpaceComment
Build a suffix trie, then compressO(n²)O(n²) during constructionConceptually simple; impractical for large n.
Naive suffix tree constructionO(n²)O(n)Insert suffixes one by one into a compressed trie.

Storing edge labels as (start, end) index pairs is what keeps the space linear: a long edge does not duplicate the substring, it only records where the substring lives in T$. The unique terminator guarantees that no suffix is a prefix of another, so each suffix reaches a distinct leaf and the leaf count is exactly n + 1.

6.5 Applications

  • Substring search in a static text: build once, answer many queries in O(m).
  • Longest repeated substring: the deepest internal node; its path label is the longest substring occurring at least twice.
  • Longest common substring of two strings: build a generalized suffix tree for both, mark leaves by source, and find the deepest node with leaves from both.
  • Bioinformatics: index DNA/protein sequences for motif search, repeat detection and genome alignment.
  • Data compression: repeated substrings reveal redundancy; suffix-based dictionaries exploit it.
  • Plagiarism and duplicate detection: shared long substrings are evidence of copying.
  • Text editors and search engines: suffix arrays (a space-efficient relative) and suffix automata are used for large-scale indexing.

Suffix array connection: a suffix array stores the starting positions of all suffixes in lexicographic order. It uses O(n) space like a suffix tree, is much simpler to build and store, and can answer many of the same queries with binary search plus an LCP array. It is the practical alternative when a full pointer-based suffix tree would be too heavy.

7. Hashing: Keys, Tables & Hash Functions

Every structure so far trades time for order: a sorted array gives binary search in O(log n), an AVL tree keeps height logarithmic, a heap gives the extreme element in O(1). Hashing takes a different route. If repeated retrieval is the dominant operation, we want lookup whose cost does not grow with the number of records. A hash table achieves this by computing the storage location directly from the key, so a well-spread table answers a search in expected O(1) time.

WHERE HASH TABLES APPEAR

AWK calls them associative arrays, Python calls them dict, C++ calls them unordered_map, and compilers use them for symbol tables. The idea is the same everywhere: map a key to a slot with a function instead of searching.

7.1 The core vocabulary

TermMeaning
KeyA unique value identifying a record. Non-integer keys (identifiers, strings) are first converted to an integer, e.g. by summing character codes.
Hash function h(k)A function that maps a key k to an index in the range 0 … m−1, where m is the table size.
Hash tableThe array of m slots in which records (or pointers to them) are stored.
CollisionTwo distinct keys k₁ ≠ k₂ with h(k₁) = h(k₂) map to the same slot.
OverflowAn attempt to insert into a fixed-size table whose slots are all occupied. (Collision handling is covered here; general overflow techniques are outside this course.)
Load factor αThe average number of keys per slot: α = n / m, with n stored keys and m slots.
Load factor
α = n / m

n = number of keys stored, m = number of table slots. α measures how full the table is; every collision strategy degrades as α rises.

7.2 When to use an array and when to use a hash table

  • Integer keys, dense range — use a plain array and index directly. House numbers 1 … n need no hashing.
  • Non-integer keys — use a hash table. Program identifiers must be converted to integers first.
  • Integer keys, sparse range — a hash table avoids allocating a huge, mostly empty array (e.g. keys like 10, 100000, 7000000).

7.3 Properties of a good hash function

Four requirements
fast  ·  deterministic  ·  uniform  ·  few collisions
  • Fast to compute — the function must not cost more than the search it replaces.
  • Deterministic — the same key must always map to the same index.
  • Uniform — keys should be spread evenly over 0 … m−1.
  • Collision-minimising — any fixed function can collide, but a good one keeps collisions rare in practice.

7.4 Common hash functions

Division method

The simplest and the one used throughout the course examples: take the remainder after dividing the key by the table size. A prime table size gives a good spread because it has no small factors that would make many keys land on the same residue.

Division method
h(k) = k mod m

Example: k = 40, m = 19 ⇒ h(40) = 40 mod 19 = 2.

Multiplication method

Multiply the key by a constant fraction A, keep the fractional part, then scale by the table size and take the floor. Because the fraction A is fixed, the table size need not be prime.

Multiplication method
h(k) = ⌊ m · ( kA mod 1 ) ⌋

A is a constant in (0,1); kA mod 1 extracts the fractional part. Knuth suggests A ≈ (√5 − 1)/2 ≈ 0.618.

Mid-square method

Square the key and take a selected middle portion of the result (middle digits or middle bits). The middle digits depend on every digit of the input, which mixes the key well.

Mid-square method
k = 44 ⇒ k² = 1936 ⇒ select middle digits

The chosen middle portion is then reduced modulo m to land inside the table. Different table sizes can select different digit counts.

Folding method

Split the key into equal-length parts, add the parts, and map the sum into the table range. This is common when hashing long identifiers or account numbers.

Folding method
123456 → 12 + 34 + 56 = 102 → 102 mod m

The final modulo maps the folded sum into 0 … m−1.

String hashing

A string key is reduced to an integer character by character. Summing character codes is the simplest version, but it ignores order ("ab" and "ba" collide). A polynomial rolling hash fixes this by weighting each character by a power of a base.

Polynomial rolling hash
h = ( h · b + ci ) mod m   for each character ci

A common base is b = 31 (or 37 / 131). Horner's form lets the hash be computed in one left-to-right pass, O(|s|) time.

/* Polynomial rolling hash of a C string. */
unsigned long hash_string(const char *s)
{
    unsigned long h = 0;
    const unsigned long b = 31;

    for (int i = 0; s[i] != '\0'; ++i)
        h = (h * b + (unsigned char)s[i]) % TABLESIZE;

    return h;                       /* index in 0 … TABLESIZE-1 */
}
COLLISION IS UNAVOIDABLE

If the key universe is larger than m, then by the pigeonhole principle two keys must share a slot. Even with a perfect distribution, collisions occur once n > m. The rest of this unit is about handling them correctly and cheaply.

8. Separate Chaining (Open Hashing)

Separate chaining resolves collisions outside the table. Each slot is the head of a linked list (a bucket). A key is hashed to a slot and then appended to that slot's list. Because the lists grow dynamically, the number of stored keys may exceed the table size — there is no overflow as long as memory is available.

8.1 Structure

The table is an array of node pointers. Each node holds the key, the record (here a string), and a next pointer. Null heads mark empty buckets.

#define TABLESIZE 19

struct node {
    int key_;
    char word_[WORDSIZE];
    struct node *next_;
};
typedef struct node node_t;

struct hash_table {
    struct node *head_[TABLESIZE];   /* one list head per slot */
};
typedef struct hash_table hash_table_t;

The table size is normally a prime number: with the division method, a prime modulus avoids the pattern where many keys share a factor with m and pile into a few residues.

8.2 Operations

Initialise — set every head to NULL. Deinitialise — walk each chain, free every node, then ground the head.

void init_hash_table(hash_table_t *ht)
{
    for (int i = 0; i < TABLESIZE; ++i)
        ht->head_[i] = NULL;
}

void deinit_hash_table(hash_table_t *ht)
{
    for (int i = 0; i < TABLESIZE; ++i) {
        node_t *p = ht->head_[i];
        while (p) {
            node_t *next = p->next_;
            free(p);
            p = next;
        }
        ht->head_[i] = NULL;
    }
}

Insert

Hash the key, create a node, and link it at the front of the chain. Insertion at the head is O(1) after hashing: no traversal is needed.

void insert_word(hash_table_t *ht, int key, const char *word)
{
    int index = key % TABLESIZE;

    node_t *p = (node_t *)malloc(sizeof(node_t));
    if (!p) { printf("out of memory\n"); return; }

    p->key_ = key;
    strncpy(p->word_, word, WORDSIZE - 1);
    p->word_[WORDSIZE - 1] = '\0';
    p->next_ = ht->head_[index];    /* prepend */
    ht->head_[index] = p;
}

Search

Hash the key to find the bucket, then walk that chain comparing keys. A match returns the record pointer; reaching NULL means the key is absent.

char *search(hash_table_t *ht, int key)
{
    int index = key % TABLESIZE;

    for (node_t *p = ht->head_[index]; p != NULL; p = p->next_)
        if (p->key_ == key)
            return p->word_;

    return "";
}

Delete

Find the node in its chain while tracking the previous node. Unlink it with the usual list-deletion cases (head or middle) and free it. Deletion is straightforward precisely because the nodes live outside the table.

void delete_key(hash_table_t *ht, int key)
{
    int index = key % TABLESIZE;
    node_t *prev = NULL, *p = ht->head_[index];

    while (p && p->key_ != key) {
        prev = p;
        p = p->next_;
    }
    if (!p) { printf("key not found\n"); return; }

    if (prev) prev->next_ = p->next_;   /* middle / tail */
    else      ht->head_[index] = p->next_;  /* head */
    free(p);
}

Display

Walk every slot from 0 to TABLESIZE−1 and print each non-empty chain. This also reveals which slot each key occupies.

8.3 Complexity of separate chaining

Expected cost with load factor α = n / m
search / insert / delete  =  Θ( 1 + α )

Hashing takes Θ(1); the chain walk takes the expected chain length, which is α. With α held constant, all operations are expected O(1). Worst case is Θ(n) if every key lands in one chain.

Advantages

  • Simple collision handling.
  • Table may hold more entries than it has slots.
  • Deletion is straightforward — unlink and free.

Disadvantages

  • Extra memory for next pointers and allocator overhead.
  • Poor cache locality from pointer jumping.
  • A poor hash function creates long chains and degrades to linear search.

9. Open Addressing: Linear, Quadratic & Double Hashing

Open addressing (also called closed hashing) keeps every record inside the array — no pointers, no lists. When the home slot h(k) is occupied, the algorithm follows a deterministic probe sequence until it finds a free slot. The table size must be at least the number of keys, and the load factor α must stay below 1.

PROBE SEQUENCE

A probe sequence is h(k, 0), h(k, 1), h(k, 2), … — the order in which slots are examined. Insert, search, and delete must all follow the same sequence for a given key, otherwise a stored key could never be found again.

9.1 Linear probing

Linear probing examines consecutive slots, wrapping around with modular arithmetic. On insertion, if a slot is occupied we simply advance by one:

Linear probing
h(k, i) = ( h(k) + i ) mod m   for i = 0, 1, 2, …

The record may end up far from its home slot, but it is always in the first free slot at or after h(k).

struct node {
    int in_use_;                 /* 0 = free, 1 = occupied */
    int key_;
    char word_[WORDSIZE];
};
typedef struct node node_t;

struct hash_table {
    node_t elem_[TABLESIZE];
    int count_;
};
typedef struct hash_table hash_table_t;

void insert_word(hash_table_t *ht, int key, const char *word)
{
    if (ht->count_ == TABLESIZE) {
        printf("table full; cannot insert\n");
        return;
    }

    int index = key % TABLESIZE;

    while (ht->elem_[index].in_use_ != 0)
        index = (index + 1) % TABLESIZE;   /* linear step */

    ht->elem_[index].key_    = key;
    strncpy(ht->elem_[index].word_, word, WORDSIZE - 1);
    ht->elem_[index].word_[WORDSIZE - 1] = '\0';
    ht->elem_[index].in_use_ = 1;
    ++ht->count_;
}

Search uses the same walk: start at h(k) and move forward until the key is found or an empty slot is reached. An empty slot proves the key is absent, because a colliding key would have been placed before the gap.

Primary clustering

Occupied slots form runs. A key hashing into the middle of a run must scan to the end of it, and every insertion lengthens the run, making future collisions more likely. This feedback loop is called primary clustering: average probe length grows sharply as α approaches 1.

Expected probes for linear probing
successful: ½ ( 1 + 1/(1−α) )   ·   unsuccessful: ½ ( 1 + 1/(1−α)² )

As α → 1 these blow up. Linear probing is only efficient at low load factors (rule of thumb α ≤ 0.5).

Deletion and tombstones

You cannot simply mark a deleted slot as free: that would break a probe chain and make later keys unfindable. Instead mark it DELETED — a tombstone. Search treats a tombstone as "keep probing", while insert may reuse it. The slot needs three states: EMPTY (never used), OCCUPIED, and DELETED.

THE COURSE CODE USES A FLAG, NOT TOMBSTONES

The lecture implementation stores only in_use_ and decrements count_ on delete, walking only count_ filled slots. That works for the demo but is not a general deletion scheme. A production table must use expired markers (tombstones) or rebuild the chain, otherwise a search can terminate early at a cleared slot.

/* Three-state slot: a tombstone keeps probe chains intact. */
enum { EMPTY = 0, OCCUPIED = 1, DELETED = 2 };

char *search(hash_table_t *ht, int key)
{
    int index = key % TABLESIZE;

    for (int probes = 0; probes < TABLESIZE; ++probes) {
        if (ht->elem_[index].state_ == EMPTY)
            return "";                          /* genuine gap: absent */
        if (ht->elem_[index].state_ == OCCUPIED &&
            ht->elem_[index].key_ == key)
            return ht->elem_[index].word_;
        index = (index + 1) % TABLESIZE;
    }
    return "";
}

9.2 Quadratic probing

Linear probing's weakness is the long contiguous run. Quadratic probing steps by increasing squares instead of by one, so successive probes leap farther away and break up runs:

Quadratic probing
h(k, i) = ( h(k) + i² ) mod m   for i = 0, 1, 2, …

Probe offsets: 0, 1, 4, 9, 16, 25, …. Because the offset depends only on i, all keys with the same home slot follow the same sequence.

void insert_word(hash_table_t *ht, int key, const char *word)
{
    if (ht->count_ == TABLESIZE) { printf("table full\n"); return; }

    int home  = key % TABLESIZE;
    int index = home;

    for (int i = 0; i < TABLESIZE; ++i) {
        index = (home + i * i) % TABLESIZE;
        if (ht->elem_[index].in_use_ == 0)
            break;
    }

    ht->elem_[index].key_    = key;
    strncpy(ht->elem_[index].word_, word, WORDSIZE - 1);
    ht->elem_[index].word_[WORDSIZE - 1] = '\0';
    ht->elem_[index].in_use_ = 1;
    ++ht->count_;
}

Secondary clustering

Quadratic probing removes primary clustering but not every collision pattern. Keys with the same home index probe the same sequence, so they still cluster — this is secondary clustering. Double hashing is designed to break it.

NOT EVERY SLOT IS GUARANTEED

For m a prime of the form 4j+3, the sequence i² mod m for i = 0…(m−1)/2 covers all distinct residues, so quadratic probing can reach every slot. For general m it may not: the probe sequence can cycle before finding a free slot even when the table is not full. Choosing a suitable prime table size avoids this.

9.3 Double hashing

Double hashing computes the probe step from a second hash function h₂(k), so different keys with the same home slot take different paths through the table. This eliminates the shared-sequence clustering of the previous two schemes.

Double hashing
h(k, i) = ( h₁(k) + i · h₂(k) ) mod m

h₁ gives the home slot, h₂ gives the step size. The step must never be 0, and it must be coprime with m so the probe sequence visits every slot.

A common second hash function
h₂(k) = q − ( k mod q )   with q prime and q < m

Course example with m = 11: h₂(k) = 7 − (k mod 7), which returns a value in 1 … 7. Every step is non-zero and coprime to 11.

int hash_double(int key) { return 7 - key % 7; }   /* prime 7 < m */

void insert_word(hash_table_t *ht, int key, const char *word)
{
    int home  = key % TABLESIZE;
    int step  = ht->hash_fn_(key);        /* callback, fixed per key */
    int index = home;

    for (int i = 0; i < TABLESIZE; ++i) {
        index = (home + i * step) % TABLESIZE;
        if (ht->elem_[index].in_use_ == 0)
            break;
    }
    /* store record at index and mark in_use_ */
}

The table struct carries a function pointer so the second hash can be chosen at initialisation time. Insert, delete, and search all use the identical step, which is what makes a stored key retrievable.

struct hash_table {
    node_t elem_[TABLESIZE];
    int count_;
    int (*hash_fn_)(int);      /* second hash callback */
};

9.4 Worked collision example (m = 11)

Hash the keys 22, 12, 13, 27, 32, 45 into an 11-slot table using the division method h(k) = k mod 11. The first five keys are placed without collision; key 45 collides at slot 1 with 12.

For uniform hashing (the ideal that double hashing approximates). At α = 0.5 an unsuccessful search averages 2 probes; at α = 0.9 it averages 10.

Open addressing — advantages

  • No pointer overhead; records sit in one contiguous array.
  • Excellent cache locality.
  • Memory-efficient when the load factor is moderate.

  • Clustering raises probe length as the table fills.
  • Deletion needs tombstones or rebuilding.
  • Performance collapses near α = 1; table must stay below full.

10. Rehashing & Load-Factor Management

No matter which collision strategy is used, performance depends on the load factor. As α grows, chains lengthen and probe sequences stretch. Rehashing keeps α bounded: when the table passes a threshold, allocate a larger table and reinsert every existing key using the new table size.

WHY THE HASH FUNCTION MUST CHANGE

With the division method, h(k) = k mod m depends on m. When the table is resized, every key's index changes, so old positions are meaningless. Each key must be re-hashed and re-inserted into the new array — you cannot simply copy the slots across.

10.1 When to rehash

StrategyTypical thresholdReason
Separate chainingα ≈ 1.0Chains stay short; the table may briefly exceed m.
Linear probingα ≈ 0.5Primary clustering makes probes expensive beyond half full.
Quadratic / double hashingα ≈ 0.7Probe cost rises sharply as α → 1.

10.2 The rehash procedure

α exceeds threshold→ choose new prime size ≈ 2m→ allocate new table→ re-insert every old key→ free old table
  1. Detect that n / m > threshold (usually checked just before or just after an insertion).
  2. Choose a new table size, commonly roughly double the old one, rounded up to a prime.
  3. Allocate the new array and initialise every slot.
  4. Traverse the old table and insert each key into the new table with the new modulus. For chaining, walk each chain; for open addressing, skip empty/tombstone slots.
  5. Free the old storage and update the table pointer and size.
void rehash(hash_table_t *ht)
{
    int old_size = ht->size_;
    node_t *old    = ht->elem_;

    int new_size = next_prime(2 * old_size);
    ht->elem_  = calloc(new_size, sizeof(node_t));
    ht->size_  = new_size;
    ht->count_ = 0;

    for (int i = 0; i < old_size; ++i)
        if (old[i].in_use_)
            insert_word(ht, old[i].key_, old[i].word_);  /* re-hash */

    free(old);
}
Amortised cost
one rehash of n keys = Θ(n)  ⇒  amortised per insertion = Θ(1)

Doubling the size means the total work of all rehashes is dominated by the last one (a geometric series), so the cost spread over all insertions is constant. Rehashing is not O(1) for the single insertion that triggers it; it is O(1) amortised.

REHASHING IS NOT FREE

During a rehash the table is unavailable and memory use briefly doubles. Real-time systems may use incremental rehashing: move a few buckets per operation so no single call pays the whole cost.

10.3 Applications of hashing

  • Compiler symbol tables — map identifiers to type, scope, and location information.
  • Database indexing — locate records by key without scanning.
  • Caches — retrieve stored values quickly by lookup key.
  • Dictionaries and sets — fast membership tests and key–value storage.
  • Duplicate detection — insert into a hash set and report keys already present.
  • String matching — rolling hashes (Rabin–Karp) compare substrings in O(1).
