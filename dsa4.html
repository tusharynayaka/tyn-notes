1. Trees, Binary Trees and the BST Ordering

A tree is a non-linear, hierarchical data structure. Formally it is an acyclic, connected graph. A tree with n nodes has exactly n − 1 edges (branches). Adding any edge creates a cycle; removing any edge disconnects the structure. A general tree is either empty, or a root followed by zero or more disjoint subtrees. This recursive definition is what makes recursive algorithms natural.

Tree edge identity
|E| = n − 1   ·   |E| = n − 1 + c for a forest with c components

A forest is a collection of disjoint trees. A single tree is the special case c = 1.

1.2 Binary trees and their shapes

A binary tree is either empty, or a root with a left subtree and a right subtree, both themselves binary trees. The two children are distinguished: a node with one child must still be identified as left-only or right-only. The recursive definition suggests the recursive node representation used throughout this unit.

Full (proper) binary tree

Every node has either 0 or 2 children. No node has exactly one child.

Complete binary tree

All levels except possibly the last are completely filled, and the last level is filled from left to right with no gaps.

Perfect binary tree

All internal nodes have two children and all leaves are at the same level. Height h implies 2h+1 − 1 nodes.

Degenerate (skewed) tree

Every internal node has only one child. It behaves like a linked list, with height n − 1 and linear-time search.

Binary-tree counting formulas
max nodes at level k = 2k
max nodes in a tree of height h = 2h+1 − 1
min height for n nodes = ⌊log2 n⌋
max height for n nodes = n − 1 (skewed)

For any non-empty binary tree, if n0 is the number of leaves and n2 the number of nodes with two children, then n0 = n2 + 1.

Why the leaf formula is true

Count edges downward: every node except the root has exactly one incoming edge, so n − 1 = n1 + 2n2, where n1 counts one-child nodes. Also n = n0 + n1 + n2.

Subtracting gives n0 − 1 = n2, so n0 = n2 + 1. This holds for every binary tree, not only balanced ones.

1.4 Binary search tree (BST) ordering

A binary search tree is a binary tree in which every node stores a key and the following predicate holds for every node:

BST invariant
all keys in left subtree < key(node) < all keys in right subtree

The comparison must hold against the whole subtree, not merely against the immediate child. Equal keys need an explicit policy: reject duplicates, keep a count in one node, or send equal keys consistently to one side. The code in this course sends key ≥ root to the right.

  • Insertion always creates a leaf. Search from the root, turn left when the new key is smaller, right otherwise, and attach the new node where the search falls off the tree.
  • Inorder traversal produces the keys in sorted (non-decreasing) order. This is the defining operational consequence of the invariant.
  • Search follows one root-to-leaf path, discarding an entire subtree at every comparison. Cost is proportional to height h, not to n directly.
  • The minimum is the leftmost node; the maximum is the rightmost node.
  • The shape depends on insertion order. The same set of keys can build a bushy tree of height Θ(log n) or a skewed list of height n − 1.
The central weakness

A BST gives no shape guarantee. Inserting 10, 20, 30, 40, 50 in ascending order produces a right-skewed chain. Search, insert and delete then cost O(n), not O(log n). AVL and splay trees in Section 4 exist specifically to address this.

2. Dynamic BST: Every Core Operation

The dynamic implementation stores one heap-allocated node per key. The tree object holds only the root pointer; the recursive structure lives in the node. The tree-level function is a thin wrapper that calls a node-level recursive function, so the client never manipulates pointers directly.

typedef struct node {
    int key;
    struct node *left;
    struct node *right;
} node_t;

typedef struct tree {
    node_t *root;
} tree_t;

void init(tree_t *t)        { t->root = NULL; }
int  is_empty(tree_t *t)    { return t->root == NULL; }

2.1 Insertion

Create the node first, then let the recursive helper return the root of the (possibly changed) subtree. The return value is assigned to root->left or root->right; this single assignment is what links the new leaf into the tree. When the empty position is reached, the new node is returned and becomes that subtree's root.

static node_t *insert_rec(node_t *root, node_t *fresh)
{
    if (root == NULL)                 return fresh;
    if (fresh->key < root->key)        root->left  = insert_rec(root->left,  fresh);
    else                              root->right = insert_rec(root->right, fresh);
    return root;
}

void insert(tree_t *t, int key)
{
    node_t *fresh = malloc(sizeof *fresh);
    if (!fresh) { fprintf(stderr, "out of memory\n"); exit(1); }
    fresh->key = key;
    fresh->left = fresh->right = NULL;
    t->root = insert_rec(t->root, fresh);
}

Iterative version — often preferable because it uses constant stack space:

void insert_iter(tree_t *t, int key)
{
    node_t *fresh = malloc(sizeof *fresh);
    fresh->key = key; fresh->left = fresh->right = NULL;
    if (t->root == NULL) { t->root = fresh; return; }

    node_t *cur = t->root, *parent = NULL;
    while (cur != NULL) {
        parent = cur;
        cur = (key < cur->key) ? cur->left : cur->right;
    }
    if (key < parent->key) parent->left  = fresh;
    else                    parent->right = fresh;
}

2.2 Search, minimum and maximum

Search returns a pointer to the node, not a printed message. A display routine is for the user; a search routine must give the client something it can use. Returning NULL means "not found".

node_t *search_rec(node_t *root, int key)
{
    if (root == NULL || root->key == key) return root;
    if (key < root->key) return search_rec(root->left,  key);
    return                      search_rec(root->right, key);
}

node_t *search(tree_t *t, int key) { return search_rec(t->root, key); }

node_t *minimum(node_t *root)       /* leftmost node */
{
    if (!root) return NULL;
    while (root->left) root = root->left;
    return root;
}

node_t *maximum(node_t *root)       /* rightmost node */
{
    if (!root) return NULL;
    while (root->right) root = root->right;
    return root;
}
Inorder successor and predecessor

Successor of node x: if x has a right subtree, it is the minimum of that right subtree. Otherwise walk up through ancestors until the first ancestor for which x lies in its left subtree; that ancestor is the successor.

Predecessor is symmetric: maximum of the left subtree, or the first ancestor for which x lies in its right subtree. The successor is the replacement key when deleting a node with two children.

2.3 Deletion — the four cases

Deletion is the hardest basic BST operation because removing an internal node must preserve the ordering. There are four situations once the key is located:

  1. Key not found / empty tree: return NULL; nothing changes.
  2. Leaf: free it and return NULL to ground the parent's pointer.
  3. Only a right child: return the right subtree to the parent; the node is freed.
  4. Only a left child: return the left subtree to the parent; the node is freed.
  5. Both children: copy the inorder successor's key into the node, then recursively delete that successor from the right subtree. The successor has no left child, so its deletion falls into case 3 or 2.
static node_t *delete_rec(node_t *root, int key)
{
    if (root == NULL) return NULL;

    if (key < root->key) {
        root->left = delete_rec(root->left, key);
    } else if (key > root->key) {
        root->right = delete_rec(root->right, key);
    } else {
        /* found the node */
        if (root->left == NULL && root->right == NULL) {
            free(root); return NULL;
        }
        if (root->left == NULL) {
            node_t *right = root->right; free(root); return right;
        }
        if (root->right == NULL) {
            node_t *left = root->left; free(root); return left;
        }
        node_t *succ = minimum(root->right);
        root->key = succ->key;
        root->right = delete_rec(root->right, succ->key);
    }
    return root;
}

void delete_key(tree_t *t, int key) { t->root = delete_rec(t->root, key); }

2.4 Counting, comparing, copying and height

These operations all follow the same recursive pattern: handle the empty tree, combine the root with the results of the left and right subtrees.

int count_nodes(node_t *root)
{
    if (!root) return 0;
    return 1 + count_nodes(root->left) + count_nodes(root->right);
}

int count_leaves(node_t *root)
{
    if (!root) return 0;
    if (!root->left && !root->right) return 1;
    return count_leaves(root->left) + count_leaves(root->right);
}

int height(node_t *root)          /* edges; empty = -1, leaf = 0 */
{
    if (!root) return -1;
    int l = height(root->left);
    int r = height(root->right);
    return 1 + (l > r ? l : r);
}

int are_same(node_t *a, node_t *b)
{
    if (!a && !b) return 1;
    if (!a || !b)  return 0;
    return a->key == b->key
        && are_same(a->left,  b->left)
        && are_same(a->right, b->right);
}

node_t *copy_tree(node_t *src)
{
    if (!src) return NULL;
    node_t *n = malloc(sizeof *n);
    if (!n) { fprintf(stderr, "out of memory\n"); exit(1); }
    n->key   = src->key;
    n->left  = copy_tree(src->left);
    n->right = copy_tree(src->right);
    return n;
}
Why copy_tree returns a node while copy() is void

The recursive helper must return the newly created subtree root so the caller can attach it. The public tree-level function has the destination object already; it simply assigns dst->root = copy_tree(src->root). This is the same "return the new subtree root" pattern used by insertion.

2.5 Deinitialization

Freeing must be postorder: free the left subtree, the right subtree, then the node. Freeing the root first would lose the only pointers to its children.

void destroy_rec(node_t *root)
{
    if (!root) return;
    destroy_rec(root->left);
    destroy_rec(root->right);
    free(root);
}

void deinit(tree_t *t) { destroy_rec(t->root); t->root = NULL; }

3. Traversals, Level Order and Reconstruction

A traversal is a systematic way to visit every node exactly once. The three depth-first orders differ only in when the root is processed relative to its subtrees.

Inorder

left → root → right

On a BST this yields keys in sorted order.

Preorder

root → left → right

Useful for copying/serializing a tree: the root is seen before its subtrees.

Postorder

left → right → root

Useful for deletion and expression evaluation: children are finished before the parent.

void inorder(node_t *r)  { if (!r) return; inorder(r->left);  printf("%d ", r->key); inorder(r->right); }
void preorder(node_t *r) { if (!r) return; printf("%d ", r->key); preorder(r->left); preorder(r->right); }
void postorder(node_t *r){ if (!r) return; postorder(r->left); postorder(r->right); printf("%d ", r->key); }

All three run in O(n) time, because each node is visited once and each edge is followed twice. The recursion stack uses O(h) space, which is O(log n) for a balanced tree and O(n) for a skewed one.

3.1 Iterative inorder using an explicit stack

Recursion is convenient but uses the call stack. The iterative version makes the stack explicit: push every node along the left spine, pop one, visit it, then move to its right child and repeat.

void inorder_iter(node_t *root)
{
    node_t *stack[1000];
    int top = -1;
    node_t *cur = root;

    while (cur != NULL || top >= 0) {
        while (cur != NULL) {
            stack[++top] = cur;       /* remember the ancestors */
            cur = cur->left;
        }
        cur = stack[top--];           /* leftmost unvisited node */
        printf("%d ", cur->key);
        cur = cur->right;             /* its right subtree, if any */
    }
}

Preorder iteratively: push the root, then repeatedly pop, visit, push right, push left (so left is processed first). Postorder iteratively: use two stacks, or push root-left-right and reverse the output.

3.2 Level-order (breadth-first) traversal

Level order visits all nodes at depth 0, then depth 1, then depth 2, and so on. It cannot be expressed by the simple three-line recursion because the traversal order is horizontal, not vertical. A queue is the natural structure: enqueue the root, then repeatedly dequeue a node, visit it, and enqueue its existing children.

void level_order(node_t *root)
{
    if (!root) return;
    node_t *q[1000];
    int front = 0, rear = 0;
    q[rear++] = root;

    while (front < rear) {
        node_t *cur = q[front++];
        printf("%d ", cur->key);
        if (cur->left)  q[rear++] = cur->left;
        if (cur->right) q[rear++] = cur->right;
    }
}

To print one level per line, record the queue size rear − front before processing that level and loop exactly that many times. Level order is the basis for finding the minimum depth, testing completeness, and producing a breadth-first serialization. It also works identically for the array implementation — replace child pointers with child indices.

3.3 Reconstructing a tree from traversals

A single traversal does not uniquely determine a binary tree. An inorder sequence of three keys such as A B C is consistent with five different binary-tree shapes. Two traversals are needed:

  • Inorder + preorder — the first preorder element is the root; its position in inorder splits the remaining keys into left and right subtrees; recurse.
  • Inorder + postorder — the last postorder element is the root; split inorder at that root; recurse on the portions.
  • Inorder + level order — also works, because level order identifies roots level by level.
  • Preorder + postorder alone is not enough for a general binary tree (it cannot distinguish a left-only child from a right-only child).
/* Build from inorder[ib..ie] and postorder[pb..pe]. */
node_t *build(int in[], int ib, int ie, int post[], int pb, int pe)
{
    if (ib > ie) return NULL;
    int rootkey = post[pe];
    node_t *root = new_node(rootkey);

    int k = ib;
    while (in[k] != rootkey) ++k;      /* root position in inorder */
    int left_count = k - ib;

    root->left  = build(in, ib, k - 1, post, pb, pb + left_count - 1);
    root->right = build(in, k + 1, ie, post, pb + left_count, pe - 1);
    return root;
}
Inorder:   D B H E A F C G J I
Postorder: D H E B F J I G C A

Postorder's last key A is the root.
Inorder splits into:  left = D B H E      right = F C G J I
Postorder left part = D H E B, right part = F J I G C
Repeat: B is left root, C is right root, and so on.

Complexity: the straightforward scan for the root in inorder is O(n2) in the worst case. With a hash table mapping each key to its inorder index, reconstruction becomes O(n); the recursion still needs O(h) stack space.

4. Binary Search Tree Using Arrays and a Free-List Manager

There are three distinct ways to put a binary tree into an array. They are easy to confuse, so separate them clearly:

SchemeWhat is storedWhen it is appropriate
Implicit / heap mappingOnly keys. The parent and child positions are computed from the index.Only for complete binary trees — heaps are the standard example. A sparse tree wastes most slots.
Array of nodes with child indiceskey, left index, right index per slot.General binary trees without pointers. Requires a free-list manager on deletion.
Array of structs, indices for linksSame as above, but indices are used instead of addresses.Useful when the tree must live in a fixed block of memory, a file, or shared memory.

4.1 Implicit mapping (the heap layout)

Index arithmetic
0-based: left = 2i + 1, right = 2i + 2, parent = ⌊(i − 1)/2⌋
1-based: left = 2i, right = 2i + 1, parent = ⌊i/2⌋

The course uses the 1-based mapping for heaps: the root sits at index 1 and index 0 is left unused. Choose one convention and never mix them.

This layout stores no links at all, so it has perfect locality and zero pointer overhead. Its fatal limitation is shape: a tree with height h may need an array of size 2h+1 − 1 even if it contains only h + 1 nodes. A right-skewed chain of 10 nodes needs indices up to 1022 in the 0-based layout. Consequently, implicit mapping is used for complete trees (heaps), not for arbitrary BSTs. Detecting a filled slot also requires a sentinel value that cannot be a valid key, or a separate occupancy array.

4.2 Array of node records with a free list

For a general BST, each slot must store the indices of its two children. The tree object holds the index of the root (-1 means empty), the number of live nodes, and a free-list of unused slots. The free list is essential: after deletions, free slots are scattered through the array, so "the next unused index" is not necessarily count.

#define MAXSIZE 200

typedef struct {
    int key;
    int left;      /* index of left child, -1 if none */
    int right;     /* index of right child, -1 if none */
} node_t;

typedef struct {
    int root;                  /* index of root, -1 if empty */
    int count;                 /* number of live nodes */
    int free_top;              /* number of indices currently on the free stack */
    int free_stack[MAXSIZE];   /* stack of available slots */
    node_t elem[MAXSIZE];
} tree_t;

void init(tree_t *t)
{
    t->root = -1;
    t->count = 0;
    t->free_top = MAXSIZE;
    for (int i = 0; i < MAXSIZE; ++i)
        t->free_stack[i] = MAXSIZE - 1 - i;   /* reverse so 0 is allocated first */
}

int alloc_node(tree_t *t)
{
    if (t->free_top == 0) return -1;          /* array full */
    ++t->count;
    return t->free_stack[--t->free_top];
}

void free_node(tree_t *t, int idx)
{
    t->elem[idx].left = t->elem[idx].right = -1;
    t->free_stack[t->free_top++] = idx;
    --t->count;
}
Why a stack works as the memory manager

Allocation and deallocation are LIFO in this simple design: allocation pops any free index, deallocation pushes the index back. The order does not matter for correctness, but a stack is the simplest implementation. A more sophisticated manager could keep a linked free list threaded through unused slots, reuse a freed slot immediately, or coalesce adjacent free runs. The key invariant is that the free list and the live tree partition the array: no index may appear in both.

4.3 Insertion and traversal by index

The recursive helper is structurally identical to the pointer version. The only changes are that NULL becomes -1, and an index is returned instead of a pointer.

static int insert_rec(tree_t *t, int root, int fresh)
{
    if (root == -1) return fresh;
    if (t->elem[fresh].key < t->elem[root].key)
        t->elem[root].left  = insert_rec(t, t->elem[root].left,  fresh);
    else
        t->elem[root].right = insert_rec(t, t->elem[root].right, fresh);
    return root;
}

void insert(tree_t *t, int key)
{
    int fresh = alloc_node(t);
    if (fresh == -1) { fprintf(stderr, "tree full\n"); return; }
    t->elem[fresh].key   = key;
    t->elem[fresh].left  = -1;
    t->elem[fresh].right = -1;
    t->root = insert_rec(t, t->root, fresh);
}

static void inorder_rec(tree_t *t, int root)
{
    if (root == -1) return;
    inorder_rec(t, t->elem[root].left);
    printf("%d ", t->elem[root].key);
    inorder_rec(t, t->elem[root].right);
}

void inorder(tree_t *t) { inorder_rec(t, t->root); printf("\n"); }

4.4 Deletion with index splicing

Deletion mirrors the pointer algorithm. When a node is removed, its index is pushed onto the free list. For a two-child node, copy the successor's key and delete the successor; the successor has no left child, so it is removed by one of the simpler cases.

static int min_index(tree_t *t, int root)
{
    while (t->elem[root].left != -1)
        root = t->elem[root].left;
    return root;
}

static int delete_rec(tree_t *t, int root, int key)
{
    if (root == -1) return -1;

    if (key < t->elem[root].key) {
        t->elem[root].left = delete_rec(t, t->elem[root].left, key);
    } else if (key > t->elem[root].key) {
        t->elem[root].right = delete_rec(t, t->elem[root].right, key);
    } else {
        if (t->elem[root].left == -1 && t->elem[root].right == -1) {
            free_node(t, root); return -1;
        }
        if (t->elem[root].left == -1) {
            int r = t->elem[root].right; free_node(t, root); return r;
        }
        if (t->elem[root].right == -1) {
            int l = t->elem[root].left;  free_node(t, root); return l;
        }
        int succ = min_index(t, t->elem[root].right);
        t->elem[root].key = t->elem[succ].key;
        t->elem[root].right = delete_rec(t, t->elem[root].right, t->elem[succ].key);
    }
    return root;
}

void delete_key(tree_t *t, int key) { t->root = delete_rec(t, t->root, key); }

4.5 Counting, comparing and copying array trees

int count_nodes(tree_t *t, int root)
{
    if (root == -1) return 0;
    return 1 + count_nodes(t, t->elem[root].left)
             + count_nodes(t, t->elem[root].right);
}

int count_leaves(tree_t *t, int root)
{
    if (root == -1) return 0;
    if (t->elem[root].left == -1 && t->elem[root].right == -1) return 1;
    return count_leaves(t, t->elem[root].left)
         + count_leaves(t, t->elem[root].right);
}

int are_same(tree_t *a, int ra, tree_t *b, int rb)
{
    if (ra == -1 && rb == -1) return 1;
    if (ra == -1 || rb == -1) return 0;
    return a->elem[ra].key == b->elem[rb].key
        && are_same(a, a->elem[ra].left,  b, b->elem[rb].left)
        && are_same(a, a->elem[ra].right, b, b->elem[rb].right);
}

void copy(tree_t *src, tree_t *dst)
{
    *dst = *src;     /* structure assignment copies the whole array, free list and counters */
}

Array copying is a single bulk assignment only because the structure owns no external pointers. If the array were dynamically allocated, the destination would need its own allocation and a deep copy. A recursive copy is also possible but is unnecessarily slow compared with memcpy-style copying; this is one place where the array implementation is simpler than the pointer implementation.

}

4.7 Checking whether a binary tree is a BST

Comparing only a parent with its immediate children is not sufficient: a node in the left subtree might still be larger than an ancestor. Two correct methods exist:

  1. Range method: pass down an allowed open interval (low, high). The root starts with (−∞, +∞); a left child must be in (low, root.key) and a right child in (root.key, high). If any key falls outside its interval, the tree is not a BST.
  2. Inorder method: perform an inorder traversal and verify that every visited key is strictly greater than the previous one. This works because a BST's inorder sequence must be sorted.
int is_bst_rec(node_t *root, long long low, long long high)
{
    if (!root) return 1;
    if (root->key <= low || root->key >= high) return 0;
    return is_bst_rec(root->left,  low, root->key)
        && is_bst_rec(root->right, root->key, high);
}
int is_bst(node_t *root) { return is_bst_rec(root, LLONG_MIN, LLONG_MAX); }
Common mistake

The test root->left->key < root->key && root->right->key > root->key accepts invalid trees such as root 10 with left child 5 whose right child is 12. The value 12 is greater than 10 but sits in the left subtree. Always propagate the allowed range or verify the inorder sequence.

5. Expression Trees

An expression tree is a binary tree that represents an arithmetic expression structurally:

  • Leaves are operands — constants or variables.
  • Internal nodes are operators — +, −, *, /, and so on.
  • The children of an operator are its two operands (which may themselves be subexpressions).

The shape encodes precedence and associativity without parentheses. An inorder traversal gives the original infix expression (parentheses may be needed to preserve meaning), a preorder traversal gives prefix notation, and a postorder traversal gives postfix notation. Evaluation is naturally postorder: compute both children, then apply the operator.

The three views of the same tree
postfix = left, right, root  ·  prefix = root, left, right  ·  infix = left, root, right

5.1 Building from a postfix expression

Postfix (reverse Polish) notation places each operator after its operands, so it can be processed with a single left-to-right scan and a stack of tree nodes:

  1. Read the next token.
  2. If it is an operand, create a leaf node and push it.
  3. If it is an operator, pop the top two nodes. Create an operator node; attach the second popped node as the left subtree and the first popped node as the right subtree. Push the new node.
  4. At the end, the stack must contain exactly one node — the root.
Order matters

The first pop is the right operand and the second pop is the left operand. Reversing them turns a − b into b − a, which is wrong for non-commutative operators such as subtraction and division.

5.2 Stack and node structures

typedef struct node {
    char ch;                 /* operator for internal nodes, digit for leaves */
    struct node *left;
    struct node *right;
} node_t;

typedef struct {
    node_t *item[MAXSIZE];
    int top;
} stack_t;

void init_stack(stack_t *s) { s->top = -1; }
int  is_empty(stack_t *s)   { return s->top == -1; }
int  is_full(stack_t *s)    { return s->top == MAXSIZE - 1; }

node_t *make_node(char ch)
{
    node_t *n = malloc(sizeof *n);
    if (!n) { fprintf(stderr, "out of memory\n"); exit(1); }
    n->ch = ch;
    n->left = n->right = NULL;
    return n;
}

void push_operand(stack_t *s, char ch)
{
    if (is_full(s)) { fprintf(stderr, "stack full\n"); return; }
    s->item[++s->top] = make_node(ch);
}

void push_operator(stack_t *s, char op)
{
    if (is_full(s)) { fprintf(stderr, "stack full\n"); return; }
    node_t *n = make_node(op);
    n->right = pop(s);       /* first pop = right operand */
    n->left  = pop(s);       /* second pop = left operand */
    s->item[++s->top] = n;
}

node_t *pop(stack_t *s)
{
    if (is_empty(s)) { fprintf(stderr, "stack empty\n"); return NULL; }
    return s->item[s->top--];
}

5.3 Construction and evaluation

node_t *build_from_postfix(const char *expr)
{
    stack_t s;
    init_stack(&s);

    for (int i = 0; expr[i] != '\0'; ++i) {
        char ch = expr[i];
        if (ch == ' ') continue;
        if (ch == '+' || ch == '-' || ch == '*' || ch == '/')
            push_operator(&s, ch);
        else
            push_operand(&s, ch);
    }
    node_t *root = pop(&s);       /* exactly one node must remain */
    if (!is_empty(&s)) {
        fprintf(stderr, "malformed expression\n");
    }
    return root;
}

int evaluate(node_t *root)
{
    if (root == NULL) return 0;
    if (root->left == NULL && root->right == NULL)
        return root->ch - '0';       /* single-digit operand */

    int left  = evaluate(root->left);
    int right = evaluate(root->right);

    switch (root->ch) {
        case '+': return left + right;
        case '-': return left - right;
        case '*': return left * right;
        case '/': return (right == 0) ? 0 : left / right;
        default : return 0;
    }
}
Limitations and a better node design

Storing every token in a char limits operands to one character. Real expressions need multi-digit integers, floating-point values and identifiers. A robust node uses a union plus a discriminator:

typedef enum { OPERAND, OPERATOR } kind_t;
typedef struct node {
    kind_t kind;
    union { double value; char op; } u;
    struct node *left, *right;
} node_t;

6. Threaded Binary Search Tree

A binary tree with n nodes contains 2n child pointers. Only n − 1 of them can be structural (one per edge), so exactly n + 1 pointers are grounded (NULL). A threaded binary tree puts those wasted pointers to work: a null right pointer is replaced by a thread to the node's inorder successor, and a null left pointer by a thread to its inorder predecessor. Traversal then becomes iterative and needs no stack.

Pointer accounting
2n pointers − (n − 1) structural edges = n + 1 null pointers

Those n + 1 nulls are exactly the slots available for threads.

6.1 One-way vs two-way threading

  • One-way (right-threaded): only null right pointers become successor threads. Inorder traversal is fast, but finding a predecessor is not.
  • Two-way (fully threaded): both null left and right pointers become predecessor/successor threads. This is the version used in the course, because the node already has both pointers.
  • With a header node: some implementations add a dummy head whose left points to the root and whose right points to the last node. This removes special cases at the ends of the traversal. The course version omits the header; the first node's left thread and the last node's right thread remain NULL.

6.2 Node representation and flag semantics

typedef struct node {
    int key;
    struct node *left;
    struct node *right;
    int lthread;      /* 1 = left is a thread (predecessor); 0 = structural child */
    int rthread;      /* 1 = right is a thread (successor);   0 = structural child */
} node_t;

typedef struct {
    node_t *root;
} tree_t;

static node_t *make_node(int key)
{
    node_t *n = malloc(sizeof *n);
    if (!n) { fprintf(stderr, "out of memory\n"); exit(1); }
    n->key = key;
    n->left = n->right = NULL;
    n->lthread = n->rthread = 1;   /* a new leaf has no structural children */
    return n;
}
Flag convention

1 means thread; 0 means structural pointer. A new node is created with both flags 1 because its pointers are not yet structural; insertion later clears the flag on the side where the node is attached. If both flags are 1, the node is a leaf. (Some textbooks invert the flag; always state your convention.)

6.3 Insertion

Insertion is ordinary BST descent, but the descent must stop at a thread rather than at NULL:

  • If the key is smaller, move left only while lthread == 0. If lthread == 1, this is the insertion point.
  • If the key is larger or equal, move right only while rthread == 0. If rthread == 1, this is the insertion point.
  • The first node becomes the root with both threads still null.
  • When attaching as a left child, the new node inherits the parent's left thread (its predecessor) and points its right thread to the parent. The parent's left pointer becomes structural, so parent->lthread = 0.
  • When attaching as a right child, the new node inherits the parent's right thread (its successor) and points its left thread to the parent. The parent's right pointer becomes structural, so parent->rthread = 0.
static node_t *insert_rec(node_t *root, int key)
{
    node_t *fresh = make_node(key);
    if (root == NULL) return fresh;        /* first node */

    node_t *parent = NULL;
    node_t *cur = root;
    while (cur != NULL) {
        parent = cur;
        if (key < cur->key) {
            if (cur->lthread == 0) cur = cur->left;
            else break;
        } else {
            if (cur->rthread == 0) cur = cur->right;
            else break;
        }
    }

    if (key < parent->key) {              /* attach on the left */
        fresh->left  = parent->left;       /* inherit predecessor thread */
        fresh->right = parent;             /* successor thread */
        fresh->lthread = 1;
        fresh->rthread = 1;
        parent->left = fresh;
        parent->lthread = 0;               /* now a structural pointer */
    } else {                                /* attach on the right */
        fresh->right = parent->right;      /* inherit successor thread */
        fresh->left  = parent;             /* predecessor thread */
        fresh->lthread = 1;
        fresh->rthread = 1;
        parent->right = fresh;
        parent->rthread = 0;
    }
    return root;
}

void insert(tree_t *t, int key) { t->root = insert_rec(t->root, key); }

6.4 Inorder traversal without recursion or a stack

The traversal starts at the leftmost node. From any node, the inorder successor is obtained in O(1):

  • If rthread == 1, the right pointer is the successor thread — follow it.
  • If rthread == 0, the successor is the leftmost node of the right subtree: go right once, then keep following structural left links while lthread == 0.
static node_t *leftmost(node_t *n)
{
    if (!n) return NULL;
    while (n->lthread == 0) n = n->left;
    return n;
}

void inorder(tree_t *t)
{
    node_t *cur = leftmost(t->root);
    while (cur != NULL) {
        printf("%d ", cur->key);
        if (cur->rthread == 1) cur = cur->right;   /* thread to successor */
        else                   cur = leftmost(cur->right);
    }
}

6.5 Search

Search is the same as in a BST, but the loop uses the thread flags to know when a subtree is absent. If lthread == 1, there is no left subtree, so a smaller key cannot exist and the search fails. Symmetrically for the right side.

node_t *search(tree_t *t, int key)
{
    node_t *cur = t->root;
    while (cur != NULL) {
        if (key == cur->key) return cur;
        if (key < cur->key) {
            if (cur->lthread == 1) return NULL;
            cur = cur->left;
        } else {
            if (cur->rthread == 1) return NULL;
            cur = cur->right;
        }
    }
    return NULL;
}

6.6 Deletion — the thread-repair problem

Deletion is significantly harder than in an ordinary BST because removing a node invalidates threads that point to it. The structural cases are the same (leaf, one child, two children), but each case also requires repairing the predecessor and successor links:

  1. Leaf: detach it from its parent. If it was a left child, the parent's left pointer becomes a thread to the deleted node's predecessor, and parent->lthread = 1. If it was a right child, the parent's right pointer becomes a thread to the deleted node's successor, and parent->rthread = 1.
  2. One child: splice the child into the parent. The child's outer thread must be redirected to the deleted node's predecessor (if the child is a left subtree) or successor (if it is a right subtree). The inorder predecessor/successor of the deleted node may also need their threads repointed.
  3. Two children: copy the inorder successor's key into the node, then delete the successor. The successor has no left child, so its removal is a one-child or leaf case; afterward, repair the successor's predecessor thread so that it skips over the removed node.
  4. Root deletion: special care is needed because the root has no parent. A header/dummy node makes all of these cases uniform, which is why production threaded trees often use one.
Why deletion is rarely implemented in threaded trees

Every structural change can invalidate O(1) threads, but finding the affected predecessor/successor may require a descent unless parent pointers or a header are maintained. In practice, threaded trees are chosen for fast inorder traversal, while ordinary or balanced BSTs are chosen when deletion is frequent. If deletion is required, a header node plus parent pointers keeps the repair logic manageable.

6.7 Advantages, costs and comparison

Advantages

  • Inorder traversal in O(n) time and O(1) auxiliary space — no recursion, no stack.
  • Successor/predecessor queries are O(1) when the relevant thread exists.
  • All n + 1 null pointers become useful.
  • No shape change; the BST ordering is untouched.

Costs

  • Two extra flag fields per node (or packed bits) increase memory.
  • Insert and delete must maintain the flags and threads.
  • Code is more error-prone than ordinary BST code.
  • Not automatically balanced; worst-case search is still O(n).

7. Heaps in Arrays: Build, Insert, Delete

The word heap has two unrelated meanings in computer science. In memory management it is the region used for dynamic allocation; in data structures it is a complete binary tree with parental dominance. This section is about the data structure, not the memory region.

7.1 Defining properties

  1. Completeness: every level is full except possibly the last, and the last level is filled from left to right with no gaps.
  2. Parental dominance: for a max-heap, the key at every node is greater than or equal to the keys of its children, recursively. For a min-heap, it is less than or equal to its children.

A heap is not a binary search tree: there is no left-versus-right ordering. The only guarantee is between parent and child, so the root holds the global maximum (max-heap) or minimum (min-heap), but the left and right subtrees have no relative order.

7.2 Mapping a complete tree to an array

Completeness is what makes an array representation exact: if nodes are numbered level by level, left to right, there are no holes and the parent/child positions follow arithmetic formulas.

1-based mapping (used in this course)
left(i) = 2i   ·   right(i) = 2i + 1   ·   parent(i) = ⌊i/2⌋
0-based mapping (alternative): left = 2i+1, right = 2i+2, parent = ⌊(i−1)/2⌋

The 1-based version leaves a[0] unused. This is a deliberate convenience: the formulas are slightly simpler and 2i/2i+1 are easy to reason about.

#define MAXSIZE 200

typedef struct {
    int key[MAXSIZE];      /* 1-based: root at index 1 */
    int n;                 /* number of elements */
} heap_t;

void init(heap_t *h) { h->n = 0; }
int  is_empty(heap_t *h) { return h->n == 0; }
int  is_full(heap_t *h)  { return h->n == MAXSIZE - 1; }
int  peek(heap_t *h)     { return h->key[1]; }

7.3 Heapify: restoring one subtree

Precondition: the left and right subtrees of position i are already heaps. Postcondition: the subtree rooted at i is a heap. The algorithm "sifts down" a hole: save the value at i, repeatedly move the larger child up into the hole, and finally place the saved value in the last hole. This avoids swapping at every level.

static void swap(int *a, int *b) { int t = *a; *a = *b; *b = t; }

/* Max-heapify the subtree rooted at pos. n is the number of elements. */
static void heapify(int a[], int n, int pos)
{
    int i = pos;
    int j = 2 * i;               /* left child */
    int val = a[i];
    int done = 0;

    while (j <= n && !done) {
        if (j + 1 <= n && a[j + 1] > a[j])
            ++j;                  /* choose the larger child */
        if (a[j] > val) {
            a[i] = a[j];          /* move child up into the hole */
            i = j;
            j = 2 * i;
        } else {
            done = 1;
        }
    }
    a[i] = val;                   /* place the saved value in the final hole */
}
Why the loop moves a hole, not the value

Copying the larger child upward leaves a gap at the child's old position. Only at the end is the saved value written once. This reduces the number of assignments compared with swapping at every level, although both are O(log n).

7.4 Building a heap in O(n)

Leaves are already valid heaps (they have no children). Start at the last internal node, ⌊n/2⌋, and heapify positions downward to 1. The result is a max-heap.

void build_heap(heap_t *h, int a[], int n)
{
    h->n = n;
    for (int i = 1; i <= n; ++i) h->key[i] = a[i];  /* a is 1-based */
    for (int i = n / 2; i >= 1; --i)
        heapify(h->key, h->n, i);
}
Why bottom-up build is O(n), not O(n log n)
Σh=0⌊log n⌋ ⌈n / 2h+1⌉ · O(h) = O(n)

Most nodes are near the bottom and have tiny height. The sum is dominated by the many leaves (height 0) and converges to a constant multiple of n. Building by repeated insertion would cost O(n log n).

7.5 Insertion: sift up

Place the new key at the end of the array (the next complete-tree position), then repeatedly compare it with its parent and swap upward while it violates parental dominance. At most ⌊log2 n⌋ levels are crossed.

void insert(heap_t *h, int key)
{
    if (is_full(h)) { fprintf(stderr, "heap full\n"); return; }
    int pos = ++h->n;
    h->key[pos] = key;

    while (pos > 1 && h->key[pos] > h->key[pos / 2]) {
        swap(&h->key[pos], &h->key[pos / 2]);
        pos /= 2;
    }
}

7.6 Deleting the root (maximum)

The maximum is always at index 1. Replace it with the last element, decrease the size, and sift the new root down with heapify. The last element is removed from the complete tree, so completeness is preserved.

int delete_max(heap_t *h)
{
    if (is_empty(h)) { fprintf(stderr, "heap empty\n"); return -1; }
    int result = h->key[1];
    h->key[1] = h->key[h->n];
    --h->n;
    heapify(h->key, h->n, 1);
    return result;
}

7.7 Generic min-heap / max-heap with a comparator

The only difference between a min-heap and a max-heap is the comparison direction. Passing a function pointer removes the duplicated code and makes the heap reusable — the same design used in the course's running-median exercise.

typedef struct {
    int key[MAXSIZE];
    int n;
    int (*compare)(int, int);   /* returns true if first has higher priority */
} gen_heap_t;

int max_cmp(int a, int b) { return a > b; }
int min_cmp(int a, int b) { return a < b; }

void init_heap(gen_heap_t *h, int (*cmp)(int, int))
{
    h->n = 0;
    h->compare = cmp;
}

static void sift_down(gen_heap_t *h, int pos)
{
    int i = pos, j = 2 * i;
    int val = h->key[i];
    int done = 0;

    while (j <= h->n && !done) {
        if (j + 1 <= h->n && h->compare(h->key[j + 1], h->key[j]))
            ++j;
        if (h->compare(h->key[j], val)) {
            h->key[i] = h->key[j];
            i = j;
            j = 2 * i;
        } else {
            done = 1;
        }
    }
    h->key[i] = val;
}

void gen_insert(gen_heap_t *h, int key)
{
    int pos = ++h->n;
    h->key[pos] = key;
    while (pos > 1 && h->compare(h->key[pos], h->key[pos / 2])) {
        swap(&h->key[pos], &h->key[pos / 2]);
        pos /= 2;
    }
}

int gen_delete_root(gen_heap_t *h)
{
    int result = h->key[1];
    h->key[1] = h->key[h->n--];
    if (h->n > 0) sift_down(h, 1);
    return result;
}

7.8 Other heap operations

  • Peek: return key[1] in O(1).
  • Increase-key (max-heap): change the value at position i to a larger value, then sift up. O(log n).
  • Decrease-key (min-heap): symmetric; sift up after decreasing. This is the operation used by Dijkstra and Prim.
  • Delete arbitrary element: replace it with the last element, decrease the size, then decide whether to sift up or down depending on the comparison with its parent. O(log n).
  • Search for an arbitrary key: O(n), because a heap has no search-tree ordering. If arbitrary lookup is needed, keep a separate index map or use a balanced BST instead.
  • Merge two heaps: not efficient with a simple array heap; a meldable heap (leftist, binomial, Fibonacci) is needed.

7.9 Heapsort

Heapsort has two phases: build a max-heap in O(n), then repeatedly swap the root to the end of the active region and shrink the heap. Each extraction costs O(log n), giving O(n log n) overall and O(1) extra space.

void heapsort(int a[], int n)        /* a is 1-based, a[1..n] */
{
    for (int i = n / 2; i >= 1; --i)
        heapify(a, n, i);            /* phase 1: build max-heap */

    for (int end = n; end > 1; --end) {
        swap(&a[1], &a[end]);       /* move current max to its final place */
        heapify(a, end - 1, 1);      /* restore heap on the remaining prefix */
    }
}

Heapsort is in-place and has a worst-case O(n log n) bound, but it is not stable and has poor cache locality because it jumps between indices i, 2i and 2i+1. This is why standard libraries usually prefer quicksort or introsort for general sorting, even though heapsort is theoretically competitive.

8. Priority Queues Using Heaps (Min and Max)

A priority queue is an abstract data type that stores elements with priorities and always removes the element of highest (or lowest) priority. It is not FIFO like an ordinary queue. The heap is the standard implementation because it gives O(log n) enqueue and dequeue, with O(1) peek.

Max-priority queue

Dequeues the largest key. Implemented with a max-heap. Use compare(a,b) = a > b. Typical for scheduling the most urgent task, or extracting the largest value repeatedly.

8.1 Composition: a queue that owns a heap

The priority queue can be implemented by composition: the queue structure contains a heap, and its operations delegate to the heap. This keeps the ADT boundary clean and lets the same queue code work with a min-heap or a max-heap depending on the comparator supplied at initialization.

typedef struct {
    gen_heap_t heap;          /* owns the storage */
} pqueue_t;

void pq_init(pqueue_t *q, int (*cmp)(int, int))
{
    init_heap(&q->heap, cmp);
}

void pq_enqueue(pqueue_t *q, int key)
{
    gen_insert(&q->heap, key);
}

int pq_dequeue(pqueue_t *q)
{
    return gen_delete_root(&q->heap);
}

int pq_peek(pqueue_t *q)     { return q->heap.key[1]; }
int pq_is_empty(pqueue_t *q) { return q->heap.n == 0; }

/* Usage: */
pqueue_t maxq, minq;
pq_init(&maxq, max_cmp);      /* largest first */
pq_init(&minq, min_cmp);      /* smallest first */
Implementation alternatives

An unsorted array/list makes enqueue O(1) but dequeue O(n). A sorted array/list makes dequeue O(1) but enqueue O(n). A balanced BST gives O(log n) for both but uses more memory and supports ordered iteration. A heap gives O(log n) for both with an array and no pointers — the best general-purpose trade-off.

8.2 Application: running median with two heaps

A classic use of both heap directions at once. Maintain two halves of the numbers seen so far:

  • Left half — max-heap: stores the smaller half. Its root is the largest of the lower half.
  • Right half — min-heap: stores the larger half. Its root is the smallest of the upper half.

For each incoming x:

  1. If the left heap is empty or x ≤ left.peek(), push x into the left (max) heap; otherwise push it into the right (min) heap.
  2. Rebalance: if left.size > right.size + 1, move the left root to the right. If right.size > left.size, move the right root to the left.
  3. Query: if the total count is odd, the median is the root of the larger heap (left by the balancing rule). If even, the median is the average of the two roots.
typedef struct {
    gen_heap_t left;    /* max-heap */
    gen_heap_t right;   /* min-heap */
} median_t;

void median_init(median_t *m)
{
    init_heap(&m->left,  max_cmp);
    init_heap(&m->right, min_cmp);
}

void median_add(median_t *m, int x)
{
    if (m->left.n == 0 || x <= m->left.key[1])
        gen_insert(&m->left, x);
    else
        gen_insert(&m->right, x);

    if (m->left.n > m->right.n + 1)
        gen_insert(&m->right, gen_delete_root(&m->left));
    else if (m->right.n > m->left.n)
        gen_insert(&m->left, gen_delete_root(&m->right));
}

double median_value(median_t *m)
{
    if (m->left.n == m->right.n)
        return (m->left.key[1] + (double)m->right.key[1]) / 2.0;
    return (double)m->left.key[1];    /* left holds the extra element */
}

8.3 Applications of priority queues

  • Dijkstra's shortest path and Prim's minimum spanning tree: repeatedly extract the minimum tentative distance/edge weight, and decrease keys.
  • Huffman coding: repeatedly merge the two least frequent nodes.
  • CPU and OS scheduling: highest-priority or earliest-deadline task first.
  • Event-driven simulation: process the next earliest event.
  • k largest/smallest elements: keep a heap of size k while streaming.
  • A* search: expand the node with the smallest estimated total cost.
  • Load balancing and bandwidth allocation by priority.

9. AVL Trees: Height-Balanced BSTs

A plain BST can degenerate into a chain. The fix is to constrain the height, not the insertion order. An AVL tree (Adelson-Velsky and Landis, 1962) is a self-balancing BST with one local invariant:

AVL invariant
for every node, |height(left subtree) − height(right subtree)| ≤ 1

Equivalently, the balance factor BF(node) = h(left) − h(right) must be −1, 0 or +1. A BF of +2 is left-heavy; −2 is right-heavy.

Height convention matters. This course counts edges: an empty tree has height −1 and a leaf has height 0. In code it is often easier to count nodes: an empty tree has height 0 and a leaf has height 1. The balance factor is unchanged as long as one convention is used consistently.

9.1 Why height balance gives logarithmic operations

Search, insert and delete all walk a root-to-leaf path, so their cost is O(h). The AVL invariant forces h = O(log n). The minimum number of nodes N(h) in an AVL tree of height h satisfies the Fibonacci-like recurrence:

Minimum nodes in an AVL tree
N(0) = 1,   N(1) = 2,   N(h) = N(h−1) + N(h−2) + 1
N(h) = Fh+3 − 1  ⇒  h < 1.44 log2(n + 2) − 0.328

So an AVL tree with n nodes has height at most about 1.44 log2 n, only 44% taller than a perfectly balanced tree. All operations are therefore O(log n) in the worst case.

9.2 Rotations: the only restructuring tool

A rotation changes the parent–child relationships locally while preserving the BST inorder sequence. It costs O(1) pointer updates and fixes one imbalance.

Right rotation around y

      y                x
     / \              / \
    x   C    →       A   y
   / \                  / \
  A   B                B   C

x = y.left; y.left = x.right; x.right = y; Update heights bottom-up: first y, then x.

Left rotation around x

    x                  y
   / \                / \
  A   y      →       x   C
     / \            / \
    B   C          A   B

y = x.right; x.right = y.left; y.left = x; Update heights bottom-up: first x, then y.

typedef struct node {
    int key;
    int height;              /* nodes: empty = 0, leaf = 1 */
    struct node *left, *right;
} node_t;

int h(node_t *n) { return n ? n->height : 0; }
int max(int a, int b) { return a > b ? a : b; }
int bf(node_t *n) { return n ? h(n->left) - h(n->right) : 0; }

static void update_height(node_t *n) { n->height = 1 + max(h(n->left), h(n->right)); }

node_t *rotate_right(node_t *y)
{
    node_t *x  = y->left;
    node_t *t2 = x->right;

    x->right = y;
    y->left  = t2;

    update_height(y);
    update_height(x);
    return x;                /* new root of this subtree */
}

node_t *rotate_left(node_t *x)
{
    node_t *y  = x->right;
    node_t *t2 = y->left;

    y->left  = x;
    x->right = t2;

    update_height(x);
    update_height(y);
    return y;
}

9.3 The four imbalance cases

Name the case by the path from the unbalanced node to the newly inserted node. Same direction → single rotation. Opposite direction → double rotation.

9.4 Insertion

Insert exactly as in a BST, then walk back up the recursion. At each ancestor, update the height, compute the balance factor, and apply one of the four rotations if the factor is outside [−1, +1].

node_t *insert(node_t *root, int key)
{
    if (root == NULL) {
        node_t *n = malloc(sizeof *n);
        if (!n) { fprintf(stderr, "out of memory\n"); exit(1); }
        n->key = key; n->height = 1;
        n->left = n->right = NULL;
        return n;
    }

    if (key < root->key)      root->left  = insert(root->left,  key);
    else if (key > root->key) root->right = insert(root->right, key);
    else                      return root;        /* duplicate: ignore */

    update_height(root);
    int balance = bf(root);

    /* LL */
    if (balance > 1 && key < root->left->key)
        return rotate_right(root);

    /* RR */
    if (balance < -1 && key > root->right->key)
        return rotate_left(root);

    /* LR */
    if (balance > 1 && key > root->left->key) {
        root->left = rotate_left(root->left);
        return rotate_right(root);
    }

    /* RL */
    if (balance < -1 && key < root->right->key) {
        root->right = rotate_right(root->right);
        return rotate_left(root);
    }

    return root;
}

9.5 Deletion

Delete as in a BST (leaf, one child, or two children with inorder successor), then rebalance on the way back up. The case analysis is slightly broader than insertion because the imbalance can come from either child, and a child's balance factor decides whether a single or double rotation is needed.

static node_t *rebalance(node_t *root)
{
    update_height(root);
    int balance = bf(root);

    if (balance > 1) {                       /* left-heavy */
        if (bf(root->left) >= 0) return rotate_right(root);       /* LL */
        root->left = rotate_left(root->left);
        return rotate_right(root);                                 /* LR */
    }
    if (balance < -1) {                      /* right-heavy */
        if (bf(root->right) <= 0) return rotate_left(root);       /* RR */
        root->right = rotate_right(root->right);
        return rotate_left(root);                                  /* RL */
    }
    return root;
}

node_t *delete_node(node_t *root, int key)
{
    if (root == NULL) return NULL;

    if (key < root->key)      root->left  = delete_node(root->left,  key);
    else if (key > root->key) root->right = delete_node(root->right, key);
    else {
        if (root->left == NULL || root->right == NULL) {
            node_t *child = root->left ? root->left : root->right;
            free(root);
            return child;
        }
        node_t *succ = root->right;
        while (succ->left) succ = succ->left;
        root->key = succ->key;
        root->right = delete_node(root->right, succ->key);
    }
    return rebalance(root);
}
Deletion can cascade

Unlike insertion, one deletion may require rotations at several ancestors. Each rotation is O(1), and the recursion visits only the path from the deleted node to the root, so the total remains O(log n). The heights must be updated after every rotation, in bottom-up order.

10. Splay Trees: Self-Adjusting BSTs

A splay tree is a BST with no balance factor, no color bit and no height field. Its rule is purely operational: every time a node is accessed, move it to the root. This restructuring is called splaying. The tree continuously reshapes itself around the workload instead of enforcing a fixed shape.

The splay principle
access(x)  ⇒  restructure so that x becomes the root

No metadata is stored. The only cost is the rotations performed during the access.

Salient features

  • No extra metadata — saves the height/color storage used by AVL and red-black trees.
  • Locality of reference — a recently accessed key is at the root, so repeated lookups are O(1).
  • Amortized efficiency — a single operation can be O(n), but any sequence of m operations on n keys costs O(m log n).
  • Dynamic adaptation — the shape follows the access pattern rather than a rigid invariant.

Costs

  • Worst-case single search/insert/delete is O(n).
  • The tree can be arbitrarily skewed at a given moment.
  • Read-only searches modify the structure, which complicates concurrency.
  • Not suitable when every operation must have a strict worst-case bound.

10.1 The three splaying cases

Let x be the accessed node, p its parent and g its grandparent.

CaseConfigurationRotation sequence
Zigx is a child of the root (no grandparent).One rotation: right if x is a left child, left if it is a right child.
Zig-Zigx and p are both left children, or both right children (same direction).Rotate g first, then rotate p — two rotations in the same direction.
Zig-Zagx and p are on opposite sides (left-right or right-left).Rotate p first, then rotate g — two rotations in opposite directions.

10.2 Bottom-up splay implementation

The simplest implementation stores a parent pointer in each node, then walks upward applying the appropriate pair of rotations. The rotate function is a standard BST rotation that also maintains parent links.

typedef struct node {
    int key;
    struct node *left, *right, *parent;
} node_t;

static void rotate(node_t *x)                 /* x moves up one level */
{
    node_t *p = x->parent;
    node_t *g = p ? p->parent : NULL;

    if (p->left == x) {                       /* right rotation around p */
        p->left = x->right;
        if (x->right) x->right->parent = p;
        x->right = p;
    } else {                                  /* left rotation around p */
        p->right = x->left;
        if (x->left) x->left->parent = p;
        x->left = p;
    }
    p->parent = x;
    x->parent = g;
    if (g) {
        if (g->left == p) g->left = x;
        else              g->right = x;
    }
}

void splay(node_t **root, node_t *x)
{
    while (x->parent != NULL) {
        node_t *p = x->parent;
        node_t *g = p->parent;

        if (g == NULL) {
            rotate(x);                        /* Zig */
        } else if ((g->left == p) == (p->left == x)) {
            rotate(p);                        /* Zig-Zig: rotate parent first */
            rotate(x);
        } else {
            rotate(x);                        /* Zig-Zag: rotate x twice */
            rotate(x);
        }
    }
    *root = x;
}

10.3 Search, insert and delete

node_t *search_splay(node_t **root, int key)
{
    node_t *cur = *root, *last = NULL;
    while (cur != NULL) {
        last = cur;
        if (key == cur->key) { splay(root, cur); return cur; }
        cur = (key < cur->key) ? cur->left : cur->right;
    }
    if (last) splay(root, last);     /* splay the last accessed node even on failure */
    return NULL;
}

void insert_splay(node_t **root, int key)
{
    node_t *fresh = malloc(sizeof *fresh);
    fresh->key = key; fresh->left = fresh->right = fresh->parent = NULL;

    if (*root == NULL) { *root = fresh; return; }

    node_t *cur = *root, *parent = NULL;
    while (cur != NULL) {
        parent = cur;
        cur = (key < cur->key) ? cur->left : cur->right;
    }
    fresh->parent = parent;
    if (key < parent->key) parent->left = fresh;
    else                   parent->right = fresh;
    splay(root, fresh);
}
Deletion by splaying twice

Splay the node to the root. Its left subtree L contains all smaller keys and its right subtree R all larger keys. Detach R, then splay the maximum of L (the rightmost node of the left subtree) to the root of L; that node has no right child, so attach R as its right subtree. If L is empty, R becomes the new root.

Why this works: after splaying the maximum of L, it is the root of L and all other keys in L are in its left subtree, leaving its right slot free for R.

10.4 Amortized analysis

A single splay can touch every node and cost O(n). The amortized bound uses a potential function based on subtree sizes:

Splay potential and access lemma
Φ(T) = Σx ∈ T log2(size(x))
amortized cost of splaying x = O(log n)

A sequence of m accesses therefore costs O((m + n) log n); with m ≥ n this is O(m log n). The expensive accesses pay for themselves by making future accesses cheaper.

11. Graphs: Properties, Vocabulary and ADT

A graph G = (V, E) is a non-linear data structure consisting of a set of vertices (nodes) V and a set of edges E connecting pairs of vertices. Graphs model arbitrary relationships: roads, friendships, hyperlinks, dependencies, flights, circuits, and state transitions.

Undirected graph

An edge {u, v} is symmetric: it connects u to v and v to u. Degree counts all incident edges.

Directed graph (digraph)

An edge (u, v) has a direction from u to v. Each vertex has an in-degree and an out-degree.

Weighted graph

Each edge carries a value — distance, time, cost, capacity. The adjacency matrix stores the weight instead of 1; the adjacency list stores a weight field in each edge node.

Unweighted graph

Edges simply exist or do not exist. Every edge has implicit weight 1.

Euler vs Hamiltonian

Eulerian graph: there is a closed walk that traverses every edge exactly once. An undirected connected graph has an Euler circuit iff every vertex has even degree. It has an Euler path (not necessarily closed) iff exactly 0 or 2 vertices have odd degree. This is the resolution of the Königsberg bridge problem: the four land masses had odd degrees, so the walk was impossible.

Hamiltonian graph: there is a cycle that visits every vertex exactly once. Unlike Euler's criterion, no simple necessary-and-sufficient condition is known; deciding whether a Hamiltonian cycle exists is NP-complete. The superficial similarity between the two problems hides a huge complexity difference.

  • Computer networks: computers/routers are vertices, communication links are edges.

12. Graph Representation & Implementation

Two representations dominate. The choice depends on density: a dense graph has |E| ≈ |V|²; a sparse graph has |E| ≈ |V|. The representation determines the cost of every later algorithm.

12.1 Adjacency matrix

A V × V array. For an unweighted graph, A[i][j] = 1 if there is an edge from i to j, otherwise 0. For a weighted graph, store the weight (and a sentinel such as INF or 0 for "no edge"). An undirected graph produces a symmetric matrix; a directed graph need not be symmetric.

#define MAXV 100
#define INF  1000000000

typedef struct {
    int n_vertices;
    int n_edges;
    int adj[MAXV][MAXV];       /* 0 = no edge; weight if weighted */
} graph_t;

void init_graph(graph_t *g, int vertices)
{
    g->n_vertices = vertices;
    g->n_edges = 0;
    for (int i = 0; i < vertices; ++i)
        for (int j = 0; j < vertices; ++j)
            g->adj[i][j] = 0;
}

void add_edge(graph_t *g, int u, int v)
{
    if (g->adj[u][v] == 0) ++g->n_edges;   /* avoid double-counting in a multigraph */
    g->adj[u][v] = 1;
    g->adj[v][u] = 1;                       /* omit for a directed graph */
}

int has_edge(graph_t *g, int u, int v) { return g->adj[u][v] != 0; }
Adjacency-matrix costs
space = O(V²)  ·  edge test = O(1)  ·  list neighbours = O(V)
iterate all edges = O(V²)

Great for dense graphs and constant-time edge queries. Wasteful when E ≪ V²; also cannot represent parallel edges without extra storage.

12.2 Adjacency list

An array of lists: one list per vertex, containing its neighbours. With V list heads and one node per directed edge (two per undirected edge), the space is O(V + E).

typedef struct edge_node {
    int vertex;
    int weight;                 /* omit if unweighted */
    struct edge_node *next;
} edge_node_t;

typedef struct {
    edge_node_t *head;
    edge_node_t *tail;          /* optional: O(1) append */
} list_t;

typedef struct {
    int n_vertices;
    int n_edges;
    list_t adj[MAXV];
} graph_t;

void init_graph(graph_t *g, int vertices)
{
    g->n_vertices = vertices;
    g->n_edges = 0;
    for (int i = 0; i < vertices; ++i)
        g->adj[i].head = g->adj[i].tail = NULL;
}

static void append(list_t *list, int v, int w)
{
    edge_node_t *n = malloc(sizeof *n);
    if (!n) { fprintf(stderr, "out of memory\n"); exit(1); }
    n->vertex = v; n->weight = w; n->next = NULL;
    if (list->tail) list->tail->next = n;
    else            list->head = n;
    list->tail = n;
}

void add_edge(graph_t *g, int u, int v, int w)
{
    append(&g->adj[u], v, w);
    append(&g->adj[v], u, w);       /* omit for a directed graph */
    ++g->n_edges;
}

13. Graph Traversal: DFS and BFS

Traversal visits every reachable vertex exactly once. A visited array is mandatory: unlike a tree, a graph can have cycles, so without it the traversal would loop forever. DFS explores one path as deeply as possible before backtracking (implicit stack / recursion); BFS explores all neighbours of a vertex before going deeper (explicit queue).

13.1 Depth-first search — recursive

void dfs_rec(graph_t *g, int u, int visited[])
{
    visited[u] = 1;
    printf("%c ", u + 'A');          /* or visit(u) */

    for (int v = 0; v < g->n_vertices; ++v)
        if (g->adj[u][v] && !visited[v])
            dfs_rec(g, v, visited);
}

void dfs(graph_t *g, int start)
{
    int visited[MAXV] = {0};
    dfs_rec(g, start, visited);
}

For an adjacency list, replace the inner loop with a walk of g->adj[u].head. The recursion is the stack: when a vertex has no unvisited neighbour, the call returns and the previous vertex resumes.

13.2 Depth-first search — iterative

The explicit-stack version is useful when recursion depth could overflow. Push neighbours in reverse order if you want to match the recursive left-to-right order. Mark a vertex when it is popped (or, with care, when pushed).

void dfs_iter(graph_t *g, int start)
{
    int visited[MAXV] = {0};
    int stack[MAXV], top = -1;

    stack[++top] = start;
    while (top >= 0) {
        int u = stack[top--];
        if (visited[u]) continue;
        visited[u] = 1;
        printf("%c ", u + 'A');

        for (int v = g->n_vertices - 1; v >= 0; --v)
            if (g->adj[u][v] && !visited[v])
                stack[++top] = v;
    }
}

13.3 Breadth-first search — queue

BFS marks a vertex as visited when it is enqueued, not when it is dequeued. This guarantees that a vertex never enters the queue twice. The queue holds the "frontier" of the current level; processing it level by level gives the shortest-path tree in an unweighted graph.

void bfs(graph_t *g, int start)
{
    int visited[MAXV] = {0};
    int q[MAXV], front = 0, rear = 0;

    visited[start] = 1;
    q[rear++] = start;

    while (front < rear) {
        int u = q[front++];
        printf("%c ", u + 'A');

        for (int v = 0; v < g->n_vertices; ++v) {
            if (g->adj[u][v] && !visited[v]) {
                visited[v] = 1;
                q[rear++] = v;
            }
        }
    }
}

13.4 Complexity and comparison

Traversal cost
adjacency list: O(V + E)  ·  adjacency matrix: O(V²)
extra space: O(V) for visited + O(V) stack/queue

Every vertex is visited once; every edge is examined once (twice in an undirected list). The matrix version scans all V entries for each vertex, even when the graph is sparse.

FeatureDFSBFS
Data structureRecursion / stackQueue

Why a visited array is not optional

In a tree, every node except the root has one parent, so there is no way back. In a graph, an edge can return to an already-seen vertex. Without visited, DFS would recurse forever around a cycle and BFS would enqueue the same vertex repeatedly. The array also defines the traversal forest: each restart after the queue/stack empties begins a new component.

Trees and BSTs

Binary-tree counts
max level k nodes = 2k  ·  max height-h nodes = 2h+1 − 1

BST operation cost
search / insert / delete = O(h),   ⌊log₂ n⌋ ≤ h ≤ n − 1

Best case O(log n); worst (skewed) O(n). Inorder traversal is O(n).

Threaded tree
2n pointers − (n − 1) edges = n + 1 null pointers converted to threads

Inorder traversal becomes O(n) time and O(1) auxiliary space.
