Unit 4: Applications of Graphs, Suffix Tree and Hashing

Applications of BFS and DFS (connectivity, connected components, finding a path), tries and their delete and search operations, suffix tries and suffix trees, and hashing — hash functions, hash tables and every collision-handling scheme: separate chaining, linear probing, quadratic probing, double hashing and rehashing.

1. Connectivity and Connected Components

1.1 Connectivity

Two vertices are connected if there is a path between them (in a directed graph, vertex A is connected to B if there is a path from A to B). A graph is connected if every pair of vertices is connected. A connected component is a maximal set of vertices in which every pair is connected; a graph may have several.

DFS or BFS started from a vertex visits exactly the vertices of that vertex's component: DFS stops when its stack becomes empty and BFS stops when its queue becomes empty. So, if the graph is not connected, a single traversal does not reach all vertices.

1.2 Algorithm: counting the components

  1. Mark every vertex not visited (visited[] = 0).
  2. While the visited array still contains an unvisited vertex, start a DFS (or BFS) from it. Each such traversal covers one complete component.
  3. Count the traversals — that count is the number of connected components. The graph is connected exactly when the count is 1.
Components and connectivity
number of components = number of times a fresh DFS/BFS must be started

Graph connected ⇔ components = 1.

The helper to_visit returns an unvisited vertex 0 … n−1, or -1 if all have been visited; it supplies the starting vertex of the next component and the stopping criterion. The new interface function is int connected_components(graph_t *ptr_graph).

Example graph: 12 vertices, components (0,1),(1,2),(2,3),(3,0),(0,2) · (4,5),(5,6),(6,7),(7,4),(5,7) · (8,9),(9,10),(10,11),(11,8),(9,11). There are 3 connected components.

Adjacency matrix + DFS: mark all vertices unvisited, ask to_visit for a start vertex, and while it is not −1 call dfs_recursive to cover that component, then ask to_visit again.

int to_visit(int v[], int n)         // next unvisited vertex, or -1
{
    for(int i = 0; i < n; ++i)
        if(v[i] == 0) return i;
    return -1;
}

int connected_components(graph_t *ptr_graph)          // adjacency matrix, dfs
{
    int visited[MAXSIZE];
    int count = 0;
    for(int i = 0; i < ptr_graph->n_vertices_; ++i)
        visited[i] = 0;
    int u = to_visit(visited, ptr_graph->n_vertices_);
    while(u != -1)
    {
        printf("count : %d\n", ++count);
        dfs_recursive(ptr_graph->n_vertices_, ptr_graph->adj_mat_, visited, u);
        printf("\n");
        u = to_visit(visited, ptr_graph->n_vertices_);
    }
    return count;
}

Adjacency matrix + BFS: identical, but BFS is invoked instead; the visited array is created and manipulated in connected_components (not inside bfs), so it is passed to bfs.

int connected_components(graph_t *ptr_graph)          // adjacency matrix, bfs
{

        visited[i] = 0;
    int u = to_visit(visited, ptr_graph->n_vertices_);

    {

        bfs(ptr_graph, u, visited);       // bfs now receives visited[] from the caller

}

Adjacency list + DFS / BFS: very similar to the matrix versions — only the way neighbours are found changes (walk the vertex's list instead of scanning a row). The storage influences only how adjacent vertices are found, not the component logic.

Cost
O(V2) with an adjacency matrix    O(V + E) with an adjacency list

Every vertex is visited once and every edge is examined a constant number of times in total across all the traversals.

2. Finding a Path in a Network

Finding a component does not tell us how to get from one vertex to another. Path problem: given a source vertex from and a destination to, find a path between them if one exists. This is how a route is found in a network. Two methods are shown: DFS on an adjacency matrix and BFS on an adjacency list. The representation only affects how adjacent vertices are found — either method works with either representation.

2.1 Client code (same for both methods)

The client creates the graph, declares an array path to hold the sequence of vertices, and calls find_path. The function fills path, updates the length through a pointer, and returns 1 if a path exists.

int path[12];
int len = 0;
int from, to;
printf("Enter two vertices : ");
scanf("%d %d", &from, &to);
int found = find_path(&g, path, &len, from, to);
if(found)
    for(int i = 0; i < len; ++i) printf("%d ", path[i]);
else
    printf("no path\n");

2.2 Path using DFS (adjacency matrix)

  • find_path initialises visited[] to 0 and puts the source in path[0], then calls find_path_recursive.
  • The recursive function mimics DFS: mark from visited; for each unvisited adjacent vertex i, append it to path as a candidate.
  • If i == to the search is over — return 1. Otherwise recurse with i as the new source.
  • Backtracking: if the loop ends without success, the last vertex added cannot be part of the solution, so drop it by decreasing the length (--(*ptr_len)) and return 0.
int find_path(graph_t *ptr_graph, int path[], int* ptr_len, int from, int to)
{
    int visited[MAXSIZE];
    path[(*ptr_len)++] = from;                 // path starts with the source
    for(int i = 0; i < ptr_graph->n_vertices_; ++i)
        visited[i] = 0;
    return find_path_recursive(ptr_graph, path, ptr_len, from, to, visited);
}

int find_path_recursive(graph_t *ptr_graph, int path[], int* ptr_len,
                        int from, int to, int visited[])
{
    visited[from] = 1;
    int n = ptr_graph->n_vertices_;
    for(int i = 0; i < n; ++i)
    {
        if(ptr_graph->adj_mat_[from][i] && ! visited[i])
        {
            path[(*ptr_len)++] = i;            // i is a candidate for the path
            if(i == to) return 1;              // destination reached
            if(find_path_recursive(ptr_graph, path, ptr_len, i, to, visited))
                return 1;                      // found further down
        }
    }
    --(*ptr_len);                              // dead end: drop the last vertex
    return 0;
}
Note on the lecture code

The slides write return find_path_recursive(...) directly inside the loop, which returns after trying only the first unvisited neighbour. The version above tests the result (if (find_path_recursive(...)) return 1;) so that the loop moves on to the next neighbour when a branch fails; the structure and idea are otherwise the same.

2.3 Path using BFS (adjacency list)

DFS used the stack implicitly and backtracked by dropping the last vertex. BFS uses a queue explicitly, and to recover the route we must remember how each vertex was reached — its parent (the predecessor in the traversal).

  • Create parent[] and initialise every entry to -1 (parent unknown).
  • Run an ordinary BFS from from. When visiting v from u, record parent[v] = u; if v == to, return 1. If the queue empties, return 0 (no path).
  • If found, fill_path starts at to and follows parent[] back to the source, storing vertices — which gives the path in reverse, so the array is reversed before returning.
int find_path(graph_t *ptr_graph, int path[], int* ptr_len, int from, int to)
{
    int n = ptr_graph->n_vertices_;
    int parent[MAXSIZE];
    for(int i = 0; i < n; ++i) parent[i] = -1;           // no parent known yet
    int res = find_path_bfs(ptr_graph, parent, from, to);
    if(res) fill_path(parent, path, ptr_len, to);
    return res;
}

int find_path_bfs(graph_t *ptr_graph, int parent[], int from, int to)
{
    queue_t q;
    init_queue(&q);
    int v;
    int visited[MAXSIZE];
    for(int i = 0; i < ptr_graph->n_vertices_; ++i) visited[i] = 0;
    visited[from] = 1;
    enqueue(&q, from);
    while(!is_empty(&q))
    {
        int u = dequeue(&q);
        node_t* temp = ptr_graph->adj_list_[u].head_;
        while(temp)
        {
            v = temp->vertex_;
            if(!visited[v])
            {
                visited[v] = 1;
                parent[v] = u;                 // v was reached from u
                if(v == to) { deinit_queue(&q); return 1; }
                enqueue(&q, v);
            }
            temp = temp->next_;
        }
    }
    deinit_queue(&q);
    return 0;
}

void fill_path(int parent[], int path[], int *ptr_len, int to)
{
    while(parent[to] != -1)                    // walk back to the source
    {
        path[(*ptr_len)++] = to;
        to = parent[to];
    }
    path[(*ptr_len)++] = to;                   // the source itself
    reverse(path, *ptr_len);                   // built backwards, so reverse
}

3. Trie (Prefix Tree)

A trie (pronounced “try”), or prefix tree, is a tree used to store and retrieve strings efficiently, particularly when many strings share common prefixes — strings with a shared prefix store that prefix only once. In a general tree or graph the key is stored in a vertex and/or an edge; here the edges implicitly carry the value (characters are not stored explicitly in the nodes).

A trie is not a binary tree; it is a general tree. If the alphabet has n symbols, each node has n child pointers — 256 for extended ASCII. Initially all are NULL; to insert a character, a node is created and attached at the index of that character. A path from the root spells a prefix of one or more strings, and a Boolean flag marks where a word ends.

3.1 Building a trie: Cat, Bat, Ball, Rat, Cap, Be

To insert Cat: create a node for C attached at the index of ‘C’ in the root, then from it a node for ‘a’, then ‘t’; as the word ends, mark the end-of-word flag in the last node. Bat is inserted the same way. When inserting Ball, edges for B and a already exist (Bat and Ball share the prefix Ba), so only l and another l are created. Words with the same prefix share the path from the root up to the matching prefix.

3.2 Important characteristics

  • The root represents the empty prefix; it normally stores no character.
  • Each edge represents one character.
  • A node may have multiple children; tries are not necessarily binary — the number of children depends on the alphabet.
  • A special end-of-word flag distinguishes complete words from mere prefixes.
  • A node may represent a valid prefix without representing a complete word (e.g. Ba above).

3.4 Structure and operations

  • init: an empty trie has one node (the root) with every child pointer grounded and is_word_end false.
  • deinit: traverse recursively and delete the children (then the node).
  • insert_word(s): start at the root; create or follow the edge for s[0], then s[1], and so on; at the last character set is_word_end true.
  • search(s): follow the path for the characters of s; if an edge is missing the search fails; at the end of the string, if is_word_end is not true the search fails (it was only a prefix); otherwise it succeeds.
  • delete_word(s): a bit complicated. Find the path for s; if it does not exist or does not end a word, do nothing. Otherwise set is_word_end to false — no node is removed yet. Then remove nodes that are no longer needed, working backwards from the leaf (stack the nodes while descending, or use recursion), and stop at a node that has other branches or ends another word. Deletion must never remove a shared prefix still needed by another word.
  • display: from the root, visit every non-empty child recursively, keeping the string seen so far (the prefix) in a buffer; whenever is_word_end is true, print the word. Children are visited in index order, so words come out in alphabetical order.
  • starts_with / all_prefix(prefix): search the prefix; the node reached need not end a word. From that node display all strings below it.
#define MAXSIZE 256
struct node
{
    struct node *child[MAXSIZE];
    int is_word_end;
};
typedef struct node node_t;
struct trie { node_t* root_; };
typedef struct trie trie_t;

static node_t* create_node(void)
{
    node_t *n = (node_t*)malloc(sizeof(node_t));
    for(int i = 0; i < MAXSIZE; ++i) n->child[i] = NULL;   // all pointers grounded
    n->is_word_end = 0;
    return n;
}
void init_trie(trie_t *t) { t->root_ = create_node(); }    // empty trie = one node

static void deinit_rec(node_t *n)
{
    if(!n) return;
    for(int i = 0; i < MAXSIZE; ++i) deinit_rec(n->child[i]);
    free(n);
}
void deinit_trie(trie_t *t) { deinit_rec(t->root_); t->root_ = NULL; }

void insert_word(trie_t *t, char *s)
{
    node_t *cur = t->root_;
    for(int i = 0; s[i]; ++i)
    {
        unsigned char c = (unsigned char)s[i];
        if(cur->child[c] == NULL)               // create the edge only if missing
            cur->child[c] = create_node();
        cur = cur->child[c];                    // otherwise follow the shared prefix
    }
    cur->is_word_end = 1;                       // mark the end of the word
}

static node_t* find_node(trie_t *t, char *s)    // node reached by following s, or NULL
{
    node_t *cur = t->root_;
    for(int i = 0; s[i] && cur; ++i)
        cur = cur->child[(unsigned char)s[i]];
    return cur;
}
int search(trie_t *t, char *s)                  // complete word present?
{
    node_t *n = find_node(t, s);
    return n != NULL && n->is_word_end;
}
int starts_with(trie_t *t, char *prefix)        // any word with this prefix?
{   return find_node(t, prefix) != NULL;   }

static int has_children(node_t *n)
{
    for(int i = 0; i < MAXSIZE; ++i) if(n->child[i]) return 1;
    return 0;
}
static int delete_rec(node_t *n, char *s)       // returns 1 if n itself may be freed
{
    if(*s == '\0')
    {
        if(!n->is_word_end) return 0;           // word not present: do nothing
        n->is_word_end = 0;                     // unmark the word
        return !has_children(n);                // free only if no other word needs it
    }
    unsigned char c = (unsigned char)*s;
    if(n->child[c] == NULL) return 0;           // word not present
    if(delete_rec(n->child[c], s + 1))
    {
        free(n->child[c]);                      // remove the no-longer-needed node
        n->child[c] = NULL;
        return !n->is_word_end && !has_children(n);
    }
    return 0;
}
void delete_word(trie_t *t, char *s) { delete_rec(t->root_, s); }

static void display_rec(node_t *n, char *buf, int depth)
{
    if(n->is_word_end) { buf[depth] = '\0'; printf("%s\n", buf); }
    for(int i = 0; i < MAXSIZE; ++i)
        if(n->child[i]) { buf[depth] = (char)i; display_rec(n->child[i], buf, depth + 1); }
}
void display(trie_t *t) { char buf[100]; display_rec(t->root_, buf, 0); }

void all_prefix(trie_t *t, char *prefix)        // all words that start with prefix
{
    node_t *n = find_node(t, prefix);
    if(!n) return;
    char buf[100]; strcpy(buf, prefix);
    display_rec(n, buf, (int)strlen(prefix));
}

Deleting from the example: deleting Ball removes the two l nodes (nothing else uses them) but stops at the node for a, because Bat still needs it. Deleting Be clears the flag on e; that node has no children, so it is removed, while B stays because Ba… still hangs from it. Deleting a word that is a prefix of another (say Ba were a word) only clears its flag.

4. Suffix Trie and Suffix Tree

A trie is a fine dictionary: it finds a word and all words with a given prefix. It does not help when we must decide whether a string is a substring of another. For that we use a suffix trie and a suffix tree; the first is impractical but shapes the design of the second.

4.1 Suffix trie

Consider all suffixes of a text T and build a trie of them.

  • A suffix trie for a text T is a trie containing all suffixes of T.
  • Every suffix ends in a leaf; there is one leaf per suffix.
  • Every substring of T is a prefix of some suffix of T.
  • Each edge represents one character; concatenating the edge labels from the root to leaf i gives the suffix that starts at i.
  • Construction is the same as for a trie (insert each suffix).

Substring search is like a trie search: start at the root, follow the path spelled by the given string; if an edge is missing the string is not a substring; the string may end anywhere — not necessarily at a leaf — and still be found.

4.2 Why it is impractical

The suffixes have lengths 1, 2, …, n, so the total number of characters is 1 + 2 + … + n = n(n + 1)/2 — the space (and construction time) is proportional to n² for a string of length n.

Suffix trie size
1 + 2 + … + n = n(n + 1)/2   ⇒   space = O(n2)

To reduce it, observe that a node with just one branch is “silly”: it adds nothing. Why not merge all consecutive silly nodes on a path into a single edge labelled with the whole string? That gives the Patricia trie.

4.3 Patricia (compressed) trie

  • A silly node is an internal node with exactly one child: it contributes nothing and only increases space and height.
  • A Patricia trie is a compressed trie in which all silly nodes are merged with their parents — chains of single-child nodes are replaced by one edge labelled with the whole character sequence.
  • Every internal node is a branching point and has at least two children; less memory and a smaller height (often faster traversal).

4.4 Suffix tree

  • A suffix tree for a string T is a Patricia trie of all the suffixes of T$, where $ is a unique terminating symbol not in the alphabet.
  • Each leaf is labelled with the starting position of the suffix it represents in T$; every root-to-leaf path spells a suffix.
  • Edges are labelled with substrings (stored as index pairs, not copies).
Suffix tree complexity
space = O(n)    construction = O(n) (Ukkonen’s algorithm)    substring search = O(m) for a pattern of length m

Ukkonen’s linear-time construction algorithm is beyond this course.

5. Hashing — Hash Functions and Hash Tables

Every data structure is built to make some operation efficient: an array is best for dense integer indices, a heap for repeated selection of the maximum or minimum, a height-balanced tree (AVL) gives insert, delete and search in time proportional to the log of the number of elements. When repeated retrieval is the main operation — e.g. a compiler storing every identifier and revisiting it to update or read its attributes — we want retrieval time independent of the number of elements. That is what hash tables provide. They appear in most languages: associative array in AWK, dict in Python, unordered_map in C++.

5.1 Concepts

  • Hashing: a technique to store and retrieve records efficiently by transforming a key into an index of a table using a hash function; the table is the hash table.
  • Key: part of the record, or computed from elements of the record (e.g. add the ASCII values of the characters of an identifier). Keys may be non-unique in general; here they are assumed unique.
  • Hash function: converts the key to an index of the table; the record is stored at, and retrieved from, that index.
  • Collision: two distinct keys hash to the same index.
  • Overflow: a fixed-size table is found full when one more record must be inserted. (Techniques exist but are not covered in this course.)

5.3 A good hash function

It converts a key k into a valid table index (0 … TABLESIZE − 1) and should:

  • be fast to compute;
  • always map the same key to the same index;
  • distribute keys uniformly across the table;
  • minimise collisions.

With a modulo hash function, a prime table size normally gives a good distribution (the examples use TABLESIZE = 19).

5.4 Common hash functions

1. Division method (used in the programs)
h(k) = k mod TABLESIZE

Example: k = 40, TABLESIZE = 19 → h(40) = 40 mod 19 = 2.

2. Multiplication method
h(k) = ⌊ TABLESIZE × ( k · A mod 1 ) ⌋

Multiply the key by a constant fraction A (0 < A < 1), keep the fractional part (mod 1), scale by the table size and take the floor. Example with A = 0.618034 (the usual choice): k = 40, TABLESIZE = 19: 40 × 0.618034 = 24.7214 → fraction 0.7214 → ⌊19 × 0.7214⌋ = 13.

3. Mid-square method
h(k) = middle digits (or bits) of k2

Example: k = 44 → 442 = 1936; a selected middle portion (e.g. 93) is used as the index, subject to the table size.

4. Folding method
h(k) = (sum of the parts of k) mapped into the table range

Common for hashing identifiers in compilers. Example: key 123456 → parts 12, 34, 56 → 12 + 34 + 56 = 102, then mapped into the index range.

Load factor
λ = n / TABLESIZE

n = number of records stored. Open hashing can have λ > 1; closed hashing needs λ ≤ 1 (and performs well only for much smaller λ).

6. Collision Handling — Overview

When two keys hash to the same index (collision), one of two broad strategies is used.

Open hashing — separate chaining

  • Collisions are resolved outside the main table: each slot points to a separate structure, typically a linked list.
  • A key hashing to an occupied slot is added to the list at that index.
  • The number of keys can exceed the table size.
  • Pros: simple; degrades gracefully; deletion is straightforward.
  • Cons: extra memory for pointers; poor cache locality (pointer jumping).

Closed hashing — open addressing

  • Collisions are resolved inside the table: every key must sit directly in an array slot.
  • On a collision a probe sequence finds the next free slot: linear probing, quadratic probing, double hashing.
  • Table size must be ≥ the number of keys.
  • Pros: better cache performance (contiguous array); no pointer overhead.
  • Cons: clustering (esp. linear probing); performance drops sharply as the table fills; deletion needs special markers (lazy deletion).

6.1 Probe formulas

Linear probing
index = (index + 1) mod TABLESIZE
Quadratic probing
index = (initial_index + i2) mod TABLESIZE    0 ≤ i < TABLESIZE
Double hashing
index = (initial_index + i · h2(key)) mod TABLESIZE    0 ≤ i < TABLESIZE

6.2 The client program

The client is the same for all four implementations (folders separate_chaining, linear_probing, quadratic_hashing, double_hashing). It is a menu-driven program that creates and initialises a hash_table, offers four operations, and de-initialises the table at the end. A record is just a string, and the key may be derived from it.

The interface is the same everywhere: init_hash_table, deinit_hash_table, insert_word, delete_key, search (returns the string, or ""), disp_hash_table.

7. Separate Chaining (Open Hashing)

The hash table is an array of lists (it looks like an adjacency list). The array has a fixed size — normally a prime — and the key is converted to an index; the element at that index is the head of a list, and the record is added to that list. If several keys hash to the same index (a collision) they are simply added to the same list. So the table can hold more keys than it has slots, since records live outside the array.

7.1 Operations

  • Initialise: ground every head pointer.
  • Deinitialise: walk the array, free each list, ground each head.
  • Insert: index = key mod TABLESIZE; create a node with the key and string; add it at the beginning of the list at that index.
  • Search: find the index and the list head; walk the list comparing keys; on a match return the string, otherwise "".
  • Delete: find the list; walk it looking for the key; if absent return; otherwise unlink the node, taking care of deletion at the beginning (head changes) and in the middle.
  • Display: for every index walk its list.
#define TABLESIZE 19
struct node { int key_; char word_[WORDSIZE]; struct node *next_; };
typedef struct node node_t;
struct hash_table { struct node *head_[TABLESIZE]; };
typedef struct hash_table hash_table_t;

void init_hash_table(hash_table_t *h)
{   for(int i = 0; i < TABLESIZE; ++i) h->head_[i] = NULL;   }

void deinit_hash_table(hash_table_t *h)                 // free every list
{
    for(int i = 0; i < TABLESIZE; ++i)
    {
        node_t *t = h->head_[i];
        while(t) { node_t *nx = t->next_; free(t); t = nx; }
        h->head_[i] = NULL;
    }
}

void insert_word(hash_table_t *h, int key, char s[])
{
    int index = key % TABLESIZE;                        // hash function
    node_t *temp = (node_t*)malloc(sizeof(node_t));
    temp->key_ = key;
    strcpy(temp->word_, s);
    temp->next_ = h->head_[index];                      // add at the beginning
    h->head_[index] = temp;
}

char* search(hash_table_t *h, int key)
{
    node_t *t = h->head_[key % TABLESIZE];
    while(t)
    {
        if(t->key_ == key) return t->word_;             // found: return the string
        t = t->next_;
    }
    return "";                                          // not found
}

void delete_key(hash_table_t *h, int key)
{
    int index = key % TABLESIZE;
    node_t *curr = h->head_[index], *prev = NULL;
    while(curr && curr->key_ != key) { prev = curr; curr = curr->next_; }
    if(curr == NULL) return;                            // no match
    if(prev == NULL) h->head_[index] = curr->next_;     // deletion at the beginning
    else             prev->next_     = curr->next_;     // deletion in the middle / end
    free(curr);
}

void disp_hash_table(hash_table_t *h)
{
    for(int i = 0; i < TABLESIZE; ++i)
        for(node_t *t = h->head_[i]; t; t = t->next_)
            printf("index : %d key : %d word : %s\n", i, t->key_, t->word_);
}

7.2 Advantages and disadvantages

AdvantagesDisadvantages
Simple collision handlingNeeds additional memory for pointers
The table can store more entries than it has slotsLinked-list traversal is slow when chains become long
Deletion is straightforward when list pointers are managed correctlyA poor hash function creates heavily unbalanced chains
Chaining cost (standard results)
average chain length = λ    unsuccessful search ≈ λ    successful search ≈ 1 + λ/2

With a good hash function, search, insert and delete are O(1 + λ); worst case O(n) when everything falls into one chain.

8. Linear Probing (Closed Hashing)

The hash table is a fixed-size array of records: no pointers, no linked lists. Every slot has an in_use flag, initially 0 (free). To insert a key, compute the index with the hash function; if that slot is free, store the record and mark it in use. If not, keep going to the next slot (using modulo arithmetic, so it wraps around) until a free slot is found. If the table is full, insertion is impossible. A record may thus end up far from the index the hash function gave.

#define TABLESIZE 19
struct node { int in_use_; int key_; char word_[WORDSIZE]; };
typedef struct node node_t;
struct hash_table
{
    struct node elem_[TABLESIZE];
    int count_;                      // number of records present
};
typedef struct hash_table hash_table_t;

void init_hash_table(hash_table_t *h)       // deinit is identical (nothing allocated)
{
    h->count_ = 0;
    for(int i = 0; i < TABLESIZE; ++i)
        h->elem_[i].in_use_ = 0;
}

8.1 Insert

Return with a message if the table is full; compute index = key % TABLESIZE; while the slot is in use do index = (index + 1) % TABLESIZE; store the record, mark it in use and increment count_.

void insert_word(hash_table_t *h, int key, char word[])
{
    if(h->count_ == TABLESIZE) { printf("table full; cannot insert\n"); return; }
    int index = key % TABLESIZE;                       // hash function
    while(h->elem_[index].in_use_ != 0)
        index = (index + 1) % TABLESIZE;               // linear probe
    h->elem_[index].key_ = key;
    strcpy(h->elem_[index].word_, word);
    h->elem_[index].in_use_ = 1;
    ++h->count_;
}

8.2 Delete

If the table is empty, return with a message. Otherwise start at the hashed index and examine filled slots; if the key in a filled slot matches, mark the slot not in use and decrement count_. If not, move to the next slot. After examining count_ filled slots without a match, report “key not found”. (Because a deletion simply frees a slot and leaves a hole inside an earlier probe chain, this version does not stop at the first free slot — it counts filled slots instead. The usual alternative is lazy deletion: a special “deleted” marker that searches skip over but insertions may reuse.)

void delete_key(hash_table_t *h, int key)
{
    if(h->count_ == 0) { printf("empty table; cannot delete\n"); return; }
    int index = key % TABLESIZE;
    int i = 0;                                         // filled slots examined so far
    while(i < h->count_)
    {
        if(h->elem_[index].in_use_)
        {
            ++i;
            if(h->elem_[index].key_ == key)
            {
                printf("deleting key : %d word :%s\n", h->elem_[index].key_, h->elem_[index].word_);
                h->elem_[index].in_use_ = 0;           // mark slot free
                --h->count_;
                return;
            }
        }
        index = (index + 1) % TABLESIZE;
    }
    printf("key not found\n");
}

8.3 Search and display

Search follows exactly the logic of delete without changing any slot, and returns the word or an empty string. Display walks the array and prints each slot that is in use; it does not change in the next two implementations.

char* search(hash_table_t *h, int key)          // same logic; nothing is modified
{
    if(h->count_ == 0) { printf("empty table\n"); return ""; }
    int index = key % TABLESIZE;
    int i = 0;
    while(i < h->count_)
    {
        if(h->elem_[index].in_use_)
        {
            ++i;
            if(h->elem_[index].key_ == key) return h->elem_[index].word_;
        }
        index = (index + 1) % TABLESIZE;
    }
    return "";
}
void disp_hash_table(hash_table_t *h)
{
    for(int index = 0; index < TABLESIZE; ++index)
        if(h->elem_[index].in_use_)
            printf("index : %d key : %d word : %s\n", index, h->elem_[index].key_, h->elem_[index].word_);
}
Primary clustering

Linear probing makes runs of occupied slots that keep growing: a key hashing anywhere into a run is pushed to its end, lengthening it further. Searches then need many probes. This is the main weakness that quadratic probing and double hashing try to avoid.

Linear probing cost (standard results)
successful ≈ ½(1 + 1/(1 − λ))    unsuccessful ≈ ½(1 + 1/(1 − λ)2) probes

Cost explodes as λ → 1, which is why a closed table should be kept well below full (and rehashed — see below).

9. Quadratic Probing

Very similar to linear probing — the structure is unchanged; only the way the next slot is probed changes. Linear probing always tries the next index (index = (index + 1) % TABLESIZE). Quadratic probing moves away from the initial index by the square of an integer i that goes 0, 1, 2, …, TABLESIZE − 1, which hopefully avoids clustering.

Quadratic probing
indexi = (init_index + i2) mod TABLESIZE

Probe sequence: init, init + 1, init + 4, init + 9, … (mod TABLESIZE).

Insert: store the initial index (init_index), then while the slot is in use increase i and recompute the index from init_index (not from the previous index). Delete and search use the same probing logic.

void insert_word(hash_table_t *h, int key, char word[])
{
    if(h->count_ == TABLESIZE) { printf("table full; cannot insert\n"); return; }
    int index = key % TABLESIZE;
    int init_index = index;                            // remember the home slot
    int i = 0;
    while(i < TABLESIZE && h->elem_[index].in_use_ != 0)
    {
        ++i;
        index = (init_index + i * i) % TABLESIZE;      // quadratic probe
    }
    if(i == TABLESIZE) { printf("could not insert\n"); return; }
    h->elem_[index].key_ = key;
    strcpy(h->elem_[index].word_, word);
    h->elem_[index].in_use_ = 1;
    ++h->count_;
}

The version with the if(i == TABLESIZE) test is the corrected one: without it, a probe sequence that never finds a free slot would overwrite an occupied one.

Limitation

Quadratic probing may not visit every slot, so an insertion can fail even though free slots remain. For a prime table size only about half the slots (the first ⌈TABLESIZE/2⌉ probes) are distinct, so a free slot is guaranteed only while the table is less than half full (λ < 0.5). Keys that hash to the same index still follow the same probe sequence (secondary clustering).

10. Double Hashing

Linear probing visits slots one after another and clusters around an index; quadratic probing jumps by squares and hopefully avoids that. In double hashing, on a collision a second hash function decides the step size, both for insertion and for finding the key during search and delete. The interface is unchanged; the structure now holds a callback (pointer to the second hash function), registered after the table is created.

Double hashing
indexi = (init_index + i · h2(key)) mod TABLESIZE    i = 0, 1, …, TABLESIZE − 1

h1(key) = key mod TABLESIZE gives init_index; h2 gives the step. Different keys with the same home slot get different steps.

struct hash_table
{
    struct node elem_[TABLESIZE];
    int count_;
    int (*hash_fn_)(int);                              // second hash function (callback)
};
int hash_double(int key) { return 7 - key % 7; }       // result in 1..7 (never 0)

void init_hash_table(hash_table_t *h, int (*hash_fn)(int))
{
    h->count_ = 0;
    for(int i = 0; i < TABLESIZE; ++i) h->elem_[i].in_use_ = 0;
    h->hash_fn_ = hash_fn;                             // register the callback
}
/* client:  hash_table_t h;  init_hash_table(&h, hash_double);

   insert / delete / search are as in quadratic probing; only the step differs: */
index = (init_index + i * h->hash_fn_(key)) % TABLESIZE;     // i = 0 .. TABLESIZE-1

The recommended second function, 7 - key % 7, returns a value from 1 to 7 and is based on a prime smaller than TABLESIZE (preferred). The step must never be 0, and with a prime TABLESIZE every step visits all slots.

12. Rehashing

As a table fills, its load factor λ = n / TABLESIZE rises: chains get long (separate chaining) and probe sequences get longer, and with a fixed array the table can overflow. Rehashing is the remedy: when λ crosses a chosen threshold, build a larger table and re-insert all the records into it.

12.1 Procedure

  1. Trigger: before (or after) an insertion, check whether λ exceeds the threshold — commonly about 0.5 for open addressing and about 1 for separate chaining; or when the table is full or an insertion fails.
  2. New size: allocate a table about twice the size, rounded up to the next prime.
  3. Re-insert every record from the old table, computing each index with the new TABLESIZE. Records cannot be copied slot-for-slot because the hash value key mod TABLESIZE depends on the table size, so positions and collisions change.
  4. Free the old table.
Rehashing
new size = next_prime(2 × old size)    new index = key mod new size

Cost of one rehash = O(n); amortised over the insertions it is O(1) per insert, because the table size doubles each time.

struct hash_table { node_t *elem_; int size_; int count_; };   // table now allocated dynamically

static int next_prime(int n)                          // smallest prime >= n
{
    for(;; ++n)
    {
        int ok = n > 1;
        for(int d = 2; d * d <= n && ok; ++d) if(n % d == 0) ok = 0;
        if(ok) return n;
    }
}
static void place(hash_table_t *h, int key, char word[])   // plain linear-probing insert
{
    int index = key % h->size_;
    while(h->elem_[index].in_use_) index = (index + 1) % h->size_;
    h->elem_[index].key_ = key;
    strcpy(h->elem_[index].word_, word);
    h->elem_[index].in_use_ = 1;
    ++h->count_;
}
void rehash(hash_table_t *h)
{
    node_t *old = h->elem_;
    int old_size = h->size_;
    h->size_  = next_prime(2 * old_size);              // bigger table, prime size
    h->elem_  = (node_t*)calloc(h->size_, sizeof(node_t));   // all slots free
    h->count_ = 0;
    for(int i = 0; i < old_size; ++i)                  // re-insert every record with the NEW size
        if(old[i].in_use_) place(h, old[i].key_, old[i].word_);
    free(old);
}
void insert_word(hash_table_t *h, int key, char word[])
{
    if((double)(h->count_ + 1) / h->size_ > 0.5)       // load factor would exceed threshold
        rehash(h);
    place(h, key, word);
}

Example. TABLESIZE = 5 with linear probing and a threshold of 0.5: after two keys the next insert would give λ = 3/5 > 0.5, so the table is rehashed into size next_prime(10) = 11 and the two keys are re-inserted with key mod 11 before the new key is added.

13.2 Applications of hashing

  1. Symbol tables in compilers: map identifiers to information about variables, functions and types.
  2. Database indexing: find records using keys.
  3. Caches: retrieve stored values quickly using lookup keys.
  4. Dictionaries and sets: support fast membership tests.
  5. Duplicate detection: identify repeated values efficiently.
