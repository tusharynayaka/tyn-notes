Unit 4: Network Layer Protocols, Routing, Link Layer, LANs & Wireless

DHCP, ICMP, IPv6 and tunnelling; link-state and distance-vector routing; the link layer — error detection, multiple access, ARP, Ethernet, switches, VLANs; a day in the life of a web request; the physical layer and 802.11 wireless LANs.

1. DHCP — Dynamic Host Configuration Protocol

1.1 How a host gets an address

An IP address has a network part (prefix, identifies the subnet) and a host part (identifies the interface). An organisation gets a block (prefix) from its ISP, which slices its own block (or gets blocks via a regional registry/ICANN). Hosts then get addresses by:

  1. Manual / static configuration: an admin sets IP, mask, default gateway and DNS in the OS (e.g. /etc/rc.config on UNIX, adapter properties on Windows). Fine for servers, tedious and error-prone for thousands of hosts.
  2. DHCP: the host obtains an address and related parameters automatically when it joins the network — plug-and-play / zeroconf.

1.2 Goals and benefits

Client–server protocol over UDP (RFC 2131).

  • Centralised control — rules in one server; avoids typos and duplicate-IP conflicts.
  • Temporary leases and reuse — an address is leased (e.g. 3600 s or 24 h) and returned to the pool when the host leaves. Vital when there are more devices than addresses.
  • Lease renewal — connected hosts renew before expiry without changing address.
  • Mobile users — every new subnet needs a new matching address and gateway; DHCP supplies them within milliseconds.

1.3 The four-step DORA exchange

Client UDP port 68, server UDP port 67. Example: DHCP server 223.1.2.5 on subnet 223.1.2.0/24; arriving laptop.

  • Discover: client knows neither its own IP nor the server's, so it broadcasts from 0.0.0.0 to 255.255.255.255 with a random transaction ID to match replies.
  • Offer: one or more servers propose an address (still broadcast because the client has no IP) plus mask and lease time.
  • Request: client picks the best offer and broadcasts the choice. The broadcast both accepts the chosen server's offer and tells the other servers theirs were declined so they free the address.
  • ACK: the chosen server commits the lease binding and confirms; the client can use the address for the lease period.
  • Skipping steps 1–2 (RFC 2131): a returning client that remembers its old address goes straight to a Request to renew/re-verify; the server replies ACK, or NAK if the address is no longer valid.

1.4 What else DHCP returns

  1. First-hop router (default gateway) address.
  2. Name and IP address of the DNS server.
  3. Network mask (e.g. 255.255.255.0 / /24) — tells the host which destinations are local.

1.5 Encapsulation walkthrough

  1. Client builds a DHCP request → UDP (src 68, dst 67) → IP (src 0.0.0.0, dst 255.255.255.255) → 802.3 Ethernet frame with broadcast MAC FF:FF:FF:FF:FF:FF.
  2. The switch floods the frame; the router interface (168.1.1.1) with the embedded DHCP server receives it.
  3. Router demultiplexes: Ethernet → IP → UDP (port 67) → DHCP server process.
  4. The server builds a DHCP ACK (client IP, first-hop router 168.1.1.1, DNS name/IP), encapsulates DHCP → UDP → IP → Ethernet and the switch delivers it; the client demultiplexes back up the stack.

2. ICMP — Internet Control Message Protocol

RFC 792. Used by hosts and routers to communicate network-layer information: error reporting (unreachable host/network/port/protocol, TTL expiry, bad header) and echo request/reply (ping). ICMP sits "just above IP": its messages are carried as IP payloads (IP protocol field = 1), like TCP/UDP segments.

Format: 8-bit Type, 8-bit Code, 16-bit checksum, and for errors the IP header plus first 8 bytes of the offending datagram. Those 8 bytes hold the TCP/UDP port numbers, so the IP layer can pass the error to the exact socket that sent the packet.

Five message categories

  1. Source quench (4/0): early network-layer congestion control; deprecated because TCP does end-to-end control and extra ICMP packets worsen congestion.
  2. Parameter problem (12/0): invalid, corrupted or missing option in the IP header.
  3. Time exceeded (11/0): router drops a datagram at TTL 0, or destination's reassembly timer expires before all fragments arrive.
  4. Destination unreachable (3, codes 0–7): subnet, host, protocol or port cannot be reached.
  5. Redirection (type 5): default router tells a LAN host a better first-hop router exists for a destination network so it updates its cache.

Ping and traceroute

  • Ping: sends ICMP Type 8 Code 0 (echo request); a live host's OS replies Type 0 Code 0 (echo reply). Tests reachability and measures RTT.
  • Traceroute: source sends sets of three UDP segments to an unlikely unused port with TTL = 1, 2, 3, …. A router that decrements TTL to 0 drops the datagram and replies ICMP TTL expired (11/0), revealing its address and the RTT to that hop. TTL = 1 → router 1, TTL = 2 → router 2, etc. When the probe finally reaches the destination, no application listens on that port, so the destination returns ICMP port unreachable (3/3) — that different reply tells the source it reached the end and traceroute stops.

3. IPv6 — Motivation & Datagram Format

3.1 Why IPv6

  1. Address exhaustion: 232 ≈ 4.3 billion addresses ran out (phones, broadband, cloud VMs, IoT). IPv6 uses 128 bits → 2128 ≈ 3.4 × 1038 addresses.
  2. Fixed 40-byte base header (IPv4 is 20–60 bytes) → hardware parses and forwards faster.
  3. Flow label and traffic class in the base header: 20-bit Flow Label and 8-bit Traffic Class to identify real-time streams / QoS flows.
  4. Better options mechanism: rare options moved to daisy-chained extension headers pointed to by Next Header; most are examined only by the destination.
  5. Built-in security and ICMPv6: IPsec ESP/AH extension headers; ICMPv6 subsumes ARP (Neighbor Discovery) and IGMP (Multicast Listener Discovery).

2128 = 232 × 296 ≈ 340 undecillion

IPv6 is 296 times larger than IPv4.

What IPv6 removed from IPv4

  1. No header checksum: TTL/hop limit changes every hop so IPv4 recomputes it each time; link-layer CRC and TCP/UDP checksums already check errors, so removing it speeds forwarding.
  2. No fragmentation fields (Identification, Flags, Fragment offset): routers never fragment. Too-large packet → dropped, ICMPv6 Packet Too Big sent. Only the source host fragments, via a Fragmentation extension header (Next Header = 44) after discovering the path MTU.

4. IPv6 Address Notation & Compression

128 bits = eight 16-bit blocks (hextets) separated by colons. One hex digit = 4 bits (nibble), so each block is 4 hex digits (8 × 4 = 32 hex digits). Example: FDEC:BA98:7654:3210:ADBF:BBFF:2922:FFFF.

Three abbreviation rules

  1. Drop leading zeros in each block (keep at least one digit; 0000 → 0). Trailing zeros (e.g. 6300) can never be dropped.
  2. Replace a run of consecutive all-zero blocks with :: (two or more blocks).
  3. :: may appear at most once. If several zero runs exist, compress the longest; write the others as :0:.

Example: 2001:0000:3238:DFE1:0063:0000:0000:FEFB → rule 1 → 2001:0:3238:DFE1:63:0000:0000:FEFB → rule 2 → 2001:0:3238:DFE1:63::FEFB. Another: FDEC:0000:0000:0000:0000:BBFF:0000:FFFF → FDEC::BBFF:0:FFFF.

Why only one "::"

A parser counts the k explicit blocks and inserts 8 − k zero blocks at "::". With two "::" it cannot tell how to split them. 2001::abcd::1234 has 3 explicit blocks, so 5 zero blocks are missing and could be split 1+4, 2+3, 3+2 or 4+1 — four different addresses. Hence invalid.

5. IPv6 Address Types & Allocation

  1. Unicast — one-to-one: delivered to the single interface identified.
  2. Multicast — one-to-many: delivered to all interfaces in the group.
  3. Anycast — one-to-nearest: an address assigned to several interfaces (e.g. root DNS, CDN edge); a packet goes to only the nearest one by routing metric. Improves performance and gives automatic failover to the next-nearest replica.
  4. No broadcast. Broadcast-like jobs (router discovery, neighbor resolution) use scoped multicast such as all-nodes ff02::1 or solicited-node multicast, so uninterested hosts are not interrupted.

6. Transition from IPv4 to IPv6 — Tunneling

Billions of devices can't switch at once — no flag day. Networks must work with a mix of IPv4 and IPv6 routers. Tunneling carries the whole IPv6 datagram as the payload of an IPv4 datagram across IPv4-only routers (a packet within a packet). Inside the tunnel the IPv4 cloud looks like a single virtual point-to-point link.

Path A → B → C → D → E → F: A and F are IPv6; B (tunnel entry) and E (tunnel exit) are dual-stack; C and D are IPv4-only.

  • Hop limit/TTL: inner IPv6 hop limit is decremented at B (and E); C and D decrement only the outer IPv4 TTL. The whole tunnel counts as one IPv6 hop. Example: hop limit 10 at A → 9 after B → still 9 inside → 8 after E (F receives 8); IPv4 TTL 64 at B → 63 at C → 62 at D.
  • Cost: an extra IPv4 header (≥ 20 bytes) on every packet.
  • In the lab-style exercise (D→E IPv6, E→d, d→b, b→c, c→B IPv4 carrying an encapsulated IPv6 datagram): E is the tunnel entrance, B the exit, and IPv4 encapsulates IPv6; the inner source/destination (IPv6) never change.

Adoption: about 40 % of clients reach Google over IPv6 (45–50 % in India and the US); about one-third of US government domains are IPv6-capable. It takes decades because changing the network layer means upgrading core routers, firewalls, DNS, DHCP and management tools across thousands of autonomous systems, unlike an application-layer change at the edge.

7. Routing — Goal, Graph Model & Classification

Forwarding moves a packet from input to output port using the local table; routing computes those tables network-wide. A routing protocol seeks a "good" path — the sequence of routers from source to destination — usually the least-cost, fastest or least congested one.

Graph abstraction

Network = graph G = (N, E). N = set of routers {u, v, w, x, y, z}; E = set of links {(u,v), (u,x), (v,x), (v,w), (x,w), (x,y), (w,y), (w,z), (y,z)}. Each edge has a cost c(a,b); if two nodes aren't directly connected c = ∞ (e.g. c(u,z) = ∞).

  • Costs are set by operators: always 1 (→ minimum-hop routing), inversely proportional to bandwidth (c ∝ 1/bandwidth), or related to congestion (queuing delay / load).
  • Path cost of (x1, x2, …, xp) = c(x1,x2) + c(x2,x3) + … + c(xp−1,xp).

8. Dijkstra's Link-State Algorithm

Centralised, global knowledge: every node broadcasts Link State Packets (LSPs) (identities and costs of its attached links) by flooding, so all hold the same graph. It computes the least-cost paths from one source u to all others, which gives u's forwarding table. It is iterative: after k iterations the least-cost paths to k destinations are known (the k smallest).

9. Distance-Vector Routing & Bellman-Ford

DV is decentralised, distributed, based on dynamic programming.

Bellman-Ford equation
Dx(y) = minv { c(x,v) + Dv(y) }

min over all direct neighbours v of x. c(x,v) = cost to neighbour v; Dv(y) = v's least cost to y. The neighbour achieving the min is the next hop for y in x's forwarding table.

Worked example — Du(z)

c(u,v)=2, c(u,x)=1, c(u,w)=5; neighbours report Dv(z)=5, Dx(z)=3, Dw(z)=3.

Du(z) = min{ 2+5, 1+3, 5+3 } = min{7, 4, 8} = 4 (next hop x)

Mechanics

  • Distance vector Dx = [Dx(y) : y ∈ N] — x's current estimates to every destination. From time to time x sends it to each direct neighbour.
  • Update rule: on receiving Dv from a neighbour, x saves it and recomputes Dx(y) ← minv{c(x,v) + Dv(y)} for each y. With non-negative costs the estimates converge to the true least costs.
  • Iterative and asynchronous: each local iteration is triggered by (1) a local link-cost change or (2) a DV update message from a neighbour. Nodes need not move in lockstep.
  • Distributed and self-stopping: a node notifies neighbours only if its own DV changed. No change → no messages → quiescent until a link cost changes.

10. DV Dynamics — Count-to-Infinity & DV vs. LS

10.1 Link-cost change in a 3-node triangle

Nodes x, y, z with c(x,y) = 4, c(y,z) = 1, c(x,z) = 50. Converged estimates to x: Dx(x) = 0, Dy(x) = 4, Dz(x) = 5 (via z → y → x).

Good news travels fast — c(x,y) falls 4 → 1

  1. t0: y detects the change, Dy(x) = min(1+0, 1+5) = 1, sends its DV to z.
  2. t1: z recomputes Dz(x) = min(50+0, 1+1) = 2, sends to y.
  3. t2: y recomputes Dy(x) = min(1+0, 1+2) = 1 — unchanged, so it sends nothing. Done in 2 iterations.

Bad news travels slow — c(x,y) rises 4 → 60 (count-to-infinity)

  1. Loop forms at y: using z's stale Dz(x) = 5, y computes Dy(x) = min(60+0, 1+5) = 6 (via z) — not realising z's 5 goes through y. It advertises 6 to z. Packets for x now bounce y ↔ z.
  2. z receives 6: Dz(x) = min(50+0, 1+6) = 7, sends 7 to y.
  3. y: min(60, 1+7) = 8; z: 9; … ping-pong for ~44 iterations (6 → 7 → … → 50) until z finds 1 + Dy(x) = 51 > 50 and switches to its direct link of cost 50; y then converges to 51. If c(x,z) were 10,000 it would count to 10,000.

Five defences

  1. Split horizon: don't advertise a route back out the interface it was learned from (z learned x via y, so it doesn't tell y).
  2. Route poisoning / poisoned reverse: z advertises Dz(x) = ∞ (RIP metric 16) to y for routes it reaches through y. Solves 2-node loops; loops of 3+ nodes can still occur.
  3. Triggered updates: send an update immediately on a change instead of waiting for the periodic timer (30 s in RIP).
  4. Hold-down timers: after a route fails, suppress acceptance of worse/questionable updates for that destination until the network settles.
  5. Small maximum "infinity": RIP defines ∞ = 16 hops, bounding the count.

11. Introduction to the Link Layer

Terminology: every device running a link-layer protocol (hosts, routers, link-layer switches, Wi-Fi APs) is a node; channels joining adjacent nodes are links (wired point-to-point, wireless, broadcast LANs); the layer-2 packet is a frame. The link layer moves a datagram between two physically adjacent nodes over one link, and different links on a path can use different protocols (802.11 → optical WAN/PPP → 802.3 Ethernet), each with its own services (some reliable, some best effort).

Analogy (Princeton → Lausanne): tourist = datagram; each segment (limo, plane, train) = a link; transport mode = link-layer protocol; travel agent = routing algorithm.

11.1 Link-layer services

  1. Framing and link access: add header and trailer (error detection); MAC rules for a shared medium; MAC addresses in the header identify source and destination interfaces on this one link — distinct from end-to-end IP addresses.
  2. Reliable delivery between adjacent nodes: ACKs and retransmissions per hop. Used on wireless links (high bit-error rate — fixing locally is faster and cheaper than an end-to-end TCP retransmission across the Internet) but seldom on low-error wired links (fibre, coax, twisted pair), where per-hop ACKs and buffering add needless latency and cost.
  3. Flow control: pace frames so a fast sender doesn't overrun an adjacent receiver's buffer.
  4. Error detection: noise and attenuation cause bit errors; the receiver detects them via the trailer (CRC/checksum) and drops or requests retransmission. Done in NIC hardware (transport checksums are software).
  5. Error correction (FEC): receiver locates and fixes the bad bits without retransmission — used in storage (CD/DVD), DSL modems, and deep-space links where retransmission takes minutes or hours.
  6. Half-duplex and full-duplex: full-duplex = both ends transmit simultaneously (switched Ethernet); half-duplex = both can transmit but not at once (hub Ethernet, Wi-Fi).

11.2 Where it is implemented — the NIC

In every host the link layer lives in a NIC / network adapter (e.g. Intel 700-series Ethernet, Atheros AR5006 Wi-Fi) attached to the host's system bus (PCI/PCIe) alongside CPU and memory; it implements both link and physical layers. It is a mix of hardware (framing, MAC, signalling, CRC generation/check), software (device driver: handle interrupts on frame arrival, DMA, pass datagrams up) and firmware.

  • Sending side: take the datagram from host memory, encapsulate in a frame, add CRC bits, handle reliable delivery/flow control/medium access, transmit.
  • Receiving side: receive signal, check CRC, reliable delivery/flow control, extract the datagram, interrupt the upper layer.

12. Error Detection & Correction

12.1 General model

D = d-bit data (may include header fields). The sender computes EDC bits and sends ⟨D, EDC⟩. The receiver gets ⟨D′, EDC′⟩, recomputes the check from D′ and compares. Mismatch → error. Detection is never 100 % reliable (multiple flips might yield another valid codeword); a bigger EDC field gives better detection/correction at the cost of overhead and computation.

12.2 Parity

  • Single-bit parity: one extra bit makes the total number of 1s even (even parity) or odd. Detects any odd number of flips, misses every even number. Under burst errors the chance of an undetected error approaches 50 %.
  • Two-dimensional parity: arrange d bits in an i × j matrix; add a parity bit per row, per column, plus a corner bit. A single flipped bit makes exactly one row and one column fail — their intersection locates it, so it can be corrected. Any 2-bit error is detected.

Examples: 0111000110101011 has nine 1s → even-parity bit = 1. 1011 0110 has five 1s → parity bit 1 (total six); any two flips leave the parity even → no error detected.

2D parity matrix: words 1100111, 1011101, 0111001, 0101001 → row parities 1, 1, 0, 1 → bytes 11001111, 10111011, 01110010, 01010011; column parities (0,1,0,1,0,1,0) + corner 1 → 01010101. Stream: 11001111 10111011 01110010 01010011 01010101.

12.3 Internet checksum

Used in TCP, UDP and the IPv4 header.

Internet checksum
checksum = NOT( 1's-complement sum of all 16-bit words )

Sender: treat the packet as 16-bit integers, add with end-around carry (a carry out of the MSB wraps into the LSB), invert, store in the checksum field. Receiver: add all words including the checksum; result must be 1111111111111111 (inverse = all 0s).

Example: W1 = 0110011001100110, W2 = 0101010101010101, W3 = 0000111100001111. W1 + W2 = 1011101110111011; + W3 = 1100101011001010; checksum = inverse = 0011010100110101.

12.4 CRC — cyclic redundancy check

Standard hardware scheme in Ethernet, 802.11, HDLC. A d-bit string is a polynomial of degree d−1 (11011011 = x7 + x6 + x4 + x3 + x + 1). Sender and receiver agree on an (r+1)-bit generator G (MSB and LSB must be 1). The sender picks r bits R so ⟨D,R⟩ is exactly divisible by G in modulo-2 arithmetic.

CRC
D·2r XOR R = nG ⇔ R = remainder( D·2r / G )

Modulo-2: add = subtract = XOR (no carries or borrows). D·2r = D left-shifted r places (append r zeros). Transmit D followed by R. Receiver divides ⟨D,R⟩ by G; non-zero remainder → error.

  • An r-bit CRC detects all burst errors of length ≤ r, all odd-bit errors if (x+1) divides G(x), and longer bursts with probability 1 − 0.5r. Ethernet and 802.11 use a 32-bit CRC.
  • Procedure: (1) write G from the polynomial (x4 + x + 1 → 10011); (2) r = bits(G) − 1; append r zeros; (3) XOR-divide; (4) remainder = CRC; (5) replace the zeros with the CRC.

14. CSMA and CSMA/CD

CSMA — "listen before speaking": if the channel is sensed idle, transmit the whole frame; if busy, defer until idle. Collisions still happen because of propagation delay: B senses idle at t0 and starts; before B's first bit reaches D, D senses idle at t1 and also starts; the wavefronts collide. In plain CSMA both finish their damaged frames, wasting the whole frame time.

CSMA/CD adds collision detection: the NIC monitors the wire while sending, and aborts at once on detecting another transmission — far less wasted channel time.

Ethernet CSMA/CD algorithm

  1. Framing: NIC builds an Ethernet frame from the datagram.
  2. Carrier sense: idle → start; busy → wait until idle, then transmit.
  3. Success: if the whole frame goes out with no detected collision, done.
  4. Collision: abort and send a short 48-bit jam signal so every transmitter notices.
  5. Binary exponential backoff: after the n-th consecutive collision, m = min(n, 10), pick K uniformly from {0, 1, …, 2m − 1}, wait K × 512 bit times, return to step 2.
Backoff
K ∈ {0, 1, …, 2m − 1}, m = min(n, 10)
wait = K × 512 bit times (51.2 µs per unit on 10 Mbps)

1st collision → K ∈ {0,1}; 2nd → {0..3}; 3rd → {0..7}; 4th → {0..15}; 10th → {0..1023}. Frame discarded after 16 attempts. Exponential growth spreads out more contenders. Example: 4 collisions, K = 9 on 10 Mbps → 9 × 51.2 = 460.8 µs.

Frame-size numericals (CSMA/CD)

Minimum frame size
Lmin = 2 × tprop × Bandwidth (frame time ≥ round-trip propagation)
Max cable length: L ≤ (frame bits / BW) × v / 2

With a jam signal: time to cover = round trip + jam time. Examples: 20 Mbps, 40 µs → 2 × 40 µs × 20 Mbps = 1600 bits = 200 B. 1 Gbps, 1 km, 2×108 m/s → tprop = 5 µs → 10,000 bits. 500 Mbps, 10,000-bit frame, 2×105 km/s → 20 µs ≥ 2L/v → L = 2 km. 10 Mbps, round trip 46.4 µs + 48-bit jam (4.8 µs) = 51.2 µs → 512 bits.

Two-station backoff probability: after A wins the first race, A has 1 collision (K ∈ {0,1}) while B has 2 (K ∈ {0..3}). A wins when its K is smaller: 5 of 8 equally likely pairs = 0.625.

15.2 Private / randomised Wi-Fi MACs

  • Problem: Wi-Fi probe requests and data frames carry the source MAC in clear text, so sniffers in malls/airports can track a device without it joining any network.
  • Fix: the OS uses a different random MAC per SSID and rotates it during background scans.
  • U/L bit: second-least-significant bit of the first byte: 0 = universally administered (IEEE), 1 = locally administered. With the multicast I/G bit 0, the second hex digit of a random unicast MAC is always 2, 6, A or E (6A-…, 3E-…, D2-…).

15.3 ARP — Address Resolution Protocol (RFC 826)

Given a destination IP on the same LAN, ARP finds its MAC. Each node keeps an ARP table of <IP; MAC; TTL> (TTL: when the mapping is forgotten, typically ~20 min).

A (137.196.7.23, 71-65-F7-2B-08-53) → B (137.196.7.14, 58-23-D7-FA-20-B0), same LAN:

  1. A broadcasts an ARP query (contains target IP, and A's own IP + MAC) in an Ethernet frame with dest FF-FF-FF-FF-FF-FF. All nodes receive it.
  2. B replies by unicast ("137.196.7.14 is at 58-23-D7-FA-20-B0") directly to A's MAC; nodes with other IPs silently drop the query.
  3. A caches the entry and sends the queued datagram. ARP is plug-and-play (no configuration).
  • Who gets new entries? Both A (from the reply) and B (the query already carried A's IP/MAC, so B caches it and needn't ARP back). Bystanders update only if they already had an entry for A.
  • ARP spoofing / poisoning: ARP is stateless and unauthenticated; an attacker sends forged (gratuitous) replies mapping the gateway IP to its own MAC, so victims send traffic to it (man-in-the-middle).
  • ARP packet fields (Wireshark labs): hardware type (Ethernet 1), protocol type (IPv4 0x0800), hardware size 6, protocol size 4, opcode (1 = request, 2 = reply), sender MAC/IP, target MAC/IP. In a request the target MAC is 00:00:00:00:00:00 (unknown) and the Ethernet destination is broadcast; the reply's target MAC is the requester's MAC. An ARP probe (sender IP 0.0.0.0, asking about one's own proposed IP) checks that no one else uses the address (duplicate-address detection); an ARP announcement/gratuitous ARP advertises one's own mapping.

15.4 Routing a datagram to another subnet (A → R → B)

A = 111.111.111.111 (MAC 74-29-9C-E8-FF-55) on 111.111.111.0/24; router R left 111.111.111.110 (E6-E9-00-17-BB-4B), right 222.222.222.220 (1A-23-F9-CD-06-9B); B = 222.222.222.222 (49-BD-D2-C7-56-2A) on 222.222.222.0/24. A knows its gateway (DHCP) and B's IP (DNS). All ARP tables empty.

  4. R strips the frame, looks up the IP destination, picks its right interface.
  5. R ARPs on the right LAN for B's MAC; B replies.

16.2 Service & standards

  • Connectionless (no handshake) and unreliable (no ACK/NAK; CRC-failed frames dropped). Lost data is recovered only by a higher layer such as TCP at the original sender. Omitting link ACKs makes Ethernet fast and cheap given its very low bit-error rate.
  • Naming: <speed>BASE-<medium>; BASE = baseband. 100BASE-TX (100 Mb/s, 2 pairs Cat-5 UTP, 100 m); 100BASE-FX (fibre, ~2000 m); 1000BASE-T (4 pairs Cat 5/5e/6, 100 m); 10GBASE-T (Cat 6A/7). All share one MAC protocol and frame format.
  • Modern switched Ethernet: dedicated full-duplex links (separate TX/RX pairs in 100BASE-TX, separate fibres in 100BASE-FX, DSP echo cancellation in 1000BASE-T). No wire collisions, CSMA/CD switched off. Contention moves into the switch's output queue (A, B, C all sending to D are queued; overflow → tail drop). CSMA/CD is still studied because Wi-Fi uses CSMA/CA with backoff, and a duplex mismatch (one end forced full, other half) makes the half-duplex side see constant late collisions and crawl.

18. VLANs & IEEE 802.1Q

A single flat L2 network of hundreds of ports has problems: (1) no broadcast isolation — ARP/DHCP/unknown unicast cross the whole network; (2) security/privacy — Finance, HR, CCTV share a domain with labs and guests (ARP spoofing, sniffing); (3) mobility — a CS user moving to the EE building wants to stay in the CS subnet without a long cable.

VLAN: multiple virtual LANs over one physical infrastructure. Port-based: ports are grouped in software (ports 1–8 = EE, 9–15 = CS); one switch acts as several virtual switches and frames never cross groups. Ports can be reassigned in software. A VLAN spanning several switches uses a shared trunk port carrying all VLANs, with 802.1Q tags.

18.4 Inter-VLAN routing

Each VLAN is its own broadcast domain and IP subnet (VLAN 10 = 10.0.10.0/24, VLAN 20 = 10.0.20.0/24), so an L2 switch cannot pass traffic between them; it needs layer 3:

  • Router on a stick: an external router connects to the switch over one trunk using logical 802.1Q sub-interfaces (eth0.10 = gateway 10.0.10.1 for VLAN 10; eth0.20 = 10.0.20.1 for VLAN 20). Cheap, but all inter-VLAN traffic shares one link.
  • Layer-3 switch: routing inside the switch, one gateway (SVI) per VLAN, at hardware speed; firewall rules can be applied there.

20. A Day in the Life of a Web Request

Laptop on a campus network 68.80.2.0/24, ISP Comcast 68.80.0.0/13, requesting http://www.google.com (64.233.169.105 in 64.233.160.0/19).

  1. DHCP — get IP, gateway, DNS. The laptop has none. DHCP request → UDP (68→67) → IP (0.0.0.0 → 255.255.255.255) → Ethernet broadcast (FF-FF-FF-FF-FF-FF). The switch learns the laptop's MAC/port and floods; the router's embedded DHCP server replies with a DHCP ACK: laptop IP, first-hop router IP, subnet mask, DNS server IP.
  2. ARP — first-hop router's MAC. The laptop knows the router's IP but not its MAC; it broadcasts an ARP query, the router replies by unicast.
  3. DNS — www.google.com → 64.233.169.105. DNS query → UDP port 53 → IP to the Comcast DNS server → Ethernet to the router's MAC. The router forwards into Comcast; tables are pre-populated by intra-domain (RIP, OSPF, IS-IS) and inter-domain (BGP) routing. The reply carries Google's IP.
  4. TCP — 3-way handshake to 64.233.169.105 port 80: SYN → SYNACK → ACK.
  5. HTTP: GET written into the socket; Google returns the HTML (200 OK) over the connection; the browser renders it.

21. Physical Layer

OSI layers 3–7 are mostly software; the data link and physical layers are hardware (NIC and transceivers). The physical layer converts the frame's logical bits into physical electromagnetic signals and back at the receiver.

  • Analog signal: continuous waveform (amplitude, frequency or phase varies continuously). Digital signal: discrete pulses between distinct levels (high = 1, low = 0).

Three functions

  1. Physical components: hardware, cables, jacks, antennas, connectors (RJ-45, ST, SC, LC).
  2. Encoding (line/block coding): bits → code patterns that mark frame boundaries, keep DC balance and embed clock timing.
  3. Signalling (modulation): generate the electrical/optical/radio signals representing the encoded 1s and 0s.

Layer-1 devices: hub (multiport repeater; one collision domain), repeater (regenerates attenuated signal to extend distance), modem (digital ↔ modulated analog carrier), cables (Cat 5/5e/6 twisted pair, coax, fibre), NIC transceivers.

22. Wireless Networks — Elements & Taxonomy

There are ~10× more mobile than fixed phone subscribers and ~5× more mobile-broadband than fixed-broadband devices; 4G/5G fully use the Internet stack (including SDN). Two challenges: (1) wireless link (path loss, multipath fading, interference, hidden terminals); (2) mobility (handoff, session continuity as the attachment point changes).

Elements

  • Wireless hosts (laptops, phones, IoT) — stationary or mobile; wireless ≠ mobile.
  • Base station (cell tower, 802.11 AP): link-layer relay between wired network and wireless hosts in its area.
  • Wireless link: joins mobiles to a base station (or as a backbone); multiple-access protocol coordinates use.
  • Infrastructure mode: base station connects mobiles to the wired network; handoff when a mobile changes base station. Ad hoc mode: no base stations; nodes reach only nodes in range, self-organise and route among themselves.

Architecture

  • BSS (cell): building block. Infrastructure mode: wireless hosts + one access point; APs joined by a wired switch/router. Ad hoc mode: hosts only.
  • Channels: the 2.4–2.485 GHz band (~85 MHz) has 11 partially overlapping channels (channel 1 = 2.412 GHz, 5 MHz spacing). Each channel is ~22 MHz wide, so neighbours overlap; only channels 1, 6 and 11 are non-overlapping. The admin chooses each AP's channel; neighbouring APs on the same/overlapping channel interfere.
  • Association: a host must associate with an AP before sending data. Each AP has an SSID (network name) and a 48-bit MAC. The host scans channels, picks an AP, optionally authenticates (WPA2/WPA3, 802.1X), then runs DHCP to get an IP in that AP's subnet.

24. Lab 5 — Ethernet and ARP in Wireshark

Part A — Ethernet frame of an HTTP GET

  • Ethernet source = MAC of your NIC (yes, your device's physical address).
  • Ethernet destination = MAC of your first-hop router/gateway, not the web server — the server is on another network, and MAC addresses only identify the next hop on the same LAN.
  • Destination IP = the web server's IP (the IP does stay end to end; compare with the server address from DNS/the TCP connection).
  • Response frame: MAC source = the router's MAC (last hop), MAC destination = your NIC; the IP source is the server and IP destination is you. Compared with the GET, MAC addresses are swapped and now belong to the router/your NIC, while IPs are swapped between server and client.

Part B — ARP

Clear the ARP cache first (arp -d * on Windows as administrator; sudo arp -a -d on macOS; on Linux ip neigh flush all), start capture with the arp filter, then reconnect.

  • ARP probe: sender IP 0.0.0.0, target IP = the address the host intends to use; sent to check no other device already uses that address (duplicate address detection).
  • ARP request from your device: sender IP = yours, target IP = the one being resolved. Difference from the probe: the sender IP is real, not 0.0.0.0. Target MAC = 00:00:00:00:00:00 because it is unknown (that is what is being asked); the Ethernet destination is broadcast FF:FF:FF:FF:FF:FF. Opcode 1 = request.
  • ARP reply: sender and target are swapped relative to the request; the target MAC is now the requester's MAC (the reply is unicast); the sender MAC is the answer. Opcode 2 = reply.
