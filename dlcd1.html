1Introduction to Circuits

What is a circuit?

In digital electronics, a circuit is a network that processes discrete-valued variables — signals that only ever take one of a fixed set of values (almost always just 0 and 1), rather than a continuous range. You can treat any circuit as a black box: you don't need to know what's inside it to reason about it, as long as you know four things about it.

A circuit is fully described by 1. One or more discrete-valued input terminals
2. One or more discrete-valued output terminals
3. A functional specification — the relationship between inputs and outputs
4. A timing specification — the delay between an input changing and the output responding

The functional spec tells you what the circuit computes; the timing spec tells you how fast. Two circuits can compute the exact same function yet have very different timing specs — that distinction matters a lot later (see the propagation-delay MCQ below).

Nodes, circuit elements, and internal wires

A circuit is built from smaller circuits wired together. In the example used in the slides:

  • Inputs: A, B, C
  • Outputs: Y, Z
  • Circuit elements: E1, E2, E3 — each of these is itself a (smaller) circuit
  • Internal node: n1 — a wire that isn't an input or output of the overall circuit, just a connection between two elements

So a large circuit is really just nodes (inputs, outputs, internal wires) connected through elements. This recursive view — "a circuit is made of circuits" — is exactly what lets you build complex logic out of simple gates.

Rule of thumb: if you could compute the output with only a truth table (no notion of "before" or "after"), it's combinational. If you need to know the circuit's previous state to know what it will output next, it's sequential.

Rules of Combinational Composition

It isn't enough to say "a combinational circuit has no memory" — you need a precise, checkable definition, because circuits are built by wiring smaller circuits together and you need to know whether the result is still combinational. A circuit is combinational if, and only if, all three rules hold:

Rules of combinational composition 1. Every circuit element used is itself combinational.
2. Every node is either an input to the circuit, or connects to exactly one output terminal of a circuit element (no two outputs fighting over the same wire).
3. The circuit contains no cyclic paths — every path through the circuit visits each node at most once.

Rule 3 is the one people forget: it's not enough for the individual elements to be combinational — if their wiring creates a loop (a signal's own node feeds back into computing itself), the composite circuit is no longer guaranteed memoryless, because the output can now depend on what value was circulating in the loop a moment earlier. That's precisely how sequential elements like latches are built out of otherwise-simple gates.

Think About It — MCQs

MCQ 1 — A designer replaces element E2 with a faster implementation that computes the exact same Boolean function. What changes?
  • A. Functional specification changes.
  • B. Timing specification may improve while functionality remains unchanged.
  • C. Both functional and timing specifications change.
  • D. Overall logic becomes sequential.
Correct answer: B. This is exactly the functional-spec vs. timing-spec split from the definition of a circuit: swapping in a faster gate that computes the same function only touches the timing spec (propagation delay), never the functional spec (what it computes).
MCQ 2 — Propagation delay calculation

Given: Delay(E1) = 5 ns, Delay(E2) = 8 ns, Delay(E3) = 4 ns, and E3 only begins computing once both E1's and E2's outputs are valid. What is the worst-case propagation delay of the whole circuit?

  • A. 9 ns
  • B. 12 ns
  • C. 13 ns
  • D. 17 ns
Correct answer: B — 12 ns.
Why E3 must wait for the slower of its two inputs (E1 or E2) before it can even start, then add its own delay on top:
Worst-case delay = max(Delay(E1), Delay(E2)) + Delay(E3) = max(5, 8) + 4 = 8 + 4 = 12 ns
This "max of parallel paths, then add the next stage" rule is the general method for computing worst-case propagation delay through any chain of combinational elements.
MCQ 3 — Classifying circuits by memory

Circuit X: output depends only on current inputs. Circuit Y: output depends on previous and current inputs. Which classification is correct?

  • A. X is Sequential, Y is Combinational
  • B. X is Combinational, Y is Sequential
  • C. Both are Sequential
  • D. Both are Combinational
Correct answer: B. This is the defining test from the Combinational vs Sequential table above — "depends only on current inputs" is the textbook definition of combinational; "depends on past and present inputs" is the textbook definition of sequential (memory required).

2Boolean Equations

A Boolean equation is just the functional specification from Section 1, written algebraically: each output expressed as a function of the inputs. The classic example is a full adder, which takes two bits A, B and a carry-in Cin, and produces a sum bit S and a carry-out Cout:

SumS = A ⊕ B ⊕ Cin
Carry-outCout = AB + ACin + BCin

Both S and Cout are functions of the same three inputs (A, B, Cin) — one circuit, two outputs, two independent Boolean equations.

Terminology

Before you can manipulate Boolean equations fluently, these five terms need to be second nature:

COMPLEMENTA variable with a bar over it — negation. Written A′, B′, C′ in text (the bar can't always be typeset).
LITERALA variable or its complement, on its own: A, A′, B, B′, C, C′.
IMPLICANTA product (AND) of literals: ABC, A′C, BC′. Doesn't need to involve every variable.
MINTERMA product that includes every input variable, each appearing exactly once (true or complemented): A′B′C′, AB′C, ABC.
MAXTERMA sum that includes every input variable: (A+B+C′), (A+B′+C), (A′+B′+C′).

Notice the pattern: a minterm is the AND-version and a maxterm is the OR-version of "use every variable, once each." That symmetry is exactly why SOP and POS (next section) are mirror images of each other.

From Truth Table to Boolean Formula — and Minimizing It

Going from a circuit/formula to its truth table is mechanical. The genuinely hard direction is the reverse:

  • Given only a truth table, how do you construct a Boolean formula (or logic circuit) for it?
  • Since many different formulas/circuits can implement the same truth table, how do you pick the best one?

That second question is called logic minimization. There are many possible metrics you could minimize for — smallest circuit, fastest circuit, least power — and different metrics can favour different circuits. For this course, the metric adopted is:

Our metric: the smallest two-level Sum-of-Products formula. ("Two-level" means one layer of AND gates feeding one OR gate — no deeply nested logic.) Note there may be more than one equally-minimal solution.

Sum-of-Products (SOP) Form

Every Boolean equation can be written in SOP form, and the recipe is completely mechanical:

SOP construction rule 1. Each row of the truth table has an associated minterm.
2. A minterm is a product (AND) of literals, and is TRUE for that row and only that row.
3. Build the function by OR-ing together every minterm whose output is TRUE.
Result: a sum (OR) of products (AND terms) — hence "Sum of Products."

Example. For a 2-input function Y = F(A,B) that is TRUE on rows A′B and AB:

Y = F(A, B) = A′B + AB = Σ(1, 3)

The Σ (sigma) notation is shorthand: instead of writing out every minterm, you just list the row numbers (in decimal) where the output is 1.

Example: Ben Bitdiddle's Picnic

Ben Bitdiddle is having a picnic. He won't enjoy it if it rains or if there are ants. Design a circuit that outputs TRUE only if Ben enjoys the picnic.

Solution. First name the inputs and output:

  • A = TRUE if there are ants, FALSE otherwise.
  • R = TRUE if it rains, FALSE if the sun shines.
  • E = Ben's enjoyment — TRUE if he enjoys the picnic, FALSE if he suffers.

Ben only enjoys the picnic in the one row where there are no ants and it doesn't rain — i.e. A = 0 and R = 0. Writing that row's minterm directly in SOP form:

E = A′R′ = Σ(0)

This is a nice small example of the general principle: when only one row is TRUE, the SOP formula collapses to a single minterm — you don't need a truth table or minimization at all.

Product-of-Sums (POS) Form

POS is the exact mirror image of SOP, built around FALSE rows and maxterms instead of TRUE rows and minterms:

POS construction rule 1. Each row of the truth table has an associated maxterm.
2. A maxterm is a sum (OR) of literals, and is FALSE for that row and only that row.
3. Build the function by AND-ing together every maxterm whose output is FALSE.
Result: a product (AND) of sums (OR terms) — hence "Product of Sums."

Example. For Y = F(A,B) that is FALSE on rows A+B and A′+B:

Y = F(A, B) = (A + B)(A′ + B) = Π(0, 2)

The Π (pi) notation mirrors Σ: list the row numbers (decimal) where the output is 0.

Quick sanity check that trips people up: in SOP you collect the rows that are TRUE; in POS you collect the rows that are FALSE. Mixing these up is the single most common Boolean-equations mistake — always double-check which value (1 or 0) you're indexing on.

You're going to the cafeteria for lunch. You won't eat lunch (E) if it's not open (O), or if they only serve corndogs (C). Build a truth table for E, then write both an SOP and a POS formula.

Logic Minimization Using Boolean Identities

SOP/POS give you a correct formula, straight from the truth table — but not necessarily the smallest one. Before Karnaugh maps existed, the only way to shrink a formula was applying Boolean algebra identities by hand. Here's the worked example from the slides:

Minimizey = a′bc + ab′c′ + abc′ + abc
STEP 1 — group by shared literal, using the distributive law
y = bc(a′ + a) + ac′(b′ + b)

The two terms a′bc and abc both contain "bc", so factor it out — that's exactly what's left after grouping abc′ and abc (both contain "ac′"... actually abc′ contains ac′, and abc pairs with a′bc for the bc-factor). Each pair differs in exactly one literal (a vs a′), which is the signal that they can be merged.

STEP 2 — apply the complement law (x + x′ = 1)
y = bc(1) + ac′(1)
STEP 3 — apply the identity law (x·1 = x)
y = bc + ac′
Minimized resulty = bc + ac′

Four product terms collapsed down to two. This is the exact same function you'll see minimized again — faster and more visually — with a Karnaugh map in K-Map Example 1, so it's worth remembering this result to compare against.

Equivalence Example (Consensus Theorem)

Prove that: bc + ac′ + ab = bc + ac′  (hint given: expand bc + ac′ + ab(c + c′))

STEP 1 — multiply ab by (c + c′), which equals 1, so nothing changes
bc + ac′ + ab(c + c′) = bc + ac′ + abc + abc′
STEP 2 — regroup: abc absorbs into bc, and abc′ absorbs into ac′
(bc + abc) + (ac′ + abc′) = bc(1 + a) + ac′(1 + b)
STEP 3 — apply the null law (1 + x = 1), then the identity law
bc(1) + ac′(1) = bc + ac′ ✓
What this really shows: the term ab in bc + ac′ + ab is entirely redundant — it never contributes a row that isn't already covered by bc or ac′. This is a named identity, the Consensus Theorem: xy + x′z + yz = xy + x′z (here x=c, y=b, z=a). The "consensus term" yz is always safe to drop.

3Karnaugh Maps

Why Use K-Maps?

Take the same function minimized algebraically above:

abcymintermname
0000a′b′c′m0
0010a′b′cm1
0100a′bc′m2
0111a′bcm3
1001ab′c′m4
1010ab′cm5
1101abc′m6
1111abcm7

SOP form: y = a′bc + ab′c′ + abc′ + abc. Minimizing this algebraically required noticing that row 3 combines with row 7, and row 4 combines with row 6 — spotting which implicants can merge takes real effort, and the identity-based route can require unintuitive steps and trial and error. A slightly different truth table for the same three variables, y = bc + ac′ + ab, needs the extra trick of expanding ab into ab(c + c′) just to notice the redundancy — as you just did in the Consensus Theorem practice problem above.

So: minimizing with Boolean identities is important to know, and is useful in some cases — but it doesn't scale well, because there's no systematic procedure telling you which terms to combine next. K-Maps fix exactly this problem.

Karnaugh Map (K-Map): Maurice Karnaugh's 1953 refinement of an original charting idea from 1881. The key idea: arrange minterms so that any two that differ in exactly one literal are placed physically adjacent to each other on a grid — turning "spot the mergeable pair" into "look for adjacent 1s," which your visual system is very good at.

K-Map Structure (Three-Input Function)

For a 3-input function, the map is a 2×4 grid: one variable (a) labels the rows, and the other two (b,c) label the columns — but critically, the columns are not ordered 00, 01, 10, 11. They're ordered in Gray code:

bc=00011110
a=0m0a′b′c′m1a′b′cm3a′bcm2a′bc′
a=1m4ab′c′m5ab′cm7abcm6abc′
  • Each square corresponds to exactly one row of the truth table (one minterm).
  • Because the column order is 00 → 01 → 11 → 10 (Gray code, not binary counting order), any two horizontally or vertically adjacent squares differ in only one literal.
  • Wrap-around: the far-left column (bc=00) and the far-right column (bc=10) are also considered adjacent — the grid wraps around like a cylinder. The same applies top-to-bottom on larger maps.
Why Gray code and not binary order? If columns went 00, 01, 10, 11 (plain binary counting), the squares for bc=01 and bc=10 would sit next to each other on the grid — but they differ in two literals (both b and c flip), breaking the "adjacent squares differ in one literal" property the whole method depends on.

Implicants & Prime Implicants

IMPLICANT (on a K-map)An area made up of squares containing 1s, where the area is square/rectangular (wrap-around allowed) and the number of squares is a power of two (1, 2, 4, 8, …). Each implicant corresponds to one product term.
RULE OF THUMBDouble the area of an implicant → drop exactly one literal from its product term.
PRIME IMPLICANTAn implicant that has the largest possible number of squares while still obeying the rules above — it can't be enlarged any further.
ESSENTIAL PRIME IMPLICANTA prime implicant that contains at least one square not covered by any other prime implicant — meaning it is mandatory, not optional, in any minimal solution.

Converting a map back into a formula: each implicant becomes a product of literals — specifically, the literals that stay constant across every square in that implicant's area (the ones that vary get dropped).

Minimization Procedure

Step-by-step 1. Plot every 1 from the truth table onto the K-map.
2. Find all prime implicants (largest legal groupings of 1s).
3. Identify the essential prime implicants among them — these must be included.
4. Include enough additional prime implicants so that every square containing a 1 is covered.
5. Convert the required implicants into a Boolean formula (OR them together).

The result is a minimal SOP formula — though note it may not be unique: when a non-essential prime implicant could be swapped for a different one that covers the same remaining square, you get two equally-minimal answers (you'll see this happen explicitly in Worked Example 3 below).

Don't Cares

Sometimes certain input combinations are guaranteed never to occur — the physical system that feeds this circuit will simply never present them. 4Combinational Building Blocks

So far every circuit has been built literal-by-literal, gate-by-gate. In practice, combinational logic is usually grouped into larger, reusable building blocks — this is an application of the general principle of abstraction: hiding unnecessary gate-level detail so you can reason about what a block does, not how it's wired inside. The two building blocks covered here are multiplexers and decoders (plus the closely related encoders).

Multiplexers (Mux)

A multiplexer is a digital switch: it selects one of several data inputs and forwards it, unchanged, to a single output, based on the value of one or more select (control) inputs. It's often affectionately shortened to "mux." Multiplexers reduce hardware and simplify circuit design because a single mux can stand in for a whole tree of gates that would otherwise implement the same "choose one of N" behaviour.

2:1 Multiplexer

The simplest mux has two data inputs D0, D1, one select line S, and one output Y. When S=0, Y follows D0; when S=1, Y follows D1:

Two Ways to Implement a 2:1 Mux

1. Logic gates (SOP form) — build Y = S′D0 + SD1 directly with two AND gates, one inverter, and one OR gate, exactly like any other two-level SOP circuit.

2. Tristate buffers — for an N-input mux, use N tristate buffers, one per data input, and turn on exactly one of them (based on the select signal) to connect that input to the shared output wire.

How the tristate mux works: a tristate buffer has three possible output states — 0, 1, and High Impedance (Z), i.e. electrically disconnected. In a tristate mux only one buffer is enabled at a time, so only the selected input actually drives the output; every other buffer outputs Z and stays out of the way. For a 2:1 mux: if S=0, the D0 buffer is enabled (D1's buffer outputs Z) so Y=D0; if S=1, the D1 buffer is enabled (D0's buffer outputs Z) so Y=D1. Because only one buffer ever drives the output at once, there's never a conflict on the shared wire.

Logic Using Multiplexers

A mux isn't just a data-routing switch — it can implement any Boolean function, by using it as a lookup table. The trick: use the function's own inputs as the mux's select lines, and hard-wire each data input to whatever constant (0 or 1) the truth table says the output should be for that combination of select values.

Example: 2-input AND using a 4:1 mux

To implement Y = AB with a 4:1 mux, let A and B drive the two select lines. Then simply wire each data input to the corresponding row of AND's truth table: D0=0 (A=0,B=0), D1=0 (A=0,B=1), D2=0 (A=1,B=0), D3=1 (A=1,B=1). The mux now behaves exactly like the AND gate — no gate-level Boolean minimization needed at all, just read the truth table straight into the mux's data inputs.

Halving the Mux Size: the 2N−1 Trick

You can implement any N-input logic function with a mux half the expected size — a 2N−1-input mux instead of a 2N-input one — by using only N−1 of the inputs as select lines, and feeding the data inputs not just 0s and 1s but also the remaining literal (uncomplemented or complemented) where needed.

Worked example — AND, with the size halved: for Y = AB, use only A as the select line (so we need just a 2:1 mux, not 4:1). Read the truth table conditioned on A:
  • When A = 0: Y = 0 regardless of B.
  • When A = 1: Y = 0 if B = 0, and Y = 1 if B = 1 — i.e. Y = B exactly.
So the reduced lookup table is D0 = 0, D1 = B — a 2:1 mux with select line A, one data input tied to 0, and the other data input tied to the literal B (not a constant).

Worked Example: OR using the halved trick

For Y = A + B, again select on A and look at the two halves of the truth table separately:

Decoders

A decoder is, in a sense, the mirror image of an encoder (covered next): it has N inputs and 2N outputs, and asserts exactly one of its outputs — the one corresponding to the binary value on its inputs. This is called a one-hot output pattern: only one output line is HIGH at any given time, and all others are LOW.

2:4 Decoder example: with 2 inputs there are 2² = 4 possible input combinations, so there are 4 outputs, each one asserted for exactly one of those combinations (e.g. input 10 asserts only output line 2).

Logic Using Decoders

Because each decoder output corresponds to exactly one input combination — i.e. exactly one minterm — decoders combine naturally with OR gates to implement any Boolean function directly from its truth table, with zero minimization required.

Implementing logic functions with decoders 1. An N-input Boolean function needs an N : 2ᴺ decoder.
2. The decoder generates all 2ᴺ possible minterms — one per output line.
3. If the function's truth table has M rows where the output is 1, connect those M corresponding decoder outputs into an M-input OR gate.
General structure: N Inputs → N:2ᴺ Decoder → Selected Minterms → M-input OR Gate → Function Output

Example — two-input XNOR: a 2:4 decoder generates all four minterms of A,B; XNOR is TRUE on exactly two of them (00 and 11), so OR-ing just those two decoder outputs together reproduces XNOR exactly.

Example — full adder: the full adder has 3 inputs (A, B, Cin), so it needs a 3:8 decoder to generate all 8 minterms. Given S = Σ(1, 2, 4, 7) and Cout = Σ(3, 5, 6, 7), you connect decoder outputs m1, m2, m4, m7 to one OR gate for S, and m3, m5, m6, m7 to a second OR gate for Cout — implementing the entire full adder with one decoder and two OR gates, no gate-level minimization at all.

This is exactly the flip side of K-Map minimization: a decoder-plus-OR implementation is the unminimized, one-minterm-per-term circuit — simple and systematic to build, but not the smallest possible circuit. K-Maps exist precisely to shrink circuits below what a raw decoder-and-OR implementation would need.

Encoders

An encoder does the opposite job of a decoder: it converts multiple input signals into a compact binary code. Typically only one input is active at a time, and the encoder outputs the binary index of that active input. With 2n inputs, an encoder needs only n output lines (compare: a decoder needs 2N outputs for N inputs — encoders and decoders are structural inverses of each other).

  • Inputs are usually active high (a high voltage represents "this input is active").
  • Binary-weighted encoders assign codes based on the position of the active input.
  • Encoders are useful for data compression and efficient transmission — converting many parallel wires into a compact binary format.
Four types of encoder covered: (1) the 4-to-2 encoder, (2) the Octal-to-Binary (8-to-3) encoder, (3) the Decimal-to-BCD encoder, and (4) the Priority Encoder (next section) — which solves a problem the first three all share.

4. Priority Encoder

All three encoders above share a hidden assumption: exactly one input is 1 at a time. What happens if two inputs become 1 simultaneously — e.g. Y3Y2Y1Y0 = 0110? An ordinary encoder cannot decide between Y2 and Y1, since both are active. This is exactly the problem a priority encoder solves.

Priority Encoder rule: assign each input a fixed priority — here Y3 has the highest priority and Y0 the lowest. Even if several inputs are 1 simultaneously, the output reflects whichever active input has the highest priority.

5Latches & Flip-Flops

Sequential Circuits

Combinational logic's output depends only on the current inputs — given a truth table or Boolean equation, you can build an optimized circuit that meets the spec, full stop. Sequential logic is different: its outputs depend on both the current input and prior inputs, which means the circuit needs somewhere to keep a record of the past.

  • A sequential circuit is a combinational circuit with storage elements connected via a feedback path.
  • The storage elements hold binary information; the values they currently hold define the state of the circuit at that moment.
  • Outputs are a function of both the external inputs and the present state.
  • The next state is also a function of the external inputs and the present state.

Synchronous vs Asynchronous Sequential Circuits

Sequential circuits split into two families based purely on signal timing:

SynchronousAsynchronous
Behaviour is defined from the signal values only at discrete instants of time (clock edges).Behaviour depends on the input signals at any instant, and on the order in which inputs change.
This distinction resurfaces in full in Section 6 (Synchronous Sequential Logic Circuits) — everything in this section builds the storage elements; Section 6 explains the composition rules that keep circuits built from them well-behaved.

Two memory elements are introduced in this section: the latch and the flip-flop.

Building Memory: Cross-Coupled Inverters

The inverter is the simplest possible logic gate. What happens if you connect its output back to its own input, forming a loop? An inverter loop of just one inverter has no stable state (it would have to equal its own complement) — so a single-inverter loop cannot store a bit.

A loop of two inverters is different. Feed the output of I1 into I2, and the output of I2 back into I1 — this is called cross-coupling. Such a loop settles into one of two stable states, which is exactly what's needed to represent one bit.

Bistable Operation of Cross-Coupled Inverters

Case I — Q = 0
I2 receives Q=0 (FALSE) as input, so it produces a TRUE output on Q′. I1 receives Q′=1 (TRUE) as input, so it produces a FALSE output on Q. This is consistent with the original assumption Q=0 — the case is stable.
Case II — Q = 1
I2 receives a TRUE input and produces a FALSE output on Q′. I1 receives a FALSE input and produces a TRUE output on Q. Again consistent — stable.
BistabilityThe cross-coupled inverters have exactly two stable states, Q=0 and Q=1 — hence "bistable."

The Problem: No Way to Change the Bit

Although cross-coupled inverters can store a bit, they're impractical: there's no input that lets a user control or change the stored state. Suppose the loop currently stores A=0, B=1 — the feedback keeps reinforcing that state forever. To force it to A=1, B=0 you need some external control mechanism that can temporarily override the feedback. Adding exactly that control is how you get from cross-coupled inverters to an SR latch.

Cross-coupled inverters + control inputs = SR latch

SR Latch

One of the simplest sequential circuits is the SR latch, built from two cross-coupled NOR gates instead of two inverters. It behaves like the cross-coupled inverter loop, but now its state can be controlled through two inputs: S (set) and R (reset).

Behaviour

  • When R is asserted (R=1, S=0), the state resets to 0.
  • When S is asserted (S=1, R=0), the state sets to 1.
  • When neither is asserted (S=R=0), the state retains its old value.
Key property: no matter what sequence of sets and resets happened in the past, all you need to predict the SR latch's future behaviour is whether it was most recently set or most recently reset. That's the entire meaning of "state" here — one bit of history is all that matters.

Problems With the SR Latch

Problem 1 — what vs. when are tangled together. S tells the latch what to store (Q=1) but also directly causes the change the instant S becomes 1 — there's no separate signal that says "change now, using whatever S/R currently say." What to store and when to change are mixed into the same two wires.

Problem 2 — the S=R=1 case is invalid. Both "set" and "reset" being asserted simultaneously produces an undefined/invalid result (in the NOR implementation, both outputs Q and Q′ are forced to 0, breaking the assumption that they're always complementary). Designers want a memory element where they never have to separately worry about avoiding this illegal combination.

D Latch

Designing circuits becomes much easier once the questions of what to store and when to change are separated into two dedicated inputs. The D latch does exactly that:

D — the data inputControls WHAT the next state should be
CLK — the clock inputControls WHEN the state should change
  • When CLK = 1, the latch is transparent (open): D flows straight through to Q, as if the latch were just a wire/buffer.
  • When CLK = 0, the latch is opaque (closed): new data is blocked, and Q retains its old value.
Because of this behaviour the D latch is sometimes called a transparent latch or a level-sensitive latch — "level-sensitive" because its behaviour depends on the clock's level (0 or 1), not on the instant it changes. Internally, the circuit that generates S and R from D and CLK guarantees S and R can never both be 1 — this is exactly how the D latch structurally eliminates Problem 2 of the SR latch.

Why Flip-Flops? (Level-Sensitive vs Edge-Triggered)

The D latch still has a problem: it responds to the clock's level, not to a specific instant. While CLK = 1, any change on D can potentially change Q — if D toggles several times during the HIGH period, Q can toggle right along with it. The final state ends up depending on exactly when D happened to change during the active level, which is unpredictable and hard to reason about.

What We Really Want

Instead of "keep looking at D for the entire HIGH period," we want the memory element to look at D only at one particular instant. That instant is called an edge.

Two kinds of clock edge Rising edge (0→1): also called the positive edge or positive-going edge.
Falling edge (1→0): also called the negative edge or negative-going edge.

Worked Example: Traffic Light Controller

A city traffic light controller uses digital storage to decide when to move Green → Yellow → Red.

Using a latch (level-triggered): since the latch is transparent whenever enable is HIGH, any noise or glitch during that active period gets captured immediately — the light could jump straight from Green to Red without passing through Yellow. Not safe for traffic control: continuous input changes during the active level can corrupt the output.
Using a flip-flop (edge-triggered): the light state updates only at the clock's rising (or falling) edge; any glitches occurring between edges are simply ignored until the next edge arrives. This gives controlled, predictable transitions (e.g. every 30 seconds, exactly on the clock edge) — much safer and the standard choice for real sequential control systems (traffic lights, elevators, etc.).

D Flip-Flop

There are two general ways to turn a latch into a flip-flop: (1) chain two latches together in a "master-slave" configuration that isolates the output from changes at the input while the input is changing, or (2) build a circuit that triggers only during a signal transition and is disabled the rest of the time. The D flip-flop uses the master-slave approach.

Master-Slave Construction

A D flip-flop is built from two back-to-back D latches, L1 (the master) and L2 (the slave), driven by complementary clocks, with a node N1 between them:

  • CLK = 0: the master (L1) is transparent, the slave (L2) is opaque. Whatever value is at D propagates through to N1 (but no further, since the slave is closed).
  • CLK = 1: the master goes opaque (locking in whatever was last at N1) and the slave becomes transparent, so N1's value propagates through to Q.

The net effect: whatever value was at D immediately before the clock rises from 0 to 1 gets copied to Q immediately after the rising edge. At all other times Q retains its old value, because there is always at least one opaque latch blocking the D-to-Q path.

D flip-flop behaviourA D flip-flop copies D to Q on the rising edge of the clock, and holds its state at all other times. Q(next) = D, sampled only at the clock edge.

A D flip-flop is also called a master-slave flip-flop, an edge-triggered flip-flop, or a positive edge-triggered flip-flop. In circuit symbols, a small triangle on the clock input denotes an edge-triggered clock.

Characteristic & Excitation Tables

Beyond the master-slave construction, every flip-flop type is fully described by four related representations:

FUNCTION TABLEShows the raw outputs Q and Q′ for given inputs.
CHARACTERISTIC TABLEDefines the next state, Q(n+1), as a function of the current inputs and the current state Qn.
CHARACTERISTIC EQUATIONThe characteristic table's behaviour written algebraically, usually simplified with a K-Map.
EXCITATION TABLEThe mirror image of the characteristic table — given a desired transition Qn → Q(n+1), it tells you what inputs you must supply to make that happen. Used to build state diagrams and for flip-flop conversion.
Easiest way to remember the distinction: the characteristic table describes what the flip-flop DOES given its inputs; the excitation table tells you what you MUST GIVE it to make it do what you want.

General Procedure for Flip-Flop Conversion

Steps 1. Identify the available flip-flop type and the required flip-flop type.
2. Write the characteristic table of the required FF.
3. Write the excitation table of the available FF.
4. Combine the two (side by side, over the same Qn → Q(n+1) transitions) and derive the Boolean expression for the available FF's inputs in terms of the required FF's input(s) and Qn.
5. Draw the resulting circuit: the required FF's input(s) feed combinational logic, whose outputs drive the available FF's actual inputs.

Worked Example: JK → D Conversion (build a D flip-flop from a JK flip-flop)

Available: JK flip-flop. Required: D flip-flop. Since D's characteristic equation is simply Q(n+1) = D, walk through each case:

  • D = 0 ⇒ Q(n+1) = 0. Using the JK excitation table: for (Qn,Q(n+1)) = (0,0), J=0, K=X; for (1,0), J=X, K=1.
  • D = 1 ⇒ Q(n+1) = 1. For (0,1), J=1, K=X; for (1,1), J=X, K=0.
ResultJ = D, K = D′  (matches the "JK as universal FF" table above exactly)

Worked Example: D → JK Conversion (build a JK flip-flop from a D flip-flop)

Available: D flip-flop (D = Q(next) directly). Required: JK flip-flop, whose characteristic equation is Q(n+1) = JQn′ + K′Qn. Since a D flip-flop's next state is whatever value is put on D, simply feed D the JK characteristic equation itself:

ResultD = JQn′ + K′Qn

Build this with combinational logic (an AND-OR network computing JQn′ + K′Qn from J, K, and the flip-flop's own current output Qn) feeding the D input of an ordinary D flip-flop.

Registers, Enabled & Resettable Flip-Flops

Registers

An N-bit register is a bank of N flip-flops sharing a common CLK input, so every bit updates simultaneously. Registers are the key building block of most sequential circuits.

How much can an N-bit register store? Each flip-flop stores 0 or 1 independently, so N flip-flops together can represent 2ᴺ distinct combinations. A 4-bit register, for example, stores values from 0000 to 1111 — 2⁴ = 16 different values. "An N-bit register stores N bits, but can represent 2ᴺ different values."

Enabled Flip-Flop

An enabled flip-flop adds an EN (enable) input to control whether data is loaded on the clock edge at all.

  • EN = TRUE: behaves exactly like an ordinary D flip-flop — Q(next) = D.
  • EN = FALSE: the flip-flop ignores the clock entirely and retains its state — Q(next) = Q.

Two equivalent implementations: (a) an input multiplexer chooses between D (if EN) or the recycled old value Q (if not EN) — the mux output feeds an ordinary D flip-flop; (b) the clock itself is gated — if EN is TRUE the CLK input toggles normally, if EN is FALSE the gated clock stays FALSE and the flip-flop never sees an edge at all.

Timing caution: EN must not change while CLK = 1 — doing so risks the flip-flop seeing a clock glitch (an unintended, incorrectly-timed transition).
Example — EN=1 → LOAD
Q=0, D=1, EN=1. At the clock edge, the new data (1) is loaded: Q(next) = D = 1.
Example — EN=0 → HOLD
Q=1, D=0, EN=0. At the clock edge, the flip-flop is not allowed to load D, so Q(next) = Q = 1 — even though D is 0, D is simply not loaded.

A resettable flip-flop adds a RESET input, which has higher priority than D:

  • RESET = TRUE: ignores D entirely and forces the output to 0. (When RESET=1, D's value is a don't-care — RESET always wins.)

Resettable flip-flops are essential for forcing a system into a known state (all zeros) at power-on. There are two flavours:

Synchronous vs Asynchronous Reset Synchronously resettable: resets only on the next rising edge of CLK.
Asynchronously resettable: resets immediately as soon as RESET becomes TRUE, independent of CLK.

A synchronously-resettable flip-flop can be built from an ordinary D flip-flop plus an AND gate: when RESET′ (active-low) is FALSE, the AND gate forces a 0 into the flip-flop's D input; when RESET′ is TRUE, the AND gate passes D straight through. Asynchronous reset instead requires modifying the flip-flop's internal structure directly. Analogous settable flip-flops exist too — they load a 1 when SET is asserted — and resettable/settable flip-flops may also carry an enable input and be grouped into N-bit registers.

Worked Comparison: Ben Bitdiddle's D Latch vs D Flip-Flop

Ben Bitdiddle applies the same D and CLK waveforms to a D latch and a D flip-flop, and is asked to determine the output Q of each. The general method: for the latch, trace Q as following D continuously throughout every interval where CLK=1, and holding constant whenever CLK=0. For the flip-flop, Q only updates at the instant of each rising edge of CLK, copying whatever D happened to equal right at that edge, and holds constant everywhere else — even while CLK stays HIGH for an extended period. This is the same level-vs-edge distinction from earlier in this section, now applied to a concrete waveform.

6Synchronous Sequential Logic Circuits

Potential Problems With Sequential Logic Circuits

Combinational logic circuits never contain loops or cyclic paths (recall Rule 3 of combinational composition, back in Section 1). Sequential logic circuits, by contrast, are built from feedback loops — and unmanaged loops can cause two distinct kinds of trouble: instability and race conditions.

Astable Circuits — the Ring Oscillator

Alyssa P. Hacker connects three inverters in a loop, output of the third feeding back to the first. Each inverter has a 1 ns propagation delay. What does the circuit do?

Suppose node X starts at 0. Then Y=1, Z=0, which forces X=1 — contradicting the original assumption that X=0. There is no value of X that is self-consistent: the circuit has no stable state at all, and is called unstable or astable.

Timeline (each inverter delay = 1 ns)
If X rises at t=0ns: Y falls at 1ns, Z rises at 2ns, X falls again at 3ns, Y rises at 4ns, Z falls at 5ns, X rises again at 6ns — then the whole pattern repeats.
ResultEach node oscillates between 0 and 1 with a period of 6 ns (2 × number of inverters × delay per inverter). This circuit is called a ring oscillator.

Race Conditions

Ben Bitdiddle designs a "better" D latch using fewer gates. He derives Boolean equations for output Q from a truth table over D, CLK, and the old state Qprev — obtaining Qprev by feeding Q back into the equations. Does his latch work correctly, independent of each gate's delay?

This is an example of asynchronous circuit design, where outputs are directly fed back into inputs. Asynchronous circuits are notorious for race conditions: the circuit's actual behaviour depends on which of two paths through the logic gates happens to be fastest — a property that depends on manufacturing variation and operating conditions, not on the logical design itself. Two circuits meant to be identical can race differently and produce different results, which makes such designs unreliable and very hard to verify.

Sequential circuits contain feedback (cyclic) paths by nature. These paths can cause race conditions and unstable behaviour, and analyzing them directly (gate-delay by gate-delay) is difficult and error-prone. The fix, described next, is architectural rather than case-by-case debugging.

The Fix: Registers Break Cyclic Paths

The solution to both astability and race conditions is the same: insert registers (flip-flops) into every feedback path. Registers store the system's state and update only on the clock edge — this converts the design into ordinary combinational logic plus registers, and eliminates races, because a register's output only ever changes at one well-defined instant rather than continuously chasing the fastest gate path.

Synchronous Sequential Circuit State changes only at the rising edge of the clock.
Uses Current State (present state of the system) and Next State (state after the next clock edge).
If the clock period is slow enough for all combinational signals to settle before the next edge, the circuit operates reliably.
Registers synchronize state changes with the clock, preventing race conditions and ensuring reliable sequential circuit operation. This is the single biggest reason synchronous design dominates real-world digital systems.

Rules of Synchronous Sequential Circuit Composition

Just as Section 1 gave a precise, checkable definition of "combinational," synchronous sequential circuits need one too — because circuits are built by wiring smaller pieces together, and you need a way to tell whether the result is still well-behaved. A circuit is synchronous if all of the following hold:

Rules of synchronous sequential composition 1. Every circuit element is either a Register or Combinational Logic.
2. The circuit contains at least one register.
3. All registers share the same clock signal.
4. Every feedback (cyclic) path contains at least one register.

Sequential circuits that fail to follow these rules are called asynchronous circuits — they're more prone to race conditions and unpredictable behaviour, exactly as illustrated by the ring-oscillator and Ben Bitdiddle examples above.

The flip-flop itself is the simplest possible synchronous sequential circuit: inputs D (data) and CLK (clock), output Q, states {0, 1}. On every clock edge, next state = D, and Q represents the current state. It trivially satisfies all four rules (it is the one register; it has no internal feedback path lacking a register, since it's a single register).
