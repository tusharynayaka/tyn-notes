Sequential Building Blocks: Counters

A combinational circuit has no memory: its outputs depend only on the present inputs. A sequential circuit also remembers something. It stores state in flip-flops and changes that state only at clock edges. Two sequential blocks appear everywhere in digital design: counters, which move through a fixed sequence of binary values, and shift registers, which move bits from one flip-flop to the next.

Binary counters

An N-bit binary counter has a clock, a reset, and an N-bit output Q. Reset forces Q = 0. After reset is released, every active clock edge adds one to the stored value. The counter is simply a resettable register feeding an adder whose second input is 1.

NEXT-STATE EQUATION
Qnext = (Q + 1) mod 2N
Adding 1 to the largest value wraps the counter back to zero. Reset is usually given priority over counting.

An N-bit register can hold 2N distinct patterns, so the counter passes through 2N states, from 0 to 2N − 1, before repeating. A 3-bit counter therefore has 8 states; an 8-bit counter counts from 0 to 255. The least-significant bit toggles on every clock, the next bit on every second clock, and so on: bit i changes at one-half the rate of bit i − 1. This is why a counter also acts as a frequency divider.

000→ 001→ 010→ 011→ 100→ 101→ 110→ 111→ 000
A 3-bit up-counter: 23 = 8 states, then wrap-around.

Asynchronous (ripple) counters

In an asynchronous counter only the first flip-flop receives the external clock. Its output clocks the second flip-flop, that output clocks the third, and so on. The count therefore ripples through the chain instead of changing everywhere at once. Each stage divides the frequency by two, so n flip-flops give a MOD-2n counter: one flip-flop is MOD-2 (output frequency f/2), two are MOD-4 (f/4), three are MOD-8, and four are MOD-16.

Because the later stages wait for the earlier ones, the outputs settle one after another. The accumulated propagation delay limits the maximum clock frequency and can produce brief wrong codes (glitches) while the chain settles. The advantage is extreme simplicity. A decade counter (MOD-10) is a four-bit ripple counter that is cleared as soon as it reaches 10: a NAND gate watches Q3 and Q1 (binary 1010) and drives the clear input low, so the sequence is 0–9 and then 0 again.

A ripple counter can count down as well as up. With a mode input M, the clock fed to each later stage is Y = Q when M = 0 (up-counting) and Y = Q' when M = 1 (down-counting). A small combinational circuit selects the true or complemented output between every pair of flip-flops. The same idea gives a 3-bit up sequence 000→001→…→111 and a down sequence 111→110→…→000.

Synchronous counters

A synchronous counter drives every flip-flop from one common clock. All outputs change in parallel, so there is no cumulative ripple delay and the circuit can run much faster. The price is a little combinational logic that decides, for each flip-flop, whether it should toggle on the next edge.

DESIGN RECIPE

1. Choose the number of flip-flops: n such that 2n ≥ modulus. 2. Write the flip-flop excitation table. 3. Draw the state diagram and the circuit excitation table. 4. Solve for each input with K-maps. 5. Draw the logic diagram. 6. Check unused states return to the intended sequence.

For a T flip-flop, T = 0 holds the state and T = 1 toggles it, so the excitation table is simply T = Qn ⊕ Qn+1. For a JK flip-flop, J = K = 1 toggles, J = K = 0 holds, and the other combinations set or clear. Designing a 3-bit synchronous up-counter with T flip-flops gives:

WHY T AND JK FLIP-FLOPS ARE PREFERRED

A T flip-flop has one input and toggles when it is 1, so it directly divides the clock by two and needs the least logic per counter stage. A JK flip-flop is more flexible—it can set, clear, hold or toggle—and with J = K = 1 it behaves exactly like a T flip-flop. It also removes the invalid state of an SR flip-flop, which is why JK and T devices dominate counter design.

3-BIT SYNCHRONOUS UP-COUNTER (T FLIP-FLOPS)
T0 = 1     T1 = Q0     T2 = Q1Q0
The lowest bit toggles every cycle; each higher bit toggles only when all lower bits are 1 (a carry).

With JK flip-flops the same 3-bit counter uses J0 = K0 = 1, J1 = K1 = Q0, and J2 = K2 = Q1Q0. A 2-bit synchronous up-counter with JK flip-flops reduces to J0 = K0 = 1 and J1 = K1 = Q0. This carry-chain structure is exactly how binary incrementers are built.

Ring and Johnson counters

A ring counter is a shift register whose last output feeds the first input. It is initialized with a single 1, and that 1 circulates: 1000 → 0100 → 0010 → 0001 → 1000. With n flip-flops there are exactly n valid states, so it is a MOD-n counter. Each state is already one-hot, so no decoder is needed. The all-zero state is invalid and the counter would stay stuck there, so a preset/override input is used to inject the initial 1.

A Johnson counter (twisted-ring or switch-tail counter) feeds back the complement of the last output. The inversion doubles the number of states: n flip-flops give 2n states. Starting from 0000, a 4-bit Johnson counter runs:

0000→ 1000→ 1100→ 1110→ 1111→ 0111→ 0011→ 0001→ 0000
4-bit Johnson counter: 2 × 4 = 8 states, then repeat.

Shift Registers

A shift register is a chain of flip-flops sharing one clock. On every active edge a new bit enters at the serial input Sin, every stored bit moves one position toward the output, and the oldest bit leaves at Sout. After N clocks, N serial bits have been assembled into one N-bit word on the parallel outputs Q0…QN−1. The block therefore performs serial-to-parallel conversion; run in reverse it performs parallel-to-serial conversion.

Sin→ FF0→ FF1→ FF2→ …→ FFN−1→ Sout
All flip-flops share CLK; Q0…QN−1 are available in parallel.

Parallel load

A plain shift register can only shift. Adding a parallel data input DN−1:0 and a control signal Load turns it into a general-purpose register. A multiplexer in front of each flip-flop chooses between the shifted bit and the corresponding parallel data bit. When Load = 1 the whole word is captured in one clock; when Load = 0 the register shifts normally. Reset has the highest priority.

always @(posedge clk or posedge rst)
  if (rst)          q <= 0;
  else if (load)    q <= data_in;        // parallel load
  else              q <= {q[N-2:0], sin}; // shift in sin

assign sout = q[N-1];

The concatenation {q[N-2:0], sin} drops the oldest bit, moves every remaining bit one place toward the high end, and inserts sin at the bottom. sout is simply the top bit. Shift registers are used for serial communication, serial/parallel conversion, delay lines, pattern generation, and—combined with feedback—the ring and Johnson counters above.

Scan Chains and Testability

Why sequential circuits need special testing

Testing a combinational circuit is straightforward: apply an input and compare the output with the truth table. A sequential circuit is different because its output depends on the internal state reached after many cycles. To prove that bit 31 of a 32-bit counter really flips from 0 to 1, the naive approach is to reset the counter and apply about two billion clock pulses. It is also impractical to bring out a separate test pin for every flip-flop.

The solution is a scan chain. Every flip-flop is replaced by a scannable flip-flop containing a multiplexer that selects either the normal D input or a scan input Sin. In normal mode the flip-flops behave exactly as before and the scan path is ignored. In test mode all flip-flops are connected into one long shift register: an arbitrary state can be shifted in, the circuit is clocked normally for one or more cycles, and the resulting state is shifted out and inspected.

SCAN-CHAIN TEST OF A 32-BIT COUNTER

Shift in the pattern 0111…111 (32 cycles) → switch to normal mode and allow one count (1 cycle) → shift the new state out (32 cycles) and check for 1000…000. Total = 32 + 1 + 32 = 65 cycles instead of roughly 231 cycles. The same mechanism gives controllability and observability of every internal state bit.

Memory Arrays: Organization and Operation

A memory array stores many words in a two-dimensional grid of one-bit bit cells. Rows are words and columns are bit positions. An N-bit address selects one of 2N rows; each row contains M data bits. A decoder converts the address into a single active wordline, and the vertical bitlines carry data into or out of the selected cells.

MEMORY SIZE
Size = depth × width = 2N × M bits
Depth = number of words (addresses); width = bits per word. Address bits N = log2(depth).

For example, 10 address bits and 32 data bits give 210 = 1024 words of 32 bits, or 1024 × 32 = 32 Kb (4 KB). The total number of stored bits is always the product of depth and width, not the sum.

Address→ Decoder→ one wordline HIGH→ selected row of cells→ bitlines / data
Only the row whose wordline is asserted participates in the access.

Reading and writing a bit cell

A read is non-destructive in the logical sense: the bitlines are first left floating (high impedance, Z), the wordline is turned on, and the selected cell drives each bitline to 0 or 1. The values on the bitlines are the word. A write is the reverse: the bitlines are driven strongly to the desired values, the wordline is turned on, and the strong bitline signal overpowers the cell's stored value. In DRAM the read actually disturbs the capacitor, so the value must be restored afterwards.

Consider a 4 × 3 memory (four words, three bits each, two address bits). Reading address 10 asserts wordline 2; if that row stores 100, the data bitlines show 100. Writing 001 to address 11 drives the data lines to 001, asserts wordline 3, and stores the word in row 3. The same array has 4 × 3 = 12 bit cells.

Ports and register files

A port is an independent access point with its own address and data. A single-ported memory can perform one access per cycle; a multi-ported memory can perform several. A processor's register file is a small, fast, multi-ported SRAM: the classic MIPS register file has two read ports and one write port, so two source registers can be read while a destination register is written in the same cycle.

32 × 32 REGISTER FILE

32 registers × 32 bits = 1024 bits. Each address is log232 = 5 bits. Ports: A1→RD1, A2→RD2 (read); A3/WD3 (write, clocked).

WHY NOT FLIP-FLOPS?

A register file built from a multi-ported SRAM array is far more compact than 32 separate 32-bit flip-flop registers with multiplexers, and it scales better as the number of registers grows.

RAM: DRAM and SRAM

Memory is first divided into RAM (random-access memory, normally volatile and read/write) and ROM (read-only memory, nonvolatile). Both allow random access—any location can be reached in roughly the same time—but they store a bit in very different ways.

Dynamic RAM (DRAM)

A DRAM cell stores one bit as charge on a capacitor. A charged capacitor represents 1 and a discharged capacitor represents 0. The cell needs only about one transistor, so DRAM is extremely dense and cheap per bit. The charge leaks away, however, so every row must be refreshed periodically. A read moves charge from the capacitor onto the bitline, which disturbs the stored value, so the value must be sensed and written back. Sensing a small charge through a relatively long bitline is slow, which is why DRAM has higher latency and lower throughput than SRAM.

Static RAM (SRAM)

An SRAM cell stores a bit with cross-coupled inverters. The two inverters continuously reinforce each other: if Q is 1, the feedback holds Q at 1 and Q' at 0; if Q is 0, the feedback holds the opposite. As long as power is applied, no refresh is needed—hence “static.” A typical SRAM cell uses six transistors, so it is larger than DRAM but faster and simpler to use. A flip-flop is even larger (roughly 20 transistors per bit) but presents its value immediately at an output.

Improving DRAM throughput

SDRAM (synchronous DRAM) adds a clock and pipelines accesses, so the memory can accept a new request before the previous one has fully completed. DDR SDRAM (double data rate) transfers data on both the rising and falling edges of the clock, roughly doubling throughput at the same clock frequency. DDR was standardized around 2000 at 100–200 MHz; DDR2, DDR3 and DDR4 subsequently raised clock rates. None of these changes remove the fundamental capacitor-refresh cost—they improve how efficiently the interface is used.

More transistors per bit means more area, more power and higher cost, but also faster access. Larger memories are generally slower than smaller memories built from the same technology. A good design chooses the smallest, fastest memory that fits the required capacity and access pattern.

Read-Only Memory (ROM)

A ROM stores a bit by the presence or absence of a transistor at the intersection of a wordline and a bitline. The bitline is weakly pulled high; when the wordline turns on a transistor, the transistor pulls the bitline low, storing 0. If no transistor is present, the bitline stays high, storing 1. Because the cell is a combinational connection rather than a stored charge or feedback loop, ROM is nonvolatile: removing power does not erase it.

Dot notation

ROM contents are drawn as a grid. Rows are wordlines (addresses), columns are bitlines (data bits), a dot at an intersection means a stored 1, and the absence of a dot means 0. A 4 × 3 ROM has 22 = 4 words of 3 bits, or 12 stored bits. If the top row has a dot only in the Data1 column, that word is 010.

A PROM starts with all transistors present (all fuses intact). Programming applies a high voltage to blow selected fuses, disconnecting those transistors and changing the stored bit. A blown fuse cannot be repaired, so PROM is one-time programmable. An EPROM uses a floating-gate transistor: a high voltage places charge on the floating gate, and intense UV light removes it. EEPROM can be erased electrically, cell by cell. Flash is similar but erases whole blocks, which needs fewer erase circuits and makes it cheaper than EEPROM.

Memory Arrays as Logic and Lookup Tables

A memory is normally thought of as storage, but a 2N-word × M-bit memory can also implement any combinational function of N inputs with M outputs. The N inputs are the address, each input combination selects one row, and the M bits stored in that row are the outputs. The memory contents are literally the truth table of the function.

LOOKUP TABLE (LUT) SIZE
LUT size = 2N × M bits
N = number of inputs (address bits); M = number of outputs (data bits).

A ROM viewed as logic is a two-level circuit: the row decoder is a set of AND gates that generate all minterms, and the bitline connections are OR gates that combine the selected minterms into each output. Real ROMs replace the gates with transistors to save area. This is the same structure used in programmable logic: a memory array used to evaluate logic is called a lookup table (LUT).

Worked example: Y = AB

Two inputs need 22 = 4 rows and one output needs one bit, so a 4 × 1 memory is enough. Store the truth table in address order:

ABAddressY = AB
00000
01010
10100
11111

The LUT simply stores 0, 0, 0, 1. Applying A and B as an address selects the row and returns the function value. The same idea generalizes: a 4 × 3 ROM implements three functions of two inputs; a 2N × M ROM implements M functions of N inputs. This is exactly how FPGAs implement arbitrary logic—small LUTs loaded with a truth table.

Memory HDL

A synchronous memory is described by a clocked write and a read that may be combinational or registered. The essential behavior is: on a clock edge with write enable, store the data at the address; otherwise, drive the read data from the addressed word.

// synchronous write, asynchronous read
always @(posedge clk)
  if (we) mem[addr] <= wd;

assign rd = mem[addr];

In a processor, the instruction and data memories are often modeled this way. The read path determines the memory latency; the write path determines the setup requirement. When the same memory serves both instructions and data (a von Neumann organization), the designer must either use a single port carefully or provide separate instruction/data ports to avoid a structural conflict.

Introduction to Computer Architecture

Computer architecture is the programmer's view of a computer. It is the contract between software and hardware: which instructions exist, what they mean, where operands live, how many registers there are, how data is represented, and how instructions are encoded. The concrete realization of that contract in gates, memories and control logic is the microarchitecture. One architecture can have many microarchitectures—for example, several generations of x86 chips with very different internal pipelines all execute the same x86 instruction set.

ARCHITECTURAL STATE

The state a program can observe: the program counter (PC), the 32 registers, and memory. The ISA defines the instruction formats, register set, data types, addressing modes and memory model; the microarchitecture decides how those state elements are built and sequenced.

The instruction set architecture (ISA) includes the instruction formats, the register set, the data types, the addressing modes, and the memory model. Well-known ISAs include x86, MIPS, ARM, SPARC and PowerPC. Instruction sets are like dialects: once one is learned, another is mostly a change of vocabulary. Even large applications ultimately compile into simple operations such as add, subtract, load, store, compare and jump.

MIPS

MIPS stands for Microprocessor without Interlocked Pipeline Stages. It is a family of reduced instruction set computer (RISC) instruction set architectures developed by John Hennessy and colleagues at Stanford in the 1980s and commercialized by MIPS Computer Systems (later MIPS Technologies). MIPS powered Silicon Graphics workstations and appeared in Nintendo and Cisco products. It is an excellent teaching architecture because its instruction formats are regular, its register file is uniform, and its load/store model is clean.

MIPS is a 32-bit architecture: registers are 32 bits wide, the ALU operates on 32-bit values, addresses are 32 bits, and instructions are 32 bits. It provides 32 general-purpose registers. Keeping the register file small is deliberate: a smaller structure has shorter wires and lower access latency.

Four Design Principles

Computer architectures are shaped by a small set of principles that trade performance against simplicity, cost and power. Every one of them appears in MIPS.

1. Simplicity favors regularity

Uniform instruction formats make decoding simple, fast and reliable. Most MIPS arithmetic instructions use exactly the same shape: two source registers and one destination register, as in add $s0, $s1, $s2 and sub $t0, $t1, $t2. Because the fields are always in the same place, the hardware does not need a complicated decoder that varies with the instruction. Regularity also makes it easier to test and optimize the design.

2. Make the common case fast

Performance is dominated by the operations that execute most often. MIPS keeps a small set of simple, frequently used instructions that decode and execute quickly. Complex operations are synthesized from several simple instructions instead of being implemented as one slow instruction. This is the RISC philosophy: move complexity into the compiler, where it can be optimized once, rather than into the hardware, where it slows every instruction.

3. Smaller is faster

Smaller hardware structures have shorter wires, lower capacitance and lower access time. That is why MIPS has 32 registers rather than hundreds, and why a register file is faster than main memory. The compiler's job is to keep the hottest variables in registers and spill the rest to memory. A larger register file would reduce spills but would also increase access latency and area.

4. Good design demands good compromises

Performance, cost, power and complexity pull in different directions. A deeper pipeline raises clock frequency but adds hazard and forwarding complexity; a bigger cache reduces misses but costs area and power; a richer instruction set reduces program size but complicates decode. A good architecture chooses the balance that is best for its intended workload rather than maximizing a single number.

EXAMPLE: ENCODING COST

An instruction set with 64 simple instructions needs log264 = 6 bits to encode the operation; 256 instructions need log2256 = 8 bits. In a CISC machine, rarely used complex instructions still consume encoding space and decoder complexity that affects every instruction.

RISC versus CISC

RISC (reduced instruction set computer) keeps instructions simple, fixed-length and register-oriented. CISC (complex instruction set computer) provides many powerful, variable-length instructions that may combine several operations, including memory access. MIPS, ARM and RISC-V are RISC; Intel x86 and VAX are CISC.

The useful takeaway is the trade-off: RISC spends instruction bits and program size to buy regular, fast hardware; CISC spends hardware complexity to buy compact programs.

Assembly Language: Instructions and Operands

An instruction is a command in the computer's language. Assembly language is its human-readable form; machine language is the binary form the processor actually executes. A typical assembly statement has a mnemonic (the operation), one destination, and one or more sources:

add a, b, c      # a = b + c
sub a, b, c      # a = b - c

In MIPS the destination is written first, then the sources. The mnemonic names the operation; the operands say where the data comes from and where the result goes. A complete program is just a sequence of such instructions plus labels that mark branch targets.

Instructions can use operands in exactly three places: registers (fast storage inside the CPU), memory (large storage outside the CPU), and constants encoded directly in the instruction (immediates). MIPS is a load/store architecture: arithmetic instructions only touch registers, and only lw/sw move data between registers and memory.

TRANSLATING HIGH-LEVEL CODE (EXAMPLE 6.1)

Assume a–c are in $s0–$s2 and f–j are in $s3–$s7. Translate a = b − c; and f = (g + h) − (i + j);

sub $s0, $s1, $s2        # a = b - c
add $t0, $s3, $s4        # t0 = g + h
add $t1, $s5, $s6        # t1 = i + j
sub $s7, $t0, $t1        # f = t0 - t1

Note how a single high-level expression becomes several simple instructions. This is the RISC bargain: the compiler breaks complex operations into a regular sequence that the hardware can decode and pipeline efficiently. A left shift by three, for example, can be done with three adds (add t, s, s doubles, repeated three times multiplies by 8) even before shift instructions are introduced.

The MIPS Register File

MIPS provides 32 general-purpose registers, each 32 bits wide. Because 25 = 32, every register is named by a 5-bit number in an instruction. The names are conventions agreed by programmers and compilers; the hardware only sees register numbers, but the conventions make separate compilation and function calls possible.

The register file is written by the instruction on a clock edge and read combinationally. Register 0 is special: it always reads as zero and cannot be changed, which gives the assembler a convenient source of zero and a way to turn an operation into a copy or a comparison. For example, sub $t8, $s1, $0 copies $s1 into $t8.

The split between preserved ($s0–$s7, $ra, $sp) and nonpreserved ($t0–$t9, $a0–$a3, $v0–$v1) registers is the key to independent functions. A callee may freely overwrite temporaries and argument registers, but if it uses a saved register it must save the old value on the stack and restore it before returning.

Memory Operands, Byte Addressing and Endianness

Thirty-two registers cannot hold a whole program, so larger data lives in memory. MIPS uses a byte-addressable memory with 32-bit addresses: every byte has its own address, and 232 addresses cover 4 GB. A 32-bit word occupies four consecutive byte addresses, so aligned word addresses are always multiples of 4 (0, 4, 8, 12, …).

EFFECTIVE ADDRESS (LOAD/STORE)
EA = Base register + Sign-extended offset
The 16-bit offset in lw/sw is measured in bytes and may be positive or negative.

Data moves with load word and store word:

lw $s3, 4($0)     # $s3 = Memory[0 + 4]; reads bytes 4,5,6,7
sw $t4, 0x7($0)   # Memory[0 + 7] = $t4

A word-addressable memory would give each whole word one address, so address 2 would mean the third word. MIPS instead gives every byte an address, so word i starts at byte 4i. For an integer array with base address Base, element i is at Base + 4i; for a character array it is at Base + i.

Big-endian and little-endian

Within a 32-bit word, the bytes can be numbered from either end. Big-endian puts the most-significant byte at the lowest address; little-endian puts the least-significant byte there. The word address is the same either way; only the byte order differs.

WORKED EXAMPLE

Let $t0 = 0x23456789, then execute sw $t0, 0($0) and lb $s0, 1($0).

Big-endian layout: 23 45 67 89 at addresses 0–3 → byte 1 is 0x45, so $s0 = 0x00000045.
Little-endian layout: 89 67 45 23 at addresses 0–3 → byte 1 is 0x67, so $s0 = 0x00000067.

Endianness is invisible until data is shared between machines or inspected byte by byte. MIPS itself is bi-endian: a particular implementation can be configured either way, but a program must know which convention the system uses. The byte load lb sign-extends the loaded byte; lbu zero-extends it; sb stores only the low byte of a register.

Constants and Immediate Operands

Many operations use a small constant: incrementing a loop counter, adding an offset, masking a field. Fetching that constant from memory would be wasteful, so MIPS encodes it directly in the instruction. The I-type immediate field is 16 bits, interpreted as a signed two's-complement number for arithmetic and memory instructions.

addi $s0, $s0, 4       # a = a + 4
addi $s1, $s0, -12     # b = a - 12
andi $s2, $s1, 0xFA34  # bitwise AND with a zero-extended constant
ori  $s3, $s1, 0xFA34  # bitwise OR
xori $s4, $s1, 0xFA34  # bitwise XOR

There is no subi instruction: subtracting a constant is the same as adding its negative, so addi $s1, $s0, -12 implements b = a − 12. This is another example of regularity—one instruction covers both addition and subtraction of constants.

Sign extension versus zero extension

Arithmetic and memory instructions (addi, lw, sw, branches) sign-extend the 16-bit field: bit 15 is copied into the upper 16 bits, so a negative offset stays negative. Logical immediates (andi, ori, xori) zero-extend the field, because a logical operation should not turn a bit pattern into a negative number. This distinction is a common source of exam errors.

SIGN EXTENSION
imm31:16 = imm15   (copy the sign bit 16 times)
0x8000 (−32768) sign-extends to 0xFFFF8000; the same 16 bits zero-extend to 0x00008000.

Building a 32-bit constant

A single 16-bit immediate cannot hold a 32-bit constant. MIPS uses load upper immediate followed by or immediate. lui places the upper 16 bits in the top half of the register and clears the lower half; ori inserts the lower 16 bits.

# int a = 0x6D5E4F3C;
lui $s0, 0x6D5E      # $s0 = 0x6D5E0000
ori $s0, $s0, 0x4F3C # $s0 = 0x6D5E4F3C

The same pair of instructions can form any 32-bit constant (or address). Compilers use it constantly when materializing large addresses and constants.

Encoding Instructions into Machine Code

Encoding is mechanical once the fields are known: write each field in binary, concatenate them into 32 bits, then group the result into four-bit hexadecimal digits. Two worked examples cover the two most important formats.

Example 1: add $t0, $s4, $s5

The registers are $t0 = 8, $s4 = 20, $s5 = 21. The instruction is R-type (op = 0) with funct = 32, shamt = 0. Assembly places the destination first, so rd = 8, rs = 20, rt = 21.

ENCODING CHECKLIST

1. Identify the format from the mnemonic. 2. Look up the opcode (and funct for R-type). 3. Convert register names to numbers. 4. Convert the immediate to 16-bit two's complement (or the jump target to 26 bits). 5. Place fields in the correct order. 6. Group bits by four and write hexadecimal.

Decoding Machine Code

Decoding reverses the process. Because every format begins with a 6-bit opcode, the opcode is always the first thing to inspect. If it is zero, the instruction is R-type and the funct field selects the operation. Otherwise the opcode itself identifies an I-type or J-type instruction, and the remaining fields are interpreted accordingly.

1. Read the opcode. 2. If opcode = 0, treat the instruction as R-type and read funct. 3. Otherwise use the opcode to identify the instruction and format. 4. Convert register numbers to names. 5. Interpret the immediate as signed or unsigned according to the instruction. 6. Write the assembly statement.

The Stored-Program Concept and the Program Counter

A stored-program computer keeps both instructions and data in the same memory. Each instruction occupies a unique address, and the processor fetches and executes instructions one after another. This is the idea that separates a general-purpose computer from a fixed-function machine: changing the program means changing memory contents, not rewiring the hardware.

The program counter (PC) holds the address of the next instruction to execute. After a normal instruction is fetched, the PC advances by 4 bytes because every MIPS instruction is 32 bits. Branch and jump instructions write a different value into the PC, redirecting execution. At the hardware level the PC is just a 32-bit register whose next value is selected by a multiplexer.

RepresentationExampleReadable by
High-level languagea = b + c;Humans, compiler

Machine language0x02324020Processor

The three representations are successive translations of the same program. The processor executes only the binary form, but the binary form is just a structured encoding of the assembly statement, and the assembly statement is a structured encoding of the high-level operation.

Arithmetic, Logical and Shift Instructions

High-level constructs are built from a small set of arithmetic and logical instructions. Most operate on two register values and write a third; immediate versions replace one source with a 16-bit constant.

add  $t0, $s1, $s2     # $t0 = $s1 + $s2
sub  $t0, $t3, $t5     # $t0 = $t3 - $t5
addi $t0, $s3, -12     # $t0 = $s3 - 12

Bitwise logic

MIPS provides AND, OR, XOR and NOR on registers, plus immediate versions of AND, OR and XOR. They operate bit by bit. AND is useful for masking (forcing selected bits to zero), OR for combining fields, XOR for comparing bits or toggling, and NOR for inversion. There is no separate NOT instruction: nor rd, rs, $0 computes NOT rs.

WORKED BITWISE EXAMPLE

Let $s1 = 0xFFFF0000 and $s2 = 0x46A1F0B7.

and $s3, $s1, $s2   # 0x46A10000
or  $s4, $s1, $s2   # 0xFFFFF0B7
xor $s5, $s1, $s2   # 0xB95EF0B7
nor $s6, $s1, $s2   # 0x00000F48

Immediate logical instructions zero-extend the 16-bit constant before operating. If $s1 = 0x000000FF and the immediate is 0xFA34, then andi gives 0x00000034, ori gives 0x0000FAFF, and xori gives 0x0000FACB. There is no nori because ori followed by nor with $0 produces the same result in two instructions; adding a dedicated instruction would complicate the decoder for little benefit.

Shifts

Shifts move bits within a register by up to 31 positions. sll shifts left and fills with zeros; srl shifts right and fills with zeros; sra shifts right and replicates the sign bit. A left shift by N multiplies by 2N; an arithmetic right shift by N divides by 2N with sign preservation. The shift amount can be a constant in shamt or a register value: sllv rd, rt, rs, srlv and srav take the shift amount from the low five bits of rs.

Variable shifts look as if rs and rt are reversed. In sllv rd, rt, rs the value being shifted is rt and the shift count is rs, because the format keeps the shifted data in the rt field and uses the rs field for the second source. The assembler syntax follows that encoding, so the count is written last even though it is logically the second operand.

SHIFT AS MULTIPLY / DIVIDE
x << N = x × 2N     x >> N (arithmetic) = x ÷ 2N
Compilers replace multiplication and division by powers of two with shifts because a shift is a single fast operation.

Multiplication and division

Multiplying two 32-bit numbers produces a 64-bit product, and dividing produces a quotient and a remainder. MIPS keeps these extra results in two special registers: HI and LO. For mult, HI:LO holds the 64-bit product. For div, LO holds the quotient and HI holds the remainder. The results move to general registers with mflo and mfhi.

# $s0 = 20, $s1 = 6
div  $s0, $s1
mflo $t0          # $t0 = 3  (quotient)
mfhi $t1          # $t1 = 2  (remainder)

mult $s0, $s1
mflo $t0          # low 32 bits of the product
mfhi $t1          # high 32 bits of the product

mul  $s1, $s2, $s3  # 32-bit product directly in a general register

Worked numerical

Let $s0 = 0x0000000F (15) and $s1 = 0xFFFFFFF1 (−15). Then mult $s0, $s1 produces −225. In 64-bit two's complement, −225 = 0xFFFFFFFFFFFFFF1F, so mfhi returns 0xFFFFFFFF and mflo returns 0xFFFFFF1F. For div $s0, $s1, 15 ÷ (−15) gives quotient −1 (0xFFFFFFFF in LO) and remainder 0 (in HI). Division truncates toward zero; the sign of the remainder follows the dividend, which is why reading HI and LO separately matters.

Branching and Conditional Statements

By default the PC advances by four bytes. A branch changes that flow. Conditional branches test registers; unconditional branches always transfer control. MIPS provides beq (branch if equal) and bne (branch if not equal) for conditional transfer, and j, jr and jal for unconditional transfer.

InstructionMeaningTypical use
beq rs, rt, labelPC = label if rs == rtExit a loop, take an if-branch
bne rs, rt, labelPC = label if rs != rtSkip a block when the condition is false

A label names an instruction address. It ends with a colon and is resolved by the assembler. Assembly programmers usually test the opposite of the high-level condition so that the branch skips the block when the block should not run.

if and if/else

# if (i == j) f = g + h;
bne $s3, $s4, L1     # if i != j, skip the body
add $s0, $s1, $s2    # f = g + h
L1: ...

# if (i == j) f = g + h; else f = f - i;
bne $s3, $s4, L1
add $s0, $s1, $s2
j done
L1: sub $s0, $s0, $s3
done: ...

The j done is essential: without it, execution would fall through into the else block after completing the if block. A switch/case is implemented as a chain of comparisons—equivalent to nested if/else—with a final default case when no match occurs.

switch/case

A switch compares one value against several constants and runs the matching block. The compiler emits one comparison and branch per case, and a final jump to default when nothing matches. Because the cases are independent, each block must end with a jump past the remaining comparisons.

# switch (k) { case 0: f = f + 1; break; case 1: f = f - 1; break; default: f = 0; }
# assume k = $s3, f = $s0
      addi $t0, $0, 0        # t0 = 0
      beq  $s3, $t0, C0      # k == 0?
      addi $t0, $0, 1        # t0 = 1
      beq  $s3, $t0, C1      # k == 1?
      add  $s0, $0, $0       # default: f = 0
      j    done
C0:   addi $s0, $s0, 1      # f = f + 1
      j    done
C1:   addi $s0, $s0, -1     # f = f - 1
done:

Loops

A loop repeats a block while a condition holds. In assembly there is no loop instruction; the compiler emits a condition test, a conditional exit, the body, an update, and an unconditional jump back to the test.

while loop

# while (pow != 128) { pow = pow * 2; x = x + 1; }
while: beq  $s0, $t0, done   # exit when pow == 128
       sll  $s0, $s0, 1      # pow = pow * 2
       addi $s1, $s1, 1      # x = x + 1
       j    while
done:

The original condition is pow != 128, but the branch tests pow == 128 to decide when to leave. Testing the exit condition directly avoids an extra jump inside the body.

for loop

# for (i = 0; i != 10; i++) sum = sum + i;
      addi $s1, $0, 0     # sum = 0
      add  $s0, $0, $0    # i = 0
      addi $t0, $0, 10    # limit = 10
for:  beq  $s0, $t0, done
      add  $s1, $s1, $s0
      addi $s0, $s0, 1
      j    for
done:

Magnitude comparisons with slt

beq and bne only test equality. For “less than” and “greater than” conditions, MIPS provides set less than: slt rd, rs, rt writes 1 if rs < rt and 0 otherwise. The result can then be tested with beq or bne.

$s0 = 5, $s1 = 8
slt $t1, $s0, $s1     # $t1 = 1 because 5 < 8

# for (i = 1; i < 101; i = i * 2) sum = sum + i;
      addi $s1, $0, 0      # sum = 0
      addi $s0, $0, 1      # i = 1
      addi $t0, $0, 101    # limit = 101
loop: slt  $t1, $s0, $t0   # $t1 = (i < 101)
      beq  $t1, $0, done   # exit if i >= 101
      add  $s1, $s1, $s0   # sum += i
      sll  $s0, $s0, 1     # i = i * 2
      j    loop
done:

The values added are 1 + 2 + 4 + 8 + 16 + 32 + 64 = 127, so sum = 127 at the end. The slt instruction turns a magnitude comparison into a 0/1 value that a branch can consume, which is exactly how “less than”, “greater than or equal”, and similar conditions are synthesized.

Arrays and Character Data

An array stores elements of the same type in consecutive memory locations. Element 0 is at the base address; element i is offset by the element size. For 32-bit integers the offset is 4i; for characters it is i.

ARRAY ADDRESSING
int array:   address(i) = Base + 4i
char array:   address(i) = Base + i
The base address is held in a register; the index is scaled by the element size and added.

For a small array the offsets can be written directly. If $s0 = 0x10007000 is the base, then lw $t1, 4($s0) loads array[1] and sw $t1, 8($s0) stores array[2]. For a large array, the index must be scaled at run time:

# for (i = 0; i < 1000; i++) array[i] = array[i] * 8;
      sll $t0, $s1, 2      # t0 = i * 4 (byte offset)
      add $t0, $t0, $s0    # t0 = &array[i]
      lw  $t1, 0($t0)      # t1 = array[i]
      sll $t1, $t1, 3      # t1 = array[i] * 8
      sw  $t1, 0($t0)      # array[i] = t1

The shift sll $t0, $s1, 2 multiplies by four because each integer occupies four bytes. This is why the base-plus-offset addressing mode is so useful: one base register can reach every element by changing the offset.

Byte arrays and characters

Characters use one byte each. MIPS provides lb (load byte, sign-extended), lbu (load byte, zero-extended) and sb (store byte). The following loop converts a lowercase character array to uppercase by subtracting 32 (0x20), because ASCII 'a' is 0x61 and 'A' is 0x41.

# char chararray[10]; for (i=0; i!=10; i++) chararray[i] -= 32;
      addi $s1, $0, 0      # i = 0
      addi $t0, $0, 10     # limit = 10
loop: beq  $t0, $s1, done
      add  $t1, $s1, $s0   # address = base + i (1 byte each)
      lb   $t2, 0($t1)
      addi $t2, $t2, -32   # lowercase -> uppercase
      sb   $t2, 0($t1)
      addi $s1, $s1, 1
      j    loop
done:

Functions, the Stack and Register Preservation

A function makes code reusable. The caller and callee follow a convention so that independently compiled code can cooperate: arguments go in $a0–$a3, the return value comes back in $v0–$v1, the call uses jal, and the return uses jr $ra. jal stores the address of the following instruction (PC + 4) in $ra before jumping.

CALL AND RETURN

If jal simple is at 0x00400200, the next instruction is at 0x00400204, so $ra = 0x00400204. The callee finishes with jr $ra, which writes that address into the PC.

Example: diffofsums

int diffofsums(int f, int g, int h, int i) {
    return (f + g) - (h + i);
}

# caller
addi $a0, $0, 2
addi $a1, $0, 3
addi $a2, $0, 4
addi $a3, $0, 5
jal  diffofsums
add  $s0, $v0, $0

# callee
add $t0, $a0, $a1
add $t1, $a2, $a3
sub $s0, $t0, $t1
add $v0, $s0, $0
jr  $ra

The computation is (2 + 3) − (4 + 5) = 5 − 9 = −4, so $v0 = −4 on return.

The stack and stack frames

The stack is a LIFO region of memory used for saved registers, local variables, and arguments that do not fit in the four argument registers. The MIPS stack grows toward lower addresses. $sp points to the top, so allocating space means subtracting from $sp.

If $sp = 0x7FFFFFFC and a function needs two words, addi $sp, $sp, -8 makes $sp = 0x7FFFFFF4. The area a function allocates is its stack frame. The standard sequence is: allocate space, save registers, execute, restore registers, deallocate.

addi $sp, $sp, -12    # 3 words = 12 bytes
sw   $s0, 8($sp)
sw   $t0, 4($sp)
sw   $t1, 0($sp)
# ... function body ...
lw   $t1, 0($sp)
lw   $t0, 4($sp)
lw   $s0, 8($sp)
addi $sp, $sp, 12
jr   $ra

Only preserved registers ($s0–$s7, $ra, $sp) must be saved if the callee changes them. Temporaries, argument registers and value registers are nonpreserved: the callee may overwrite them freely. In the optimized diffofsums, only $s0 needs saving, so the frame is just four bytes.

STACK FRAME CONTENTS

Local variables and arrays, saved $s registers, saved argument registers when needed, the return address, and additional arguments beyond the first four. The caller allocates space for extra arguments; the callee can read them from the caller's frame.

When a function has more than four arguments, the first four still travel in $a0–$a3 and the caller places the rest in its own stack frame at fixed offsets before the call. Local variables that do not fit in registers are also kept in the frame. The frame pointer $fp can point to a fixed place in the frame so that offsets remain stable even while $sp changes during expression evaluation; a compiler may omit $fp and address everything relative to $sp when the frame size is known. On return the callee restores $sp, and the caller removes any outgoing argument space.

Recursion

A leaf function calls no other function. A nonleaf function does; a recursive function is a nonleaf function that calls itself. Each invocation needs its own stack frame because the old argument and the old return address must survive while the new call runs.

int factorial(int n) {
    if (n <= 1) return 1;
    else return n * factorial(n - 1);
}
factorial:
    addi $sp, $sp, -8      # frame for $a0 and $ra
    sw   $a0, 4($sp)
    sw   $ra, 0($sp)

    addi $t0, $0, 2
    slt  $t0, $a0, $t0     # t0 = (n < 2)
    beq  $t0, $0, else
    addi $v0, $0, 1        # base case: return 1
    addi $sp, $sp, 8
    jr   $ra

else:
    addi $a0, $a0, -1      # n - 1
    jal  factorial         # recursive call
    lw   $ra, 0($sp)
    lw   $a0, 4($sp)
    addi $sp, $sp, 8
    mul  $v0, $a0, $v0     # n * factorial(n-1)
    jr   $ra

For factorial(3) the calls descend 3 → 2 → 1. The base case returns 1, then the pending multiplications unwind: 2 × 1 = 2, then 3 × 2 = 6. Each frame is 8 bytes, so three nested calls use 24 bytes of stack. If the recursion were unbounded, the stack would eventually collide with the heap or the data segment—the hardware does not prevent it, so the programmer must ensure a base case is reached.

Addressing Modes

An addressing mode specifies how an instruction finds its operands. The mode determines whether an operand is in a register, in memory, or inside the instruction itself, and therefore influences instruction size, execution speed and programming flexibility. MIPS uses five modes, one for each natural kind of access.

ModeWhere the operand isUsed byExample
Register-onlyCPU registersAll R-type instructionsadd $s0, $t2, $t3

Register-only addressing

Both sources and the destination are registers. The ALU reads the register file, computes, and writes the result back. No memory access occurs, so this is the fastest mode. add $s0, $t2, $t3 performs $s0 = $t2 + $t3; sub $t8, $s1, $0 copies $s1 because $0 is always zero.

Immediate addressing

One operand is a 16-bit constant inside the instruction; the other is a register. Because no memory fetch is needed, immediates are ideal for initializing registers, updating counters, and applying small offsets. Examples include addi $s4, $t5, −73 and ori $t3, $t7, 0xFF. Arithmetic and memory immediates are sign-extended; logical immediates are zero-extended.

Base addressing

The operand is in memory. Its address is a base register plus a 16-bit signed offset. This is the mode used by loads and stores, and it is what makes arrays, structures, stack frames and dynamically allocated memory practical: keep the base fixed and change the offset, or change the base and keep the offset.

BASE ADDRESSING
Effective Address = Base register + Sign-extended offset
The offset is in bytes. It may be positive or negative, so one base register can reach data on either side of it.
lw $s4, 72($0)     # EA = 0 + 72 = 72; load word at address 72
sw $t2, -25($t1)   # EA = $t1 - 25; store $t2 there

PC-relative addressing

Branch instructions do not store a full destination address. They store a 16-bit signed offset in instructions relative to the next instruction. The hardware sign-extends the offset, multiplies by four (each instruction is four bytes), and adds it to PC + 4. This keeps branches compact and lets the same code run after being relocated, because the branch distance does not change.

BRANCH TARGET ADDRESS
BTA = (PC + 4) + (Sign-extended offset × 4)
The offset counts instructions, not bytes. A negative offset branches backward; a positive offset branches forward.
BRANCH OFFSET EXAMPLE

At 0x10: beq $t0, $0, else. The next instruction is at 0x14 and the target else is at 0x20. The distance is (0x20 − 0x14) / 4 = 3 instructions, so the immediate field is 3. The processor computes 0x14 + (3 × 4) = 0x20.

Pseudo-direct addressing

Jump instructions use a 26-bit address field. The processor forms the full 32-bit target by taking the upper four bits of PC + 4, appending the 26-bit field, and appending two zero bits because instructions are word-aligned. Only part of the destination is stored, which is why the mode is called pseudo-direct.

JUMP TARGET ADDRESS
JTA = {(PC + 4)[31:28], addr[25:0], 2'b00}
The low two bits are always 00. A jump can reach any word within the same 256 MB region selected by the top four PC bits.

For example, a j sum at 0x0040005C targeting 0x004000A0 has a 26-bit field of 0x0100028 (the target shifted right by two), opcode 2, and machine code 0x08100028. The top four bits of PC + 4 are zero, which is why the text segment is placed at 0x00400000: a jump can then reach any instruction in the program directly.

The MIPS Memory Map

A 32-bit address space contains 232 bytes = 4 GB. MIPS divides it into regions with different purposes. Word addresses are multiples of four, so the highest word address is 0xFFFFFFFC.

Address rangeSegmentPurpose
0x00000000 – 0x003FFFFCReservedOperating system, interrupts, memory-mapped I/O
0x00400000 – 0x0FFFFFFCTextMachine-language program; PC starts at 0x00400000
0x10000000 – 0x1000FFFCGlobal dataGlobal variables; $gp = 0x10008000
0x10010000 – 0x7FFFFFFCDynamic dataHeap (grows up from bottom) and stack (grows down from top)
0x80000000 – 0xFFFFFFFCReservedOperating system

The text segment is large enough for almost 256 MB of code. Its top four address bits are zero, so a J-type jump can reach any instruction in it. The global data segment holds variables declared outside functions; it is 64 KB because a 16-bit signed offset from $gp can reach ±32 KB around the fixed middle address 0x10008000. The offset is known at assembly time, so a global access is one base-addressed load or store.

The dynamic data segment is the largest, spanning almost 2 GB. The stack starts at 0x7FFFFFFC and grows downward as functions are called. The heap starts at the bottom and grows upward as malloc/new allocates memory. They grow toward each other; if they collide, the allocator reports an out-of-memory error. The stack is LIFO and holds stack frames; the heap is used and freed in arbitrary order.

SEGMENT ANALOGY

Text is the recipe book—read-only instructions. Global data is the shared noticeboard—everyone can see it. The stack is your own desk—local notes pushed and popped as you work. The heap is a storage room—space requested and released as needed.

Compiling and Assembling

A complete program passes through four tools: compiler → assembler → linker → loader. The compiler turns high-level code into assembly; the assembler turns assembly into an object file of machine code; the linker combines object files and libraries into an executable; the loader places the executable in memory and starts it. In practice a single command often runs all four.

High-level code→ Compiler→ Assembly→ Assembler→ Object file→ Linker→ Executable→ Loader→ Memory

Step 1: compilation

The compiler translates statements into instructions and emits assembler directives. .data marks the beginning of data, .text marks the beginning of code, and labels such as f:, g:, y: name global variables. At this stage the addresses are still symbolic; the assembler will assign them.

int f, g, y;
int main(void) { f = 2; g = 3; y = sum(f, g); return y; }
int sum(int a, int b) { return a + b; }

        .data
f:      g:      y:
        .text
main:   addi $sp, $sp, -4
        sw   $ra, 0($sp)
        addi $a0, $0, 2
        sw   $a0, f
        addi $a1, $0, 3
        sw   $a1, g
        jal  sum
        sw   $v0, y
        lw   $ra, 0($sp)
        addi $sp, $sp, 4
        jr   $ra
sum:    add  $v0, $a0, $a1
        jr   $ra

Step 2: assembly (two passes)

The assembler must resolve labels that may be defined later, so it makes two passes. Pass 1 walks the program assigning an address to every instruction and recording every label and global in a symbol table. Pass 2 emits the machine code, looking up symbol addresses and filling in branch/jump fields.

Globals are assigned storage starting at 0x10000000: f at 0x10000000, g at 0x10000004, y at 0x10000008. The symbol table records these addresses alongside the text labels. In this example there are 13 instructions, so the text size is 13 × 4 = 52 bytes (0x34), and three globals occupy 12 bytes (0xC).

Linking, Loading and Starting the Program

Linking combines several object files and library files into one executable. It relocates code and data so that different modules do not overlap, and it patches symbol references using each object file's symbol table. Linking exists because recompiling every file whenever one changes would be wasteful; if a high-level file is unchanged, its object file can be reused. Library files almost never change.

The resulting executable has three parts: a header giving the text and data sizes, a text segment containing the instructions in memory order, and a data segment containing the initial values of global variables. In the example the text size is 0x34 and the data size is 0xC.

Relocation and $gp

The linker converts a global access such as sw $a0, f into sw $a0, 0x8000($gp). The offset 0x8000 is a 16-bit signed value; sign-extending it gives 0xFFFF8000. Since $gp = 0x10008000:

GLOBAL DATA ADDRESS
$gp + 0xFFFF8000 = 0x10008000 + 0xFFFF8000 = 0x10000000
0x10000000 is the address of f. A negative 16-bit offset reaches globals below $gp.

Step 4: loading

The operating system's loader reads the executable's text segment from disk into the text region of memory, initializes the data segment, and sets up the machine state:

  • Read the text segment into memory starting at 0x00400000.
  • Set $gp = 0x10008000, the middle of the global data segment.
  • Set $sp = 0x7FFFFFFC, the top of the dynamic data segment.
  • Set the PC to 0x00400000 (often via jal 0x00400000) and begin execution.

At the first instruction, the text holds the 13 instructions, the globals f, g, y sit at 0x10000000–0x10000008, the stack is at the top of the dynamic segment, and the heap begins at the bottom. From that point the processor simply fetches, decodes and executes—the toolchain has done its job.

Parallelism: Latency and Throughput

Parallelism means performing multiple operations at the same time or overlapping their execution. Its main goal is to increase throughput—the amount of work completed per unit time—without necessarily reducing the latency of a single task. Raising clock frequency alone is no longer enough: it increases power and heat, so modern systems add hardware and overlap work instead.

LATENCY AND THROUGHPUT
Latency = time for one task     Throughput = tasks completed / unit time
Non-parallel system:   Throughput = 1 / Latency
High throughput does not imply low latency: many tasks can finish per hour while each one still takes a long time.

The cookie example

Ben rolls a tray of cookies in 5 minutes and bakes it in 15 minutes. If he waits for one tray to finish before starting the next, one tray takes 5 + 15 = 20 minutes and he completes three trays per hour. Latency is 20 minutes; throughput is 3 trays/hour.

ArrangementLatencyThroughputWhy
No parallelism20 min3 trays/hourOne tray at a time
Spatial: Alyssa helps20 min6 trays/hourTwo independent workers
Temporal: prepare while baking20 min4 trays/hourA new tray enters the oven every 15 min
Both20 min8 trays/hourTwo workers, each overlapping stages

The lesson is exact: parallelism multiplies throughput but leaves the latency of one tray unchanged. Spatial parallelism buys throughput with duplicate hardware; temporal parallelism buys throughput by overlapping stages of the same hardware.

MATHEMATICAL MODEL OF PARALLELISM
No parallelism:   Throughput = 1 / L     (L = latency of one task)
Spatial, N units:   Throughput = N / L
Temporal, N equal stages:   Throughput = N / L
Unequal stages, longest stage L1:   Throughput = 1 / L1
Latency stays L in every case. Adding stages raises throughput only when the stages are balanced; the slowest stage sets the rate.

Spatial versus temporal parallelism

SPATIAL PARALLELISM

Add copies of hardware so different tasks run literally at the same time: multiple processors, multiple ALUs, multicore CPUs, GPUs. High performance, but higher cost, area and power.

TEMPORAL PARALLELISM

Split one task into stages and let different tasks occupy different stages at the same time—an assembly line. Reuses the same hardware, so it is cheaper, but adds pipeline registers and control complexity.

Pipelining as Temporal Parallelism

A pipeline divides a long combinational path into shorter stages separated by registers. One task moves through the stages while the next task enters the first stage, exactly like an assembly line. The clock period is set by the slowest stage, not by the sum of all stages, so throughput rises sharply. The latency of one task is still the sum of all stage delays (plus register overhead).

PIPELINE TIMING
Tc = max(stage delays)     Throughput = 1 / Tc
Latency of one task = k × Tc    (k stages)
Unequal stages waste time: the slowest stage determines the clock, and faster stages sit idle part of each cycle.

Numerical example 1: two-stage pipeline

A circuit has clock-to-Q delay 0.3 ns, logic blocks of 3 ns, 2 ns and 4 ns, and setup time 0.2 ns. Without pipelining the whole path must settle in one cycle:

NO PIPELINE
Tc = 0.3 + 3 + 2 + 4 + 0.2 = 9.5 ns
Throughput = 1 / 9.5 ns ≈ 105 MHz

Insert one register after the 3 ns and 2 ns blocks. Stage 1 is 0.3 + 3 + 2 + 0.2 = 5.5 ns; stage 2 is 0.3 + 4 + 0.2 = 4.5 ns. The clock must satisfy the slower stage, so Tc = 5.5 ns and throughput is 1/5.5 ns ≈ 182 MHz. The individual task still takes about the same total time, but the system completes more tasks per second.

Numerical example 2: three-stage pipeline

Stages of 3.5 ns, 2.5 ns and 4.5 ns give Tc = max(3.5, 2.5, 4.5) = 4.5 ns. Latency = 3 × 4.5 = 13.5 ns. Throughput = 1/4.5 ns ≈ 222 MHz. The 3.5 ns and 2.5 ns stages are underutilized; balancing the stages would raise throughput further.

SPEEDUP

Speedup = old execution time / new execution time. If the original circuit runs at 9.5 ns per task and the two-stage pipeline runs at 5.5 ns per task, the ideal throughput speedup is 9.5/5.5 ≈ 1.73×. In a processor, pipeline overhead (register setup, clock-to-Q, hazards) reduces this below the ideal number of stages.

Pipelining is attractive because it does not duplicate the datapath: it inserts registers into the existing logic. Shorter combinational paths allow a higher clock, and the hardware is reused every cycle. The costs are pipeline registers, control complexity, and the hazards discussed next.

Pipeline Hazards

A hazard is a situation that prevents the next instruction from executing in its intended cycle. The pipeline must stall (insert a bubble) or forward data, and either response reduces throughput below the ideal one instruction per cycle.

HazardCauseTypical remedy
Data hazardAn instruction needs a value still being produced by an earlier instruction (read-after-write).Forwarding/bypassing; stall for load-use; register-file write/read timing.
Control hazardA branch or jump changes the PC, but the next instructions have already been fetched.Flush wrong-path instructions; branch prediction; delayed branch; move branch decision earlier.
Structural hazardTwo instructions need the same hardware resource in the same cycle.Duplicate resources (separate instruction/data memories, multiple ports) or schedule around the conflict.

Data hazards are the most common. If add $s0, $s1, $s2 is followed immediately by sub $t0, $s0, $s3, the subtract needs $s0 before the add has written it back. Forwarding routes the ALU result directly from the pipeline register to the next instruction's ALU input, avoiding a stall. A load followed immediately by a use of the loaded register cannot always be forwarded in time, so the pipeline stalls one cycle—the load-use hazard.

Control hazards arise because the processor does not know whether a branch is taken until the branch is evaluated. Instructions fetched after the branch may be wrong and must be flushed. Moving the branch decision to an earlier stage, predicting the direction, or defining a delayed branch slot reduces the penalty.

Structural hazards arise when the datapath has only one memory or one write port. MIPS avoids the worst case by using separate instruction and data memories and a register file that writes in the first half of the cycle and reads in the second half.

IDEAL VERSUS REAL

An ideal k-stage pipeline completes one instruction per cycle after filling, so CPI ≈ 1 and throughput ≈ 1/Tc. Hazards, stalls and flushes raise the effective CPI; the performance equation Time = IC × CPI × Tc still applies, with CPI now including pipeline penalties.

Parallelism at the instruction level (pipelining, multiple issue), at the data level (SIMD, GPUs) and at the task level (multicore) all follow the same trade-off: spend hardware or overlap time to raise throughput, while keeping latency and correctness under control.
