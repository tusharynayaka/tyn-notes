Unit 4: Microarchitecture

Microarchitecture introduction, performance analysis, and the single-cycle, multicycle and pipelined processors — datapaths, control, hazards, and every numerical.

1. Microarchitecture: Introduction

Microarchitecture is the specific arrangement of registers, ALUs, finite state machines, memories, multiplexers and other logic blocks used to implement an architecture in hardware. It connects the programmer-visible architecture (instructions, registers, memory) with the underlying digital logic and determines how those features are physically implemented. Different microarchitectures can implement the same architecture, differing in performance, cost and complexity while executing the same programs.

1.1 Architectural state

  • Architectural state determines everything about a processor: the PC, the 32 registers and memory (architecture = instruction set specification + architectural state).
  • Based on the current architectural state, the processor executes an instruction with its operands and produces a new architectural state.
  • Any MIPS microarchitecture must contain all of this state. It may also contain nonarchitectural state (temporary or pipeline registers) used to simplify the design or improve performance, not visible to the programmer.

1.2 Processor = datapath + control

  • Datapath — functional blocks (memories, registers, ALUs, multiplexers) operating on 32-bit words (MIPS is a 32-bit architecture).
  • Control unit — receives the current instruction from the datapath and generates control signals (mux selects, register enables, memory write signals).

1.3 Three implementations of one architecture

MicroarchitectureIdea
Single-cycleEach instruction executes in a single cycle
MulticycleEach instruction is broken into a series of shorter steps
PipelinedEach instruction is broken into steps and multiple instructions execute at once

1.4 MIPS subset implemented

R-type: and, or, add, sub, slt; memory: lw, sw; branch: beq (later extended with addi and j).

1.5 Design process

  1. Begin with the state elements: PC, register file, instruction memory, data memory.
  2. Add combinational logic (ALU, adders, muxes) between them to compute the next state.
  3. Organise memory (separate instruction and data memories for the basic designs).
  4. Design the datapath by connecting the blocks so every instruction can execute.
  5. Design the control that generates the select/enable signals.

Architectural state elements

  • PC — 32-bit register, input PC′
  • Register file — 32 × 32, ports A1/RD1, A2/RD2 (read), A3/WD3/WE3 (write), 5-bit addresses
  • Instruction memory — address A → RD (32-bit instruction)
  • Data memory — A, RD, WD, WE

Why clock frequency is not everything

  • Intel advertised Pentium III/4 by clock frequency, but AMD Athlon chips ran programs faster at the same frequency
  • Reason: lower CPI (more instructions per cycle) — performance = instruction count × CPI × clock period, not frequency alone

2. Performance Analysis

Processor performance is how quickly a computer completes a task; it is measured by execution time (lower time = better). The design challenge is to satisfy the constraints of cost, power and performance.

PROGRAM EXECUTION TIME
Execution Time = (# instructions)(cycles/instruction)(seconds/cycle) = # instructions × CPI × Tc
CPI = cycles per instruction; clock period Tc = seconds per cycle; IPC = instructions per cycle = 1/CPI.
  • Instruction count depends on the program and the instruction set; CPI on the processor implementation and instruction mix; Tc on the clock frequency. Reducing any factor (others constant) reduces execution time.
  • Clock frequency alone is not a sufficient measure — a faster clock with much higher CPI can still be slower.
RELATED FORMULAE
clock cycles = instruction count × CPI
Tc = 1 / clock frequency
average CPI = Σ (fractioni × CPIi)
Speedup = old execution time / new execution time
Amdahl: Speedup = 1 / [ (1 − f) + f / S ]
f = fraction of execution time improved; S = speedup of that fraction. Overall speedup is limited by the portion that cannot be improved.

3. Single-Cycle Datapath

A single-cycle processor completes each instruction in exactly one clock cycle; the clock period must be long enough for the slowest instruction. The PC holds the address of the instruction to be fetched; the datapath is built up one instruction at a time.

3.1 lw — step by step

  1. Fetch: PC is connected to the address input of instruction memory, which reads out the 32-bit Instr.
  2. Read source operand: the base register is in rs = Instr[25:21], connected to register-file address A1; RD1 outputs its value.
  3. Sign-extend the immediate: offset in Instr[15:0] is sign-extended to 32 bits: SignImm[15:0] = Instr[15:0], SignImm[31:16] = Instr[15].
  4. Compute the address: the ALU adds SrcA (from the register file) and SrcB (SignImm); 3-bit ALUControl = 010 (add). It produces a 32-bit ALUResult and a Zero flag (ALUResult == 0); ALUResult is the data-memory address.
  5. Read memory and write back: data goes onto ReadData and is written to the register file through port 3 (WD3). The destination is rt = Instr[20:16] connected to A3; RegWrite = 1 (to WE3) and the write happens on the rising clock edge at the end of the cycle.
  6. PC increment: an adder computes PCPlus4 (instructions are 4 bytes); the new address is written to the PC on the next rising edge.

3.2 sw

Same as lw (base register read, sign-extended immediate, ALU add for the address), plus the second register rt = Instr[20:16] goes to A2, and RD2 → WriteData of data memory. MemWrite = 1, ALUControl = 010, RegWrite = 0 (nothing written to the register file; ReadData is ignored).

3.3 R-type (add, sub, and, or, slt)

All read two registers (rs, rt), perform an ALU operation, and write the result to a third register; they differ only in ALUControl, so the same hardware is used. Additional muxes: ALUSrc = 0 selects RD2 (not SignImm) as SrcB; RegDst = 1 selects rd = Instr[15:11] (instead of rt) as the write register; MemtoReg = 0 selects ALUResult (not ReadData) for write-back; RegWrite = 1; MemWrite = 0.

3.4 beq

  • Two registers are read and compared with the ALU (subtract, ALUControl = 110). If Zero = 1 they are equal.
  • Offset = number of instructions to branch past, so SignImm is shifted left by 2 (×4) and added to PC + 4.
BRANCH TARGET & PC SELECT
BTA = (SignImm << 2) + (PC + 4)
PCSrc = Branch · Zero
PCSrc = 1 selects PCBranch as the next PC; otherwise PCPlus4. RegWrite = 0, MemWrite = 0, Branch = 1, ALUSrc = 0.
MUXES ARE ESSENTIAL

They let one datapath serve many instruction types: ALUSrc chooses register vs sign-extended immediate for SrcB; RegDst chooses rt vs rd as destination; MemtoReg chooses ALUResult vs ReadData for write-back; PCSrc chooses PC+4 vs branch target. The sign-extender widens the 16-bit signed immediate to 32 bits preserving sign.

4. Single-Cycle Control Unit

The control unit computes the control signals from the opcode (Instr[31:26]) and funct (Instr[5:0]). Most information comes from the opcode; R-type instructions also use funct to choose the ALU operation. The control unit is factored into two combinational blocks:

  • Main decoder — computes most outputs from the opcode and a 2-bit ALUOp.
  • ALU decoder — uses ALUOp together with funct to compute ALUControl[2:0].

4.5 Extended functionality

  • addi: no change to the datapath; it needs only a new main-decoder row (RegWrite 1, RegDst 0, ALUSrc 1, Branch 0, MemWrite 0, MemtoReg 0, ALUOp 00 → add).
  • j: adds a Jump control signal and a mux selecting PCJump as the next PC. PCJump = {PCPlus4[31:28], Instr[25:0], 00} (the 26-bit field shifted left by 2 → 28 bits, plus the upper 4 bits of PC+4).

6. Multicycle Datapath

A multicycle processor breaks each instruction into a series of shorter steps, each taking one (shorter) clock cycle. Different instructions use only the cycles they need, a single hardware unit is reused in different cycles (only one ALU, which also computes PC + 4 and branch targets), and the clock period is shorter. The architecture is unchanged.

Advantages

  • Shorter clock period
  • Hardware reuse (one ALU/adder, one memory)
  • Different instructions take different numbers of cycles

Disadvantages

  • More complex control (FSM sequencing)
  • Additional temporary (nonarchitectural) registers
  • Only one instruction executes at a time

6.1 State elements and new registers

  • Program counter, register file and main memory remain; the separate instruction and data memories are replaced by a single unified memory — more realistic, and possible because instruction fetch and data access occur in different cycles.
  • IR (instruction register) holds the fetched instruction (IRWrite) so it stays available through later cycles.
  • MDR / Data register holds data read from memory (written to the register file on a load).
  • A and B hold the register-file outputs (RD1, RD2) so operands stay available in later cycles.
  • ALUOut holds the ALU result at the end of a cycle for use in a later cycle (memory address, branch target).
  • Multiplexers: IorD (memory address = PC or ALUOut), ALUSrcA (PC or A), ALUSrcB (B, constant 4, SignImm, SignImm << 2), PCSrc (ALUResult or ALUOut).

6.2 lw, step by step

  1. Fetch: IorD = 0; memory read; IRWrite asserted, instruction → IR.
  2. Register read: rs (Instr[25:21]) read into A; rt into B.
  3. Immediate: Instr[15:0] sign-extended to SignImm.
  4. Address: ALUSrcA = 1 (A), ALUSrcB = 10 (SignImm), ALUControl = 010 → ALUResult saved in ALUOut.
  5. Memory read: IorD = 1 selects ALUOut as the address; data saved in the Data register.
  6. Write register: MemtoReg = 1 selects Data, destination rt (Instr[20:16], RegDst = 0), RegWrite asserted.
  7. Increment PC: the ALU is idle during fetch, so ALUSrcA = 0 (PC), ALUSrcB = 01 (constant 4), ALUControl = 010, PCSrc = 0, PCWrite → PC ← PC + 4 (done in the fetch cycle).

Only one adder (inside the ALU) is used; the lab datapath uses a separate adder for the PC. Using two adders would not change the architecture.

6.3 sw, R-type, beq

  • sw: after fetch and decode, the ALU computes base + SignImm into ALUOut; then B supplies the data and MemWrite is asserted with IorD = 1.
  • R-type: read rs, rt into A, B; ALU operates (ALUSrcB = 00); result written to the register file with RegDst = 1 (rd) and MemtoReg = 0.
  • beq: is rs == rt? BTA = (SignImm << 2) + (PC + 4). PCEn = PCWrite + (Branch · Zero); PCSrc = 1 selects ALUOut.

6.4 j (extended)

The PCSrc mux grows to three inputs (00 = ALUResult, 01 = ALUOut, 10 = PCJump) with PCJump = {PC[31:28], Instr[25:0] << 2}.

7. Multicycle Control: Main Controller FSM

The control unit has two parts as in the single-cycle design: the ALU decoder is unchanged (ALUOp/funct → ALUControl), and the main controller is an FSM that applies the proper control signals on the proper cycle. The sequence depends on the instruction. The FSM enters S0 on reset and every instruction ends by returning to S0.

7.2 The states

  • S0 Fetch: read memory at PC (IorD = 0); IRWrite asserted. The ALU is idle, so compute PC + 4 (ALUSrcA = 0, ALUSrcB = 01, ALUOp = 00 → add) and update the PC (PCSrc = 0, PCWrite).

8. Multicycle Performance

Instructions take different numbers of cycles — 3 cycles: beq, j; 4 cycles: R-type, sw, addi; 5 cycles: lw. CPI is the weighted average. SPECINT2000 mix: 25% loads, 10% stores, 11% branches, 2% jumps, 52% R-type.

AVERAGE CPI AND CLOCK PERIOD
CPI = (0.11 + 0.02)(3) + (0.52 + 0.10)(4) + (0.25)(5) = 4.12
Tc = tpcq + tmux + max(tALU + tmux, tmem) + tsetup

With the same delays as the single-cycle example: Tc = 30 + 25 + 250 + 20 = 325 ps (the memory term dominates max(ALU + mux, mem)).

Execution time = (# instructions) x CPI x Tc
               = (100 x 10^9)(4.12)(325 x 10^-12)
               = 133.9 seconds
WHY SLOWER THAN SINGLE-CYCLE (92.5 s)?

Not all steps are the same length (the clock must fit the slowest step), and there is a sequencing overhead (tpcq + tsetup = 50 ps) paid in every cycle.

9. Pipelined Processor: Introduction

A pipelined processor improves performance by executing multiple instructions simultaneously. Instruction execution is divided into stages; each stage does one part and passes the result on.

  1. Instruction Fetch (IF) — fetch the instruction from memory.
  2. Instruction Decode (ID) — decode and read the registers.
  3. Execute (EX) — perform the ALU operation (or address calculation).
  4. Memory Access (MEM) — read or write memory operands.
  5. Write Back (WB) — write the result to the register file.

After the pipeline fills, ideally one instruction completes every clock cycle, increasing throughput; individual instruction latency is not reduced (it is divided among stages). Each stage is represented by its main component: IM (instruction memory), RF read, ALU, DM (data memory), RF write-back.

9.1 Single-cycle vs pipelined: timing example

Stage delays: IF = 250, ID = 150, EX = 200, MEM = 250, WB = 100 ps.

10. Pipelined Datapath & Control

The pipelined datapath is formed by chopping the single-cycle datapath into five stages, separated by four pipeline registers. Pipeline registers hold data and control signals between stages: IF/ID holds the fetched instruction, ID/EX the decoded operands and control information, EX/MEM the ALU results, and MEM/WB the memory/ALU data for write-back. They let all stages operate concurrently; signals and registers are suffixed F, D, E, M, W by stage.

CRITICAL ISSUE: SIGNALS ADVANCE IN UNISON

All signals belonging to one instruction must advance through the pipeline together. A flawed design uses WriteRegE (Execute stage) as the register-file write address while the data comes from ResultW (Writeback stage); then in cycle 5 the result of lw would be written to the wrong register (e.g. $s4 instead of $s2). The fix is to pipeline the write-register number to the Writeback stage (WriteRegW).

10.1 Pipelined control

The pipelined processor takes the same control signals as the single-cycle processor and therefore uses the same control unit. The control unit examines opcode and funct in the Decode stage; the signals are then pipelined along with the instruction.

11. Hazards: Data, Control & Structural

A hazard occurs when the next instruction cannot execute in its intended clock cycle because of a conflict or dependency with another instruction. Types: structural (two instructions need the same hardware resource at once), data, and control.

11.1 Data hazards — RAW (read after write)

One instruction writes a register ($s0) and subsequent instructions read it (e.g. add $s0,$s2,$s3 followed by and, or, sub using $s0). The add writes $s0 in the first half of cycle 5; and reads $s0 in cycle 3 and or in cycle 4 — both get the wrong value; sub reads in the second half of cycle 5 and gets the correct value.

Solution 1: forwarding (bypassing)

  • Send a recently computed result directly from a later stage (Memory or Writeback) to the Execute-stage ALU input, reducing stalls.
  • Needed when the instruction in Execute has a source register matching the destination register of an instruction in the Memory or Writeback stage.
  • Hardware: a hazard detection unit and two forwarding multiplexers. The unit receives the source registers of the Execute-stage instruction, the destination registers of the Memory and Writeback instructions, and their RegWrite signals (sw and beq do not write registers, so their results need not be forwarded).
FORWARDING LOGIC (textbook form)
if (rsE ≠ 0 AND rsE == WriteRegM AND RegWriteM) ForwardAE = 10
else if (rsE ≠ 0 AND rsE == WriteRegW AND RegWriteW) ForwardAE = 01
else ForwardAE = 00 (same for ForwardBE with rtE)
10 → forward ALUOutM; 01 → forward ResultW; 00 → value from the register file (register $0 is never forwarded).

lw dependency (load-use hazard) — solution 2: stall

  • lw does not finish reading data until the end of the Memory stage, so its result cannot be forwarded to the Execute stage of the next instruction (data arrives at the end of cycle 4, the next instruction needs it at the start of cycle 4). Forwarding alone cannot solve it.
  • Stall the dependent instruction in the Decode stage (it stays through cycle 4); the following instruction must stay in Fetch for both cycles because Decode is full. In cycle 5 the result is forwarded from the Writeback stage of lw to the Execute stage of the dependent instruction.
  • The unused Execute stage in cycle 4 (Memory in cycle 5, Writeback in cycle 6) propagating through the pipeline is a bubble; it behaves like a nop, introduced by zeroing the Execute-stage control signals during a Decode stall so it changes no architectural state.
STALL LOGIC (textbook form)
lwstall = ((rsD == rtE) OR (rtD == rtE)) AND MemtoRegE
StallF = StallD = FlushE = lwstall

11.2 Control hazards (branches)

For beq the processor does not know which instruction to fetch next because the branch decision has not been made by the time the next instruction is fetched (in the basic pipeline the decision is made in the Memory stage).

  • Method 1 — stall until the branch decision is made (PCSrc computed): three stall cycles at every branch, which severely degrades performance.
  • Method 2 — predict (e.g. predict branches not taken and continue in order). If the branch should have been taken, the three following instructions must be flushed (discarded by clearing their pipeline registers). The wasted cycles are the branch misprediction penalty.
  • Reducing the penalty: decide earlier. Compare the two registers with a dedicated equality comparator (much faster than subtraction and zero detection) moved into the Decode stage, so the next PC is known by the end of Decode.
FLUSHING

Flushing removes instructions that entered the pipeline but should not execute, e.g. after a taken branch when sequential-path instructions were fetched before the outcome was known; they are replaced by bubbles or valid target-path instructions.

11.3 Hazard summary

Forwarding reduces data stalls, hazard detection identifies dependencies needing a stall, and branch prediction reduces control-hazard penalties — together keeping CPI close to one. The complete pipelined processor combines the control unit, forwarding muxes, stall/flush logic and the Decode-stage comparator under one hazard unit.

12. Pipelined Performance Analysis

The clock period is set by the slowest of the five stages:

PIPELINED CYCLE TIME
Tc = max of:
Fetch: tpcq + tmem + tsetup
Decode: 2(tRFread + tmux + teq + tAND + tmux + tsetup)
Execute: tpcq + tmux + tmux + tALU + tsetup
Memory: tpcq + tmemwrite + tsetup
Writeback: 2(tpcq + tmux + tRFwrite)
The factor 2 in Decode and Writeback arises because the register file is written in the first half and read in the second half of a cycle, so each of those stages gets half a cycle.

Because every instruction advances one stage per cycle, an ideal pipeline has CPI ≈ 1; stalls and flushes raise it slightly (e.g. about 1.15 for typical instruction mixes). Execution time = (# instructions) × CPI × Tc, which is why a pipeline (shorter Tc with CPI near 1) beats both single-cycle (long Tc, CPI 1) and multicycle (short Tc, CPI ≈ 4.12).
